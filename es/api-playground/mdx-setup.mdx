title: "Crear páginas de API manualmente"
description: "Crea páginas de referencia de API manualmente con archivos MDX cuando necesites un control total del diseño para APIs pequeñas, prototipos o documentación personalizada."
keywords: ["documentación de API", "documentación de endpoints"]
---

Puedes definir endpoints de API manualmente en páginas MDX individuales. Este enfoque resulta útil para APIs pequeñas o para prototipos.

<div id="setup">
  ## Configuración
</div>

<Steps>
  <Step title="Configura los ajustes de tu API">
    En tu archivo `docs.json`, define la URL base y el método de autenticación.

    ```json Example docs.json
    "api": {
      "mdx": {
        "server": "https://api.acme.com/",
        "auth": {
          "method": "key",
          "name": "x-api-key"
        }
      }
    }
    ```

    Si quieres ocultar el entorno de pruebas de API, establece el campo `display` como `none`. No necesitas incluir un método de autenticación si ocultas el entorno de pruebas.

    ```json
    "api": {
      "playground": {
        "display": "none"
      }
    }
    ```

    Encuentra la lista completa de configuraciones de la API en [Settings](/es/organize/settings-api).
  </Step>

  <Step title="Crea las páginas para tus endpoints">
    Crea un archivo MDX para cada endpoint. Define `title` y `api` en el frontmatter:

    ```mdx
    ---
    title: 'Create new user'
    api: 'POST /v1/users'
    ---
    ```

    El campo `api` del frontmatter acepta una URL completa o una ruta relativa:

    * **URL completa** como `POST https://api.acme.com/v1/users`. El campo `server` de `docs.json` se ignora para ese endpoint.
    * **Ruta relativa** como `POST /v1/users`. Requiere un campo `server` en `docs.json`. La URL del servidor se antepone a la ruta.

    Especifica los parámetros de la ruta encerrándolos entre `{}`:

    ```bash
    https://api.example.com/v1/endpoint/{userId}
    ```

    Para anular el modo de visualización global del entorno de pruebas en una página específica, agrega `playground` al frontmatter:

    ```mdx
    ---
    title: 'Create new user'
    api: 'POST https://api.mintlify.com/user'
    playground: 'none'
    ---
    ```

    Opciones:

    * `playground: 'interactive'` - Muestra el entorno de pruebas interactivo (predeterminado)
    * `playground: 'simple'` - Muestra un endpoint que se puede copiar, sin entorno de pruebas
    * `playground: 'none'` - Oculta el entorno de pruebas por completo
  </Step>

  <Step title="Añade parámetros y respuestas">
    Usa [campos de parámetros y de respuesta](/es/components/fields) para documentar los parámetros y los valores devueltos de tu endpoint.

    ```mdx
    <ParamField path="userId" type="string" required>
      Unique identifier for the user
    </ParamField>

    <ParamField body="email" type="string" required>
      User's email address
    </ParamField>

    <ResponseField name="id" type="string" required>
      Unique identifier for the newly created user
    </ResponseField>

    <ResponseField name="email" type="string" required>
      User's email address
    </ResponseField>
    ```
  </Step>

  <Step title="Añade tus endpoints a tu documentación">
    Agrega las páginas de tus endpoints a la navegación actualizando el campo `pages` en tu `docs.json`:

    ```json docs.json
    "navigation": {
      "tabs": [
        {
          "tab": "API Reference",
          "groups": [
            {
              "group": "Users",
              "pages": [
                "api-reference/users/create-user",
                "api-reference/users/get-user",
                "api-reference/users/update-user"
              ]
            },
            {
              "group": "Orders",
              "pages": [
                "api-reference/orders/create-order",
                "api-reference/orders/list-orders"
              ]
            }
          ]
        }
      ]
    }
    ```

    Cada ruta de página corresponde a un archivo MDX en tu repositorio de documentación. Por ejemplo, `api-reference/users/create-user.mdx`. Obtén más información sobre cómo estructurar tu documentación en [Navegación](/es/organize/navigation).

    ### Uso de endpoints de OpenAPI en la navegación

    Si tienes una especificación OpenAPI, puedes incluir endpoints directamente en tu navegación sin crear archivos MDX individuales. Haz referencia a endpoints específicos incluyendo la ruta del archivo OpenAPI y el endpoint:

    ```json docs.json
    "navigation": {
      "pages": [
        "introduction",
        "/path/to/users-openapi.json POST /users",
        "/path/to/orders-openapi.json GET /orders"
      ]
    }
    ```

    También puedes establecer una especificación de OpenAPI predeterminada para un grupo de Navegación y hacer referencia a endpoints por método y ruta:

    ```json docs.json
    {
      "group": "API reference",
      "openapi": "/path/to/openapi-v1.json",
      "pages": [
        "overview",
        "authentication",
        "GET /users",
        "POST /users",
        {
          "group": "Orders",
          "openapi": "/path/to/openapi-v2.json",
          "pages": [
            "GET /orders",
            "POST /orders"
          ]
        }
      ]
    }
    ```

    Para obtener más información sobre la integración con OpenAPI, consulta la [configuración de OpenAPI](/es/api-playground/openapi-setup).
  </Step>
</Steps>

<div id="enable-authentication">
  ## Habilitar la autenticación
</div>

Puedes configurar la autenticación globalmente en `docs.json` o sustituirla en páginas individuales mediante el campo `authMethod` en el frontmatter. Un método específico de una página sustituye la configuración global.

<div id="bearer-token">
  ### Token Bearer
</div>

<CodeGroup>
  ```json docs.json
  "api": {
    "mdx": {
      "auth": {
        "method": "bearer"
      }
    }
  }
  ```

  ```mdx Page Metadata
  ---
  title: "Your page title"
  authMethod: "bearer"
  ---
  ```
</CodeGroup>

<div id="basic-authentication">
  ### Autenticación básica
</div>

<CodeGroup>
  ```json docs.json
  "api": {
    "mdx": {
      "auth": {
        "method": "basic"
      }
    }
  }
  ```

  ```mdx Page Metadata
  ---
  title: "El título de tu página"
  authMethod: "basic"
  ---
  ```
</CodeGroup>

<div id="api-key">
  ### Clave de API
</div>

<CodeGroup>
  ```json docs.json
  "api": {
    "mdx": {
      "auth": {
        "method": "key",
        "name": "x-api-key"
      }
    }
  }
  ```

  ```mdx Page Metadata
  ---
  title: "Título de tu página"
  authMethod: "key"
  ---
  ```
</CodeGroup>

<div id="none">
  ### Ninguna
</div>

Para desactivar la autenticación en una página específica, establece `authMethod` en `none`:

```mdx Page Metadata
---
title: "Your page title"
authMethod: "none"
---
```
