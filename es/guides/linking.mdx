Los enlaces convierten tu documentación en un sistema coherente. Ayudan a los usuarios a descubrir contenido relacionado, navegar con eficiencia y seguir una ruta lógica por temas complejos. Los enlaces de mala calidad —texto de anclaje poco claro, falta de referencias cruzadas, URL rotas— hacen que la documentación sea más difícil de usar y perjudican el SEO.

Esta guía explica cómo crear distintos tipos de enlaces en Mintlify y cómo mantener su integridad a medida que tu documentación crece.

<div id="internal-links">
  ## Enlaces internos
</div>

Enlaza a otras páginas de tu documentación mediante rutas relativas a la raíz. Las rutas relativas a la raíz parten de la raíz de tu directorio de documentación y funcionan de forma coherente independientemente de dónde se encuentre la página que enlaza dentro de la estructura de directorios.

```mdx
- [Quickstart guide](/quickstart)
- [API overview](/api-playground/overview)
- [Custom components](/customize/react-components)
```

Evita rutas relativas como `../api-playground/overview`: dejan de funcionar cuando se mueven las páginas y son más difíciles de detectar de un vistazo durante la revisión.

<div id="anchor-links">
  ## Enlaces de anclaje
</div>

Los enlaces de anclaje apuntan a secciones específicas de una página. Cada encabezado genera automáticamente un anclaje a partir de su texto.

<div id="link-to-headers-on-the-same-page">
  ### Enlace a encabezados de la misma página
</div>

Haz referencia a los encabezados de la página actual con el símbolo de almohadilla:

```mdx
[Jump to best practices](#best-practices)
```

<div id="link-to-headers-on-other-pages">
  ### Enlace a encabezados en otras páginas
</div>

Combina la ruta de la página con el anclaje:

```mdx
- [Customize your playground](/api-playground/overview#customize-your-playground)
- [Cards properties](/components/cards#properties)
```

<div id="how-mintlify-generates-anchors">
  ### Cómo Mintlify genera los anclajes
</div>

Mintlify crea automáticamente anclajes a partir del texto de los encabezados: lo convierte a minúsculas, reemplaza los espacios por guiones y elimina los caracteres especiales.

| Texto del encabezado     | Anclaje generado      |
| ------------------------ | --------------------- |
| `## Getting Started`     | `#getting-started`    |
| `### API Authentication` | `#api-authentication` |
| `#### Step 1: Install`   | `#step-1-install`     |

<Note>
  Los encabezados con la prop `noAnchor` no generan enlaces de anclaje. Consulta [Formato de texto](/es/create/text#disabling-anchor-links) para obtener más información.
</Note>

<div id="custom-anchor-ids">
  ### Identificadores de anclaje personalizados
</div>

Sobrescribe el anclaje generado automáticamente de cualquier encabezado añadiendo `{#custom-id}` al texto del encabezado:

```mdx
## Configuration options {#config}
```

Se puede acceder a este encabezado mediante `#config` en lugar de `#configuration-options`. Los ID personalizados mantienen estables los enlaces de anclaje cuando actualizas el texto del encabezado, algo útil en los encabezados a los que enlazas con frecuencia. Consulta [Formato de texto](/es/create/text#custom-heading-ids) para obtener más información.

<div id="deep-links">
  ## Enlaces profundos
</div>

Los enlaces profundos apuntan a estados o ubicaciones concretos dentro de una página, no solo a la página en sí.

<div id="accordion-deep-links">
  ### Enlaces profundos de Accordion
</div>

Cuando un usuario abre un acordeón, el hash de la URL se actualiza para reflejar que está abierto. Al visitar una URL con ese hash, el acordeón se abre automáticamente y la página se desplaza hasta él.

De forma predeterminada, el hash se deriva del `title` del acordeón. Usa la propiedad `id` para establecer un hash personalizado:

```mdx
<Accordion title="Pasos de instalación" id="install">
  ...
</Accordion>
```

Se puede acceder a este acordeón en `#install` en lugar del `#installation-steps` generado automáticamente. Consulta [Accordions](/es/components/accordions) para obtener más información.

<div id="api-playground-deep-links">
  ### Enlaces profundos al entorno de pruebas de API
</div>

Para abrir el entorno de pruebas de API desde un enlace, agrega `?playground=open` a la URL de cualquier página de endpoint:

```text
https://your-docs-url/endpoint-path?playground=open
```

La URL se actualiza a medida que los usuarios abren o cierran el entorno de pruebas. Usa enlaces profundos al entorno de pruebas en conversaciones de soporte o flujos de incorporación para llevar a los usuarios directamente al entorno de pruebas interactivo de un endpoint. Consulta [entorno de pruebas de API](/es/api-playground/overview#parameter-anchor-links) para obtener información sobre los enlaces de anclaje de parámetros.

<div id="external-links">
  ## Enlaces externos
</div>

Al enlazar a recursos externos, escribe un texto del enlace que deje claro el destino:

```mdx
See the [OpenAPI specification](https://swagger.io/specification/) in the Swagger documentation for details.
```

<div id="best-practices">
  ## Buenas prácticas
</div>

<div id="write-descriptive-anchor-text">
  ### Escribe un texto de enlace descriptivo
</div>

El texto del enlace debe indicar a los usuarios adónde irán antes de hacer clic. Las frases vagas como &quot;haz clic aquí&quot; o &quot;más información&quot; también son señales de SEO más débiles que un texto descriptivo.

<CodeGroup>
  ```mdx Good
  Consulta [Páginas ocultas](/organize/hidden-pages) para obtener más información.
  [Configura dominios personalizados](/customize/custom-domain)
  ```

  ```mdx Avoid
  [Haz clic aquí](/api-playground/overview)
  [Más información](/deploy/deployments)
  [Consulta esta página](/customize/custom-domain)
  ```
</CodeGroup>

<div id="link-prerequisites-explicitly">
  ### Enlaza explícitamente los requisitos previos
</div>

Si una página da por sentado pasos previos, enlázalos al principio en lugar de asumir que los usuarios los encontrarán:

```mdx
## Requisitos previos

Antes de desplegar tu documentación, asegúrate de haber:

- Completado la [guía de inicio rápido](/quickstart)
- Configurado tu [dominio personalizado](/customize/custom-domain)
- Configurado la [autenticación](/deploy/authentication-setup) si es necesario
```

<div id="build-topic-clusters">
  ### Crea grupos temáticos
</div>

Vincula el contenido relacionado para ayudar a los usuarios —y a los motores de búsqueda— a comprender cómo está organizada tu documentación:

```mdx
## Temas relacionados

- [Autenticación de API](/api-playground/overview#authentication)
- [Agregar ejemplos de SDK](/api-playground/adding-sdk-examples)
- [Gestionar la visibilidad de páginas](/api-playground/managing-page-visibility)
```

<div id="check-for-broken-links">
  ### Comprueba los enlaces rotos
</div>

Ejecuta la CLI de Mintlify antes de publicar para detectar enlaces rotos internos y externos:

```bash
mint broken-links
```

<div id="update-links-when-reorganizing">
  ### Actualiza los enlaces al reorganizar el contenido
</div>

Al mover o cambiar el nombre de páginas:

1. Actualiza la ruta de la página en tu configuración de Navegación.
2. Configura redirecciones de la ruta anterior a la nueva.
3. Busca en tu documentación referencias a la ruta anterior.
4. Actualiza todos los enlaces internos para que usen la nueva ruta.
5. Ejecuta `mint broken-links` para comprobarlo.

<div id="use-redirects-for-moved-content">
  ### Usa redirecciones para el contenido trasladado
</div>

Cuando traslades contenido de forma permanente, agrega redirecciones para evitar enlaces rotos para los usuarios que hayan guardado o compartido URLs antiguas.

```json
{
  "redirects": [
    {
      "source": "/old-path",
      "destination": "/new-path"
    }
  ]
}
```

Consulta [Redirecciones](/es/create/redirects) para más información.

<div id="frequently-asked-questions">
  ## Preguntas frecuentes
</div>

<AccordionGroup>
  <Accordion title="¿Debo usar URL relativas a la raíz o URL absolutas para los enlaces internos?">
    Las rutas relativas a la raíz (que empiezan por `/`) son la opción adecuada para los enlaces internos en Mintlify. Funcionan de forma consistente independientemente de dónde esté la página que enlaza dentro de tu directorio y no se rompen si cambia el dominio de tu documentación. Usar URL absolutas para enlaces internos introduce una fragilidad innecesaria.
  </Accordion>

  <Accordion title="¿Cómo mantengo estables los enlaces de anclaje cuando actualizo los encabezados?">
    Usa ID de anclaje personalizados para los encabezados a los que enlazas con frecuencia. Añadir `{#custom-id}` a un encabezado desvincula el anclaje del texto del encabezado, de modo que puedes actualizar ese texto sin romper los enlaces que apuntan a él. Esto resulta especialmente útil en encabezados de secciones de referencia muy consultadas, donde puede hacer falta ajustar el texto con el tiempo.
  </Accordion>

  <Accordion title="¿Qué ocurre con los enlaces guardados en marcadores cuando reorganizo mi documentación?">
    Sin redirecciones, los enlaces guardados en marcadores y los compartidos se convierten en errores 404. Configura redirecciones en tu `docs.json` siempre que muevas o cambies el nombre de una página. Añadir redirecciones es sencillo y evita una mala experiencia a cualquier persona que haya enlazado a tu documentación desde una fuente externa: entradas de blog, respuestas en Stack Overflow o wikis internas.
  </Accordion>

  <Accordion title="¿Cuántos enlaces internos debe tener una página?">
    Añade enlaces cuando un concepto relacionado sea realmente útil para el usuario en ese momento, no para cumplir una cuota. Muy pocos enlaces dejan a los usuarios sin contexto o sin saber cuál es el siguiente paso. Demasiados convierten la página en un ejercicio de navegación que los aleja de lo que intentan hacer. Como orientación general, enlaza la primera mención de un concepto o herramienta y no repitas el mismo enlace varias veces en una misma página.
  </Accordion>
</AccordionGroup>
