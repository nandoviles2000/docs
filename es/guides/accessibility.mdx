Cuando creas documentación accesible, priorizas un diseño de contenido que hace que tu documentación pueda usarla la mayor cantidad de personas posible, independientemente de cómo accedan a ella o interactúen con ella.

La documentación accesible mejora la experiencia de usuario para todos. Tu contenido es más claro, está mejor estructurado y es más fácil de recorrer.

Esta guía ofrece algunas prácticas recomendadas para crear documentación accesible, pero no es exhaustiva. Debes considerar la accesibilidad como un proceso continuo. Las tecnologías y los estándares cambian con el tiempo, lo que abre nuevas oportunidades para mejorar la documentación.

<div id="what-is-accessibility">
  ## ¿Qué es la accesibilidad?
</div>

La accesibilidad (a veces abreviada como a11y, por el número de letras entre la primera y la última de &quot;accessibility&quot;) consiste en diseñar y crear intencionadamente sitios web y herramientas que pueda usar el mayor número posible de personas. Las personas con discapacidades temporales o permanentes deben tener el mismo nivel de acceso a las tecnologías digitales. Además, diseñar pensando en la accesibilidad beneficia a todo el mundo, incluidas las personas que acceden a tu sitio web desde dispositivos móviles o redes lentas.

La documentación accesible sigue los estándares de accesibilidad web, principalmente las [Pautas de Accesibilidad para el Contenido Web (WCAG)](https://www.w3.org/WAI/WCAG22/quickref/). Estas pautas ayudan a garantizar que tu contenido sea perceptible, operable, comprensible y sólido.

<div id="getting-started-with-accessibility">
  ## Primeros pasos con la accesibilidad
</div>

Hacer que tu documentación sea accesible es un proceso. No tienes que solucionarlo todo de una vez ni basta con hacerlo una sola vez.

Si apenas estás empezando a implementar prácticas de accesibilidad en tu documentación, considera adoptar un enfoque por fases: empieza por los cambios de mayor impacto y avanza a partir de ahí.

<div id="first-steps">
  ### Primeros pasos
</div>

Aquí tienes tres cosas que puedes hacer ahora mismo para mejorar la accesibilidad de tu documentación:

1. **Ejecuta `mint a11y`** para identificar problemas de accesibilidad en tu contenido.
2. **Añade texto alternativo** a todas las imágenes.
3. **Revisa la jerarquía de tus encabezados** para asegurarte de que haya un H1 por página y de que los encabezados sigan un orden secuencial.

<div id="plan-your-accessibility-work">
  ### Planifica el trabajo de accesibilidad
</div>

El mejor flujo de trabajo es el que mejor funciona para tu equipo. Esta es una forma de abordar la accesibilidad:

**Fase 1: Imágenes y estructura**

* Revisa que todas las imágenes tengan un texto alternativo descriptivo.
* Revisa el texto de los enlaces y sustituye frases genéricas como &quot;haz clic aquí&quot;.
* Corrige los problemas de jerarquía de encabezados en toda tu documentación.

**Fase 2: Navegación y contenido multimedia**

* Prueba la navegación por teclado en tu documentación.
* Comprueba la compatibilidad con lectores de pantalla.
* Añade subtítulos y transcripciones a los videos incrustados.
* Revisa el contraste de color.

**Fase 3: Incorpóralo a tu flujo de trabajo**

* Ejecuta `mint a11y` antes de publicar contenido nuevo.
* Incluye comprobaciones de accesibilidad en tu proceso de revisión de contenido.
* Prueba la navegación por teclado al añadir funciones interactivas.
* Verifica que los enlaces externos y los elementos incrustados nuevos incluyan títulos y descripciones adecuados.

Empezar poco a poco e incorporar la accesibilidad a tu flujo de trabajo habitual hace que sea sostenible. Cada mejora ayuda a que más usuarios puedan acceder correctamente a tu documentación.

<div id="structure-your-content">
  ## Estructura tu contenido
</div>

Un contenido bien estructurado es más fácil de recorrer y comprender, especialmente para los usuarios de lectores de pantalla, que dependen de los encabezados para desplazarse por las páginas, y para quienes usan la navegación por teclado.

<div id="use-proper-heading-hierarchy">
  ### Usa una jerarquía de encabezados correcta
</div>

Cada página debe tener un único encabezado H1, que se define mediante la propiedad `title:` en el frontmatter de la página. Usa los encabezados adicionales en orden, sin omitir niveles. Por ejemplo, no pases de H2 a H4.

```mdx
<!-- Correcto -->
# Título de página (H1)

## Sección principal (H2)

### Subsección (H3)

### Otra subsección (H3)

## Otra sección principal (H2)

<!-- Incorrecto -->
# Título de página (H1)

## Sección principal (H2)

#### Subsección (H4)

### Otra subsección (H3)
```

Los encabezados del mismo nivel deben tener nombres únicos.

```mdx
<!-- Correcto -->
## Consejos de accesibilidad (H2)

### Escribe texto alternativo efectivo (H3)

### Usa el contraste de color adecuado (H3)

<!-- Incorrecto -->
## Consejos de accesibilidad (H2)

### Tip (H3)

### Tip (H3)
```

<div id="write-descriptive-link-text">
  ### Escribe un texto descriptivo para los enlaces
</div>

El texto de los enlaces debe ser claro y estar relacionado con el destino. Evita frases vagas como &quot;haz clic aquí&quot; o &quot;leer más&quot;.

```mdx
<!-- Correcto -->
Learn how to [configure your navigation](/organize/navigation).

<!-- Relación poco clara entre el texto del enlace y el destino -->
[Learn more](/organize/navigation).
```

<div id="keep-content-scannable">
  ### Haz que el contenido sea fácil de revisar
</div>

* Divide los párrafos largos.
* Usa listas para los pasos y las opciones.
* Resalta la información con recuadros.

<div id="use-proper-table-structure">
  ### Usa una estructura de tabla correcta
</div>

Usa las tablas con moderación y solo para datos tabulares cuyo significado provenga de los encabezados de columnas y filas.

Al usar tablas, incluye encabezados para que los lectores de pantalla puedan asociar los datos con la columna correcta:

```mdx
| Feature | Status |
| ------- | ------ |
| Search  | Active |
| Analytics | Active |
```

<div id="write-descriptive-alt-text">
  ## Escribe un texto alternativo descriptivo
</div>

El texto alternativo hace que las imágenes sean accesibles para las personas que usan lectores de pantalla y aparece cuando las imágenes no se cargan. Las imágenes de tu documentación deben incluir un texto alternativo que describa la imagen y deje claro por qué está incluida. Incluso con texto alternativo, no debes depender solo de las imágenes para transmitir información. Asegúrate de que tu contenido describa lo que la imagen comunica.

<div id="write-effective-alt-text">
  ### Escribe un texto alternativo eficaz
</div>

* **Sé específico**: Describe lo que muestra la imagen, no te limites a decir que es una imagen.
* **Sé conciso**: Procura limitarte a una o dos frases.
* **Evita la redundancia**: No empieces con &quot;Imagen de&quot; porque los lectores de pantalla ya saben que el texto alternativo está asociado a una imagen. Sin embargo, debes incluir descripciones como &quot;Captura de pantalla de&quot; o &quot;Diagrama de&quot; si ese contexto es importante para la imagen.

```mdx
<!-- Correcto -->
![Screenshot of the dashboard showing three active projects and two pending invitations](/images/dashboard.png)

<!-- No es útil -->
![Dashboard screenshot](/images/dashboard.png)
```

<div id="add-alt-text-to-images">
  ### Añade texto alternativo a las imágenes
</div>

En las imágenes en Markdown, incluye el texto alternativo entre corchetes:

```mdx
![Description of the image](/path/to/image.png)
```

En las imágenes HTML, usa el atributo `alt`:

```html
<img
  src="/images/screenshot.png"
  alt="Settings panel with accessibility options enabled. The options are emphasized with an orange rectangle."
/>
```

<div id="add-titles-to-embedded-content">
  ### Añade títulos al contenido incrustado
</div>

Los iframes y los videos incrustados requieren títulos descriptivos:

```html
<iframe
  src="https://www.youtube.com/embed/example"
  title="Tutorial: Setting up your first documentation site"
></iframe>
```

<div id="design-for-readability">
  ## Diseña para mejorar la legibilidad
</div>

Las decisiones de diseño visual afectan a la accesibilidad de tu documentación para los usuarios con baja visión, daltonismo u otras discapacidades visuales.

<div id="ensure-sufficient-color-contrast">
  ### Garantiza un contraste de color suficiente
</div>

Si personalizas los colores de tu tema, verifica que las relaciones de contraste cumplan con los requisitos de las WCAG:

* Texto principal: relación de contraste mínima de 4.5:1
* Texto grande: relación de contraste mínima de 3:1
* Elementos interactivos: relación de contraste mínima de 3:1

Haz pruebas tanto en modo claro como en modo oscuro. El comando `mint a11y` comprueba el contraste de color.

<div id="dont-rely-on-color-alone">
  ### No dependas solo del color
</div>

Si usas el color para transmitir información, incluye también una etiqueta de texto o un icono. Por ejemplo, no marques los errores solo con texto rojo. Incluye un icono de error o la palabra «Error».

<div id="use-clear-concise-language">
  ### Usa un lenguaje claro y conciso
</div>

* Escribe con un lenguaje sencillo.
* Define los términos técnicos la primera vez que los uses.
* Evita las oraciones demasiado largas.
* Usa la voz activa.

<div id="make-code-examples-accessible">
  ## Haz accesibles los ejemplos de código
</div>

Los bloques de código son una parte fundamental de la documentación técnica, pero requieren ciertas consideraciones de accesibilidad para garantizar que las personas que usan lectores de pantalla puedan comprenderlos. En general, sigue estas pautas:

* Divide los ejemplos de código largos en fragmentos más pequeños y coherentes.
* Añade comentarios para explicar la lógica compleja dentro del código.
* Considera incluir una descripción textual para los algoritmos complejos.
* Al mostrar la estructura de archivos, usa bloques de código reales con etiquetas de lenguaje en lugar de arte ASCII.

<div id="specify-the-programming-language">
  ### Especifica el lenguaje de programación
</div>

Indica siempre el lenguaje para el resaltado de sintaxis. Esto ayuda a que los lectores de pantalla comuniquen a los usuarios el contexto del código:

````mdx
```javascript
function getUserData(id) {
  return fetch(`/api/users/${id}`);
}
```
````

<div id="provide-context-around-code">
  ### Proporciona contexto sobre el código
</div>

Proporciona un contexto claro para los bloques de código:

````mdx
La siguiente función obtiene datos del usuario desde la API:

```javascript
function getUserData(id) {
  return fetch(`/api/users/${id}`);
}
```

Esto devuelve una promesa que se resuelve en el objeto de usuario.
````

<div id="video-and-multimedia-accessibility">
  ## Accesibilidad de los videos y el contenido multimedia
</div>

Los videos, las animaciones y otros contenidos multimedia necesitan alternativas textuales para que todos los usuarios puedan acceder a la información que contienen.

<div id="add-captions-to-videos">
  ### Añade subtítulos a los videos
</div>

Los subtítulos hacen que el contenido en video sea accesible para las personas sordas o con dificultades auditivas. También ayudan a quienes se encuentran en entornos donde el sonido puede resultar molesto y a quienes no son hablantes nativos:

* Usa subtítulos para todo el contenido hablado de los videos.
* Incluye en los subtítulos los efectos de sonido relevantes.
* Asegúrate de que los subtítulos estén sincronizados con el audio.
* Usa la puntuación adecuada e identifica a quien habla cuando intervienen varias personas.

La mayoría de las plataformas de alojamiento de video permiten añadir subtítulos. Sube archivos de subtítulos o usa subtítulos generados automáticamente como punto de partida y, después, revísalos para comprobar su precisión.

<div id="provide-transcripts">
  ### Proporciona transcripciones
</div>

Las transcripciones ofrecen una forma alternativa de acceder al contenido de video. Permiten hacer búsquedas, son más fáciles de consultar y son accesibles para los lectores de pantalla:

```mdx
<iframe
  src="https://www.youtube.com/embed/example"
  title="Tutorial: Setting up authentication"
></iframe>

<Accordion title="Video transcript">
In this tutorial, we'll walk through setting up authentication...
</Accordion>
```

Coloca las transcripciones junto al video o proporciona un enlace claro para acceder a ellas.

<div id="consider-alternatives-to-video-only-content">
  ### Considera alternativas al contenido exclusivamente en video
</div>

Si la información crítica solo aparece en un video:

* Proporciona la misma información en formato de texto.
* Incluye capturas de pantalla clave con texto alternativo descriptivo.
* Crea un tutorial escrito que cubra el mismo contenido.

Esto garantiza que los usuarios que no pueden acceder al contenido en video también puedan completar su tarea.

<div id="test-your-documentation">
  ## Prueba tu documentación
</div>

Las pruebas periódicas te ayudan a detectar problemas de accesibilidad antes de que los usuarios se topen con ellos.

<div id="check-for-accessibility-issues-with-mint-a11y">
  ### Comprueba si hay problemas de accesibilidad con `mint a11y`
</div>

Usa el comando de la CLI `mint a11y` para analizar automáticamente tu documentación y detectar problemas de accesibilidad comunes:

```bash
mint a11y
```

El comando comprueba lo siguiente:

* Falta de texto alternativo en imágenes y videos.
* Contraste de color insuficiente.

Cuando finalice el análisis, revisa los problemas detectados y corrígelos en tu contenido. Vuelve a ejecutar el comando para verificar las correcciones.

Usa opciones para comprobar problemas de accesibilidad específicos.

```bash
# Verificar solo el texto alternativo faltante
mint a11y --skip-contrast

# Verificar solo los problemas de contraste de color
mint a11y --skip-alt-text
```

<div id="basic-keyboard-navigation-test">
  ### Prueba básica de navegación por teclado
</div>

Navega por tu documentación usando solo el teclado:

1. Presiona <kbd>Tab</kbd> para avanzar por los elementos interactivos.
2. Presiona <kbd>Shift</kbd> + <kbd>Tab</kbd> para retroceder.
3. Presiona <kbd>Enter</kbd> para activar enlaces y botones.
4. Verifica que todos los elementos interactivos sean accesibles y tengan indicadores visibles de enfoque.

<div id="go-deeper-with-accessibility-testing">
  ### Profundiza en las pruebas de accesibilidad
</div>

Para realizar pruebas más exhaustivas:

* **Lectores de pantalla**: Prueba con [NVDA (Windows)](https://www.nvaccess.org/) o [VoiceOver (Mac)](https://www.apple.com/accessibility/voiceover/).
* **Extensiones del navegador**: Instala [axe DevTools](https://www.deque.com/axe/browser-extensions/) o [WAVE](https://wave.webaim.org/extension/) para analizar páginas y detectar problemas.
* **Pautas WCAG**: Consulta las [Web Content Accessibility Guidelines](https://www.w3.org/WAI/WCAG22/quickref/) para ver los estándares en detalle.
