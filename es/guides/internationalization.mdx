La internacionalización (i18n) es el proceso de diseñar software o contenido para que funcione en distintos idiomas y configuraciones regionales. Esta guía explica cómo estructurar los archivos, configurar la Navegación y mantener las traducciones de forma eficaz para ayudar a los usuarios a acceder a tu documentación en su idioma preferido y ampliar tu alcance global.

<div id="file-structure">
  ## Estructura de archivos
</div>

Organiza el contenido traducido en directorios específicos de cada idioma para que tu documentación sea más fácil de mantener y para organizar la Navegación por idioma.

Crea un directorio independiente para cada idioma con los [códigos de idioma ISO 639-1](https://en.wikipedia.org/wiki/List_of_ISO_639-1_codes). Coloca los archivos traducidos en estos directorios con la misma estructura que la de tu idioma predeterminado.

<Expandable title="códigos de idioma admitidos">
  * `ar` - Árabe
  * `ca` - Catalán
  * `cs` - Checo
  * `zh` o `zh-Hans` - Chino (simplificado)
  * `zh-Hant` - Chino (tradicional)
  * `de` - Alemán
  * `en` - Inglés
  * `es` - Español
  * `fi` - Finés
  * `fr` - Francés
  * `fr-CA` - Francés (canadiense)
  * `he` - Hebreo
  * `hi` - Hindi
  * `hu` - Húngaro
  * `id` - Indonesio
  * `it` - Italiano
  * `ja` - Japonés
  * `ko` - Coreano
  * `lv` - Letón
  * `nl` - Neerlandés
  * `no` - Noruego
  * `pl` - Polaco
  * `pt` o `pt-BR` - Portugués
  * `ro` - Rumano
  * `ru` - Ruso
  * `sv` - Sueco
  * `tr` - Turco
  * `uk` - Ucraniano
  * `uz` - Uzbeko
  * `vi` - Vietnamita
</Expandable>

```text Example file structure
docs/
├── index.mdx                    # Inglés (predeterminado)
├── quickstart.mdx
├── fr/
│   ├── index.mdx               # Francés
│   ├── quickstart.mdx
├── es/
│   ├── index.mdx               # Español
│   ├── quickstart.mdx
└── zh/
    ├── index.mdx               # Chino
    └── quickstart.mdx
```

<Tip>
  Mantén los mismos nombres de archivo y la misma estructura de directorios en todos los idiomas. Esto facilita mantener las traducciones e identificar el contenido que falta.
</Tip>

<div id="configure-the-language-switcher">
  ## Configura el selector de idioma
</div>

Para añadir un selector de idioma a tu documentación, configura el array `languages` en la sección de Navegación de tu `docs.json`.

```json docs.json
{
  "navigation": {
    "languages": [
      {
        "language": "en",
        "groups": [
          {
            "group": "Getting started",
            "pages": ["index", "quickstart"]
          }
        ]
      },
      {
        "language": "es",
        "groups": [
          {
            "group": "Comenzando",
            "pages": ["es/index", "es/quickstart"]
          }
        ]
      }
    ]
  }
}
```

Cada entrada de idioma en la matriz `languages` requiere lo siguiente:

* `language`: código de idioma ISO 639-1
* Estructura de navegación completa
* Rutas a los archivos traducidos

La estructura de navegación puede variar entre idiomas para adaptarse a las necesidades de contenido específicas de cada uno.

<Warning>
  No uses la misma ruta de página en más de un idioma. Duplicar rutas entre idiomas provoca un comportamiento indefinido. La ruta de cada página debe aparecer solo en la navegación de un idioma.
</Warning>

<div id="set-default-language">
  ### Establece el idioma predeterminado
</div>

El primer idioma de la matriz `languages` se usa automáticamente como predeterminado. Para usar otro idioma como predeterminado, reordena la matriz o agrega la propiedad `default`:

```json docs.json
{
  "navigation": {
    "languages": [
      {
        "language": "es",
        "groups": [...]
      },
      {
        "language": "en",
        "groups": [...]
      }
    ]
  }
}
```

También puedes usar la propiedad `default` para cambiar el orden:

```json docs.json
{
  "navigation": {
    "languages": [
      {
        "language": "en",
        "groups": [...]
      },
      {
        "language": "es",
        "default": true,
        "groups": [...]
      }
    ]
  }
}
```

<div id="single-language-documentation">
  ### Documentación en un solo idioma
</div>

Si solo quieres tener un idioma disponible sin un selector de idioma, elimina el campo `languages` de la configuración de navegación. En su lugar, define directamente la estructura de navegación:

```json docs.json
{
  "navigation": {
    "tabs": [
      {
        "tab": "Documentation",
        "groups": [
          {
            "group": "Getting started",
            "pages": ["index", "quickstart"]
          }
        ]
      }
    ]
  }
}
```

Esto muestra tu documentación en un solo idioma, sin la interfaz del selector de idioma.

<Tip>
  Traduce las etiquetas de Navegación, como los nombres de grupos o pestañas, para que coincidan con el idioma del contenido. Así crearás una experiencia totalmente localizada para tus usuarios.
</Tip>

<div id="global-navigation">
  ### Navegación global
</div>

Para añadir elementos de navegación global que aparezcan en todos los idiomas, configura el objeto `global` en la navegación de tu `docs.json`.

```json docs.json
{
  "navigation": {
    "global": {
      "anchors": [
        {
          "anchor": "Documentation",
          "href": "https://example.com/docs"
        },
        {
          "anchor": "Blog",
          "href": "https://example.com/blog"
        }
      ]
    },
    "languages": [
      // Navegación específica por idioma
    ]
  }
}
```

<div id="localized-footer-and-navbar">
  ### Pie de página y barra de navegación localizadas
</div>

Personaliza el pie de página y la barra de navegación de cada idioma para mostrar contenido traducido y enlaces específicos de cada región.

Agrega las propiedades `footer` y `navbar` a la configuración de cada idioma:

```json docs.json
{
  "navigation": {
    "languages": [
      {
        "language": "en",
        "footer": {
          "socials": {
            "x": "https://x.com/mintlify"
          },
          "links": [
            {
              "header": "Resources",
              "items": [
                { "label": "Documentation", "href": "/en/docs" },
                { "label": "Blog", "href": "https://mintlify.com/blog" }
              ]
            }
          ]
        },
        "navbar": {
          "links": [
            { "label": "Docs", "href": "/en/docs" }
          ],
          "primary": {
            "type": "button",
            "label": "Get Started",
            "href": "/en/quickstart"
          }
        },
        "groups": [
          {
            "group": "Getting started",
            "pages": ["en/quickstart", "en/index"]
          }
        ]
      },
      {
        "language": "es",
        "footer": {
          "socials": {
            "x": "https://x.com/mintlify"
          },
          "links": [
            {
              "header": "Recursos",
              "items": [
                { "label": "Documentación", "href": "/es/docs" },
                { "label": "Blog", "href": "https://mintlify.com/blog" }
              ]
            }
          ]
        },
        "navbar": {
          "links": [
            { "label": "Documentación", "href": "/es/docs" }
          ],
          "primary": {
            "type": "button",
            "label": "Comenzar",
            "href": "/es/quickstart"
          }
        },
        "groups": [
          {
            "group": "Comenzando",
            "pages": ["es/quickstart", "es/index"]
          }
```

Los elementos `footer` y `navbar` específicos de un idioma reemplazan la configuración global de ese idioma. Si un idioma no define estas propiedades, hereda la configuración global.

También puedes configurar un `banner` específico de un idioma siguiendo el mismo patrón.

<div id="translation-workflow">
  ### Flujo de trabajo de traducción
</div>

1. Actualiza el contenido original en tu idioma principal.
2. Identifica el contenido modificado.
3. Traduce el contenido modificado.
4. Revisa la exactitud de las traducciones.
5. Actualiza los archivos traducidos.
6. Verifica que la navegación y los enlaces funcionen.

<div id="external-translation-providers">
  ### Proveedores de traducción externos
</div>

Si trabajas con tus propios proveedores de traducción o traductores regionales, puedes integrar su flujo de trabajo con tu documentación de Mintlify mediante GitHub Actions o herramientas de CI/CD similares.

1. **Exporta el contenido fuente**: Extrae los archivos MDX que necesitan traducción.
2. **Envíalo a los traductores**: Proporciona los archivos a tu proveedor de traducción.
3. **Recibe las traducciones**: Recibe de vuelta los archivos MDX traducidos.
4. **Importa y despliega**: Añade los archivos traducidos a los directorios de idioma y actualiza la navegación.

Este flujo de trabajo de GitHub Actions exporta automáticamente el contenido modificado en inglés para su traducción cuando los PR se fusionan en main.

```yaml .github/workflows/export-for-translation.yml
name: Export content for translation

on:
  push:
    branches: [main]
    paths:
      - '*.mdx'
      - '!es/**'
      - '!fr/**'
      - '!zh/**'

# Evitar ejecuciones simultáneas del workflow para prevenir condiciones de carrera
concurrency:
  group: translation-export-${{ github.ref }}
  cancel-in-progress: false

jobs:
  export:
    runs-on: ubuntu-latest
    
    # Salida anticipada si no se detectan cambios (opcional - actúa como seguridad adicional)
    outputs:
      files-changed: ${{ steps.changed.outputs.has-files }}
    
    steps:
      - name: Checkout repository
        uses: actions/checkout@v4
        with:
          fetch-depth: 2

      - name: Get changed MDX files
        id: changed
        run: |
          # Verificar si existe el commit padre (gestiona el push inicial)
          if ! git rev-parse HEAD~1 >/dev/null 2>&1; then
            echo "has-files=false" >> $GITHUB_OUTPUT
            echo "files=" >> $GITHUB_OUTPUT
            echo "No parent commit found - skipping export"
            exit 0
          fi
          
          # Obtener lista de archivos MDX modificados (excluyendo directorios de traducción)
          files=$(git diff --name-only HEAD~1 HEAD -- '*.mdx' ':!es/' ':!fr/' ':!zh/' | tr '\n' ' ')
          
          if [ -z "$files" ]; then
            echo "has-files=false" >> $GITHUB_OUTPUT
            echo "files=" >> $GITHUB_OUTPUT
            echo "No MDX files changed - skipping export"
          else
            echo "has-files=true" >> $GITHUB_OUTPUT
            echo "files=$files" >> $GITHUB_OUTPUT
            echo "Found changed files: $files"
          fi
        shell: bash

      - name: Create translation package directory
        if: steps.changed.outputs.has-files == 'true'
        run: |
          mkdir -p translation-export
          echo "Created translation-export directory"

      - name: Copy changed files to export directory
        if: steps.changed.outputs.has-files == 'true'
        run: |
          failed_count=0
          for file in ${{ steps.changed.outputs.files }}; do
            if [ -f "$file" ]; then
              target_dir="translation-export/$(dirname "$file")"
              mkdir -p "$target_dir"
              cp "$file" "$target_dir/"
              echo "✓ Copied: $file"
            else
              echo "✗ File not found: $file"
              ((failed_count++))
            fi
          done
          
          if [ $failed_count -gt 0 ]; then
            echo "Warning: $failed_count file(s) could not be copied"
          fi
        shell: bash

      - name: Validate translation package
        if: steps.changed.outputs.has-files == 'true'
        run: |
          echo "Translation package contents:"
          find translation-export -type f -name "*.mdx" | sort
          echo ""
          file_count=$(find translation-export -type f -name "*.mdx" | wc -l)
          echo "Total MDX files: $file_count"

      - name: Upload translation package
        if: steps.changed.outputs.has-files == 'true'
        uses: actions/upload-artifact@v4
        with:
          name: translation-export-${{ github.sha }}
          path: translation-export/
          retention-days: 30
          if-no-files-found: error
          compression-level: 9

      - name: Print job summary
        if: steps.changed.outputs.has-files == 'true'
        run: |
          echo "## Translation Export Complete" >> $GITHUB_STEP_SUMMARY
          echo "" >> $GITHUB_STEP_SUMMARY
          echo "**Artifact:** \`translation-export-${{ github.sha }}\`" >> $GITHUB_STEP_SUMMARY
          echo "" >> $GITHUB_STEP_SUMMARY
          echo "**Changed Files:**" >> $GITHUB_STEP_SUMMARY
          echo "${{ steps.changed.outputs.files }}" | tr ' ' '\n' | sed 's/^/- /' >> $GITHUB_STEP_SUMMARY
```

Este flujo de trabajo de GitHub Actions valida e importa contenido traducido cuando se añade mediante una PR.

```yaml .github/workflows/import-translations.yml
name: Import translations

on:
  pull_request:
    paths:
      - 'es/**'
      - 'fr/**'
      - 'zh/**'

# Definir permisos explícitos
permissions:
  contents: read
  pull-requests: write

jobs:
  validate:
    runs-on: ubuntu-latest
    
    outputs:
      validation-status: ${{ steps.final-check.outputs.status }}
    
    steps:
      - name: Checkout repository
        uses: actions/checkout@v4
        with:
          fetch-depth: 0  # Full history to ensure origin/main is available

      - name: Fetch origin/main reference
        run: |
          git fetch origin main:origin/main 2>/dev/null || echo "origin/main not available, using latest"
        continue-on-error: true

      - name: Get changed translation files
        id: changed-files
        run: |
          # Obtener todos los archivos MDX modificados en los directorios de traducción
          files=$(git diff --name-only origin/main..HEAD -- 'es/**/*.mdx' 'fr/**/*.mdx' 'zh/**/*.mdx' | sort)
          
          if [ -z "$files" ]; then
            echo "No translation MDX files detected in this PR"
            echo "files=" >> $GITHUB_OUTPUT
            echo "count=0" >> $GITHUB_OUTPUT
          else
            echo "Found $(echo "$files" | wc -l) translation files"
            echo "$files"
            echo "files=$files" >> $GITHUB_OUTPUT
            echo "count=$(echo "$files" | wc -l)" >> $GITHUB_OUTPUT
          fi
        shell: bash

      - name: Validate frontmatter
        id: frontmatter
        if: steps.changed-files.outputs.count > 0
        run: |
          failed_files=()
          success_count=0
          total=${{ steps.changed-files.outputs.count }}
          
          while IFS= read -r file; do
            if [ ! -f "$file" ]; then
              echo "✗ File not found: $file"
              failed_files+=("$file")
              continue
            fi
            
            # Verificar que el frontmatter sea válido (las líneas 1-2 deben ser ---)
            first_line=$(sed -n '1p' "$file")
            second_line=$(sed -n '2p' "$file")
            last_line=$(awk 'NF' "$file" | tail -1)
            
            if [ "$first_line" = "---" ] && grep -q "^---$" "$file"; then
              echo "✓ Valid frontmatter: $file"
              ((success_count++))
            else
              echo "✗ Invalid frontmatter in $file"
              echo "  Line 1: '$first_line'"
              failed_files+=("$file")
            fi
          done <<< "${{ steps.changed-files.outputs.files }}"
          
          echo ""
          echo "Frontmatter check: $success_count/$total passed"
          
          if [ ${#failed_files[@]} -gt 0 ]; then
            echo "frontmatter_valid=false" >> $GITHUB_OUTPUT
            printf 'failed_files=%s\n' "${failed_files[@]}" >> $GITHUB_OUTPUT
          else
            echo "frontmatter_valid=true" >> $GITHUB_OUTPUT
          fi
        shell: bash

      - name: Check file structure
        id: structure
        if: steps.changed-files.outputs.count > 0
        run: |
          missing_sources=()
          orphaned_count=0
          
          while IFS= read -r translated_file; do
            # Extraer el idioma y la ruta relativa
            # p. ej., "es/docs/guide.mdx" -> lang="es", relative_path="docs/guide.mdx"
            lang=$(echo "$translated_file" | cut -d'/' -f1)
            relative_path=$(echo "$translated_file" | cut -d'/' -f2-)
            source_file="$relative_path"
            
            if [ ! -f "$source_file" ]; then
              echo "Missing source: $translated_file -> $source_file"
              missing_sources+=("$translated_file")
              ((orphaned_count++))
            else
              echo "✓ Found source: $translated_file -> $source_file"
            fi
          done <<< "${{ steps.changed-files.outputs.files }}"
          
          echo ""
          echo "Structure check: $orphaned_count orphaned file(s)"
          
          if [ $orphaned_count -gt 0 ]; then
            echo "structure_valid=false" >> $GITHUB_OUTPUT
            printf 'missing_sources=%s\n' "${missing_sources[@]}" >> $GITHUB_OUTPUT
          else
            echo "structure_valid=true" >> $GITHUB_OUTPUT
          fi
        shell: bash

      - name: Validate file integrity
        id: integrity
        if: steps.changed-files.outputs.count > 0
        run: |
          integrity_passed=true
          
          while IFS= read -r file; do
            # Verificar que el archivo sea legible y no esté vacío
            if [ ! -r "$file" ] || [ ! -s "$file" ]; then
              echo "✗ File integrity issue: $file (not readable or empty)"
              integrity_passed=false
            fi
            
            # Verificación básica: el archivo debe tener contenido después del frontmatter
            line_count=$(wc -l < "$file")
            if [ "$line_count" -lt 5 ]; then
              echo "File is suspiciously short: $file ($line_count lines)"
            fi
          done <<< "${{ steps.changed-files.outputs.files }}"
          
          if [ "$integrity_passed" = true ]; then
            echo "integrity_valid=true" >> $GITHUB_OUTPUT
          else
            echo "integrity_valid=false" >> $GITHUB_OUTPUT
          fi
        shell: bash

      - name: Generate validation report
        if: always()
        run: |
          echo "## Translation Validation Report" >> $GITHUB_STEP_SUMMARY
          echo "" >> $GITHUB_STEP_SUMMARY
          echo "**Files Changed:** ${{ steps.changed-files.outputs.count }}" >> $GITHUB_STEP_SUMMARY
          echo "" >> $GITHUB_STEP_SUMMARY
          
          if [ "${{ steps.changed-files.outputs.count }}" = "0" ]; then
            echo "No translation MDX files found in this PR" >> $GITHUB_STEP_SUMMARY
            echo "" >> $GITHUB_STEP_SUMMARY
            echo "> This could mean:" >> $GITHUB_STEP_SUMMARY
            echo "- Only non-MDX files in es/, fr/, or zh/ directories were changed" >> $GITHUB_STEP_SUMMARY
            echo "- Workflow was triggered but no translation content to validate" >> $GITHUB_STEP_SUMMARY
          else
            echo "### Validation Results" >> $GITHUB_STEP_SUMMARY
            echo "- Frontmatter: ${{ steps.frontmatter.outputs.frontmatter_valid }}" >> $GITHUB_STEP_SUMMARY
            echo "- File Structure: ${{ steps.structure.outputs.structure_valid }}" >> $GITHUB_STEP_SUMMARY
            echo "- File Integrity: ${{ steps.integrity.outputs.integrity_valid }}" >> $GITHUB_STEP_SUMMARY
            echo "" >> $GITHUB_STEP_SUMMARY
          fi
        shell: bash

      - name: Final validation check
        id: final-check
        # Ejecutar esta verificación solo si había archivos MDX para validar
        if: steps.changed-files.outputs.count > 0
        run: |
          validation_failed=false
          
          if [ "${{ steps.frontmatter.outputs.frontmatter_valid }}" != "true" ]; then
            echo "Frontmatter validation failed"
            validation_failed=true
          fi
          
          if [ "${{ steps.structure.outputs.structure_valid }}" != "true" ]; then
            echo "File structure validation failed"
            validation_failed=true
          fi
          
          if [ "${{ steps.integrity.outputs.integrity_valid }}" != "true" ]; then
            echo "File integrity validation failed"
            validation_failed=true
          fi
          
          if [ "$validation_failed" = true ]; then
            echo "status=failed" >> $GITHUB_OUTPUT
            exit 1
          else
            echo "status=passed" >> $GITHUB_OUTPUT
            echo "All validations passed"
          fi
        shell: bash

      - name: Handle no-files-to-validate case
        # Ejecutar solo cuando no haya archivos MDX para validar
        if: steps.changed-files.outputs.count == 0
        run: |
          echo "No translation MDX files to validate - PR is valid"
          echo "status=no-changes" >> ${{ steps.final-check.outputs }}
        shell: bash
```

**Buenas prácticas para los flujos de trabajo de traducción externos**

* **Conserva el frontmatter**: Asegúrate de que los traductores mantengan intacto el frontmatter YAML y traduzcan únicamente los valores de `title` y `description`.
* **Protege los bloques de código**: Marca los bloques de código como &quot;no traducir&quot; para tus proveedores.
* **Usa memoria de traducción**: Proporciona glosarios con términos técnicos que deban mantenerse en inglés o tener traducciones específicas.
* **Automatiza la validación**: Usa comprobaciones de CI para verificar la sintaxis de MDX y el frontmatter antes de integrar las traducciones.
* **Control de versiones**: Lleva un registro de la versión de origen de cada traducción para identificar contenido desactualizado.

<div id="date-and-number-formats">
  ### Formatos de fecha y número
</div>

Ten en cuenta los formatos de fecha y número específicos de cada configuración regional.

* Formatos de fecha: MM/DD/YYYY (mes/día/año) vs DD/MM/YYYY (día/mes/año)
* Formatos de número: 1,000.00 vs 1.000,00
* Símbolos de moneda: $100.00 vs 100,00€

Incluye ejemplos con el formato adecuado para cada idioma o usa formatos que se entiendan universalmente.

<div id="maintain-consistency">
  ### Mantén la consistencia
</div>

* Mantén la paridad del contenido en todos los idiomas para garantizar que cada usuario reciba información de la misma calidad.
* Crea un glosario de traducción para los términos técnicos.
* Mantén la misma estructura de contenido en todos los idiomas.
* Haz que el tono y el estilo coincidan con los del contenido fuente.
* Usa ramas de Git para gestionar el trabajo de traducción por separado de las actualizaciones del contenido principal.

<div id="layout-differences">
  ### Diferencias de diseño
</div>

Algunos idiomas requieren más o menos espacio que el inglés. Prueba el contenido traducido en distintos tamaños de pantalla para asegurarte de que:

* La navegación se ajuste correctamente.
* Los bloques de código no se desborden.
* Las tablas y otros textos con formato sigan siendo legibles.
* Las imágenes se escalen correctamente.

<div id="character-encoding">
  ### Codificación de caracteres
</div>

Asegúrate de que tu entorno de desarrollo y tu proceso de despliegue admitan la codificación UTF-8 para mostrar correctamente todos los caracteres en idiomas con distintos alfabetos y caracteres especiales.

<div id="frequently-asked-questions">
  ## Preguntas frecuentes
</div>

<AccordionGroup>
  <Accordion title="¿Necesito traducir todas las páginas antes de lanzar un nuevo idioma?">
    No. Puedes lanzar un idioma con cobertura parcial e ir ampliándola con el tiempo. Lo habitual es traducir primero las páginas más visitadas —normalmente el contenido de introducción, la autenticación y las principales guías prácticas— y dejar el contenido de referencia con menos tráfico en el idioma predeterminado hasta que las traducciones estén listas. En general, los usuarios prefieren tener algo de contenido traducido a no tener nada.
  </Accordion>

  <Accordion title="¿Qué ocurre si falta una página traducida?">
    Si un usuario accede a una URL traducida que no existe, verá un error 404. Para evitarlo, incluye solo las páginas traducidas en la navegación específica de cada idioma o mantén la paridad entre el idioma predeterminado y el contenido traducido. Usar la misma estructura de archivos en todos los idiomas facilita identificar qué traducciones faltan.
  </Accordion>

  <Accordion title="¿Deben traducirse las etiquetas de navegación?">
    Sí. Las etiquetas de navegación —como los nombres de grupos, los títulos de las pestañas y el texto de los anclajes— deben coincidir con el idioma del contenido. Una etiqueta en inglés como &quot;Getting started&quot; en una sección de documentación en español genera una experiencia poco fluida. Mintlify admite estructuras de navegación específicas por idioma, por lo que cada idioma puede tener etiquetas totalmente traducidas.
  </Accordion>

  <Accordion title="¿Cómo debo gestionar los ejemplos de código en el contenido traducido?">
    El código en sí no debe traducirse: los nombres de variables, las llamadas a funciones y la sintaxis son independientes del idioma. Los comentarios dentro de los bloques de código pueden traducirse si explican conceptos que los usuarios necesitan entender. Las instrucciones que acompañan a los bloques de código deben traducirse por completo.
  </Accordion>

  <Accordion title="¿Mintlify admite idiomas de derecha a izquierda, como árabe o hebreo?">
    Sí. El árabe (`ar`) y el hebreo (`he`) están en la lista de códigos de idioma compatibles. Mintlify gestiona automáticamente el diseño RTL cuando se configuran estos códigos de idioma. Prueba la documentación en RTL para verificar que la navegación, las tablas y los bloques de código se muestren correctamente.
  </Accordion>
</AccordionGroup>
