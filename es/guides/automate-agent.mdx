<div id="what-you-will-build">
  ## Lo que vas a crear
</div>

Una automatización que actualiza tu documentación cuando haces push de código a tu rama `main`. Puedes crear este flujo de trabajo en varias plataformas, como GitHub Actions y n8n. Supervisa tu repositorio de código y luego llama a la API del agente para actualizar tu documentación en un repositorio de documentación independiente.

Este flujo de trabajo conecta dos repositorios independientes:

* **Repositorio de código**: Donde almacenas el código de tu aplicación. Configurarás el desencadenador de la automatización en este repositorio. Algunos ejemplos son una API de backend, una aplicación frontend, un SDK o una herramienta CLI.
* **Repositorio de documentación**: Donde almacenas tu documentación y la conectas a tu proyecto de Mintlify. El agente crea solicitudes de extracción (pull request, PR) con actualizaciones de la documentación en este repositorio.

Este tutorial asume que tu documentación está en un repositorio independiente de tu código de aplicación. Si tienes un monorepo, modifica el flujo de trabajo para que apunte al directorio donde almacenas tu documentación.

<div id="workflow-overview">
  ### Descripción general del flujo de trabajo
</div>

1. Alguien hace push de código a tu rama `main`.
2. Se activa el flujo de trabajo.
3. El flujo de trabajo llama a la API del agente para actualizar tu documentación.
4. El agente crea una solicitud de extracción (pull request, PR) con actualizaciones de la documentación en el repositorio de tu documentación.

  <Tab title="GitHub Actions">
    GitHub Actions es la opción más sencilla si tu código ya está en GitHub. No necesitas servicios adicionales.

    ## Requisitos previos

    * GitHub Actions activado en tus repositorios de código y documentación
    * [Aplicación de GitHub de Mintlify](/es/deploy/github) instalada en tus repositorios de código y de documentación
    * [clave de API de administración de Mintlify](https://dashboard.mintlify.com/settings/organization/api-keys)
    * [ID del proyecto en Mintlify](https://dashboard.mintlify.com/settings/organization/api-keys)
    * [Plan Enterprise de Mintlify](https://mintlify.com/pricing)
    * Acceso administrativo a los repositorios de GitHub de tu código y documentación

    ### Instala la aplicación de Mintlify en tu repositorio de código

    Instala la aplicación de Mintlify en tu repositorio de código para que el agente pueda obtener contexto de tu base de código. Para agregar la aplicación a nuevos repositorios:

    1. Abre la página de [Agente](https://dashboard.mintlify.com/products/agent) en tu panel.
    2. Haz clic en **Agregar a una nueva organización**. Esto te llevará a la página de instalación de la aplicación en GitHub.
    3. Selecciona de la lista los repositorios a los que quieres dar acceso.
    4. Guarda los cambios.

    ### Obtén tu clave de API de administrador

    1. Ve a la página de [claves de API](https://dashboard.mintlify.com/settings/organization/api-keys) en tu panel.
    2. Selecciona **Crear clave de API de administrador**.
    3. Copia la clave y guárdala en un lugar seguro.

    ## Crea el flujo de trabajo

    ### Crea el archivo de flujo de trabajo

    1. En tu repositorio de código, crea un archivo nuevo: `.github/workflows/update-docs.yml`
    2. Agrega este flujo de trabajo:

       ```yaml
       name: Update Docs

       on:
         push:
           branches:
             - main

       jobs:
         update-docs:
           runs-on: ubuntu-latest
           steps:
             - uses: actions/github-script@v8
               env:
                 MINTLIFY_API_KEY: ${{ secrets.MINTLIFY_API_KEY }}
                 PROJECT_ID: ${{ secrets.MINTLIFY_PROJECT_ID }}
               with:
                 script: |
                   const { owner, repo } = context.repo;
                   const projectId = process.env.PROJECT_ID;
                   const apiKey = process.env.MINTLIFY_API_KEY;

                   if (!projectId || !apiKey) {
                     core.setFailed('Missing MINTLIFY_PROJECT_ID or MINTLIFY_API_KEY secrets');
                     return;
                   }

                   const url = `https://api.mintlify.com/v1/agent/${projectId}/job`;
                   const payload = {
                     branch: `mintlify/docs-update-${Date.now()}`,
                     messages: [
                       {
                         role: 'system',
                         content: 'You are an action runner that updates documentation based on code changes. You should never ask questions. If you are not able to access the repository, report the error and exit.'
                       },
                       {
                         role: 'user',
                         content: `Update the documentation for our recent pushes to main:\n\nRepository: ${owner}/${repo}`
                       }
                     ],
                     asDraft: false
                   };

                   try {
                     const response = await fetch(url, {
                       method: 'POST',
                       headers: {
                         'Authorization': `Bearer ${apiKey}`,
                         'Content-Type': 'application/json'
                       },
                       body: JSON.stringify(payload)
                     });

                     if (!response.ok) {
                       throw new Error(`API request failed with status ${response.status}: ${await response.text()}`);
                     }

                     const reader = response.body.getReader();
                     const decoder = new TextDecoder();
                     let buffer = '';

                     while (true) {
                       const { done, value } = await reader.read();
                       if (done) break;
                       buffer += decoder.decode(value, { stream: true });
                       const lines = buffer.split('\n');
                       buffer = lines.pop() || '';
                       for (const line of lines) {
                         if (line.trim()) {
                           console.log(line);
                         }
                       }
                     }
                     if (buffer.trim()) {
                       console.log(buffer);
                     }

                     core.notice(`Documentation update job triggered for ${owner}/${repo}`);
                   } catch (error) {
                     core.setFailed(`Failed to create documentation update job: ${error.message}`);
                   }
       ```

    ### Agregar secretos

    1. En tu repositorio de código, ve a **Settings** → **Secrets and variables** → **Actions**.
    2. Haz clic en **New repository secret**.
    3. Añade los siguientes secretos:
       * Nombre: `MINTLIFY_API_KEY`, Secreto: Tu clave de API de administrador de Mintlify
       * Nombre: `MINTLIFY_PROJECT_ID`, Secreto: El ID de tu proyecto de Mintlify (lo encontrarás en la página de [API keys](https://dashboard.mintlify.com/settings/organization/api-keys) de tu panel)

    Para más información, consulta [Using secrets in GitHub Actions](https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/use-secrets) en la documentación de GitHub.

    ## Prueba la automatización

    1. Haz un pequeño cambio en tu repositorio de código y envíalo a main:
       ```bash
       git add .
       git commit -m "Test: trigger docs automation"
       git push origin main
       ```

    2. Revisa la pestaña **Actions** de tu repositorio de código para ver la ejecución del flujo de trabajo.

    3. Después de que se ejecute el flujo de trabajo, revisa tu repositorio de documentación para comprobar si se ha creado una rama nueva y una solicitud de extracción (pull request, PR) con actualizaciones de la documentación.

    ## Solución de problemas

    ### El flujo de trabajo no se ejecuta

    * Verifica que hayas habilitado GitHub Actions en tu repositorio de código.
    * Revisa la pestaña **Actions** para ver si hay mensajes de error.
    * Asegúrate de que el archivo de flujo de trabajo esté en `.github/workflows/` con la extensión `.yml`.

    ### Error 401 de la API del agente

    * Verifica que tu clave de API comience por `mint_`.
    * Comprueba que el encabezado Authorization use el formato `Bearer mint_yourkey`.
    * Confirma que la clave de API pertenezca a la organización correcta de Mintlify.

    ### No aparecen actualizaciones de documentación

    * Comprueba que hayas conectado el repositorio de documentación a tu proyecto de Mintlify.
    * Verifica que el agente tenga permisos de escritura en el repositorio de documentación.
    * Revisa los registros del flujo de trabajo para identificar mensajes de error del agente.

    n8n ofrece un editor visual de flujos de trabajo y puede integrarse con múltiples servicios.

    ## Requisitos previos

    * espacio de trabajo de n8n
    * [Plan Enterprise de Mintlify](https://mintlify.com/pricing)
    * Aplicación de Mintlify instalada en tu repositorio de código
    * Clave de API de administración de Mintlify
    * Acceso de administrador a los repositorios de GitHub de tu código y documentación
    * Token de acceso personal de GitHub

    ### Instala la aplicación de Mintlify en tu repositorio de código

    Instala la aplicación de Mintlify en tu repositorio de código para que el agente pueda obtener contexto de tu base de código. Para agregar la aplicación a nuevos repositorios:

    1. Ve a la página de [Agente](https://dashboard.mintlify.com/products/agent) en tu panel.
    2. Haz clic en **Add to New Organization**. Se te redirigirá a la página de instalación de la aplicación en GitHub.
    3. Selecciona en la lista los repositorios a los que quieres conceder acceso.
    4. Guarda los cambios.

    ### Obtén tu clave de API de administrador

    1. Ve a la página de [claves de API](https://dashboard.mintlify.com/settings/organization/api-keys) de tu panel.
    2. Selecciona **Crear clave de API de administrador**.
    3. Copia la clave y guárdala en un lugar seguro.

    ### Obtén tu token de acceso personal de GitHub

    1. En GitHub, ve a **Configuración**.
    2. Haz clic en **Developer settings**.
    3. Haz clic en **Tokens de acceso personal**.
    4. Haz clic en **Tokens (classic)**.
    5. Haz clic en **Generar nuevo token (clásico)**.
    6. Selecciona estos scopes:
       * `repo` (control total sobre los repositorios privados)
       * `admin:repo_hook` (si quieres que n8n cree webhooks)
    7. Genera y guarda el token de forma segura.

    Para más información, consulta [Creación de un token de acceso personal (clásico)](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens?versionId=free-pro-team%40latest\&productId=account-and-profile#creating-a-personal-access-token-classic) en la documentación de GitHub.

    ## Crea el flujo de trabajo

    ### Crear el disparador de webhook

    1. En n8n, crea un flujo de trabajo nuevo.
    2. Añade un nodo de webhook.
    3. Configura el webhook:
       * Método HTTP: `POST`
       * Ruta: `auto-update-documentation` (o cualquier ruta única)
       * Autenticación: ninguna
       * Respuesta: inmediata
    4. Guarda el flujo de trabajo.
    5. Copia la URL del webhook de producción. Debería verse así: `https://your-n8n-instance.app.n8n.cloud/webhook/auto-update-documentation`

    ### Configura el webhook de GitHub

    1. Ve a tu repositorio de código en GitHub.
    2. Haz clic en **Configuración**.
    3. Haz clic en **Webhooks**.
    4. Haz clic en **Add webhook**.
    5. Configura el webhook:
       * URL de carga útil: pega la URL del webhook de n8n
       * Tipo de contenido: `application/json`
       * ¿Qué eventos quieres que activen este webhook?
         * Selecciona **Let me select individual events.**
         * Selecciona solo **Push events**.
       * Selecciona **Active**
    6. Haz clic en **Add webhook**.

    ### Filtrar los envíos a la rama main

    Añade un nodo de código después del webhook para filtrar los pushes a main y extraer la información relevante.

    1. Agrega un nodo de código.
    2. Llámalo &quot;Filtrar pushes a main.&quot;
    3. Establece el modo en **Ejecutar una vez para todos los elementos**.
    4. Agrega este JavaScript:

    ```javascript
    const webhookData = $input.first().json.body;

    // Solo continuar si es un push a main
    if (webhookData.ref !== "refs/heads/main") {
      return [];
    }

    // Extraer información
    const repository = webhookData.repository;
    const pusher = webhookData.pusher;

    // Construir mensaje para el agente
    const agentMessage = `Update documentation for changes pushed to main in ${repository.name}. Always edit files and create a pull request.`;

    return {
      json: {
        codeRepoName: repository.full_name,
        codeRepoShortName: repository.name,
        agentMessage: agentMessage
      }
    };
    ```

    ### Llama a la API del agente

    Agrega un nodo de solicitud HTTP para crear un trabajo de documentación.

    1. Añade un nodo de solicitud HTTP.
    2. Nómbralo &quot;Crear trabajo de agente.&quot;
    3. Configura la solicitud:

       * Método: `POST`
       * URL: `https://api.mintlify.com/v1/agent/YOUR_PROJECT_ID/job` (reemplaza `YOUR_PROJECT_ID` por el ID de tu proyecto de la página [API keys](https://dashboard.mintlify.com/settings/organization/api-keys))
       * Autenticación: Tipo de credencial genérico → Autenticación por encabezado
         * Crea una credencial nueva:
           * Nombre: `Authorization`
           * Valor: `Bearer mint_YOUR_API_KEY` (sustitúyelo por tu clave de API)
       * Enviar cuerpo: Activado
       * Tipo de contenido del cuerpo: JSON
       * Especificar cuerpo: Usar JSON
       * Agrega este JSON:

       ```json
       {
       "branch": "docs-update-from-{{ $json.codeRepoShortName }}-{{ $now.toISOString() }}",
       "messages": [
           {
           "role": "system",
           "content": "{{ $json.agentMessage }}"
           }
       ],
       "asDraft": false
       }
       ```

    ## Prueba la automatización

    1. Crea una rama de prueba en tu repositorio de código:
       ```bash
       git checkout -b test-docs-automation
       ```

    2. Haz un pequeño cambio y crea un commit:
       ```bash
       git add .
       git commit -m "Test: trigger docs automation"
       git push origin test-docs-automation
       ```

    3. Abre una solicitud de extracción (pull request, PR) en GitHub.

    4. Fusiona la solicitud de extracción (pull request, PR).

    ### Verificar la automatización

    Deberías ver una nueva ejecución de n8n con todos los nodos completados correctamente, junto con una nueva rama y una solicitud de extracción (pull request, PR) en tu repositorio de documentación.

    ## Solución de problemas

    ### El webhook no se activa

    * Comprueba que el flujo de trabajo esté activo en n8n.
    * Revisa Settings → Webhooks → Recent Deliveries del repositorio de GitHub para ver el código de respuesta.
    * Confirma que la URL del webhook coincida exactamente con la de tu webhook de n8n.

    ### Error 401 de la API del agente

    * Verifica que tu clave de API empiece por `mint_`.
    * Comprueba que el encabezado `Authorization` use el formato `Bearer mint_yourkey`.
    * Confirma que la clave de API corresponda a la organización correcta de Mintlify.

    ### Error 401 de GitHub

    * Verifica que tu token tenga el permiso `repo`.
    * Verifica que el token no haya expirado.
    * Confirma que hayas incluido el encabezado `User-Agent` en la solicitud a GitHub.
