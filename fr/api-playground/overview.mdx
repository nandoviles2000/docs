Le bac à sable API est un environnement interactif qui permet aux utilisateurs de tester et d’explorer les points de terminaison de votre API. Les développeurs peuvent composer des requêtes API, les envoyer et consulter les réponses sans quitter votre documentation.

Consultez [Déclencher une mise à jour](/fr/api/update/trigger) pour voir un exemple du bac à sable API en action.

Le bac à sable génère des pages interactives pour vos points de terminaison à partir de votre spécification OpenAPI ou de votre schéma AsyncAPI. Si vous modifiez votre API, il met automatiquement à jour les pages concernées.

Nous vous recommandons de générer votre bac à sable API à partir d’une spécification OpenAPI. Cependant, vous pouvez créer manuellement des pages de Référence de l’API après avoir défini une URL de base et une méthode d’authentification dans votre `docs.json`.

<div id="get-started">
  ## Premiers pas
</div>

<Steps>
  <Step title="Ajoutez votre fichier de spécification OpenAPI.">
    <Tip>
      Validez votre fichier de spécification OpenAPI à l’aide de [Swagger Editor](https://editor.swagger.io/) ou de la commande `mint validate` du [Mint CLI](https://www.npmjs.com/package/mint).
    </Tip>

    ```bash {3}
    /your-project
      |- docs.json
      |- openapi.json
    ```
  </Step>

  <Step title="Générez les pages des points de terminaison.">
    Mettez à jour votre `docs.json` pour faire référence à votre spécification OpenAPI.

    **Pour générer automatiquement des pages pour tous les points de terminaison de votre spécification OpenAPI**, ajoutez une propriété `openapi` à n’importe quel élément de navigation.

    Cet exemple génère une page pour chaque point de terminaison spécifié dans `openapi.json` et organise les pages dans le groupe « API reference ».

    ```json Générer toutes les pages de point de terminaison
    "navigation": {
      "groups": [
        {
          "group": "API reference",
          "openapi": "openapi.json"
        }
      ]
    }
    ```

    **Pour générer des pages uniquement pour certains points de terminaison**, répertoriez les points de terminaison dans la propriété `pages` de l’élément de navigation.

    Cet exemple génère des pages uniquement pour les points de terminaison `GET /users` et `POST /users`. Pour générer d’autres pages de point de terminaison, ajoutez des points de terminaison supplémentaires au tableau `pages`.

    ```json Générer des pages de point de terminaison spécifiques
    "navigation": {
      "groups": [
          {
            "group": "API reference",
            "openapi": "openapi.json",
            "pages": [
              "GET /users",
              "POST /users"
            ]
          }
      ]
    }
    ```
  </Step>
</Steps>

<div id="customize-your-playground">
  ## Personnalisez votre bac à sable
</div>

Personnalisez votre bac à sable API en définissant les propriétés suivantes dans votre `docs.json`.

<ResponseField name="playground" type="object">
  Configuration du bac à sable API.

  <Expandable title="playground" defaultOpen="True">
    <ResponseField name="display" type="&#x22;interactive&#x22; | &#x22;simple&#x22; | &#x22;none&#x22; | &#x22;auth&#x22;">
      Le mode d’affichage du bac à sable API.

      * `"interactive"`: affiche le bac à sable interactif.
      * `"simple"`: affiche un point de terminaison copiable, sans bac à sable.
      * `"none"`: n’affiche rien.
      * `"auth"`: affiche le bac à sable interactif uniquement pour les utilisateurs authentifiés. Les utilisateurs non authentifiés ou qui n’appartiennent pas aux groupes requis ne voient aucun bac à sable.

      La valeur par défaut est `interactive`.
    </ResponseField>

    <ResponseField name="proxy" type="boolean" defaultOpen="True">
      Indique si les requêtes API doivent transiter par le serveur proxy de Mintlify. La valeur par défaut est `true`.

      Lorsque `true`, les requêtes du bac à sable transitent par les serveurs de Mintlify. Lorsque `false`, le bac à sable envoie les requêtes directement depuis le navigateur vers votre API. Définissez cette valeur sur `false` si votre API accepte les requêtes directes depuis le navigateur et que vous n’avez pas besoin que Mintlify relaie le trafic. Par exemple, si votre API requiert des en-têtes spécifiques qui ne peuvent pas être transmis via le proxy, ou si la requête doit provenir directement du navigateur de l’utilisateur à des fins d’authentification.
    </ResponseField>

    <ResponseField name="credentials" type="boolean">
      Indique si les cookies, les en-têtes d’autorisation et les certificats client TLS doivent être inclus dans les requêtes inter-origines lorsque `proxy` est `false`. La valeur par défaut est `false`.

      Lorsque `true` et que `proxy` est `false`, le bac à sable envoie les requêtes en incluant les identifiants gérés par le navigateur. Par exemple, si votre API utilise une authentification basée sur des cookies ou des jetons de session HTTP.

      Cette option n’a aucun effet lorsque `proxy` est `true`.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="url" type="&#x22;full&#x22;">
  Le mode d’affichage des URL de base dans les en-têtes des points de terminaison. Lorsqu’il est défini sur `full`, l’URL de base complète s’affiche sur chaque page de point de terminaison. Par défaut, seul le chemin relatif du point de terminaison s’affiche.
</ResponseField>

<ResponseField name="examples" type="object">

  <Expandable title="examples" defaultOpen="True">

      Les langages s’affichent dans l’ordre indiqué.

        | PHP             | `php`        |                           |

        | PowerShell      | `powershell` |                           |
        | Swift           | `swift`      |                           |
        | C#              | `csharp`     | `c#`                      |
        | .NET            | `dotnet`     | `.net`, `.NET`, `dot-net` |

        | C               | `c`          |                           |

    <ResponseField name="defaults" type="&#x22;required&#x22; | &#x22;all&#x22;">
      Indique si les paramètres facultatifs doivent être affichés dans les exemples d’API. La valeur par défaut est `all`.
    </ResponseField>

    <ResponseField name="prefill" type="boolean">
      Indique si le bac à sable API doit être prérempli avec les données issues des exemples de schéma. Lorsqu’elle est activée, cette option renseigne automatiquement les champs de requête du bac à sable avec des valeurs d’exemple provenant de votre spécification OpenAPI. La valeur par défaut est `false`.
    </ResponseField>

    <ResponseField name="autogenerate" type="boolean">
      Indique s’il faut générer des exemples de code pour les points de terminaison à partir des spécifications API. La valeur par défaut est `true`. Lorsqu’elle est définie sur `false`, seuls les exemples de code rédigés manuellement (à partir de `x-codeSamples` dans les spécifications OpenAPI ou des composants `<RequestExample>` en MDX) apparaissent dans le bac à sable API.
    </ResponseField>
  </Expandable>
</ResponseField>

<div id="example-configuration">
  ### Exemple de configuration
</div>

Cet exemple configure le bac à sable API pour le rendre interactif, avec des extraits de code d’exemple en cURL, Python et JavaScript. Il n’affiche que les paramètres requis dans les extraits de code, et le bac à sable préremplit le corps de la requête avec des valeurs d’exemple.

```json
{
 "api": {
   "playground": {
     "display": "interactive"
   },
   "examples": {
     "languages": ["curl", "python", "javascript"],
     "defaults": "required",
     "prefill": true
   }
 }
}
```

<div id="auth-based-playground-display">
  ### Affichage du bac à sable selon l’authentification
</div>

Utilisez le mode d’affichage `auth` pour n’afficher le bac à sable interactif qu’aux utilisateurs authentifiés. Cela est utile si vous souhaitez rendre la documentation de votre API accessible publiquement tout en réservant l’accès au bac à sable aux utilisateurs connectés.

Lorsque `display` est défini sur `auth` :

* Les utilisateurs authentifiés voient le bac à sable interactif.
* Les utilisateurs non authentifiés ne voient aucun bac à sable (équivalent à `none`).

Vous pouvez également combiner `auth` avec la propriété `groups` dans les métadonnées d’en-tête de la page afin de restreindre l’accès au bac à sable à des groupes d’utilisateurs spécifiques.

```mdx Page with group-restricted playground
---
title: "Create user"
openapi: POST /users
playground: auth
groups: ["admin", "developer"]
public: true
---
```

Dans cet exemple :

* La page est visible publiquement (n’importe qui peut consulter la documentation).
* Seuls les utilisateurs authentifiés des groupes `admin` ou `developer` voient le bac à sable interactif.
* Les utilisateurs qui n’appartiennent pas à ces groupes ne voient pas le bac à sable.

Si la page n’a pas de propriété `groups`, tous les utilisateurs authentifiés voient le bac à sable interactif.

<Note>
  Le mode d’affichage `auth` nécessite que l’[authentification](/fr/deploy/authentication-setup) soit configurée pour votre documentation.
</Note>

<div id="custom-endpoint-pages">
  ### Pages personnalisées de point de terminaison
</div>

Lorsque vous avez besoin de davantage de contrôle sur votre documentation d’API, utilisez l’extension `x-mint` dans votre spécification OpenAPI ou créez des pages MDX distinctes pour vos points de terminaison.

Les deux options vous permettent de :

* Personnaliser les métadonnées de la page
* Ajouter du contenu supplémentaire, comme des exemples
* Contrôler le comportement du bac à sable sur chaque page

Nous vous recommandons d’utiliser l’extension `x-mint` afin que toute votre documentation d’API soit générée automatiquement à partir de votre spécification OpenAPI et reste centralisée dans un seul fichier.

Nous recommandons des pages MDX distinctes pour les petites API ou si vous souhaitez tester des modifications page par page.

<div id="response-rendering">
  ## Affichage des réponses
</div>

Le bac à sable affiche automatiquement les réponses en fonction de l’en-tête `Content-Type` renvoyé par votre API.

* **Images** : affichées directement dans la page (`image/*`).
* **Audio** : affiché avec un lecteur audio intégré (`audio/*`).
* **Vidéo** : affichée avec un lecteur vidéo intégré (`video/*`). Toute réponse dont le type de contenu est `video/*`, comme `video/mp4` ou `video/webm`, s’affiche directement dans le bac à sable sous forme de vidéo lisible.
* **Toutes les autres réponses** : affichées dans un bloc de code.

<div id="parameter-anchor-links">
  ## Liens d’ancrage des paramètres
</div>

Chaque paramètre du bac à sable API comporte un lien d’ancrage cliquable. Survolez le nom d’un paramètre pour faire apparaître l’icône de lien, puis cliquez dessus pour copier une URL directe vers ce paramètre.

Utilisez les liens d’ancrage des paramètres pour :

* Partager des liens vers des paramètres précis dans des échanges avec le support ou dans la documentation
* Accéder directement à un paramètre depuis une autre page ou une ressource externe
* Ajouter aux favoris les paramètres fréquemment consultés

Le format de l’URL est `your-docs-url/endpoint-path#parameter-name`. Pour les paramètres imbriqués, l’ancre inclut le chemin parent.
