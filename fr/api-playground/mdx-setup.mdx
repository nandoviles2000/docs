Vous pouvez définir manuellement des points de terminaison d’API dans des pages MDX distinctes. Cette approche est utile pour de petites API ou pour le prototypage.

<div id="setup">
  ## Configuration
</div>

<Steps>
  <Step title="Configurez les paramètres de votre API">
    Dans votre fichier `docs.json`, définissez votre URL de base et votre méthode d’authentification.

    ```json Example docs.json
    "api": {
      "mdx": {
        "server": "https://api.acme.com/",
        "auth": {
          "method": "key",
          "name": "x-api-key"
        }
      }
    }
    ```

    Si vous souhaitez masquer le bac à sable API, définissez le champ `display` sur `none`. Vous n’avez pas besoin d’inclure de méthode d’authentification si vous masquez le bac à sable.

    ```json
    "api": {
      "playground": {
        "display": "none"
      }
    }
    ```

    Retrouvez la liste complète des paramètres de l’API dans [Settings](/fr/organize/settings-api).
  </Step>

  <Step title="Créez vos pages de points de terminaison">
    Créez un fichier MDX pour chaque point de terminaison. Définissez `title` et `api` dans les métadonnées d’en-tête :

    ```mdx
    ---
    title: 'Create new user'
    api: 'POST /v1/users'
    ---
    ```

    Le champ `api` des métadonnées d’en-tête accepte soit une URL complète, soit un chemin relatif :

    * **URL complète** comme `POST https://api.acme.com/v1/users`. Le champ `server` de `docs.json` est ignoré pour ce point de terminaison.
    * **Chemin relatif** comme `POST /v1/users`. Nécessite un champ `server` dans `docs.json`. L’URL du serveur est ajoutée au début du chemin.

    Indiquez les paramètres de chemin en les entourant de `{}` :

    ```bash
    https://api.example.com/v1/endpoint/{userId}
    ```

    Pour surcharger le mode d’affichage global du playground pour une page spécifique, ajoutez `playground` dans les métadonnées d’en-tête :

    ```mdx
    ---
    title: 'Create new user'
    api: 'POST https://api.mintlify.com/user'
    playground: 'none'
    ---
    ```

    Options :

    * `playground: 'interactive'` - Affiche le playground interactif (par défaut)
    * `playground: 'simple'` - Affiche un point de terminaison que vous pouvez copier, sans playground
    * `playground: 'none'` - Masque complètement le playground
  </Step>

  <Step title="Ajouter des paramètres et des réponses">
    Utilisez les [champs des paramètres et des réponses](/fr/components/fields) pour documenter les paramètres et les valeurs renvoyées par votre point de terminaison.

    ```mdx
    <ParamField path="userId" type="string" required>
      Unique identifier for the user
    </ParamField>

    <ParamField body="email" type="string" required>
      User's email address
    </ParamField>

    <ResponseField name="id" type="string" required>
      Unique identifier for the newly created user
    </ResponseField>

    <ResponseField name="email" type="string" required>
      User's email address
    </ResponseField>
    ```
  </Step>

  <Step title="Ajoutez vos points de terminaison à votre documentation">
    Ajoutez les pages de vos points de terminaison à la navigation en mettant à jour le champ `pages` dans votre `docs.json` :

    ```json docs.json
    "navigation": {
      "tabs": [
        {
          "tab": "API Reference",
          "groups": [
            {
              "group": "Users",
              "pages": [
                "api-reference/users/create-user",
                "api-reference/users/get-user",
                "api-reference/users/update-user"
              ]
            },
            {
              "group": "Orders",
              "pages": [
                "api-reference/orders/create-order",
                "api-reference/orders/list-orders"
              ]
            }
          ]
        }
      ]
    }
    ```

    Chaque chemin de page correspond à un fichier MDX dans votre dépôt de documentation. Par exemple, `api-reference/users/create-user.mdx`. Pour en savoir plus sur l’organisation de votre documentation, consultez [Navigation](/fr/organize/navigation).

    ### Utiliser des points de terminaison OpenAPI dans la navigation

    Si vous disposez d’une spécification OpenAPI, vous pouvez faire référence directement à des points de terminaison dans votre navigation sans créer de fichiers MDX distincts. Référencez des points de terminaison spécifiques en incluant le chemin du fichier OpenAPI et le point de terminaison :

    ```json docs.json
    "navigation": {
      "pages": [
        "introduction",
        "/path/to/users-openapi.json POST /users",
        "/path/to/orders-openapi.json GET /orders"
      ]
    }
    ```

    Vous pouvez également définir une spécification OpenAPI par défaut pour un groupe de Navigation et référencer des points de terminaison à l’aide de la méthode et du chemin :

    ```json docs.json
    {
      "group": "API reference",
      "openapi": "/path/to/openapi-v1.json",
      "pages": [
        "overview",
        "authentication",
        "GET /users",
        "POST /users",
        {
          "group": "Orders",
          "openapi": "/path/to/openapi-v2.json",
          "pages": [
            "GET /orders",
            "POST /orders"
          ]
        }
      ]
    }
    ```

    Pour en savoir plus sur l’intégration d’OpenAPI, consultez [la configuration d’OpenAPI](/fr/api-playground/openapi-setup).
  </Step>
</Steps>

<div id="enable-authentication">
  ## Activer l’authentification
</div>

Vous pouvez configurer l’authentification globalement dans `docs.json` ou la remplacer pour des pages individuelles à l’aide du champ `authMethod` dans les métadonnées d’en-tête. Une méthode définie pour une page donnée remplace le paramètre global.

<div id="bearer-token">
  ### Jeton Bearer
</div>

<CodeGroup>
  ```json docs.json
  "api": {
    "mdx": {
      "auth": {
        "method": "bearer"
      }
    }
  }
  ```

  ```mdx Page Metadata
  ---
  title: "Titre de votre page"
  authMethod: "bearer"
  ---
  ```
</CodeGroup>

<div id="none">
  ### Aucun
</div>

Pour désactiver l’authentification sur une page spécifique, définissez `authMethod` sur `none` :

```mdx Page Metadata
---
title: "Your page title"
authMethod: "none"
---
```
