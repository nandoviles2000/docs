<div id="publishing-workflows">
  ## Flux de travail de publication
</div>

L’éditeur prend en charge deux flux de travail pour publier les mises à jour de la documentation. Le flux de travail utilisé dépend des règles de protection de branche de votre dépôt et de la branche sur laquelle vous travaillez.

**Créer des pull requests (PR)** : Si votre dépôt comporte une règle de protection de branche qui exige des pull requests (PR) avant que les modifications puissent être fusionnées dans votre branche de déploiement, l’éditeur crée une pull request (PR) lorsque vous publiez vos modifications.

<Tip>
  Lorsque vous créez une pull request (PR) depuis l’éditeur, l’agent Mintlify génère un titre et une description à partir de vos modifications. Vous pouvez modifier le titre et la description générés avant de créer la pull request (PR).
</Tip>

**Publier directement** : Si votre dépôt n’a pas de règle de protection de branche, vos modifications sont fusionnées dans la branche de déploiement et déployées immédiatement lorsque vous publiez.

| Type de branche                                                                                                                                                                                                        | Protection des branches | Flux de travail de publication                                           |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------- | ------------------------------------------------------------------------ |
| <Tooltip headline="Branche de déploiement" tip="La branche qui publie votre site de documentation en ligne, généralement 'main'.">Branche de déploiement</Tooltip>                                                     | Aucune                  | Effectue un commit et déploie les modifications                          |
| Branche de déploiement                                                                                                                                                                                                 | Pull requests (PR) requises  | Crée une pull request (PR)                                                    |
| <Tooltip headline="Branche de fonctionnalité" tip="Une branche isolée sur laquelle vous travaillez sur des mises à jour avant de les fusionner dans votre branche de déploiement.">Branche de fonctionnalité</Tooltip> | Aucune                  | Fusionne les modifications dans la branche de déploiement et les déploie |
| Branche de fonctionnalité                                                                                                                                                                                              | Pull requests (PR) requises  | Crée une pull request (PR)                                                    |

<Tip>
  Configurez des règles de protection de branche dans votre fournisseur Git pour exiger des pull requests (PR). Consultez [About protected branches](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches) dans la documentation GitHub ou [Protected branches](https://docs.gitlab.com/user/project/repository/branches/protected/) dans la documentation GitLab.
</Tip>

<div id="save-changes">
  ## Enregistrer les modifications
</div>

Pendant que vous modifiez du contenu, l’éditeur suit vos modifications.

* Les nouveaux fichiers et les fichiers supprimés.
* Les modifications du contenu des pages.
* Les changements dans la structure de navigation.
* Les importations de médias et leur organisation.
* Les mises à jour de la configuration.

Lorsque vous travaillez sur votre branche de déploiement, les modifications sont enregistrées automatiquement.

Pour annuler des modifications, cliquez sur **Annuler les modifications** à côté d’un nom de fichier dans le menu déroulant des fichiers modifiés.

<div id="review-branch-changes">
  ## Vérifier les modifications de la branche
</div>

Lorsque vous travaillez sur une branche de fonctionnalité, le panneau de publication affiche toutes les modifications de fichiers entre votre branche et la branche de déploiement sous **Enregistré dans la branche**. Cela inclut les modifications que vous avez enregistrées ainsi que celles de vos coéquipiers travaillant sur la même branche.

Cliquez sur un fichier dans la liste pour ouvrir une vue diff affichant les modifications entre la branche et le contenu publié. Les fichiers de documentation s’ouvrent dans un diff visuel, et les autres types de fichiers dans un diff du code source. Utilisez cette vue pour passer en revue l’ensemble des modifications apportées à une branche avant de la publier.

Les fichiers pour lesquels aucun diff ne peut être affiché, comme les images ou les fichiers supprimés, apparaissent dans la liste, mais ne sont pas cliquables.

<div id="publish-your-changes">
  ## Publier vos modifications
</div>

Cliquez sur **Publish** dans la barre d’outils. Selon votre flux de travail, vos modifications sont déployées immédiatement ou une pull request (PR) est créée pour que vous la fusionniez sur votre plateforme Git. Si vous êtes sur une branche de fonctionnalité, enregistrez vos modifications avant de publier.

S’il n’y a aucune modification en attente ou si une pull request (PR) pour la branche actuelle est déjà ouverte, le bouton **Publish** est désactivé.

<Note>
  Votre site de documentation en production est mis à jour une fois que Mintlify a compilé et déployé les modifications publiées. Cela prend généralement de 30 secondes à quelques minutes. Vérifiez l’état du déploiement de vos modifications sur votre [tableau de bord](https://dashboard.mintlify.com).
</Note>

## Résoudre les conflits

Des conflits surviennent lorsque votre branche et la branche de déploiement contiennent des modifications incompatibles dans les mêmes fichiers.

<div id="what-causes-conflicts">
  ### Causes des conflits
</div>

Les conflits surviennent lorsque vous essayez de fusionner des branches qui contiennent des modifications incompatibles sur les mêmes fichiers.

* Vous et un autre membre de l’équipe modifiez les mêmes lignes d’un fichier sur des branches différentes.
* Vous déplacez, renommez ou supprimez des fichiers sur une branche, tandis qu’ils sont modifiés différemment sur une autre branche.

<div id="resolve-conflicts">
  ### Résoudre les conflits
</div>

L’éditeur affiche des avertissements lorsque des conflits empêchent certaines opérations, comme la publication ou le passage d’une branche à l’autre. Pour résoudre les conflits, suivez les instructions de l’éditeur pour choisir les modifications à conserver.

<div id="commit-signing">
  ## Signature des commits
</div>

Signez les commits avec votre compte GitHub en l’autorisant dans vos [paramètres de compte](https://dashboard.mintlify.com/settings/account). Si vous ne l’autorisez pas, l’application GitHub de Mintlify signera les commits effectués dans l’éditeur web.

L’attribution des commits à votre compte permet de conserver un historique précis des personnes ayant modifié votre documentation.
