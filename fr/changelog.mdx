<Update label="17 avril 2026" tags={["Nouveautés", "Améliorations"]} rss={{ title: "Composant Visibility, accès au système de fichiers MCP, retours des agents, assistant de configuration Git, et plus encore" }}>
  ## Composant Visibility

  Le nouveau composant [`Visibility`](/fr/components/visibility) vous permet d&#39;afficher un contenu différent pour les lecteurs humains et les agents IA sur une même page. Encapsulez le contenu dans `<Visibility for="humans">` pour l&#39;afficher uniquement dans la version web d&#39;une page, ou dans `<Visibility for="agents">` pour l&#39;inclure uniquement dans la [sortie Markdown](/fr/ai/markdown-export) utilisée par les outils d&#39;IA. Pratique pour adapter les instructions, les exemples ou la mise en forme à chaque audience sans avoir à maintenir des pages distinctes.

  ## Retours des agents

  Activez les [retours des agents](/fr/optimize/feedback#agent-feedback) dans vos paramètres de déploiement pour permettre aux agents d&#39;envoyer des retours structurés sur votre documentation. Lorsqu&#39;elle est activée, la version Markdown de vos pages inclut des instructions de retour afin que les agents sachent comment signaler les problèmes rencontrés lors de l&#39;accès à votre documentation. Cette fonctionnalité est disponible en bêta dans le tableau de bord, sous les modules complémentaires de déploiement.

  ## Accès au système de fichiers MCP

  Les [serveurs MCP](/fr/ai/model-context-protocol) incluent désormais un outil de requête du système de fichiers qui permet aux agents de parcourir et de lire directement la structure des fichiers de votre documentation. Les agents peuvent parcourir les répertoires, lire l&#39;intégralité du contenu des pages et lire plusieurs pages en lot en un seul appel. Cet outil remplace l&#39;outil `get_page`.

  ## Assistant de configuration Git

  Un nouvel assistant étape par étape, disponible sur la page des paramètres Git, vous guide lors de votre première connexion à un dépôt GitHub ou GitLab. Choisissez entre un clonage en un clic ou une sélection manuelle du dépôt, avec prise en charge de la sélection de l&#39;organisation, de la configuration de la branche et du sous-répertoire.

  ## OAuth GitLab pour les flux de travail

  Les [flux de travail](/fr/agent/workflows) prennent désormais en charge les dépôts GitLab via l&#39;authentification OAuth. Connectez votre compte GitLab depuis le tableau de bord pour utiliser des dépôts GitLab comme sources de documentation, dépôts de déclenchement ou dépôts de contexte dans vos flux de travail. L&#39;agent ouvre des merge requests sur GitLab, tout comme il ouvre des pull requests (PR) sur GitHub.

  ## Améliorations

  * Lorsque vous collez des composants MDX valides dans l&#39;éditeur, leur structure est désormais préservée au lieu d&#39;être convertie en texte brut.
  * Les titres longs de la navigation latérale sont désormais césurés automatiquement pour éviter les débordements.
  * L&#39;éditeur résout désormais les [références `$ref`](/fr/organize/settings#split-configuration-with-%24ref) dans les fichiers de configuration fractionnés.
  * Le prompt système de l&#39;[agent Slack](/fr/agent/slack) a été amélioré pour fournir des réponses plus précises et plus utiles.
  * `llms.txt` inclut désormais des résumés sous forme de blocs de citation pour améliorer les descriptions de page.
  * Les fichiers `skill.md` personnalisés de votre dépôt sont désormais correctement détectés lors du déploiement.

  ## Dépréciations

  * Les flux de travail basés sur des fichiers sont déconseillés. Créez plutôt vos flux de travail depuis le tableau de bord. Les flux de travail existants définis dans des fichiers continuent de fonctionner, mais les nouveaux flux de travail doivent être créés dans le tableau de bord.

  ## Corrections de bugs

  * Correction de cas où les liens relatifs dans les fichiers `index.mdx` n&#39;étaient pas correctement résolus.
  * Correction du bouton de copie pour les blocs de code dans les réponses de l&#39;Assistant.
  * Correction d&#39;un problème empêchant la table des matières de se mettre à jour après des modifications du contenu d&#39;une page.
  * Correction de l&#39;affichage incorrect des titres des blocs de code.
  * Correction de la couleur de bordure par défaut en mode sombre.
  * Correction de la commande CLI `mint analytics feedback`, qui envoyait des valeurs de type de retour incorrectes.
  * Correction d&#39;un artefact d&#39;ombre sur les boutons du sélecteur numérique.
  * Correction de la navigation côté client pour les liens associés.

  ## Analyses CLI

  La commande [`mint analytics`](/fr/cli/analytics) vous permet de consulter le trafic, les requêtes de recherche, les retours des utilisateurs et les conversations de l’assistant depuis le terminal, pour une meilleure intégration avec les agents.

  Utilisez les sous-commandes pour explorer des données spécifiques :

  * `mint analytics stats` — vues, visiteurs, recherches, retours et utilisation de l’assistant sur une plage de dates
  * `mint analytics search` — requêtes de recherche avec nombre d’occurrences et taux de clics
  * `mint analytics feedback` — retours envoyés par les utilisateurs sur les pages et les extraits de code
  * `mint analytics conversation list` — conversations récentes de l’assistant

  Toutes les sous-commandes prennent en charge les options `--from`, `--to` et `--format`. Les formats de sortie incluent `plain` (par défaut), `table`, `json` et `graph`.

  ## Listes de répertoires

  Les groupes de navigation avec une [page racine](/fr/organize/navigation#root-page) peuvent désormais afficher une [liste de répertoires](/fr/organize/navigation#directory-listings) de leurs pages enfants. Définissez la propriété `directory` sur un groupe, un onglet ou l’objet `navigation` de premier niveau sur `"accordion"` ou `"card"` pour générer automatiquement une vue d’ensemble du contenu de la section. C’est utile pour les centres d’aide et les autres sites où les utilisateurs ont besoin d’un moyen rapide de parcourir toutes les pages disponibles dans une section.

  ## Prise en charge de plusieurs skills

  Servez plusieurs [fichiers de skill](/fr/ai/skillmd) depuis un répertoire `.mintlify/skills/`. Chaque sous-répertoire contenant un fichier `SKILL.md` est détecté et servi automatiquement, ce qui vous permet d’organiser les skills par fonctionnalité ou par domaine.

  ## Améliorations de l’agent Slack

  * **Déploiements multiples** : les organisations disposant de plusieurs sites de documentation peuvent désormais utiliser le [agent Slack](/fr/agent/slack) sur l’ensemble de ces sites. L’agent vous invite à choisir un déploiement lors de la première utilisation, et votre préférence est enregistrée pour chaque compte Slack.
  * **Mode lecture seule** : l’agent Slack classe désormais les messages et répond en mode lecture seule pour les questions qui nécessitent uniquement de récupérer des informations, en réservant l’accès en écriture aux demandes qui exigent des modifications de la documentation.

  ## Identifiants client pour MCP authentifié

  Les [identifiants client](/fr/ai/model-context-protocol#client-credentials) sont désormais disponibles pour les serveurs MCP authentifiés. Utilisez des identifiants client pour vous connecter de manière programmatique sans passer par une connexion dans le navigateur — idéal pour les intégrations côté serveur, les pipelines CI/CD et les flux de travail automatisés. Créez et gérez ces identifiants depuis la page du serveur MCP dans votre tableau de bord.

  ## Améliorations

  * La commande [`mint new`](/fr/cli/commands#mint-new) prend désormais en charge la création de projets à partir de modèles prédéfinis avec l’option `--template`.
  * La CLI actualise désormais automatiquement les jetons d’accès expirés, vous n’avez donc plus besoin de relancer `mint login` après l’expiration d’une session.
  * L’[assistant](/fr/assistant/index) est désormais disponible dans les aperçus locaux `mint dev`.
  * Améliorations de l’UX de la CLI : URL de connexion grisées pour plus de clarté, format de journal standardisé, et `mint status` affiche désormais la version de la CLI.
  * Prise en charge de l’extension OpenAPI `x-group` pour organiser les points de terminaison de l’API dans des groupes personnalisés.
  * Les règles horizontales (`<hr />`) sont désormais prises en charge dans le contenu MDX.
  * Les [flux de travail](/fr/agent/workflows) apparaissent désormais dans la boîte de réception du tableau de bord pour un suivi plus simple. La liste des flux de travail affiche également les noms des PR pour les identifier plus rapidement.
  * La commande `mint export` inclut désormais les pages de Référence de l’API générées à partir des spécifications OpenAPI.
  * Le menu des commandes slash dans l’éditeur a été repensé pour améliorer l’organisation et faciliter la découverte des commandes.
  * Amélioration de l’interface utilisateur du flux de publication de l’éditeur et de l’interface de création de pages.
  * Amélioration de la prévention des abus pour l’assistant.
  * Le finnois a été ajouté comme langue de localisation prise en charge.

  ## Corrections de bugs

  * Correction d’un problème où les ID de titres personnalisés n’étaient pas traités avant l’analyse MDX, ce qui pouvait casser les ancres sur certaines pages.
  * Correction du modèle de flux de travail d’audit SEO et des métadonnées, qui modifiait incorrectement les pages de point de terminaison de l’API.
  * Correction du retour à la ligne incorrect du texte des libellés obsolètes dans le tableau de bord.
  * Correction d’un problème où le formatage en ligne (gras, italique, code) ne s’appliquait pas correctement dans l’éditeur dans certains contextes.
  * Correction d’un problème où les couleurs des icônes de dossier des répertoires ne correspondaient pas au thème configuré.
  * Correction d’un problème de rendu d’une illustration de badge dans le tableau de bord.
  * Correction d’un problème où le changement de branche pouvait laisser l’éditeur dans un état incohérent.
  * Correction d’un problème de génération des exemples de réponse d’API pour certains types de schéma OpenAPI.
  * Correction d’un problème où les pages marquées comme masquées apparaissaient toujours dans le sitemap.

  ## Intégration Linear

  Connectez votre espace de travail Linear depuis la page des paramètres de l’agent pour donner à l’[agent](/fr/agent/linear) accès à vos tickets Linear. L’agent peut utiliser les tickets et les commentaires comme contexte lors de la génération de mises à jour de documentation, ou vous pouvez lui déléguer des tickets directement dans votre espace de travail Linear.

  ## Intégration Notion

  Connectez votre espace de travail Notion depuis la page des paramètres de l’agent pour donner à l’[agent](/fr/agent/notion) un accès en lecture à votre contenu Notion. L’agent peut utiliser les pages Notion comme contexte lors de la génération de mises à jour de documentation.

  ## Export hors ligne

  Regroupez l’intégralité de votre site de documentation dans une archive zip autonome avec la commande CLI [`mint export`](/fr/deploy/export). Partagez le zip pour que vos utilisateurs puissent consulter votre documentation dans leur navigateur, sans connexion Internet ni compte Mintlify.

  ## Édition IA intégrée

  Utilisez l’édition IA intégrée pour générer, réécrire et restructurer du contenu directement dans l’éditeur visuel. Sélectionnez du texte et choisissez parmi des actions prédéfinies, ou saisissez une instruction personnalisée. Les modifications s’affichent en continu sous la forme d’un diff mis en évidence, afin que vous puissiez les vérifier avant de les appliquer.

  ## `docs.json` composable

  Scindez les configurations volumineuses en fichiers plus petits à l’aide de [références `$ref`](/fr/organize/settings#split-configuration-with-%24ref). Chaque `$ref` pointe vers un fichier JSON distinct résolu au moment de la compilation.

  ## Sélecteurs CSS `data-active`

  Les éléments de la barre latérale, les entrées de la table des matières et les menus déroulants de navigation exposent désormais un [`attribut data-active` stable](/fr/customize/custom-scripts#css-selectors) pour le ciblage avec du CSS personnalisé. Utilisez des sélecteurs comme `.toc-item[data-active]` ou `#sidebar-content li[data-active]` pour styliser les états actifs sans dépendre de noms de classes internes.

  ## Point de terminaison de découverte agent-skills

  Les sites de documentation exposent désormais un point de terminaison de découverte `/.well-known/agent-skills/` conforme à la [spécification agent-skills 0.2.0](https://schemas.agentskills.io/discovery/0.2.0/schema.json). Les agents IA peuvent découvrir et récupérer par programmation vos [fichiers de compétences](/fr/ai/skillmd#discovery), avec vérification de l’intégrité du contenu.

  ## Identifiants du bac à sable API

  Une nouvelle option [`api.playground.credentials`](/fr/api-playground/overview) envoie les identifiants gérés par le navigateur (comme les cookies et les jetons de session) avec les requêtes du bac à sable API lorsque le proxy est désactivé. Utile pour les API qui utilisent une authentification basée sur les cookies.

  ## Améliorations

  * Les [ID d’en-tête personnalisés](/fr/create/text#custom-heading-ids) sont désormais pris en charge. Les résultats de recherche créent désormais des liens profonds vers les sections qui utilisent des ID personnalisés.
  * Les entrées de navigation dans `docs.json` prennent désormais en charge les liens d’ancrage (liens `#`).
  * Le tableau de bord des flux de travail a été repensé avec une vue en cartes, un historique d’exécution plus clair, des menus d’actions déroulants et de meilleurs états vides.
  * La navigation de l’éditeur se synchronise désormais avec le serveur pour conserver les modifications et résoudre les conflits entre plusieurs utilisateurs.
  * La recherche MCP respecte désormais les autorisations d’authentification, de sorte que les résultats de recherche n’incluent que les pages auxquelles l’utilisateur a accès.
  * [Heap Analytics](/fr/integrations/analytics/heap) transmet désormais correctement les vues de page et les événements personnalisés.

  ## Corrections de bugs

  * Correction d’un problème empêchant l’application de la couleur du bouton principal du thème Luma depuis `docs.json`.
  * Correction des info-bulles des blocs de code qui utilisaient des primitives d’info-bulle incorrectes.
  * Correction du comportement de repli de l’aperçu en direct dans l’éditeur.
  * Correction des liens dans le contenu HTML statique au sein de l’éditeur.
  * Correction des chemins d’icônes sur les déploiements avec authentification.
  * Correction des pages racines de navigation sur les déploiements avec authentification.
  * Correction du positionnement de l’info-bulle de sélection de texte.
  * Correction de l’export CSV de l’assistant, dans lequel la colonne des sources était manquante.
  * Correction de l’analyse des blocs de code imbriqués.
  * Correction de l’espacement interne des tableaux à l’intérieur des onglets.
  * Correction de l’alignement vertical de l’icône d’indice du composant Frame.
  * Correction du retour à la ligne du badge d’élément de navigation.

  * Gestion des branches dans l’éditeur web : créez des branches dans notre éditeur web sans passer par un IDE.
  * Personnalisation utilisateur : authentifiez les utilisateurs avec Shared Session ou JWT afin d’afficher du contenu personnalisé, par exemple en préremplissant des clés API ou en affichant du contenu réservé à certains clients.
  * Améliorations de l’automatisation OpenAPI : pour remplir automatiquement les pages du bac à sable API, vous pouvez ajouter un champ `openapi` à un objet dans les tableaux `tabs` ou `anchors` du `docs.json`.
