Mintlify gère automatiquement de nombreuses bonnes pratiques SEO, notamment :

* Génération des balises méta
* Génération du sitemap et du fichier `robots.txt`
* Structure HTML sémantique
* Optimisation pour les appareils mobiles

Vous pouvez personnaliser entièrement les balises méta de votre site en ajoutant le champ `metatags` à votre `docs.json` ou aux métadonnées d’en-tête d’une page.

<div id="automatically-generated-meta-tags">
  ## Balises méta générées automatiquement
</div>

Mintlify génère les balises méta suivantes pour chaque page. Vous pouvez remplacer ces balises méta en les spécifiant dans votre `docs.json` ou dans les métadonnées d’en-tête d’une page.

**Métadonnées de base :**

* `charset: utf-8` - Encodage des caractères
* `og:type: website` - Type Open Graph
* `og:site_name` - Nom de votre site de documentation
* `twitter:card: summary_large_image` - Type de carte Twitter

**Métadonnées spécifiques à la page :**

* `title` - Titre de la page, au format « Titre de la page - Nom du site »
* `og:title` - Titre Open Graph, utilise par défaut le titre de la page
* `twitter:title` - Titre Twitter, reprend `og:title`, puis le titre de la page
* `description` - Description de la page
* `og:description` - Description Open Graph, reprend la description de la page
* `twitter:description` - Description Twitter, reprend `og:description`, puis la description de la page

**URL et canonique :**

* `canonical` - Générée automatiquement à partir de l’URL de la page
* `og:url` - Défini sur l’URL canonique

**SEO et indexation :**

* `robots` - Générée à partir des métadonnées de la page
* `noindex` - Générée à partir des métadonnées de la page
* `keywords` - Générés à partir des métadonnées de la page

**Images :**

* `og:image` - Image Open Graph, `og:image:width` défini sur 1200 et `og:image:height` sur 630
* `twitter:image` - Image Twitter, `twitter:image:width` défini sur 1200 et `twitter:image:height` sur 630

**Métadonnées du navigateur et de l’application :**

* `applicationName` - Nom de votre site de documentation
* `generator: Mintlify` - Identifie Mintlify comme générateur du site
* `apple-mobile-web-app-title` - Nom de l’application sur l’écran d’accueil iOS
* `msapplication-TileColor` - Couleur de la tuile Windows
* Favicons et icônes issus de votre configuration
* Lien de référence vers le sitemap

Toutes les balises méta de la configuration `seo.metatags` de votre `docs.json` sont également injectées automatiquement dans chaque page, par exemple `google-site-verification` pour la validation dans la Search Console.

<div id="og-images">
  ## Images OG
</div>

Mintlify génère automatiquement une image Open Graph (OG) pour chaque page. Cette image s’affiche comme aperçu sur les réseaux sociaux et dans les applications de messagerie lorsque vous partagez un lien.

Propriétés par défaut des images OG :

* Largeur : 1200px
* Hauteur : 630px
* Le logo de votre site, issu du champ `logo` dans `docs.json`
* Le titre de la page, issu du champ `title` dans les métadonnées d’en-tête de la page
* La description de la page, issue du champ `description` dans les métadonnées d’en-tête de la page
* La couleur principale de votre site, issue du champ `colors` dans `docs.json`

<div id="custom-og-images">
  ### Images OG personnalisées
</div>

Il existe trois façons de personnaliser les images OG, selon le niveau de contrôle souhaité.

**Image d’arrière-plan personnalisée**

Pour utiliser une image d’arrière-plan personnalisée tout en conservant la superposition du logo, du titre et de la description générée automatiquement, définissez `thumbnails.background` dans votre `docs.json`.

```json Example docs.json
"thumbnails": {
  "background": "/images/og-background.png"
}
```

Consultez [`thumbnails`](/fr/organize/settings-appearance#thumbnails) pour voir la liste complète des options de personnalisation.

**Image OG statique pour toutes les pages**

Pour remplacer complètement l’image générée automatiquement par une image statique unique sur toutes les pages, définissez `og:image` dans vos balises méta globales.

```json Example docs.json
"seo": {
  "metatags": {
    "og:image": "https://example.com/og-image.png"
  }
}
```

**Image OG statique pour une page donnée**

Pour remplacer l’image OG d’une seule page, définissez `og:image` dans les métadonnées d’en-tête de cette page.

```yaml Example frontmatter
---
title: "Your page title"
description: "Your page description"
"og:image": "https://example.com/custom-og.png"
---
```

<Note>
  Définir `og:image` dans les balises méta, globalement ou page par page, remplace l’aperçu généré automatiquement pour les réseaux sociaux par une image statique. Si vous souhaitez que Mintlify superpose automatiquement votre logo, le titre de la page et la description sur un arrière-plan personnalisé, utilisez plutôt [`thumbnails.background`](/fr/organize/settings-appearance#param-thumbnails-background).
</Note>

<div id="global-meta-tags">
  ## Balises méta globales
</div>

Pour définir des balises méta par défaut sur toutes les pages, ajoutez le champ `metatags` à votre `docs.json`.

```json
"seo": {
    "metatags": {
        "og:image": "link to your default meta tag image"
    }
}
```

<div id="set-a-canonical-url">
  ### Définir une URL canonique
</div>

Si vous utilisez un domaine personnalisé, définissez la balise méta `canonical` afin que les moteurs de recherche indexent le domaine de votre choix. Une URL canonique indique aux moteurs de recherche quelle version de votre documentation doit être considérée comme la version principale. Cela améliore le SEO lorsque votre documentation est accessible via plusieurs URL et évite les problèmes de contenu dupliqué.

```json
"seo": {
    "metatags": {
        "canonical": "https://www.your-custom-domain-here.com"
    }
}
```

<Note>
  Vérifiez toujours le comportement de l’URL canonique sur votre site déployé. Lors des builds locaux, `/src/_props` est ajouté aux URL comme artefact et ne fait pas partie de l’URL canonique.
</Note>

<div id="page-specific-meta-tags">
  ## Balises méta propres à une page
</div>

Pour définir des balises méta propres à une page, ajoutez-les aux métadonnées d’en-tête de cette page.

Les balises méta propres à une page incluent :

* `title` - Titre de la page
* `description` - La description de la page s’affiche sous le titre sur la page et dans certains résultats de moteurs de recherche
* `keywords` - Mots-clés séparés par des virgules
* `og:title` - Titre Open Graph pour le partage sur les réseaux sociaux
* `og:description` - Description Open Graph, avec `description` comme valeur de repli
* `og:image` - URL de l’image Open Graph
* `og:url` - URL Open Graph
* `og:type` - Type Open Graph, comme &quot;article&quot; ou &quot;website&quot;
* `og:image:width` - Largeur de l’image Open Graph
* `og:image:height` - Hauteur de l’image Open Graph
* `twitter:title` - Titre de la carte Twitter, avec `og:title`, puis `title`, comme valeurs de repli
* `twitter:description` - Description de la carte Twitter, avec `og:description`, puis `description`, comme valeurs de repli
* `twitter:image` - Image de la carte Twitter
* `twitter:card` - Type de carte Twitter, comme `summary` ou `summary_large_image`
* `twitter:site` - Identifiant Twitter du site
* `twitter:image:width` - Largeur de l’image Twitter
* `twitter:image:height` - Hauteur de l’image Twitter
* `noindex` - Définissez sur `true` pour empêcher l’indexation par les moteurs de recherche
* `robots` - Valeur de la balise méta robots

<Tip>
  Les balises méta Twitter héritent automatiquement de leurs équivalents Open Graph. Par exemple, si vous définissez `og:title` mais pas `twitter:title`, la carte Twitter utilise la valeur de `og:title`. Définissez explicitement `twitter:title` ou `twitter:description` uniquement si vous souhaitez afficher un texte différent sur Twitter que sur les autres plateformes.
</Tip>

```mdx
---
title: "Your example page title"
description: "Page-specific description"
"og:title": "Social media title"
"og:description": "Custom description for social sharing"
"og:image": "link to your meta tag image"
"twitter:title": "Twitter-specific title"
keywords: ["keyword1", "keyword2"]
---
```

<Note>
  Vous devez mettre entre guillemets les balises méta qui contiennent des deux-points. Par exemple, `og:title: "Social media title"`.

  Vous devez formater le champ `keywords` sous forme de tableau YAML. Par exemple, `keywords: ["keyword1", "keyword2", "keyword3"]`.
</Note>

<div id="sitemaps-and-robotstxt-files">
  ## Sitemaps et fichiers robots.txt
</div>

Mintlify génère automatiquement un fichier `sitemap.xml` et un fichier `robots.txt`. Vous pouvez consulter votre sitemap en ajoutant `/sitemap.xml` à l’URL de votre site de documentation.

Par défaut, Mintlify indexe uniquement les pages incluses dans la navigation de votre `docs.json`. Il exclut les [pages masquées](/fr/organize/hidden-pages), présentes dans votre dépôt mais absentes de votre navigation, des éléments suivants :

* Les sitemaps des moteurs de recherche
  * La recherche interne dans la documentation
  * Le contexte de l’[assistant IA](/fr/assistant/index)
  * Les résultats de recherche du [serveur MCP](/fr/ai/model-context-protocol)

Pour inclure les pages masquées dans l’indexation de recherche, ajoutez `seo.indexing` à votre `docs.json` :

```json
"seo": {
    "indexing": "all"
}
```

<Note>
  Pour les sites de documentation qui nécessitent une authentification, l&#39;accès aux sitemaps et aux fichiers `robots.txt` nécessite lui aussi une authentification. Les sitemaps excluent les pages appartenant à des [groupes d&#39;utilisateurs](/fr/deploy/authentication-setup#control-access-with-groups).
</Note>

<div id="custom-sitemaps-and-robotstxt-files">
  ### Fichiers `sitemap.xml` et `robots.txt` personnalisés
</div>

Pour ajouter un fichier `sitemap.xml` ou `robots.txt` personnalisé, créez un fichier `sitemap.xml` ou `robots.txt` à la racine de votre projet. L’ajout d’un fichier personnalisé remplace le fichier du même nom généré automatiquement. Si vous supprimez un fichier personnalisé, le fichier par défaut est automatiquement réappliqué.

<Tip>
  Si votre fichier `robots.txt` personnalisé bloque des user-agents d’IA comme `GPTBot`, `ClaudeBot` ou `PerplexityBot`, les outils d’IA ne pourront pas explorer votre documentation ni la citer dans leurs réponses. Pour en savoir plus, consultez [Autoriser les agents d’IA dans robots.txt](/fr/guides/geo#allow-ai-agents-in-robotstxt).
</Tip>

<div id="disable-indexing">
  ## Désactiver l’indexation
</div>

Pour empêcher les moteurs de recherche d’indexer une page, ajoutez `noindex: true` aux [métadonnées d’en-tête](/fr/organize/pages) de cette page.

```yaml
---
noindex: true
---
```

<Tip>
  Les pages avec `hidden: true` dans leurs métadonnées d’en-tête sont automatiquement considérées comme ayant `noindex: true`. Consultez [Pages masquées](/fr/organize/hidden-pages) pour en savoir plus.
</Tip>

Vous pouvez également définir `noindex` pour toutes les pages de votre documentation en réglant le champ `metatags.robots` sur `"noindex"` dans votre `docs.json` :

```json
"seo": {
    "metatags": {
      "robots": "noindex"
    }
  }
```

<div id="seo-best-practices">
  ## Bonnes pratiques SEO
</div>

<AccordionGroup>
  <Accordion title="Rédigez des titres et des descriptions explicites">
    * Utilisez des titres de page clairs et explicites (50 à 60 caractères)
    * Rédigez des descriptions attrayantes (150 à 160 caractères)
    * Intégrez des mots-clés pertinents
    * Veillez à ce que le titre et la description de chaque page soient uniques
  </Accordion>

  <Accordion title="Optimisez la structure de votre contenu">
    * Utilisez une hiérarchie de titres appropriée (H1 → H2 → H3)
    * Écrivez d&#39;abord pour les humains, puis pour les moteurs de recherche
    * Intégrez des mots-clés pertinents dans les titres et le contenu
    * Gardez des URL courtes, explicites et organisées de manière hiérarchique
    * Structurez les contenus longs à l&#39;aide de sous-titres et de listes
  </Accordion>

  <Accordion title="Stratégie de liens internes">
    * Ajoutez des liens vers des pages connexes dans votre documentation
    * Utilisez un texte d&#39;ancrage explicite au lieu de &quot;cliquez ici&quot;
    * Créez des groupes thématiques en reliant des concepts associés
    * Utilisez les fonctionnalités de référence croisée automatiques
  </Accordion>

  <Accordion title="SEO des images">
    * Utilisez des noms de fichier explicites pour les images
    * Incluez toujours un texte alternatif pour l&#39;accessibilité et le SEO
    * Optimisez la taille des fichiers image pour accélérer le chargement
    * Utilisez des images pertinentes qui renforcent votre contenu
  </Accordion>
</AccordionGroup>
