<div id="feedback-types">
  ## Types de retours
</div>

<Note>
  Les retours contextuels et sur les extraits de code sont en version bêta. Pour les activer sur votre site de documentation, [contactez notre équipe commerciale](mailto:hahnbee@mintlify.com).
</Note>

L’onglet des retours affiche des informations selon les [modules complémentaires de feedback](https://dashboard.mintlify.com/products/addons) que vous activez.

<Frame>
  <img className="block dark:hidden" src="/images/analytics/feedback-addons-light.png" alt="Options de feedback sur la page des modules complémentaires." />

  <img className="hidden dark:block" src="/images/analytics/feedback-addons-dark.png" alt="Options de feedback sur la page des modules complémentaires." />
</Frame>

* **Évaluation par pouces** : vote simple par pouce levé ou pouce baissé pour mesurer la satisfaction globale vis-à-vis des pages.
* **Suggestions de modification** : permet aux utilisateurs de suggérer des modifications de votre documentation. Disponible uniquement pour les dépôts GitHub publics.
* **Signalement de problèmes** : permet aux utilisateurs de créer des issues GitHub directement depuis votre documentation. Disponible uniquement pour les dépôts GitHub publics.
* **Retours contextuels** : retours libres sur le contenu d’une page.
* **Retours sur les extraits de code** : retours portant spécifiquement sur les extraits de code.
* **Retours des agents** : retours envoyés par des agents IA tiers qui accèdent à votre documentation.

<div id="collect-email-addresses">
  ## Collecter des adresses e-mail
</div>

Activez la collecte d’adresses e-mail pour permettre aux utilisateurs d’indiquer, s’ils le souhaitent, leur adresse e-mail lorsqu’ils envoient un retour.

1. Accédez à la page [Add-ons](https://dashboard.mintlify.com/products/addons) dans votre tableau de bord.
2. Activez l’option **Collect reader emails** dans les paramètres de feedback.
3. Ajoutez éventuellement une mention de confidentialité expliquant comment votre équipe utilise les adresses e-mail collectées.

Consultez les adresses e-mail envoyées avec les retours dans le [tableau de bord des retours](https://dashboard.mintlify.com/products/analytics/v2/feedback), avec le contenu des retours.

<Note>
  Si vous désactivez la télémétrie dans votre fichier `docs.json`, les fonctionnalités de feedback ne sont pas disponibles sur les pages de votre documentation.
</Note>

<div id="manage-feedback">
  ## Gérer les retours
</div>

Pour les retours contextuels et les retours sur des extraits de code, vous pouvez définir le statut d’un retour et ajouter des notes internes pour suivre votre progression dans la résolution des retours des utilisateurs.

<div id="change-feedback-status">
  ### Modifier le statut d’un retour
</div>

Sélectionnez le statut à côté d’un retour pour le marquer comme **En attente**, **En cours**, **Résolu** ou **Écarté**.

Bonnes pratiques pour attribuer des statuts aux retours :

* **En attente** : Le retour est en attente d’examen.
* **En cours** : Le retour est en cours de traitement.
* **Résolu** : Le retour a été résolu.
* **Écarté** : Le retour n’est pas pertinent ou est inexact.

<div id="filter-by-status">
  ### Filtrer par statut
</div>

Utilisez le menu **Filters** pour choisir les retours à afficher. Décochez un statut pour masquer tous les retours associés. Par défaut, tous les types de retours sont affichés.

<div id="filter-by-type">
  ### Filtrer par type
</div>

Choisissez entre **Évaluations par page**, **Commentaires détaillés** et **Extraits de code** selon les informations que vous souhaitez analyser.

* **Évaluations par page** : voyez quelles pages reçoivent le plus de retours positifs et négatifs. Utilisez ces données quantitatives pour identifier les pages que les utilisateurs trouvent les plus ou les moins utiles.
* **Commentaires détaillés** : examinez les retours ouverts laissés par les utilisateurs sur les pages afin d’identifier des améliorations ciblées pour des pages précises.
* **Extraits de code** : examinez les retours ouverts laissés par les utilisateurs sur les extraits de code afin d’identifier des améliorations ciblées pour des blocs de code précis.

<div id="add-internal-notes">
  ### Ajouter des notes internes
</div>

Cliquez sur un feedback pour ajouter une note interne. Ces notes sont visibles uniquement par les personnes ayant accès à votre tableau de bord.

Utilisez les notes pour ajouter des informations utiles à la collaboration, lier des tickets de support ou d’ingénierie pertinents, ou consigner toute autre information utile.

<div id="agent-feedback">
  ## Commentaires des agents
</div>

<Note>
  Les commentaires des agents sont en version bêta et sont susceptibles d’évoluer.
</Note>

Lorsque des agents d’IA tiers consultent votre documentation, ils peuvent envoyer des commentaires structurés sur les pages qu’ils jugent incorrectes, obsolètes ou difficiles à utiliser.

Ces commentaires apparaissent dans le [tableau de bord des retours](https://dashboard.mintlify.com/products/analytics/v2/feedback), signalés par un badge **Agent**. Gérez les commentaires des agents de la même manière que les retours humains. Définissez des statuts, ajoutez des notes internes et filtrez les retours.

<div id="how-agent-feedback-works">
  ### Comment fonctionnent les retours des agents
</div>

Vous devez activer les retours des agents dans votre tableau de bord pour pouvoir les recueillir.

Une fois cette option activée, Mintlify ajoute un bloc `<AgentInstructions>` contenant des instructions et le point de terminaison auquel envoyer les retours lorsqu’un agent récupère une page via l’export Markdown.

Les agents envoient leurs retours au point de terminaison avec le chemin de la page et le texte du retour. Les retours apparaissent dans le tableau de bord à côté des retours humains.

Le point de terminaison de retour est toujours disponible à l’adresse `https://your-domain.com/feedback` via une requête `POST`, même si vous n’ajoutez pas les instructions à l’export Markdown. Vous pouvez donc inviter les agents à envoyer manuellement des retours en effectuant une requête vers ce point de terminaison.

<div id="retrieve-agent-feedback-via-api">
  ### Récupérer les retours d’agent via l’API
</div>

Utilisez le [point de terminaison des analyses des retours](/fr/api/analytics/feedback) pour récupérer les retours d’agent par programmation. Filtrez avec `source=agent` pour ne renvoyer que les retours d’agent.

Les réponses de retour d’agent incluent :

* `comment` : Le texte du retour envoyé par l’agent.
* `path` : Le chemin de la page concernée par le retour.

<div id="use-feedback-data">
  ## Utiliser les données de retour
</div>

Examinez vos données de retour pour :

* **Identifier le contenu efficace** : les pages qui reçoivent le plus de retours positifs montrent ce qui fonctionne bien dans votre documentation.
* **Prioriser les améliorations** : les pages qui reçoivent le plus de retours négatifs indiquent quel contenu mérite votre attention.
* **Passer à l&#39;action** : mettez à jour votre documentation en vous appuyant sur les retours directs des utilisateurs.
