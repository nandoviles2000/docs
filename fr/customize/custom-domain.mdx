Pour héberger votre documentation sur un domaine personnalisé :

1. Ajoutez votre domaine dans votre tableau de bord.
2. Configurez les paramètres DNS auprès de votre fournisseur de domaine.
3. Attendez la propagation DNS et le provisionnement automatique des certificats TLS.

<Info>
  Vous souhaitez configurer un sous-chemin comme `example.com/docs` ? Consultez [/docs en sous-chemin](/fr/deploy/docs-subpath).
</Info>

<div id="add-your-custom-domain">
  ## Ajoutez votre domaine personnalisé
</div>

1. Accédez à la page [Configuration du domaine personnalisé](https://dashboard.mintlify.com/settings/deployment/custom-domain) dans le tableau de bord.
2. Saisissez votre nom de domaine, par exemple `docs.example.com` ou `www.example.com`.
3. Cliquez sur **Ajouter un domaine**.

<div id="configure-your-dns">
  ## Configurez votre DNS
</div>

1. Sur le site de votre fournisseur de domaine, accédez à la configuration DNS de votre domaine.
2. Créez un nouvel enregistrement DNS avec les valeurs suivantes :

```text
CNAME | docs | cname.mintlify-dns.com.
```

<Tip>
  Chaque fournisseur de domaine a sa propre manière d’ajouter des enregistrements DNS. Consultez la documentation de votre fournisseur de domaine pour obtenir des instructions détaillées.
</Tip>

<div id="dns-propagation">
  ### Propagation du DNS
</div>

Les modifications DNS prennent généralement entre 1 et 24 heures pour se propager à l’échelle mondiale, même si cela peut prendre jusqu’à 48 heures dans certains cas. Vous pouvez vérifier que votre configuration DNS est correcte à l’aide de [DNSChecker](https://dnschecker.org).

Une fois vos enregistrements DNS actifs, votre documentation est d’abord accessible via HTTP. HTTPS est disponible une fois que Vercel a provisionné votre certificat TLS.

<div id="automatic-tls-provisioning">
  ### Provisionnement automatique de TLS
</div>

Une fois que vos enregistrements DNS sont propagés et correctement résolus, Vercel provisionne automatiquement un certificat SSL/TLS gratuit pour votre domaine via Let&#39;s Encrypt.

Cette opération s’effectue généralement dans les heures qui suivent la propagation DNS, bien qu’elle puisse prendre jusqu’à 24 heures dans de rares cas. Les certificats sont automatiquement renouvelés avant leur expiration.

<div id="caa-records">
  ### Enregistrements CAA
</div>

Si votre domaine utilise des enregistrements CAA (Certification Authority Authorization), vous devez autoriser Let&#39;s Encrypt à délivrer des certificats pour votre domaine. Ajoutez l’enregistrement CAA suivant à votre configuration DNS :

```text
0 issue "letsencrypt.org"
```

<div id="reserved-paths">
  ### Chemins réservés
</div>

Le chemin `/.well-known/acme-challenge` est réservé à la validation des certificats et ne peut faire l’objet ni d’une redirection ni d’une réécriture. Si vous avez configuré des redirections ou des réécritures pour ce chemin, le provisionnement du certificat échouera.

<div id="provider-specific-settings">
  ### Paramètres spécifiques au fournisseur
</div>

<AccordionGroup>
  <Accordion title="Vérification Vercel">
    Si Vercel est votre fournisseur de domaine, vous devez ajouter un enregistrement `TXT` de vérification. Ces informations apparaissent dans votre tableau de bord après avoir soumis votre domaine personnalisé et vous sont également envoyées par e-mail.
  </Accordion>

  <Accordion title="Mode de chiffrement Cloudflare">
    Si Cloudflare est votre fournisseur DNS, vous devez activer le mode &quot;Full (strict)&quot; pour le paramètre de chiffrement SSL/TLS. De plus, désactivez &quot;Always Use HTTPS&quot; dans vos paramètres Edge Certificates. La redirection HTTPS de Cloudflare empêche Let&#39;s Encrypt de valider votre domaine lors du provisionnement du certificat.
  </Accordion>
</AccordionGroup>

<div id="set-a-canonical-url">
  ## Définir une URL canonique
</div>

Après avoir configuré votre DNS, définissez une URL canonique afin que les moteurs de recherche indexent le domaine de votre choix. Une URL canonique indique aux moteurs de recherche quelle version de votre documentation fait foi. Cela améliore le SEO lorsque votre documentation est accessible depuis plusieurs URL et évite les problèmes de contenu dupliqué.

Ajoutez la balise méta `canonical` à votre `docs.json` :

```json
"seo": {
    "metatags": {
        "canonical": "https://www.your-custom-domain-here.com"
    }
}
```

Remplacez `https://www.your-custom-domain-here.com` par votre véritable domaine personnalisé. Par exemple, si votre domaine personnalisé est `docs.mintlify.com`, utilisez :

```json
"seo": {
    "metatags": {
        "canonical": "https://docs.mintlify.com"
    }
}
```
