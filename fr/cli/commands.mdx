<div id="global-flags">
  ## Options globales
</div>

Ces options sont disponibles sur toutes les commandes.

| Option              | Description                                              |
| ------------------- | -------------------------------------------------------- |
| `--telemetry`, `-t` | Active ou désactive la télémétrie d’utilisation anonyme. |
| `--help`, `-h`      | Affiche l’aide de la commande.                           |
| `--version`, `-v`   | Affiche la version de la CLI. Alias pour `mint version`. |

<div id="mint-dev">
  ## `mint dev`
</div>

Lancez un aperçu local de votre documentation.

```bash
mint dev [flags]
```

| Option              | Description                                                                         |
| ------------------- | ----------------------------------------------------------------------------------- |
| `--port`            | Port sur lequel exécuter l’aperçu local. Valeur par défaut : `3000`.                |
| `--no-open`         | N’ouvre pas automatiquement le navigateur.                                          |
| `--groups`          | Liste de groupes d’utilisateurs, séparés par des virgules, à simuler pour l’aperçu. |
| `--disable-openapi` | Ignore le traitement des fichiers OpenAPI pour améliorer les performances.          |
| `--local-schema`    | Autorise les fichiers OpenAPI hébergés localement et servis via HTTP.               |

<div id="mint-login">
  ## `mint login`
</div>

Authentifiez-vous à l’aide de votre compte Mintlify.

```bash
mint login
```

Ouvre une fenêtre de navigateur pour finaliser l’authentification. Si le navigateur ne s’ouvre pas, le CLI affiche une URL à ouvrir manuellement ainsi qu’une invite vous demandant de coller le code d’autorisation. Les identifiants sont enregistrés dans `~/.config/mintlify/config.json`.

Si vous avez plusieurs déploiements, le CLI vous invite à en sélectionner un par défaut après vous être connecté. Vous pourrez modifier le projet par défaut plus tard avec `mint config set subdomain <subdomain>`.

<div id="mint-analytics">
  ## `mint analytics`
</div>

Consultez les données d’analyse de votre documentation. Une authentification avec `mint login` est requise.

```bash
mint analytics <subcommand> [flags]
```

Toutes les sous-commandes acceptent ces options communes :

| option        | Description                                                                                                                                          |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--subdomain` | Sous-domaine de la documentation. Par défaut, utilise la valeur définie avec `mint config set subdomain`, ou le premier projet de votre compte.      |
| `--from`      | Date de début au format `YYYY-MM-DD`. Par défaut, la date utilisée est celle d’il y a 7 jours, ou la valeur définie avec `mint config set dateFrom`. |
| `--to`        | Date de fin au format `YYYY-MM-DD`. Par défaut, la date utilisée est celle d’aujourd’hui, ou la valeur définie avec `mint config set dateTo`.        |
| `--format`    | Format de sortie : `plain` (par défaut), `table`, `json` ou `graph`.                                                                                 |

<div id="mint-analytics-stats">
  ### `mint analytics stats`
</div>

Affiche un récapitulatif des vues, des visiteurs, des recherches, des retours et de l’utilisation de l’assistant.

```bash
mint analytics stats [flags]
```

| Option   | Description                             |
| -------- | --------------------------------------- |
| `--page` | Limiter à un chemin de page spécifique. |

<div id="mint-analytics-search">
  ### `mint analytics search`
</div>

Affiche les requêtes de recherche avec leur nombre de résultats et leur taux de clic.

```bash
mint analytics search [flags]
```

| Option    | Description                                               |
| --------- | --------------------------------------------------------- |
| `--query` | Filtrer selon une sous-chaîne de la requête de recherche. |
| `--page`  | Filtrer selon la page la plus cliquée.                    |

<div id="mint-analytics-feedback">
  ### `mint analytics feedback`
</div>

Affiche les retours envoyés par les utilisateurs.

```bash
mint analytics feedback [flags]
```

| Option   | Description                                                                                |
| -------- | ------------------------------------------------------------------------------------------ |
| `--type` | Type de feedback : `page` (agrégé par page) ou `code` (feedback sur les extraits de code). |
| `--page` | Filtrer sur un chemin de page spécifique.                                                  |

<div id="mint-analytics-conversation">
  ### `mint analytics conversation`
</div>

Consultez les données des conversations de l’assistant.

```bash
mint analytics conversation <subcommand> [flags]
```

<div id="mint-analytics-conversation-list">
  #### `mint analytics conversation list`
</div>

Répertorie les conversations de l’assistant. Chaque entrée comprend un identifiant de conversation.

```bash
mint analytics conversation list [flags]
```

| Option   | Description                                                                     |
| -------- | ------------------------------------------------------------------------------- |
| `--page` | Filtre les conversations faisant référence à une page précise dans les sources. |

<div id="mint-analytics-conversation-view-conversation-id">
  #### `mint analytics conversation view <conversation-id>`
</div>

Affichez une conversation spécifique à partir de son ID. Utilisez `mint analytics conversation list` pour obtenir les ID.

```bash
mint analytics conversation view <conversation-id>
```

<div id="mint-analytics-conversation-buckets-list">
  #### `mint analytics conversation buckets list`
</div>

Liste les catégories de conversation regroupées. Chaque entrée comprend un ID de bucket.

```bash
mint analytics conversation buckets list
```

<div id="mint-analytics-conversation-buckets-view-bucket-id">
  #### `mint analytics conversation buckets view <bucket-id>`
</div>

Affiche les conversations d’un bucket de catégorie. Utilisez `mint analytics conversation buckets list` pour obtenir les ID.

```bash
mint analytics conversation buckets view <bucket-id>
```

<div id="mint-config">
  ## `mint config`
</div>

Gérez les valeurs par défaut persistantes des commandes CLI. La configuration est enregistrée dans `~/.config/mintlify/config.json`.

```bash
mint config <subcommand> <key> [value]
```

| Sous-commande       | Description                           |
| ------------------- | ------------------------------------- |
| `set <key> <value>` | Définit une valeur de configuration.  |
| `get <key>`         | Affiche une valeur de configuration.  |
| `clear <key>`       | Supprime une valeur de configuration. |

<div id="configuration-keys">
  ### Clés de configuration
</div>

| Clé         | Description                                                          | Utilisé par      |
| ----------- | -------------------------------------------------------------------- | ---------------- |
| `subdomain` | Sous-domaine par défaut de la documentation.                         | `mint analytics` |
| `dateFrom`  | Date de début par défaut pour les requêtes d’analyse (`YYYY-MM-DD`). | `mint analytics` |
| `dateTo`    | Date de fin par défaut pour les requêtes d’analyse (`YYYY-MM-DD`).   | `mint analytics` |

<div id="mint-broken-links">
  ## `mint broken-links`
</div>

Vérifiez les liens internes brisés dans votre documentation.

```bash
mint broken-links [flags]
```

La commande exclut les fichiers qui correspondent aux motifs définis dans [.mintignore](/fr/organize/mintignore). Les liens pointant vers des fichiers ignorés sont signalés comme rompus.

| option             | Description                                                                                         |
| ------------------ | --------------------------------------------------------------------------------------------------- |
| `--check-anchors`  | Valide également les liens d’ancrage (par exemple, `/page#section`) en fonction des slugs de titre. |
| `--check-external` | Vérifie également les URL externes afin de détecter les liens rompus.                               |
| `--check-snippets` | Vérifie également les liens à l’intérieur des composants `<Snippet>`.                               |

<div id="mint-validate">
  ## `mint validate`
</div>

Validez la compilation de votre documentation en mode strict. La commande se termine par une erreur s’il y a le moindre avertissement ou la moindre erreur. Elle inclut la validation automatique des spécifications OpenAPI référencées dans votre `docs.json`.

```bash
mint validate [flags]
```

| option              | Description                                                                                                                      |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `--groups`          | Liste de groupes d’utilisateurs, séparés par des virgules, à simuler lors de la validation.                                      |
| `--disable-openapi` | Ignorer le traitement et la validation des fichiers OpenAPI.                                                                     |
| `--local-schema`    | Autoriser la validation de fichiers OpenAPI hébergés localement et servis via HTTP. Seul HTTPS est pris en charge en production. |

<Note>
  La commande autonome `mint openapi-check` est obsolète. Utilisez plutôt `mint validate`.
</Note>

Voir [Export hors ligne](/fr/deploy/export) pour en savoir plus.

<div id="mint-score">
  ## `mint score`
</div>

Exécutez des vérifications de l’état de préparation des agents sur un site de documentation public. Une authentification avec `mint login` est requise.

```bash
mint score <url> [flags]
```

| Option     | Description                                                                                               |
| ---------- | --------------------------------------------------------------------------------------------------------- |
| `--format` | Format de sortie : `table` (par défaut, en couleur), `plain` (TSV utilisable dans un pipeline) ou `json`. |

La commande affiche un score global de préparation ainsi qu’un détail des différentes vérifications, avec des indicateurs de réussite ou d’échec.

<div id="checks">
  ### Vérifications
</div>

Le score évalue les domaines suivants :

| Vérification                  | Ce qu’elle vérifie                                                                                                                                                                             |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `llmsTxtExists`               | Les agents peuvent accéder à un fichier [llms.txt](/fr/ai/llmstxt) à la racine du site.                                                                                                           |
| `llmsTxtValid`                | Le fichier `llms.txt` respecte le format attendu, avec des titres, un résumé sous forme de citation et des liens Markdown.                                                                     |
| `llmsTxtSize`                 | Le fichier `llms.txt` reste sous le seuil de taille afin que les agents puissent le traiter sans troncature.                                                                                   |
| `llmsTxtLinksResolve`         | Les liens dans `llms.txt` mènent vers des pages accessibles.                                                                                                                                   |
| `llmsTxtLinksMarkdown`        | Les liens dans `llms.txt` utilisent la syntaxe Markdown.                                                                                                                                       |
| `llmsTxtDirective`            | Le fichier `llms.txt` contient des directives d’utilisation.                                                                                                                                   |
| `llmsTxtFullExists`           | Un fichier [llms-full.txt](/fr/ai/llmstxt/#llms-full-txt) est disponible pour les agents qui ont besoin du contenu complet. S’exécute indépendamment de `llmsTxtExists`.                          |
| `llmsTxtFullSize`             | Le fichier `llms-full.txt` a une taille raisonnable pour être traité par les agents.                                                                                                           |
| `llmsTxtFullValid`            | Le fichier `llms-full.txt` contient un contenu valide avec des titres.                                                                                                                         |
| `llmsTxtFullLinksResolve`     | Les liens dans `llms-full.txt` mènent vers des pages accessibles.                                                                                                                              |
| `skillMd`                     | Les agents peuvent accéder à un fichier [skill.md](https://www.mintlify.com/docs/ai/skillmd) pour utiliser des outils.                                                                         |
| `contentNegotiationMarkdown`  | Le site renvoie du Markdown lorsque les agents le demandent via la négociation de contenu.                                                                                                     |
| `contentNegotiationPlaintext` | Le site renvoie du texte brut lorsque les agents le demandent via la négociation de contenu.                                                                                                   |
| `mcpServerDiscoverable`       | Les agents peuvent détecter un [serveur MCP](/fr/ai/model-context-protocol) pour les agents basés sur des outils.                                                                                 |
| `mcpToolCount`                | Le serveur MCP expose au moins un outil.                                                                                                                                                       |
| `openApiSpec`                 | Une spécification OpenAPI ou Swagger est disponible à un chemin standard.                                                                                                                      |
| `robotsTxtAllowsAI`           | Le fichier `robots.txt` ne bloque pas les robots d’exploration d’IA.                                                                                                                           |
| `sitemapExists`               | Un sitemap est disponible pour faciliter la découverte des pages.                                                                                                                              |
| `structuredData`              | La page d’accueil contient des données structurées [JSON-LD](https://json-ld.org/) (`<script type="application/ld+json">`). Indique le nombre de blocs JSON-LD et les types de schéma trouvés. |
| `responseLatency`             | Le site répond dans un délai acceptable pour les agents.                                                                                                                                       |

Certaines vérifications ne s’exécutent que si une vérification dont elles dépendent réussit. Si une vérification échoue, aucune des vérifications qui en dépendent ne s’exécute. Elles échouent automatiquement. Par exemple, `llmsTxtValid` ne réussit que si `llmsTxtExists` réussit d’abord.

Le score global repose sur une pondération : les vérifications ayant le plus d’impact contribuent davantage à votre score.

</div>

Créez un nouveau projet de documentation en choisissant un thème ou en clonant un modèle prédéfini à partir du dépôt [mintlify/templates](https://github.com/mintlify/templates).


| Option       | Description                                                                                                |
| ------------ | ---------------------------------------------------------------------------------------------------------- |
| `--name`     | Nom du projet. La CLI vous le demande si vous ne l’indiquez pas en mode interactif.                        |
| `--theme`    | [thème](/fr/customize/themes) du projet. La CLI vous le demande si vous ne l’indiquez pas en mode interactif. |
| `--template` | Modèle prédéfini. La CLI vous le demande si vous ne l’indiquez pas en mode interactif.                     |
| `--force`    | Écrase le répertoire sans demander de confirmation.                                                        |

<div id="telemetry">
  ## Télémétrie
</div>

La CLI collecte des données de télémétrie d’utilisation anonymisées afin d’aider à améliorer Mintlify. Ces données incluent le nom de la commande, la version de la CLI, le système d’exploitation et l’architecture. Mintlify ne collecte **pas** d’informations permettant d’identifier une personne, de contenu de projet ni de chemins de fichiers.

Par défaut, la CLI collecte des données de télémétrie. Vous pouvez désactiver cette collecte à tout moment à l’aide de l’indicateur `--telemetry` :

```bash
# Désactiver la télémétrie
mint --telemetry false

# Réactiver la télémétrie
mint --telemetry true
```

Vous pouvez également désactiver la télémétrie en définissant l’une de ces variables d’environnement :

| Variable                      | Valeur | Description                                                                                          |
| ----------------------------- | ------ | ---------------------------------------------------------------------------------------------------- |
| `MINTLIFY_TELEMETRY_DISABLED` | `1`    | Désactive la télémétrie du CLI Mintlify.                                                             |
| `DO_NOT_TRACK`                | `1`    | Désactive la télémétrie à l’aide de la norme [Console Do Not Track](https://consoledonottrack.com/). |

Votre préférence est enregistrée dans `~/.config/mintlify/config.json` et persiste d’une session CLI à l’autre.
