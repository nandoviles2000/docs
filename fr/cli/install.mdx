<div id="prerequisites">
  ## Prérequis
</div>

* [Node.js](https://nodejs.org/en) v20.17.0+ (version LTS recommandée)

<div id="install-the-cli">
  ## Installez la CLI
</div>

<CodeGroup>
  ```bash npm
  npm i -g mint
  ```

  ```bash pnpm
  pnpm add -g mint
  ```
</CodeGroup>

<div id="create-a-new-project">
  ## Créer un nouveau projet
</div>

Pour créer un nouveau projet de documentation à partir du modèle de base Mintlify, exécutez la commande suivante :

```bash
mint new [directory]
```

Si vous ne spécifiez pas de répertoire, le CLI vous invite à créer un nouveau sous-répertoire ou à remplacer le répertoire actuel.

<Warning>
  Remplacer le répertoire actuel supprime tous les fichiers existants.
</Warning>

| Option       | Description                                                                         |
| ------------ | ----------------------------------------------------------------------------------- |
| `--name`     | Nom du projet. Le CLI vous le demande s’il n’est pas fourni.                        |
| `--theme`    | [Thème](/fr/customize/themes) du projet. Le CLI vous le demande s’il n’est pas fourni. |
| `--template` | Modèle prédéfini. Le CLI vous le demande s’il n’est pas fourni.                     |
| `--force`    | Remplace le répertoire actuel sans demander de confirmation.                        |

En mode interactif, le CLI vous demande si vous souhaitez choisir un thème ou cloner un modèle. Pour éviter cette invite, passez directement l’option `--template` :

```bash
mint new my-docs --template <template-name>
```

Vous pouvez combiner `--template` avec `--theme` pour surcharger le thème par défaut du modèle :

```bash
mint new my-docs --template <template-name> --theme <theme>
```

Consultez les modèles disponibles dans le dépôt [mintlify/templates](https://github.com/mintlify/templates) sur GitHub. En mode interactif, le CLI récupère et affiche automatiquement les modèles disponibles.

Dans les environnements non interactifs, comme les pipelines CI/CD ou les agents de programmation IA, vous devez fournir soit les options `--name` et `--theme`, soit l’option `--template`.

<div id="update">
  ## Update
</div>

Si votre aperçu local n’est pas synchronisé avec votre documentation déployée, mettez à jour la CLI vers sa version la plus récente :

```bash
mint update
```

Si `mint update` n’est pas disponible dans votre version, réinstallez la CLI avec la version la plus récente :

<CodeGroup>
  ```bash npm
  npm i -g mint@latest
  ```

  ```bash pnpm
  pnpm add -g mint@latest
  ```
</CodeGroup>

Pour la coloration syntaxique et la mise en forme du code dans les fichiers MDX, nous vous recommandons d’utiliser les extensions suivantes :

* **JetBrains**: [plugin MDX pour IntelliJ IDEA](https://plugins.jetbrains.com/plugin/14944-mdx) et [Prettier](https://prettier.io/docs/webstorm)

<div id="troubleshooting">
  ## Dépannage
</div>

<AccordionGroup>
  <Accordion title="Erreur : impossible de charger le module &#x22;sharp&#x22; avec le runtime darwin-arm64">
    Cela peut être dû à une version obsolète de Node.js. Essayez la procédure suivante :

    1. Supprimez la version actuellement installée du CLI mint : `npm uninstall -g mint`
    2. Mettez à niveau vers Node.js v20.17.0 ou version ultérieure.
    3. Réinstallez le CLI mint : `npm install -g mint`
  </Accordion>

  <Accordion title="Problème : vous rencontrez une erreur inconnue">
    **Solution** : Accédez à la racine de votre appareil et supprimez le dossier `~/.mintlify`. Exécutez ensuite `mint dev` à nouveau.
  </Accordion>

  <Accordion title="Erreur : permission refusée">
    Cela signifie que vous ne disposez pas des autorisations nécessaires pour installer des packages Node globalement.

    **Solution** : Essayez d’exécuter `sudo npm i -g mint`. Lorsque vous y êtes invité, saisissez le mot de passe que vous utilisez pour déverrouiller votre ordinateur.
  </Accordion>

  <Accordion title="L’aperçu local ne ressemble pas à ma documentation sur le web">
    Cela est probablement dû à une version obsolète du CLI.

    **Solution** : Exécutez `mint update` pour obtenir les dernières modifications.
  </Accordion>

  <Accordion title="package mintlify versus package mint">
    Si vous rencontrez des problèmes avec le package CLI, exécutez d’abord `npm ls -g` pour voir quels packages sont installés globalement. Si vous n’utilisez pas npm, essayez `which mint` pour localiser l’installation.

    Si les packages `mint` et `mintlify` sont tous les deux installés, désinstallez `mintlify` :

    ```bash
    npm uninstall -g mintlify
    npm cache clean --force
    npm i -g mint
    ```
  </Accordion>

  <Accordion title="La version du client affiche 'none' après l’installation">
    Si vous exécutez `mint version` et que la version du client s’affiche comme `none`, il se peut que le CLI ne parvienne pas à télécharger l’application cliente en raison d’un pare-feu d’entreprise ou d’un VPN.

    **Solution** : Demandez à votre administrateur informatique d’ajouter `releases.mintlify.com` à la liste d’autorisation de votre réseau.
  </Accordion>
</AccordionGroup>
