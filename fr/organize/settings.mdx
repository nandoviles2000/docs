Le fichier `docs.json` est le fichier de configuration principal de votre site de documentation Mintlify. Il définit les paramètres globaux de votre site, notamment l’identité visuelle, la structure de Navigation, les intégrations, les paramètres de l’API, et bien plus encore. Considérez-le comme le plan de votre site.

<div id="required-fields">
  ## Champs obligatoires
</div>

Vous devez définir quatre champs pour créer un site fonctionnel.

| Champ            | Description                                                  |
| ---------------- | ------------------------------------------------------------ |
| `name`           | Le nom de votre projet ou de votre organisation              |
| `theme`          | Le [thème](/fr/customize/themes) de votre site                  |
| `colors.primary` | La couleur principale de votre marque, au format hexadécimal |
| `navigation`     | La structure de votre contenu                                |

Tous les autres champs sont facultatifs. Ajoutez-les au fur et à mesure que vous personnalisez et peaufinez votre site.

<div id="minimal-configuration">
  ## Configuration minimale
</div>

Pour une expérience d’édition optimale, incluez la référence `$schema` en haut de votre `docs.json`. Cela active l’autocomplétion, la validation et la documentation intégrée dans la plupart des éditeurs.

```json docs.json
{
  "$schema": "https://mintlify.com/docs.json",
  "theme": "mint",
  "name": "Your project name",
  "colors": {
    "primary": "#ff0000"
  },
  "navigation": {
    "groups": [
      {
        "group": "Home",
        "pages": ["index"]
      }
    ]
  }
}
```

<div id="split-configuration-with-ref">
  ## Scinder la configuration avec `$ref`
</div>

À mesure que votre configuration s&#39;étoffe, vous pouvez scinder `docs.json` en fichiers plus petits à l&#39;aide de références `$ref`. Chaque référence pointe vers un fichier JSON distinct, qui est résolu au moment de la compilation.

Ajoutez une propriété `$ref` avec un chemin de fichier relatif à n&#39;importe quel endroit de votre `docs.json`. Mintlify remplace l&#39;objet `$ref` par le contenu du fichier référencé.

```json docs.json
{
  "$schema": "https://mintlify.com/docs.json",
  "theme": "mint",
  "name": "Acme Docs",
  "colors": {
    "primary": "#1a73e8"
  },
  "navigation": {
    "$ref": "./config/navigation.json"
  }
}
```

```json config/navigation.json
{
  "groups": [
    {
      "group": "Get started",
      "pages": ["index", "quickstart"]
    },
    {
      "group": "Guides",
      "pages": ["guides/first-steps", "guides/advanced"]
    }
  ]
}
```

* Les fichiers référencés peuvent contenir leurs propres références `$ref`. Les chemins imbriqués sont résolus par rapport au fichier qui les contient, et non à `docs.json`.
* Les références doivent pointer vers des fichiers JSON valides.
* Les chemins doivent être relatifs et rester dans la racine du projet. La traversée de répertoires (par exemple, `../../outside`) n&#39;est pas autorisée.
* Les références circulaires provoquent une erreur de compilation.

<div id="merging-sibling-keys">
  ### Fusion des clés au même niveau
</div>

Si un `$ref` se résout en objet, Mintlify fusionne les clés au même niveau du même bloc avec le contenu référencé. Ces clés ont alors priorité sur les clés correspondantes de la référence. Si un `$ref` se résout en une valeur qui n’est pas un objet, comme un tableau, Mintlify ignore les clés au même niveau.

```json docs.json
{
  "appearance": {
    "$ref": "./config/appearance.json",
    "strict": true
  }
}
```

<div id="upgrading-from-mintjson">
  ## Passer de `mint.json` à `docs.json`
</div>

Si votre projet utilise le fichier `mint.json` déprécié, utilisez la [CLI](/fr/cli) pour migrer vers `docs.json`.

<Steps>
  <Step title="Installer ou mettre à jour la CLI">
    Si vous n&#39;avez pas encore installé la [CLI](/fr/cli/install), faites-le maintenant :

    <CodeGroup>
      ```bash npm
      npm i -g mint
      ```

      ```bash yarn
      yarn global add mint
      ```

      ```bash pnpm
      pnpm add -g mint
      ```
    </CodeGroup>

    Si la CLI est déjà installée, assurez-vous qu&#39;elle est à jour :

    ```bash
    mint update
    ```
  </Step>

  <Step title="Créer votre fichier docs.json">
    Dans votre dépôt de documentation, exécutez :

    ```bash
    mint dev
    ```

    Cette commande crée un fichier `docs.json` à partir de votre `mint.json` existant. Vérifiez le fichier généré pour vous assurer que tous les paramètres sont corrects.
  </Step>

  <Step title="Supprimer votre fichier mint.json">
    Une fois que vous avez vérifié que votre `docs.json` est correctement configuré, vous pouvez supprimer en toute sécurité votre ancien fichier `mint.json`.
  </Step>
</Steps>
