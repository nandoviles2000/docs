La propriété [navigation](/fr/organize/settings-structure#navigation) de `docs.json` contrôle la structure et la hiérarchie de l’information de votre documentation.

Avec une configuration de navigation adaptée, vous pouvez organiser votre contenu afin que les utilisateurs trouvent exactement ce qu’ils cherchent.

Choisissez un modèle d’organisation principal à la racine de votre navigation. Une fois ce modèle choisi, vous pouvez y imbriquer d’autres éléments de navigation.

<div id="pages">
  ## Pages
</div>

Les pages sont l’élément de navigation le plus fondamental. Chaque page est un fichier MDX dans votre dépôt de documentation.

<img className="block dark:hidden pointer-events-none" src="/images/navigation/pages-light.png" alt="Illustration décorative de pages." />

<img className="hidden dark:block pointer-events-none" src="/images/navigation/pages-dark.png" alt="Illustration décorative de pages." />

Dans l’objet `navigation`, `pages` est un tableau dont chaque entrée doit référencer le chemin d’accès à un [fichier de page](/fr/organize/pages).

```json
{
  "navigation": {
    "pages": [
      "settings",
      "pages",
      "navigation",
      "themes",
      "custom-domain"
    ]
  }
}
```

<div id="groups">
  ## Groupes
</div>

Utilisez des groupes pour organiser la navigation de votre barre latérale en sections. Vous pouvez imbriquer des groupes les uns dans les autres, leur attribuer des tags et les personnaliser avec des icônes.

<img className="block dark:hidden pointer-events-none" src="/images/navigation/groups-light.png" alt="Illustration décorative de groupes." />

<img className="hidden dark:block pointer-events-none" src="/images/navigation/groups-dark.png" alt="Illustration décorative de groupes." />

Dans l’objet `navigation`, `groups` est un tableau où chaque entrée est un objet qui requiert un champ `group` et un champ `pages`. Les champs `icon`, `tag`, `root` et `expanded` sont facultatifs.

```json
{
  "navigation": {
    "groups": [
      {
        "group": "Getting started",
        "icon": "play",
        "pages": [
          "quickstart",
          {
            "group": "Editing",
            "expanded": false,
            "icon": "pencil",
            "pages": [
              "installation",
              "editor"
            ]
          }
        ]
      },
      {
        "group": "Writing content",
        "icon": "notebook-text",
        "tag": "NEW",
        "pages": [
          "writing-content/page",
          "writing-content/text"
        ]
      }
    ]
  }
}
```

<div id="root-page">
  ### Page racine
</div>

Utilisez la propriété `root` pour définir une page principale pour un groupe. Lorsqu’un groupe possède une page racine, un clic sur le titre du groupe dans la navigation latérale ouvre cette page. Les pages racines fonctionnent pour les groupes de premier niveau comme pour les groupes imbriqués.

```json Example group with a root page
{
  "navigation": {
    "groups": [
      {
        "group": "API pages",
        "root": "api-overview",
        "pages": [
          "api-reference/get",
          "api-reference/post",
          "api-reference/delete"
        ]
      }
    ]
  }
}
```

<div id="directory-listings">
  ### Listes de répertoire
</div>

Utilisez la propriété `directory` pour afficher automatiquement une liste des pages et des groupes enfants sur les pages racines de groupe. Lorsque vous définissez `directory` sur n’importe quel objet de l’arborescence `navigation` dans `docs.json`, les groupes dont la page `root` correspond à cet objet ou se trouve sous celui-ci affichent une liste de leurs pages et de leurs groupes sous le contenu de leur page.

La propriété `directory` accepte trois valeurs :

| Valeur        | Comportement                                                                      |
| :------------ | :-------------------------------------------------------------------------------- |
| `"none"`      | Aucune liste de répertoire. Valeur par défaut.                                    |
| `"accordion"` | Affiche les pages enfants dans une liste repliable, groupée par section.          |
| `"card"`      | Affiche les pages enfants dans une présentation horizontale sous forme de cartes. |

La valeur `directory` se transmet récursivement dans toute l’arborescence de navigation. Définissez-la n’importe où dans l’objet `navigation`, et tous les groupes descendants héritent de la même valeur. Tout descendant peut remplacer la valeur héritée en définissant `directory` sur une autre valeur.

Vous pouvez définir `directory` n’importe où dans l’objet de navigation de votre fichier `docs.json`, notamment sur les onglets, les ancres, les menus déroulants, les produits, les versions, les langues et les groupes individuels.

```json
{
  "navigation": {
    "groups": [
      {
        "group": "Help Center",
        "root": "help/index",
        "directory": "accordion",
        "pages": [
          {
            "group": "Getting Started",
            "root": "help/getting-started/index",
            "pages": [
              "help/getting-started/quickstart",
              "help/getting-started/install"
            ]
          },
          {
            "group": "API Reference",
            "root": "help/api/index",
            "directory": "none",
            "pages": [
              "help/api/overview",
              "help/api/endpoints"
            ]
          }
        ]
      }
    ]
  }
}
```

Dans cet exemple :

* **Centre d’aide** utilise `"accordion"` et sa page racine affiche une liste des répertoires.
* **Prise en main** hérite de `"accordion"` de son parent et affiche également une liste des répertoires.
* **Référence de l’API** remplace cette valeur par `"none"` ; sa page racine n’affiche donc pas de liste des répertoires.

<Note>
  La propriété `directory` n’affecte que les groupes qui ont une page `root`. Les groupes sans page `root` ne sont pas concernés.
</Note>

<div id="default-expanded-state">
  ### État d’expansion par défaut
</div>

Utilisez la propriété `expanded` pour définir l’état par défaut d’un groupe imbriqué dans la barre latérale de navigation.

* `expanded: true` : déplie le groupe par défaut.
* `expanded: false` ou omis : replie le groupe par défaut.

<Note>
  La propriété `expanded` n’affecte que les groupes imbriqués--c’est-à-dire les groupes à l’intérieur d’autres groupes. Les groupes de premier niveau sont toujours dépliés et vous ne pouvez pas les replier.
</Note>

```json
{
  "group": "Getting started",
  "pages": [
    "quickstart",
    {
      "group": "Advanced",
      "expanded": false,
      "pages": ["installation", "configuration"]
    }
  ]
}
```

<div id="tabs">
  ## Tabs
</div>

Les Tabs créent des sections distinctes dans votre documentation, chacune avec son propre chemin d’URL. Les Tabs ajoutent une barre de navigation horizontale en haut de votre documentation, qui permet aux utilisateurs de passer d’une section à l’autre.

<img className="block dark:hidden pointer-events-none" src="/images/navigation/tabs-light.png" alt="Illustration décorative d’une navigation par onglets." />

<img className="hidden dark:block pointer-events-none" src="/images/navigation/tabs-dark.png" alt="Illustration décorative d’une navigation par onglets." />

Dans l’objet `navigation`, `tabs` est un tableau dont chaque entrée est un objet qui requiert un champ `tab` et peut contenir d’autres champs de navigation, comme des groupes, des pages, des icônes ou des liens vers des pages externes.

```json
{
  "navigation": {
    "tabs": [
      {
        "tab": "API reference",
        "icon": "square-terminal",
        "pages": [
          "api-reference/get",
          "api-reference/post",
          "api-reference/delete"
        ]
      },
      {
        "tab": "SDKs",
        "icon": "code",
        "pages": [
          "sdk/fetch",
          "sdk/create",
          "sdk/delete"
        ]
      },
      {
        "tab": "Blog",
        "icon": "newspaper",
        "href": "https://external-link.com/blog"
      }
    ]
  }
}
```

<div id="menus">
  ### Menus
</div>

Les menus ajoutent des entrées de navigation déroulantes à un onglet. Utilisez les menus pour permettre aux utilisateurs d’accéder directement à des pages spécifiques dans un onglet.

Dans l’objet `navigation`, `menu` est un tableau dans lequel chaque entrée est un objet qui doit comporter un champ `item` et peut contenir d’autres champs de navigation, comme des groupes, des pages, des icônes ou des liens vers des pages externes.

Les éléments de menu peuvent uniquement contenir des groupes, des pages et des liens externes.

```json
{
  "navigation": {
    "tabs": [
      {
        "tab": "Developer tools",
        "icon": "square-terminal",
        "menu": [
          {
            "item": "API reference",
            "icon": "rocket",
            "groups": [
              {
                "group": "Core endpoints",
                "icon": "square-terminal",
                "pages": [
                  "api-reference/get",
                  "api-reference/post",
                  "api-reference/delete"
                ]
              }
            ]
          },
          {
            "item": "SDKs",
            "icon": "code",
            "description": "SDKs are used to interact with the API.",
            "pages": [
              "sdk/fetch",
              "sdk/create",
              "sdk/delete"
            ]
          }
        ]
      }
    ]
  }
}
```

<div id="anchors">
  ## Ancres
</div>

Les ancres ajoutent des éléments de Navigation persistants en haut de votre barre latérale. Utilisez-les pour structurer votre contenu, offrir un accès rapide à des ressources externes ou créer des appels à l’action bien mis en avant.

<img className="block dark:hidden pointer-events-none" src="/images/navigation/anchors-light.png" alt="Illustration décorative d’une navigation par ancres." />

<img className="hidden dark:block pointer-events-none" src="/images/navigation/anchors-dark.png" alt="Illustration décorative d’une navigation par ancres." />

Dans l’objet `navigation`, `anchors` est un tableau dont chaque entrée est un objet qui doit contenir un champ `anchor` et peut inclure d’autres champs de Navigation, comme des groupes, des pages, des icônes ou des liens vers des pages externes.

```json
{
  "navigation": {
    "anchors": [
      {
        "anchor": "Documentation",
        "icon": "book-open",
        "pages": [
          "quickstart",
          "development",
          "navigation"
        ]
      },
      {
        "anchor": "API reference",
        "icon": "square-terminal",
        "pages": [
          "api-reference/get",
          "api-reference/post",
          "api-reference/delete"
        ]
      },
      {
        "anchor": "Blog",
        "href": "https://external-link.com/blog"
      }
    ]
  }
}
```

<div id="global-anchors">
  ### Ancres globales
</div>

Utilisez des ancres globales pour les liens qui doivent apparaître sur toutes les pages, quelle que soit la section de votre navigation que l’utilisateur consulte. Les ancres globales sont particulièrement utiles pour créer des liens vers des ressources externes à votre documentation (comme un blog, un forum communautaire ou un portail d’assistance), ou pour offrir un accès constant à des pages internes importantes (comme un journal des modifications ou une page d’état).

Les ancres globales prennent en charge à la fois les URL externes et les chemins relatifs vers des pages de votre documentation.

```json
{
  "navigation": {
    "global":  {
      "anchors": [
        {
          "anchor": "Changelog",
          "icon": "list",
          "href": "/changelog"
        },
        {
          "anchor": "Blog",
          "icon": "pencil",
          "href": "https://mintlify.com/blog"
        }
      ]
    },
    "tabs": /*...*/
  }
}
```

<div id="openapi">
  ## OpenAPI
</div>

Intégrez directement des spécifications OpenAPI à votre structure de Navigation pour générer automatiquement la documentation de votre API. Créez des sections API dédiées ou placez des pages d’endpoint dans d’autres composants de Navigation.

Définissez une spécification OpenAPI par défaut à n’importe quel niveau de votre hiérarchie de Navigation. Les éléments enfants héritent de cette spécification, sauf s’ils définissent la leur.

<Note>
  Lorsque vous ajoutez la propriété `openapi` à un élément de Navigation (comme une ancre, un onglet ou un groupe) sans spécifier de pages, Mintlify génère automatiquement des pages pour **tous les endpoints** définis dans votre spécification OpenAPI.

  Pour contrôler les endpoints affichés, listez explicitement les endpoints souhaités dans un tableau `pages`.
</Note>

Pour en savoir plus sur la façon de référencer des endpoints OpenAPI dans votre documentation, consultez la section [configuration OpenAPI](/fr/api-playground/openapi-setup).

```json
{
  "navigation": {
    "groups": [
      {
        "group": "API reference",
        "openapi": "/path/to/openapi-v1.json",
        "pages": [
          "overview",
          "authentication",
          "GET /users",
          "POST /users",
          {
            "group": "Products",
            "openapi": "/path/to/openapi-v2.json",
            "pages": [
              "GET /products",
              "POST /products"
            ]
          }
        ]
      }
    ]
  }
}
```

<div id="versions">
  ## Versions
</div>

Divisez votre Navigation en différentes versions. Les versions peuvent être sélectionnées depuis un menu déroulant.

<img className="block dark:hidden pointer-events-none" src="/images/navigation/versions-light.png" alt="Illustration décorative d’un sélecteur de version." />

<img className="hidden dark:block pointer-events-none" src="/images/navigation/versions-dark.png" alt="Illustration décorative d’un sélecteur de version." />

Dans l’objet `navigation`, `versions` est un tableau dont chaque entrée est un objet qui nécessite un champ `version` et peut contenir n’importe quel autre champ de navigation.

```json
{
  "navigation": {
    "versions": [
      {
        "version": "1.0.0",
        "groups": [
          {
            "group": "Getting started",
            "pages": ["v1/overview", "v1/quickstart", "v1/development"]
          }
        ]
      },
      {
        "version": "2.0.0",
        "groups": [
          {
            "group": "Getting started",
            "pages": ["v2/overview", "v2/quickstart", "v2/development"]
          }
        ]
      }
    ]
  }
}
```

<div id="default-version">
  ### Version par défaut
</div>

Mintlify utilise la première version du tableau `versions` comme version par défaut. Utilisez le champ `default` pour définir une autre version par défaut.

```json
{
  "navigation": {
    "versions": [
      {
        "version": "1.0.0",
        "groups": [
          {
            "group": "Getting started",
            "pages": ["v1/overview", "v1/quickstart"]
          }
        ]
      },
      {
        "version": "2.0.0",
        "default": true,
        "groups": [
          {
            "group": "Getting started",
            "pages": ["v2/overview", "v2/quickstart"]
          }
        ]
      }
    ]
  }
}
```

<div id="version-tags">
  ### Tags de version
</div>

Ajoutez un badge aux entrées de version dans le menu déroulant du sélecteur de version à l’aide du champ facultatif `tag`. Utilisez ces tags pour mettre en avant certaines versions, comme &quot;Dernière version&quot;, &quot;Recommandée&quot; ou &quot;Bêta&quot;.

```json
{
  "navigation": {
    "versions": [
      {
        "version": "2026_03",
        "tag": "Latest",
        "groups": [
          {
            "group": "Getting started",
            "pages": ["getting-started", "quickstart"]
          }
        ]
      },
      {
        "version": "2025_12",
        "tag": "Recommended",
        "groups": [
          {
            "group": "Getting started",
            "pages": ["2025_12/getting-started", "2025_12/quickstart"]
          }
        ]
      },
      {
        "version": "2025_09",
        "tag": "Deprecated",
        "groups": [
          {
            "group": "Getting started",
            "pages": ["2025_09/getting-started", "2025_09/quickstart"]
          }
        ]
      }
    ]
  }
}
```

<div id="nesting">
  ## Imbrication
</div>

Vous pouvez imbriquer des éléments de navigation les uns dans les autres afin de créer des hiérarchies complexes. Vous devez avoir un élément parent à la racine, comme des onglets, des groupes ou un menu déroulant. Vous pouvez imbriquer d’autres types d’éléments de navigation dans votre structure de navigation principale.

À chaque niveau de votre hiérarchie de navigation, chaque élément de navigation ne peut contenir qu’un seul type d’élément enfant. Par exemple, un onglet peut contenir des ancres qui contiennent des groupes, mais il ne peut pas contenir à la fois des ancres et des groupes au même niveau.

<div id="breadcrumbs">
  ## Fil d’Ariane
</div>

Le fil d’Ariane affiche le chemin de navigation complet en haut des pages. Certains thèmes l’activent par défaut, d’autres non. Vous pouvez contrôler son affichage sur votre site à l’aide de la propriété `styling` dans votre `docs.json`.

<CodeGroup>
  ```json Afficher le fil d’Ariane complet
  "styling": {
    "eyebrows": "breadcrumbs"
  }
  ```

  ```json Afficher uniquement la section parente
  "styling": {
    "eyebrows": "section"
  }
  ```
</CodeGroup>

<div id="interaction-configuration">
  ## Configuration des interactions
</div>

Contrôlez la façon dont les utilisateurs interagissent avec les éléments de navigation à l’aide de la propriété `interaction` dans votre `docs.json`.

<div id="enable-auto-navigation-for-groups">
  ### Activer la navigation automatique pour les groupes
</div>

Lorsqu’un utilisateur développe un groupe de navigation, certains thèmes redirigent automatiquement vers la première page du groupe. Vous pouvez remplacer le comportement par défaut du thème à l’aide de l’option `drilldown`.

* Définissez cette option sur `true` pour forcer la navigation automatique vers la première page lorsqu’un utilisateur sélectionne un groupe de navigation.
* Définissez cette option sur `false` pour empêcher la navigation et uniquement développer ou réduire le groupe lorsqu’un utilisateur sélectionne un groupe de navigation.
* Laissez cette option non définie pour utiliser le comportement par défaut du thème.

<CodeGroup>
  ```json Forcer la navigation
  "interaction": {
    "drilldown": true  // Forcer la navigation vers la première page lorsqu’un utilisateur développe un menu déroulant
  }
  ```

  ```json Empêcher la navigation
  "interaction": {
    "drilldown": false // Ne jamais naviguer, uniquement développer ou réduire le groupe
  }
  ```
</CodeGroup>
