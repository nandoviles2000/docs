Chaque page est un fichier Markdown. Vous pouvez utiliser les types de fichier `.mdx` ou `.md` pour vos pages. Nous recommandons MDX, qui combine Markdown et des composants React pour créer une documentation riche et interactive. Le Markdown simple (`.md`) peut accélérer la migration depuis d’autres plateformes, mais passer à MDX vous donne accès à davantage de fonctionnalités.

<div id="page-metadata">
  ## Métadonnées de la page
</div>

Chaque page commence par des métadonnées d’en-tête, c’est-à-dire les métadonnées YAML délimitées par `---` en haut du fichier. Ces métadonnées déterminent l’apparence et le comportement de votre page.

Utilisez les métadonnées d’en-tête pour définir :

* Les titres et descriptions des pages
* Les titres de la barre latérale, les icônes et les tags
* Les mises en page des pages
* Les balises méta SEO
* Les métadonnées personnalisées

<ResponseField name="title" type="string">
  Le titre de votre page, tel qu’il apparaît dans la Navigation et dans les onglets du navigateur.

  S’il est omis, Mintlify génère un titre à partir du chemin. Le dernier segment du chemin devient le titre, les tirets et les traits de soulignement étant remplacés par des espaces, puis la première lettre est mise en majuscule. Par exemple, `guides/getting-started.md` devient **Getting started**.
</ResponseField>

<ResponseField name="description" type="string">
  Une brève description du contenu de cette page. Elle s’affiche sous le titre et améliore le SEO.
</ResponseField>

<ResponseField name="sidebarTitle" type="string">
  Un titre court qui s’affiche dans la navigation de la barre latérale.
</ResponseField>

<ResponseField name="icon" type="string">
  L’icône à afficher.

  Options :

  * Nom d’une icône [Font Awesome](https://fontawesome.com/icons)
  * Nom d’une icône [Lucide](https://lucide.dev/icons)
  * Nom d’une icône [Tabler](https://tabler.io/icons)
  * URL d’une icône hébergée en externe
  * Chemin vers un fichier d’icône dans votre projet
</ResponseField>

<ResponseField name="iconType" type="string">
  Uniquement pour les icônes [Font Awesome](https://fontawesome.com/icons). Définit le style de l’icône.

  Options : `regular`, `solid`, `light`, `thin`, `sharp-solid`, `duotone`, `brands`.
</ResponseField>

<ResponseField name="tag" type="string">
  Un tag qui s’affiche à côté du titre de votre page dans la barre latérale.
</ResponseField>

<ResponseField name="hidden" type="boolean">
  Définissez ce champ sur `true` pour retirer la page de la navigation de la barre latérale. Les utilisateurs peuvent toujours accéder à la page via son URL, mais les moteurs de recherche ne l’indexent pas. Pour rendre une page de nouveau visible, supprimez entièrement ce champ. **Ne définissez pas** cette valeur sur `false`, car cela entraîne un comportement indéfini. Consultez [Hidden pages](/fr/organize/hidden-pages) pour en savoir plus.
</ResponseField>

<ResponseField name="noindex" type="boolean">
  Définissez ce champ sur `true` pour empêcher les moteurs de recherche d’indexer la page. Consultez [Disable indexing](/fr/optimize/seo#disable-indexing) pour en savoir plus. Toutes les pages avec `hidden: true` dans leurs métadonnées d’en-tête reçoivent automatiquement `noindex: true`.
</ResponseField>

<ResponseField name="deprecated" type="boolean">
  Définissez ce champ sur `true` pour afficher le libellé &quot;deprecated&quot; à côté du titre de la page. Utilisez-le pour signaler un contenu obsolète ou des fonctionnalités héritées tout en laissant la page accessible.
</ResponseField>

<ResponseField name="hideFooterPagination" type="boolean">
  Définissez ce champ sur `true` pour masquer les liens de navigation vers la page précédente et la page suivante en bas de la page. Utilisez-le pour les pages autonomes, comme les pages d’accueil ou les pages de référence, où la navigation séquentielle n’est pas pertinente.
</ResponseField>

<ResponseField name="hideApiMarker" type="boolean">
  Définissez ce champ sur `true` pour masquer le badge de méthode HTTP (comme GET ou POST) à côté du titre de la page dans la barre latérale. Utilisez-le pour les pages d’API si vous souhaitez une apparence plus épurée dans la barre latérale.
</ResponseField>

<ResponseField name="groups" type="string[]">
  Restreignez la page aux utilisateurs appartenant à des groupes spécifiques. Les utilisateurs doivent appartenir à au moins un des groupes listés pour accéder à la page. Vous devez d’abord configurer l’[authentification](/fr/deploy/authentication-setup). Consultez [Control access with groups](/fr/deploy/authentication-setup#control-access-with-groups) pour plus d’informations.
</ResponseField>

<ResponseField name="<custom>" type="string">
  Toute métadonnée YAML d’en-tête valide. Par exemple, `product: "API"` ou `version: "1.0.0"`.
</ResponseField>

```yaml Example YAML frontmatter wrap
---
title: "About frontmatter"
description: "Frontmatter is the metadata that controls how your page appears and behaves"
sidebarTitle: "Frontmatter"
icon: "book"
tag: "NEW"
---
```

<div id="page-mode">
  ## Mode de page
</div>

Contrôlez la mise en page de votre page à l’aide du paramètre `mode`.

<div id="default">
  ### Par défaut
</div>

Si vous ne définissez pas de mode, la page utilise une mise en page standard avec une navigation de la barre latérale et une table des matières.

```yaml
---
title: "Default page title"
---
```

<div id="wide">
  ### Pleine largeur
</div>

Le mode pleine largeur masque la table des matières. Utilisez ce mode pour les pages sans titres ou si vous avez besoin de plus d’espace horizontal. Tous les thèmes prennent en charge le mode pleine largeur.

```yaml
---
title: "Wide page title"
mode: "wide"
---
```

<div id="custom">
  ### Personnalisé
</div>

Le mode personnalisé offre une mise en page minimaliste et supprime tous les éléments à l’exception de la barre de navigation supérieure. Ce mode masque la barre latérale, la table des matières et le pied de page. Considérez le mode personnalisé comme une toile vierge pour créer des pages d’accueil ou des mises en page uniques avec une Navigation minimale. Tous les thèmes prennent en charge le mode personnalisé.

```yaml
---
title: "Custom page title"
mode: "custom"
---
```

<Warning>
  La propriété `style` peut provoquer un décalage de mise en page lors du chargement de la page. Privilégiez [Tailwind CSS ou du CSS personnalisé](/fr/customize/custom-scripts) pour éviter ce problème.
</Warning>

<div id="frame">
  ### Frame
</div>

Le mode Frame offre une mise en page similaire au mode personnalisé, tout en conservant la navigation de la barre latérale. Utilisez ce mode pour inclure du HTML personnalisé et des composants, tout en conservant l’expérience de navigation par défaut. Les thèmes Aspen, Almond, Luma et Sequoia prennent en charge le mode Frame.

```yaml
---
title: "Frame page title"
mode: "frame"
---
```

<div id="center">
  ### Mode centré
</div>

Le mode centré supprime la barre latérale et la table des matières, puis centre le contenu. Utilisez-le pour les changelogs ou d&#39;autres pages sur lesquelles vous souhaitez mettre l&#39;accent. Les thèmes Mint, Linden, Willow et Maple prennent en charge le mode centré.

```yaml
---
title: "Center page title"
mode: "center"
---
```

<div id="api-pages">
  ## Pages d’API
</div>

Pour créer un bac à sable API interactif, ajoutez une spécification d’API à vos métadonnées d’en-tête en définissant `api` ou `openapi`.

```yaml
---
openapi: "GET /endpoint"
---
```

En savoir plus sur la création d’une [documentation d’API](/fr/api-playground/overview).

<div id="external-links">
  ## Liens externes
</div>

Ajoutez des liens vers des sites externes directement depuis votre navigation à l’aide de la métadonnée `url`.

```yaml
---
title: "npm Package"
url: "https://www.npmjs.com/package/mint"
---
```

<div id="search-engine-optimization">
  ## Optimisation pour les moteurs de recherche
</div>

Mintlify génère automatiquement la plupart des balises méta SEO. Vous pouvez définir manuellement les balises méta SEO afin de personnaliser votre stratégie de SEO, de partage sur les réseaux sociaux et de compatibilité avec les navigateurs.

<Note>
  Mettez toujours entre guillemets les balises méta qui contiennent des deux-points.
</Note>

```yaml
---
"twitter:image": "/images/social-preview.jpg"
---
```

Consultez [SEO](/fr/optimize/seo) pour la liste complète des options de métadonnées SEO.

<div id="internal-search-keywords">
  ## Mots-clés de recherche internes
</div>

Aidez les utilisateurs à trouver une page précise dans les résultats de recherche en ajoutant des `keywords` à vos métadonnées. Ces mots-clés n&#39;apparaissent pas dans le contenu de la page. Si les utilisateurs recherchent ces mots-clés, la page apparaît dans les résultats de recherche.

```yaml
---
keywords: ['configuration', 'setup', 'getting started']
---
```

<div id="last-modified-timestamp">
  ## Horodatage de la dernière modification
</div>

Affichez la mention &quot;Dernière modification le [date]&quot; sur toutes les pages en activant `metadata.timestamp` dans vos [paramètres globaux](/fr/organize/settings-seo#metadata).

```json docs.json
"metadata": {
  "timestamp": true
}
```

Pour remplacer le paramètre global d’horodatage pour une page donnée, utilisez le champ de métadonnées d’en-tête `timestamp`. Utilisez ce champ pour afficher ou masquer les horodatages sur certaines pages.

```yaml
---
title: "Page title"
timestamp: false
---
```

Si vous définissez `timestamp: true`, la page affiche toujours l’horodatage, même si le paramètre global est `false`. Si vous définissez `timestamp: false`, la page masque l’horodatage, même si le paramètre global est `true`.
