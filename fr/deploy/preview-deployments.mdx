<Info>
  Les déploiements de prévisualisation sont disponibles avec les offres [Pro et Enterprise](https://mintlify.com/pricing?ref=preview-deployments).
</Info>

Les déploiements de prévisualisation vous permettent de voir à quoi ressembleront les modifications de votre documentation avant leur mise en production. Chaque prévisualisation crée une URL partageable qui se met automatiquement à jour lorsque vous envoyez de nouvelles modifications.

Les URL de prévisualisation sont accessibles publiquement par défaut. Partagez un lien de prévisualisation avec toute personne devant examiner vos modifications.

<div id="create-preview-deployments">
  ## Créez des déploiements de prévisualisation
</div>

Les déploiements de prévisualisation sont créés automatiquement via des pull requests (PR) ou manuellement depuis votre tableau de bord.

<div id="automatic-previews">
  ### Aperçus automatiques
</div>

<Note>
  Les aperçus automatiques sont créés uniquement pour les pull requests (PR) qui ciblent votre [branche de déploiement](/fr/guides/git-concepts#deployment-branch).
</Note>

Lorsque vous créez une pull request (PR), le bot Mintlify ajoute automatiquement un lien pour consulter le déploiement de prévisualisation dans votre pull request (PR). L’aperçu se met à jour chaque fois que vous poussez de nouveaux commits vers la branche.

<div id="manual-previews">
  ### Aperçus manuels
</div>

Vous pouvez créer manuellement un aperçu pour n’importe quelle branche.

1. Accédez à votre [tableau de bord](https://dashboard.mintlify.com/).
2. Sélectionnez **Previews**.
3. Sélectionnez **Create custom preview**.
4. Saisissez le nom de la branche dont vous voulez créer un aperçu.
5. Sélectionnez **Create preview**.

<div id="api">
  ### API
</div>

Vous pouvez également créer des déploiements de prévisualisation de manière programmatique à l’aide du point de terminaison de l’API [Trigger preview deployment](/fr/api/preview/trigger). Cela peut être utile pour intégrer la création de prévisualisations à des pipelines CI/CD ou à des outils personnalisés.

<div id="redeploy-a-preview">
  ## Redéployer un aperçu
</div>

Redéployez un aperçu pour actualiser le contenu ou relancer le déploiement après un échec.

1. Sélectionnez l’aperçu dans votre [tableau de bord](https://dashboard.mintlify.com/).
2. Sélectionnez **Redeploy**.

<div id="preview-widget">
  ## Widget d’aperçu
</div>

Le widget d’aperçu apparaît sur les déploiements de prévisualisation pour vous aider à naviguer et à passer en revue les pages mises à jour. Il prend la forme d’un bouton flottant dans l’angle inférieur droit de votre déploiement de prévisualisation.

<Frame>
  <img src="/images/previews/widget-light.png" alt="Widget d’aperçu déployé affichant la liste des fichiers modifiés." className="block dark:hidden" />

  <img src="/images/previews/widget-dark.png" alt="Widget d’aperçu déployé affichant la liste des fichiers modifiés." className="hidden dark:block" />
</Frame>

1. Cliquez sur le widget pour afficher tous les fichiers ajoutés, modifiés ou supprimés dans l’aperçu.
2. Cliquez sur un fichier pour voir les modifications sur la page correspondante.
3. Utilisez la barre de recherche pour filtrer la liste des fichiers modifiés.
4. Survolez un fichier, puis cliquez sur l’icône **Open in editor** pour le modifier directement dans l’éditeur web.

Le widget apparaît uniquement sur les déploiements de prévisualisation, pas sur votre site en production ni dans les aperçus locaux.

<div id="restrict-access-to-preview-deployments">
  ## Restreindre l’accès aux déploiements de prévisualisation
</div>

Par défaut, les déploiements de prévisualisation sont accessibles à toute personne disposant de l’URL. Vous pouvez en restreindre l’accès en exigeant une authentification de l’organisation pour toutes les prévisualisations, ou en protégeant chaque prévisualisation individuellement par mot de passe.

<div id="require-organization-authentication">
  ### Exiger l’authentification de l’organisation
</div>

Restreignez l’accès à l’aperçu aux membres authentifiés de votre organisation Mintlify.

1. Accédez à la section **Previews** de la page [Add-ons](https://dashboard.mintlify.com/products/addons) de votre tableau de bord.
2. Cliquez sur le bouton bascule **Preview authentication** pour activer ou désactiver l’authentification des aperçus.

<div id="password-protect-an-individual-preview">
  ### Protéger un aperçu spécifique par mot de passe
</div>

<Info>
  Les aperçus protégés par mot de passe sont disponibles avec les [offres Enterprise](https://mintlify.com/pricing?ref=preview-deployments).
</Info>

Protégez par mot de passe un aperçu spécifique afin de le partager avec des relecteurs externes sans les ajouter à votre organisation Mintlify. Cette option est disponible lors de la création d’un aperçu manuel et n’apparaît pas lorsque l’authentification de l’organisation est déjà activée pour votre déploiement.

1. Accédez à votre [tableau de bord](https://dashboard.mintlify.com/).
2. Sélectionnez **Previews**.
3. Sélectionnez **Create custom preview**.
4. Saisissez le nom de la branche que vous souhaitez prévisualiser.
5. Activez **Make private**, puis saisissez un mot de passe. Les mots de passe doivent contenir au moins 8 caractères.

<Frame>
  <img src="/images/previews/private-preview-light.png" alt="La fenêtre modale Create a custom preview avec l’option Make private activée et un champ de mot de passe." className="block dark:hidden" />

  <img src="/images/previews/private-preview-dark.png" alt="La fenêtre modale Create a custom preview avec l’option Make private activée et un champ de mot de passe." className="hidden dark:block" />
</Frame>

6. Sélectionnez **Create preview**.

<div id="troubleshooting-preview-deployments">
  ## Dépannage des déploiements de prévisualisation
</div>

Si votre déploiement de prévisualisation échoue, essayez les étapes de dépannage suivantes.

* **Consultez les logs de build** : dans votre [tableau de bord](https://dashboard.mintlify.com/), accédez à **Previews**, puis cliquez sur la prévisualisation en échec. Les logs de déploiement indiquent les erreurs à l’origine de l’échec.
* **Vérifiez votre configuration** :
  * Syntaxe `docs.json` invalide
  * Chemins de fichiers manquants ou incorrects référencés dans la navigation
  * Métadonnées d’en-tête invalides dans les fichiers MDX
  * Liens d’image rompus ou fichiers image manquants
* **Validez en local** : exécutez `mint dev` localement pour détecter les erreurs de build avant de pousser vos modifications vers le dépôt.
* **Vérifiez les modifications récentes** : examinez les commits les plus récents de votre branche pour identifier les changements à l’origine de l’échec du build.
