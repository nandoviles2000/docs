<Note>
  Les configurations de proxy inverse sont prises en charge uniquement avec les plans [Enterprise](https://mintlify.com/pricing?ref=reverse-proxy).
</Note>

Pour diffuser votre documentation via un proxy inverse personnalisé, vous devez configurer les règles de routage, les politiques de mise en cache et la transmission des en-têtes.

Lorsque vous mettez en place un proxy inverse, surveillez les problèmes potentiels liés à la validation du domaine, au provisionnement des certificats SSL, aux flux d’authentification, aux performances et au suivi des analyses.

<div id="choose-your-deployment-approach">
  ## Choisissez votre méthode de déploiement
</div>

Mintlify prend en charge deux configurations de proxy inverse, selon vos besoins en matière de sous-chemin.

* **Host at `/docs`** : utilisez `mintlify.dev` comme cible du proxy. Activez l’option **Host at `/docs`** sur la page [Configuration du domaine personnalisé](https://dashboard.mintlify.com/settings/deployment/custom-domain) de votre tableau de bord. Cette configuration est plus simple et comporte moins de routes.
* **Sous-chemin personnalisé** : utilisez `mintlify.app` comme cible du proxy. Cette approche prend en charge n’importe quel sous-chemin et nécessite des règles de routage supplémentaires.

<div id="host-at-docs-subpath">
  ## Héberger sur le sous-chemin `/docs`
</div>

Utilisez cette configuration si vous souhaitez diffuser votre documentation sur le chemin `/docs` de votre domaine.

Avant de configurer votre proxy inverse :

1. Accédez à [la configuration du domaine personnalisé](https://dashboard.mintlify.com/settings/deployment/custom-domain) dans votre tableau de bord.
2. Activez l’option **Host at `/docs`**.
3. Saisissez votre domaine, puis sélectionnez **Add domain**.

<Warning>
  Lorsque vous activez **Host at `/docs`**, l’URL canonique de votre documentation devient `<your-subdomain>.mintlify.dev`. L’invalidation du cache ne fonctionne plus sur `mintlify.app`, et vous devez faire pointer le proxy vers `mintlify.dev` pour que les mises à jour s’affichent.
</Warning>

<div id="routing-configuration">
  ### Configuration du routage
</div>

Faites pointer ces chemins via un proxy vers votre sous-domaine Mintlify :

| Chemin                                     | Destination                          | Mise en cache        |
| ------------------------------------------ | ------------------------------------ | -------------------- |
| `/docs`                                    | `<your-subdomain>.mintlify.dev/docs` | Aucune mise en cache |
| `/docs/*`                                  | `<your-subdomain>.mintlify.dev/docs` | Aucune mise en cache |
| `/.well-known/vercel/*`                    | `<your-subdomain>.mintlify.dev`      | Aucune mise en cache |
| `/.well-known/skills/*` (facultatif)       | `<your-subdomain>.mintlify.dev/docs` | Aucune mise en cache |
| `/.well-known/agent-skills/*` (facultatif) | `<your-subdomain>.mintlify.dev/docs` | Aucune mise en cache |
| `/skill.md` (facultatif)                   | `<your-subdomain>.mintlify.dev/docs` | Aucune mise en cache |
| `/llms.txt` (facultatif)                   | `<your-subdomain>.mintlify.dev/docs` | Aucune mise en cache |
| `/llms-full.txt` (facultatif)              | `<your-subdomain>.mintlify.dev/docs` | Aucune mise en cache |

Les routes `/.well-known/skills/*`, `/.well-known/agent-skills/*`, `/skill.md`, `/llms.txt` et `/llms-full.txt` sont facultatives. Incluez-les uniquement si vous souhaitez servir des fichiers d’IA à la racine, par exemple `your-domain.com/llms.txt`, plutôt que sous votre sous-chemin de documentation, par exemple `your-domain.com/docs/llms.txt`.

<div id="required-header-configuration">
  ### Configuration requise des en-têtes
</div>

Configurez votre proxy inverse avec les en-têtes requis suivants :

* **Origin** : contient le sous-domaine cible `<your-subdomain>.mintlify.dev`
* **X-Forwarded-For** : préserve les informations sur l’adresse IP du client
* **X-Forwarded-Proto** : préserve le protocole d’origine (HTTP/HTTPS)
* **X-Real-IP** : transmet l’adresse IP réelle du client
* **User-Agent** : transmet l’agent utilisateur

<Warning>
  Assurez-vous que l’en-tête `Host` n’est pas transmis.
</Warning>

### Exemple de configuration Nginx

```nginx
server {
    listen 80;
    server_name <your-domain>.com;

    # Chemins de vérification Vercel
    location ~ ^/\.well-known/vercel/ {
        proxy_pass https://<your-subdomain>.mintlify.dev;
        proxy_set_header Origin <your-subdomain>.mintlify.dev;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header User-Agent $http_user_agent;

        add_header Cache-Control "no-cache, no-store, must-revalidate";
    }

    # Chemins des compétences IA
    location ^~ /.well-known/skills/ {
        proxy_pass https://<your-subdomain>.mintlify.dev/docs;
        proxy_set_header Origin <your-subdomain>.mintlify.dev;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header User-Agent $http_user_agent;

        add_header Cache-Control "no-cache, no-store, must-revalidate";
    }

    # Chemins de découverte des compétences d'agent
    location ^~ /.well-known/agent-skills/ {
        proxy_pass https://<your-subdomain>.mintlify.dev/docs;
        proxy_set_header Origin <your-subdomain>.mintlify.dev;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header User-Agent $http_user_agent;

        add_header Cache-Control "no-cache, no-store, must-revalidate";
    }

    # Manifeste de compétences (facultatif)
    location = /skill.md {
        proxy_pass https://<your-subdomain>.mintlify.dev/docs;
        proxy_set_header Origin <your-subdomain>.mintlify.dev;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header User-Agent $http_user_agent;

        add_header Cache-Control "no-cache, no-store, must-revalidate";
    }

    # Fichiers d'index LLM (facultatif)
    location = /llms.txt {
        proxy_pass https://<your-subdomain>.mintlify.dev/docs;
        proxy_set_header Origin <your-subdomain>.mintlify.dev;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header User-Agent $http_user_agent;

        add_header Cache-Control "no-cache, no-store, must-revalidate";
    }

    location = /llms-full.txt {
        proxy_pass https://<your-subdomain>.mintlify.dev/docs;
        proxy_set_header Origin <your-subdomain>.mintlify.dev;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header User-Agent $http_user_agent;

        add_header Cache-Control "no-cache, no-store, must-revalidate";
    }

    # Racine de la documentation
    location = /docs {
        proxy_pass https://<your-subdomain>.mintlify.dev/docs;
        proxy_set_header Origin <your-subdomain>.mintlify.dev;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header User-Agent $http_user_agent;

        add_header Cache-Control "no-cache, no-store, must-revalidate";
    }

    # Tous les chemins de documentation
    location /docs/ {
        proxy_pass https://<your-subdomain>.mintlify.dev/docs/;
        proxy_set_header Origin <your-subdomain>.mintlify.dev;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header User-Agent $http_user_agent;

        add_header Cache-Control "no-cache, no-store, must-revalidate";
    }
}
```

<div id="custom-subpath">
  ## Sous-chemin personnalisé
</div>

Lorsque vous avez besoin d’un sous-chemin autre que `/docs` (par exemple `/help` ou `/resources`), utilisez la configuration de routage suivante.

Configurez un proxy pour ces chemins vers votre sous-domaine Mintlify avec les politiques de mise en cache indiquées :

| Chemin                            | Destination                     | Mise en cache        |
| --------------------------------- | ------------------------------- | ------------- |
| `/.well-known/vercel/*`           | `<your-subdomain>.mintlify.app` | aucune mise en cache |
| `/.well-known/skills/*`           | `<your-subdomain>.mintlify.app` | aucune mise en cache |
| `/.well-known/agent-skills/*`     | `<your-subdomain>.mintlify.app` | aucune mise en cache |
| `/skill.md`                       | `<your-subdomain>.mintlify.app` | aucune mise en cache |
| `/llms.txt`                       | `<your-subdomain>.mintlify.app` | aucune mise en cache |
| `/llms-full.txt`                  | `<your-subdomain>.mintlify.app` | aucune mise en cache |
| `/mintlify-assets/_next/static/*` | `<your-subdomain>.mintlify.app` | Cache activé  |
| `/_mintlify/*`                    | `<your-subdomain>.mintlify.app` | aucune mise en cache |
| `/*`                              | `<your-subdomain>.mintlify.app` | aucune mise en cache |
| `/`                               | `<your-subdomain>.mintlify.app` | aucune mise en cache |

<Note>
  Mintlify sert `llms.txt`, `llms-full.txt` et `skill.md` à la racine. Si votre documentation se trouve sous un sous-chemin (par exemple `/help`), vous pouvez également servir ces fichiers sous ce sous-chemin (par exemple `/help/llms.txt`). Pour cela, ajoutez des blocs `location` qui réécrivent le sous-chemin vers le chemin racine. Consultez l’exemple nginx ci-dessous pour voir les deux configurations.
</Note>

<div id="required-header-configuration">
  ### Configuration requise des en-têtes
</div>

Configurez votre proxy inverse pour respecter la configuration requise des en-têtes suivante :

* **Origin** : contient le sous-domaine cible `<your-subdomain>.mintlify.app`
* **X-Forwarded-For** : préserve les informations sur l’adresse IP du client
* **X-Forwarded-Proto** : préserve le protocole d’origine (HTTP/HTTPS)
* **X-Real-IP** : transmet l’adresse IP réelle du client
* **User-Agent** : transmet l’agent utilisateur

<Warning>
  Assurez-vous que l’en-tête `Host` n’est pas transmis
</Warning>

<div id="troubleshooting">
  ## Résolution des problèmes
</div>

<div id="changes-not-appearing">
  ### Les modifications n’apparaissent pas
</div>

**Symptômes** : Vous publiez des mises à jour de la documentation, mais les modifications n’apparaissent pas sur votre site.

**Cause** : Vous avez activé **Host at `/docs`** dans votre tableau de bord, mais votre proxy inverse pointe vers `mintlify.app` au lieu de `mintlify.dev`.

**Solution** : Mettez à jour la configuration de votre proxy inverse afin qu’elle pointe vers `<your-subdomain>.mintlify.dev` au lieu de `<your-subdomain>.mintlify.app`.

<div id="404-error">
  ### Erreur 404
</div>

**Symptômes** : la documentation se charge, mais les fonctionnalités ne fonctionnent pas. Les appels d’API échouent.

**Cause** : le proxy inverse transmet l’en-tête `Host`, ou l’en-tête `Origin` est absent.

**Solution** :

* Supprimez le transfert de l’en-tête `Host`
* Définissez l’en-tête `Origin` sur votre sous-domaine Mintlify (`mintlify.dev` pour le sous-chemin `/docs` ou `mintlify.app` pour un autre sous-chemin)

<div id="performance-issues">
  ### Problèmes de performance
</div>

**Symptômes** : chargement lent des pages et décalages de mise en page.

**Cause** : mauvaise configuration du cache.

**Solution** : Pour les configurations de sous-chemins personnalisées, activez le cache uniquement pour les chemins `/mintlify-assets/_next/static/*`. La configuration du sous-chemin `/docs` gère automatiquement le cache.
