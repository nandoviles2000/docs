Pour héberger votre documentation sur un sous-chemin tel que `yoursite.com/docs` avec AWS Route 53 et CloudFront, vous devez configurer votre fournisseur DNS afin qu’il pointe vers votre distribution CloudFront.

<div id="overview">
  ## Vue d’ensemble
</div>

Acheminez le trafic vers ces chemins avec une Cache policy définie sur **CachingDisabled** :

* `/.well-known/acme-challenge/*` - Requis pour la vérification du certificat Let&#39;s Encrypt
* `/.well-known/vercel/*` - Requis pour la vérification du domaine
* `/docs/*` - Requis pour le routage sur un sous-chemin
* `/docs/` - Requis pour le routage sur un sous-chemin

Acheminez le trafic vers ces chemins avec une Cache policy définie sur **CachingEnabled** :

* `/mintlify-assets/_next/static/*`
* `Default (*)`	- La page d’accueil de votre site web

Tous les Behaviors doivent avoir une **origin request policy** définie sur `AllViewerExceptHostHeader`.

![Page « Behaviors » de CloudFront avec 4 comportements : /docs/\*, /docs, Default et /.well-known/\*.](/images/cloudfront/all-behaviors.png)

<div id="create-cloudfront-distribution">
  ## Créer une distribution CloudFront
</div>

1. Accédez à [CloudFront](https://aws.amazon.com/cloudfront) dans la console AWS.
2. Sélectionnez **Create distribution**.

<Frame>
  ![Page des distributions CloudFront avec le bouton « Create distribution » mis en évidence.](/images/cloudfront/create-distribution.png)
</Frame>

3. Dans le champ Origin domain, saisissez `[SUBDOMAIN].mintlify.dev`, où `[SUBDOMAIN]` correspond au sous-domaine unique de votre projet.

<Frame>
  ![Page « Create distribution » de CloudFront montrant « acme.mintlify.dev » comme domaine d’origine.](/images/cloudfront/origin-name.png)
</Frame>

4. Pour « Web Application Firewall (WAF) », activez les protections de sécurité.

<Frame>
  ![Options de Web Application Firewall (WAF) avec « Enable security protections » sélectionné.](/images/cloudfront/enable-security-protections.png)
</Frame>

5. Conservez les paramètres restants par défaut.
6. Sélectionnez **Create distribution**.

<div id="add-default-origin">
  ## Ajouter l’origine par défaut
</div>

1. Après avoir créé la distribution, accédez à l’onglet &quot;Origins&quot;.

<Frame>
  ![Une distribution CloudFront avec l’onglet "Origins" mis en évidence.](/images/cloudfront/origins.png)
</Frame>

2. Trouvez votre URL de préproduction correspondant au domaine principal. Cela dépend de la façon dont votre page de destination est hébergée. Par exemple, l’URL de préproduction de Mintlify est [mintlify-landing-page.vercel.app](https://mintlify-landing-page.vercel.app).

<Info>
  Si votre page de destination est hébergée sur Webflow, utilisez l’URL de préproduction Webflow. Elle se présentera sous la forme `.webflow.io`.

  Si vous utilisez Vercel, utilisez le domaine `.vercel.app` disponible pour chaque projet.
</Info>

3. Créez une nouvelle origine et ajoutez votre URL de préproduction comme &quot;Origin domain&quot;.

<Frame>
  ![Page CloudFront "Create origin" avec le champ de saisie "Origin domain" mis en évidence.](/images/cloudfront/default-origin.png)
</Frame>

À ce stade, vous devriez avoir deux origines : l’une avec `[SUBDOMAIN].mintlify.app` et l’autre avec votre URL de préproduction.

<Frame>
  ![Page CloudFront "Origins" avec deux origines : une pour mintlify et une autre pour mintlify-landing-page.](/images/cloudfront/final-origins.png)
</Frame>

<div id="set-behaviors">
  ## Configurer les comportements
</div>

Les comportements de CloudFront vous permettent de contrôler la logique des sous-chemins. Dans les grandes lignes, l’objectif est de mettre en place la logique suivante :

* **Si un utilisateur arrive sur votre sous-chemin personnalisé**, redirigez-le vers `[SUBDOMAIN].mintlify.dev`.
* **Si un utilisateur arrive sur une autre page**, redirigez-le vers la page d’accueil actuelle.

1. Accédez à l’onglet « Behaviors » de votre distribution CloudFront.

<Frame>
  ![Onglet « Behaviors » de CloudFront mis en évidence.](/images/cloudfront/behaviors.png)
</Frame>

2. Sélectionnez le bouton **Create behavior** et créez les comportements suivants.

<div id="well-known">
  ### `/.well-known/*`
</div>

Créez des comportements pour les chemins de vérification de domaine de Vercel avec un **Path pattern** défini sur `/.well-known/*`, puis définissez **Origin and origin groups** sur l’URL de votre documentation.

Pour **Cache policy**, sélectionnez **CachingDisabled** afin de vous assurer que ces requêtes de vérification sont transmises sans mise en cache.

<Frame>
  ![Page « Create behavior » de CloudFront avec un « Path pattern » défini sur "/.well-known/\*" et « Origin and origin groups » pointant vers l’URL de préproduction.](/images/cloudfront/well-known-policy.png)
</Frame>

<Info>
  Si `.well-known/*` est trop générique, vous pouvez le limiter à un minimum de deux comportements pour Vercel :

  * `/.well-known/vercel/*` - Requis pour la vérification de domaine Vercel
  * `/.well-known/acme-challenge/*` - Requis pour la vérification du certificat Let&#39;s Encrypt
</Info>

<div id="your-subpath">
  ### Votre sous-chemin
</div>

Créez un comportement dont le **Path pattern** correspond au sous-chemin de votre choix, par exemple `/docs`, avec **Origin and origin groups** pointant vers l’URL `.mintlify.dev` (dans notre cas `acme.mintlify.dev`).

* Définissez « Cache policy » sur **CachingOptimized**.
* Définissez « Origin request policy » sur **AllViewerExceptHostHeader**.
* Définissez Viewer Protocol Policy sur **Redirect HTTP to HTTPS**

<Frame>
  ![Page CloudFront « Create behavior » avec un « Path pattern » de "/docs/\*" et « Origin and origin groups » pointant vers l’URL acme.mintlify.dev.](/images/cloudfront/behavior-1.png)
</Frame>

<div id="your-subpath-with-wildcard">
  ### Votre sous-chemin avec caractère générique
</div>

Créez un comportement avec un **Path pattern** défini sur le sous-chemin de votre choix suivi de `/*`, par exemple `/docs/*`, et des **Origin and origin groups** pointant vers la même URL `.mintlify.dev`.

Ces paramètres doivent correspondre exactement à ceux du comportement de votre sous-chemin de base, à l&#39;exception du **Path pattern**.

* Définissez &quot;Cache policy&quot; sur **CachingOptimized**.
* Définissez &quot;Origin request policy&quot; sur **AllViewerExceptHostHeader**.
* Définissez &quot;Viewer protocol policy&quot; sur **Redirect HTTP to HTTPS**

<div id="mintlify-assets_nextstatic">
  ### `/mintlify-assets/_next/static/*`
</div>

* Définissez la « Cache policy » sur **CachingOptimized**
* Définissez la « Origin request policy » sur **AllViewerExceptHostHeader**
* Définissez la « Viewer protocol policy » sur **Redirect HTTP to HTTPS**

<div id="default">
  ### `Default (*)`
</div>

Pour finir, nous allons modifier le comportement `Default (*)`.

<Frame>
  ![Une distribution CloudFront avec le comportement « Default (\*) » sélectionné et le bouton Edit mis en évidence.](/images/cloudfront/default-behavior-1.png)
</Frame>

1. Définissez **Origin and origin groups** du comportement par défaut sur l’URL de préproduction (dans notre cas, `mintlify-landing-page.vercel.app`).

<Frame>
  ![Page CloudFront « Edit behavior » avec le champ « Origin and origin groups » mis en évidence.](/images/cloudfront/default-behavior-2.png)
</Frame>

2. Sélectionnez **Save changes**.

<div id="check-behaviors-are-set-up-correctly">
  ### Vérifiez que les comportements sont correctement configurés
</div>

Si vous avez suivi les étapes précédentes, vos comportements devraient ressembler à ceci :

<Frame>
  ![Page « Behaviors » de CloudFront avec 4 comportements : /docs/\*, /docs, Default et /.well-known/\*.](/images/cloudfront/all-behaviors.png)
</Frame>

<div id="preview-distribution">
  ## Prévisualiser la distribution
</div>

Vous pouvez maintenant vérifier que votre distribution est correctement configurée en ouvrant l’onglet « General » puis en consultant l’URL du **Distribution domain name**.

<Frame>
  ![Onglet « General » de CloudFront avec l’URL du « Distribution domain name » mise en évidence.](/images/cloudfront/preview-distribution.png)
</Frame>

Toutes les pages devraient pointer vers votre page de destination principale, mais si vous ajoutez à l’URL le sous-chemin que vous avez choisi, par exemple `/docs`, vous devriez voir qu’elle mène à votre instance de documentation Mintlify.

<div id="connect-with-route-53">
  ## Connecter Route 53
</div>

Nous allons maintenant faire pointer votre domaine principal vers la distribution CloudFront.

<Note>
  Pour cette section, vous pouvez aussi consulter le guide officiel d’AWS sur la [configuration d’Amazon Route 53 pour acheminer
  le trafic vers une distribution
  CloudFront](https://docs.aws.amazon.com/Route53/latest/DeveloperGuide/routing-to-cloudfront-distribution.html#routing-to-cloudfront-distribution-config)
</Note>

1. Accédez à [Route53](https://aws.amazon.com/route53) dans la console AWS.
2. Accédez à la « Hosted zone » de votre domaine principal.
3. Sélectionnez **Create record**.

<Frame>
  ![Page « Records » de Route 53 avec le bouton « Create record » mis en évidence.](/images/cloudfront/route53-create-record.png)
</Frame>

4. Activez `Alias`, puis, dans **Route traffic to**, choisissez l’option `Alias to CloudFront distribution`.

<Frame>
  ![Page « Create record » de Route 53 avec l’option « Alias » et le menu « Route traffic to » mis en évidence.](/images/cloudfront/create-record-alias.png)
</Frame>

5. Sélectionnez **Create records**.

<Note>
  Vous devrez peut-être supprimer l’enregistrement A existant s’il y en a déjà un.
</Note>

Votre documentation est maintenant accessible sur le sous-chemin choisi de votre domaine principal.
