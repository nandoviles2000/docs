Si vous utilisez un proxy externe comme Cloudflare ou AWS CloudFront devant votre déploiement Vercel, vous devez le configurer correctement pour éviter les conflits avec la vérification du domaine de Vercel et la mise à disposition des certificats SSL.

Une configuration incorrecte du proxy peut empêcher Vercel de fournir des certificats SSL Let&#39;s Encrypt et entraîner des échecs de vérification du domaine.

Consultez les [fournisseurs pris en charge](https://vercel.com/guides/how-to-setup-verified-proxy#supported-providers-verified-proxy-lite) dans la documentation de Vercel.

<div id="required-path-allowlist">
  ## Liste d’autorisation des chemins requis
</div>

Votre proxy externe doit autoriser le trafic sur ces chemins spécifiques sans le bloquer, le rediriger ni le mettre en cache de manière agressive :

* `/.well-known/acme-challenge/*` - Requis pour la vérification du certificat Let&#39;s Encrypt
* `/.well-known/vercel/*` - Requis pour la vérification du domaine Vercel
* `/mintlify-assets/_next/static/*` - Requis pour les ressources statiques

Ces chemins doivent être transmis directement à votre déploiement Vercel, sans modification.

<div id="header-forwarding-requirements">
  ## Exigences de transfert de l’en-tête
</div>

Assurez-vous que votre proxy transfère correctement l’en-tête `HOST`. Sans un transfert correct de cet en-tête, les requêtes de vérification échouent.

<div id="testing-your-proxy-setup">
  ## Tester la configuration de votre proxy
</div>

Pour vérifier que votre proxy est correctement configuré :

1. Vérifiez que `https://[yourdomain].com/.well-known/vercel/` renvoie bien une réponse.
2. Assurez-vous que les certificats SSL sont correctement provisionnés dans votre tableau de bord Vercel.
3. Vérifiez que la vérification du domaine se termine correctement.
