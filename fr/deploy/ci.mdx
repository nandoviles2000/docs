Utilisez les contrôles CI pour analyser votre documentation, détecter les erreurs et générer des avertissements avant le déploiement. Les contrôles CI de Mintlify s’exécutent sur les pull requests (PR) ciblant une branche de déploiement configurée.

<div id="installation">
  ## Installation
</div>

Pour commencer, suivez les étapes indiquées sur la page [GitHub](/fr/deploy/github).

<Tip>
  L’application GitHub de Mintlify n’a besoin d’accéder qu’au dépôt qui contient le contenu de votre documentation. Nous vous recommandons de n’accorder l’accès qu’à ce dépôt.
</Tip>

## Configuration

Configurez les contrôles CI activés pour un déploiement en accédant à la page [Add-ons](https://dashboard.mintlify.com/products/addons) de votre tableau de bord. Activez les vérifications que vous souhaitez exécuter.

Lorsque vous activez des vérifications, vous pouvez choisir de les exécuter au niveau `Warning` ou `Blocking`.

* Une vérification de niveau `Warning` ne renvoie jamais d’état d’échec, même en cas d’erreur ou de suggestions.
* Une vérification de niveau `Blocking` renvoie un état d’échec en cas d’erreur ou de suggestions.

<div id="available-ci-checks">
  ## Contrôles CI disponibles
</div>

<div id="broken-links">
  ### Liens rompus
</div>

Tout comme le [vérificateur de liens du CLI](/fr/cli/commands#mint-broken-links) sur votre machine locale, le contrôle CI des liens rompus recherche automatiquement les liens internes rompus entre les pages de votre site dans le contenu de votre documentation. Elle ne vérifie pas les liens externes vers d&#39;autres sites web.

Pour voir les résultats détaillés des liens rompus dans une pull request (PR), cliquez sur l&#39;onglet **Checks** et sélectionnez la vérification Mintlify des liens rompus. Les résultats indiquent tous les fichiers contenant des liens rompus détectés dans la pull request (PR).

<div id="vale">
  ### Vale
</div>

[Vale](https://vale.sh/) est un linter open source basé sur des règles, conçu pour la prose, qui prend en charge différents types de documents, notamment Markdown et MDX. Utilisez Vale pour vérifier la cohérence du style et du ton de votre documentation.

Mintlify permet d’exécuter automatiquement Vale dans un contrôle CI et d’afficher les résultats sous forme de statut de vérification.

<div id="configuration">
  #### Configuration
</div>

Si vous avez un fichier `.vale.ini` à la racine du répertoire de contenu de votre déploiement, le contrôle CI Vale utilise ce fichier de configuration ainsi que tous les fichiers de configuration présents dans le `stylesPath` spécifié.

Si vous n&#39;avez pas de fichier de configuration Vale, la configuration par défaut est automatiquement chargée.

```mdx Default vale.ini configuration expandable
# Styles de niveau supérieur
StylesPath = /app/styles
MinAlertLevel = suggestion
# Balises HTML en ligne à ignorer (code/tt pour les extraits de code, img/url pour les liens/images, a pour les balises d'ancrage)
IgnoredScopes = code, tt, img, url, a
SkippedScopes = script, style, pre, figure

# Vocabulaires
Vocab = Mintlify

# Analyser le MDX comme du MD pour éviter les problèmes de fragilité avec JSX
[formats]
mdx = md

# Correspondre uniquement aux fichiers MDX
[*.mdx]
BasedOnStyles = Vale
Vale.Terms = NO # Applique des règles de capitalisation très strictes, laisser désactivé

# Ignorer les motifs de syntaxe spécifiques à JSX/MDX
# `import ...`, `export ...`
# `<Component ... />`
# `<Component>...</Component>`
# `{ ... }`
TokenIgnores = (?sm)((?:import|export) .+?$), \
(?<!`)(<\w+ ?.+ ?\/>)(?!`), \
(<[A-Z]\w+>.+?<\/[A-Z]\w+>), \
\{[^}]*\}

# Exclure le JSX multiligne et les accolades
# `<Component \n ... />`
BlockIgnores = (?sm)^(<\w+\n .*\s\/>)$, \
(?sm)^({.+.*})
```

Pour ajouter votre propre vocabulaire à la configuration par défaut, créez un répertoire `styles/config/vocabularies/Mintlify` contenant les fichiers `accept.txt` et `reject.txt`.

* `accept.txt` : mots que le linter Vale doit ignorer. Par exemple, des noms de produits ou des termes peu courants.
* `reject.txt` : mots que le linter Vale doit signaler comme des erreurs. Par exemple, du jargon ou des mots qui ne correspondent pas au ton de votre documentation.

```text Example Vale file structure
/your-project
  |- docs.json
  |- .vale.ini
  |- styles/
    |- config/
      |- vocabularies/
        |- Mintlify/
          |- accept.txt
          |- reject.txt
  |- example-page.mdx
```

```text Example monorepo Vale file structure
/your-monorepo
  |- main.ts
  |- docs/
    |- docs.json
    |- .vale.ini
    |- styles/
      |- config/
      |- vocabularies/
        |- Mintlify/
          |- accept.txt
          |- reject.txt
    |- example-page.mdx
  |- test/
```

<Note>
  Pour des raisons de sécurité, les `stylesPath` absolus ou contenant la valeur `..` ne sont pas pris en charge.

  Utilisez des chemins relatifs et veillez à ce que le `stylesPath` soit présent dans votre dépôt.
</Note>

<div id="packages">
  #### Packages
</div>

Vale prend en charge toute une gamme de [packages](https://vale.sh/docs/keys/packages) qui vérifient l’orthographe et le style. Tous les packages que vous incluez dans votre dépôt sous le bon `stylesPath` s’installent automatiquement et s’exécutent avec votre configuration Vale.

Pour les packages qui ne sont pas inclus dans votre dépôt, vous pouvez spécifier n’importe quel package du [registre de packages Vale](https://vale.sh/explorer), puis ils sont automatiquement téléchargés et utilisés dans votre configuration Vale.

<Note>
  Pour des raisons de sécurité, le téléchargement automatique de packages qui ne proviennent pas du [registre de packages Vale](https://vale.sh/explorer) n’est **pas** pris en charge.
</Note>

<div id="vale-with-mdx">
  #### Vale avec `MDX`
</div>

<Note>
  La prise en charge native de MDX nécessite Vale 3.10.0 ou version ultérieure. Vérifiez votre version de Vale avec `vale --version`.
</Note>

Pour utiliser les commentaires dans le document de Vale dans des fichiers MDX, utilisez des commentaires au format MDX `{/* ... */}` :

```mdx
{/* vale off */}

Vale ignores this text

{/* vale on */}
```

Vale reconnaît et respecte automatiquement ces commentaires dans les fichiers MDX, sans configuration supplémentaire. Utilisez des commentaires pour ignorer les lignes ou sections que vous souhaitez exclure du linting.

<Warning>
  Ne placez pas `{/* vale off */}` ni d’autres commentaires d’expression MDX similaires comme enfants directs d’un composant JSX entre des éléments frères. Par exemple, entre deux éléments `<Step>` à l’intérieur d’un composant `<Steps>`.

  Placez les commentaires dans le contenu d’un élément spécifique, ou restructurez le contenu pour éviter d’avoir à utiliser des commentaires.
</Warning>
