Hébergez votre documentation sur un sous-chemin comme `your-domain.com/docs` pour la garder sur votre domaine principal. Elle sera ainsi plus facile à trouver et offrira à vos utilisateurs une expérience de marque cohérente.

<div id="set-up-by-hosting-provider">
  ## Configurer selon votre fournisseur d’hébergement
</div>

La configuration d’un sous-chemin `/docs` varie selon votre fournisseur d’hébergement. Choisissez le vôtre et suivez les instructions de configuration.

* [Cloudflare](/fr/deploy/cloudflare): Configurez Cloudflare Workers pour votre domaine afin de diffuser votre documentation sur le sous-chemin `/docs`.
* [AWS Route 53 and CloudFront](/fr/deploy/route53-cloudfront): Déployez votre documentation sur le sous-chemin `/docs` à l’aide d’AWS, avec le DNS Route 53 et le CDN CloudFront.
* [Vercel](/fr/deploy/vercel) - Utilisez des règles de réécriture pour déployer votre documentation sur le sous-chemin `/docs`.
* [Custom reverse proxy](/fr/deploy/reverse-proxy) - Pour les autres plateformes d’hébergement, configurez un proxy inverse afin de déployer votre documentation sur le sous-chemin `/docs`.

<div id="additional-configuration-for-strict-security-policies">
  ### Configuration supplémentaire en cas de politiques de sécurité strictes
</div>

Si vous faites transiter tout le trafic de votre domaine personnalisé via un proxy, vous devrez peut-être configurer votre proxy ou les règles de votre pare-feu pour ajouter les [en-têtes](/fr/deploy/csp-configuration) appropriés afin que votre documentation s’affiche correctement.
