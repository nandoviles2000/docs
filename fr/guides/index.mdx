Les guides de cette section proposent des conseils pour créer une documentation qui aide vos utilisateurs à atteindre leurs objectifs. Que vous partiez de zéro ou que vous cherchiez à améliorer une documentation existante, ces guides vous aident à planifier, rédiger et maintenir votre documentation.

Avant tout, tenez compte des besoins et des objectifs de vos utilisateurs. Documentez ce qui les aide à utiliser votre produit, puis à reprendre leur travail.

<div id="topics">
  ## Thèmes
</div>

<div id="ai-tools">
  ### Outils d’IA
</div>

Utilisez des outils d’IA pour accélérer votre flux de travail de documentation.

* [Automatiser les mises à jour de la documentation](/fr/guides/automate-agent) : tutoriel expliquant comment configurer des mises à jour automatisées de la documentation à l’aide de l’agent.
* [Créer un assistant intégré à l’application](/fr/guides/assistant-embed) : tutoriel expliquant comment ajouter un chatbot IA dans une application React pour aider les utilisateurs à trouver des réponses dans votre documentation.
* [Configurer l’automerge](/fr/guides/configure-automerge) : ajoutez la GitHub App Mintlify à la liste d’exceptions d’un ensemble de règles pour activer la fusion automatique des flux de travail.
* [Claude Code](/fr/guides/claude-code), [Cursor](/fr/guides/cursor), [Windsurf](/fr/guides/windsurf) : guides pour utiliser des assistants de codage IA afin de maintenir votre documentation.
* [GEO](/fr/guides/geo) : bonnes pratiques pour optimiser votre documentation pour les moteurs de recherche et de réponse par IA.

<div id="api-documentation">
  ### Documentation API
</div>

Créez une documentation API qui permet aux utilisateurs de tester votre API et d’apprendre à l’utiliser, tout en restant facile à maintenir.

* [Migrer de MDX vers OAS](/fr/guides/migrating-from-mdx): Déplacez votre documentation API de pages MDX individuelles vers des pages générées automatiquement à partir d’une spécification OpenAPI.

<div id="best-practices">
  ### Bonnes pratiques
</div>

Faites de votre documentation une référence.

* [Accessibilité](/fr/guides/accessibility): Rendez votre documentation accessible au plus grand nombre.
* [Types de contenu](/fr/guides/content-types): Choisissez le bon format pour les tutoriels, les guides pratiques, les références et les explications.
* [Modèles de contenu](/fr/guides/content-templates): Copiez et adaptez des modèles pour chaque type de contenu.
* [Mises en page personnalisées](/fr/guides/custom-layouts): Utilisez les modes de page et les composants pour créer des pages d’accueil et d’autres mises en page personnalisées.
* [Améliorer votre documentation](/fr/guides/improving-docs): Utilisez les données et les retours pour améliorer continuellement votre documentation.
* [Internationalisation](/fr/guides/internationalization): Configurez une documentation multilingue pour toucher un public international.
* [Liens](/fr/guides/linking): Créez des liens internes, référencez les points de terminaison d’API et préservez l’intégrité des liens dans l’ensemble de votre documentation.
* [Maintenance](/fr/guides/maintenance): Gardez votre documentation précise et à jour.
* [Médias](/fr/guides/media): Ajoutez efficacement des images, des vidéos et d’autres médias tout en limitant la charge de maintenance.
* [Organiser la navigation](/fr/guides/navigation): Concevez une architecture de l’information adaptée à vos utilisateurs.
* [SEO](/fr/guides/seo): Optimisez votre documentation pour les moteurs de recherche.
* [Style et ton](/fr/guides/style-and-tone): Adoptez une voix cohérente.
* [Comprendre votre audience](/fr/guides/understand-your-audience): Étudiez les besoins et les objectifs de vos utilisateurs pour mieux y répondre.

<div id="git-workflows">
  ### Flux de travail Git
</div>

Comprenez Git pour tirer pleinement parti de Mintlify et d’une approche « docs as code » de la documentation.

* [Concepts de Git](/fr/guides/git-concepts): Découvrez les bases de Git pour la documentation.
* [Branches](/fr/guides/branches): Utilisez les branches pour gérer les modifications de la documentation.

<div id="use-cases">
  ### Cas d’utilisation
</div>

Découvrez comment Mintlify répond à différents cas d’utilisation et trouvez la solution qui vous convient.

* [Créer une documentation pour les développeurs](/fr/guides/developer-documentation): Aidez vos utilisateurs à tirer le meilleur parti de votre produit ou de votre API grâce à une documentation qui répond à leurs questions et leur permet de reprendre rapidement leurs tâches principales.
* [Créer une base de connaissances](/fr/guides/knowledge-base): Mettez en place une base de connaissances interne pour centraliser les informations de votre équipe, faciliter la recherche et réduire la charge de maintenance.
* [Créer un centre d’aide](/fr/guides/help-center): Créez un centre d’aide en libre-service qui permet aux utilisateurs de trouver eux-mêmes des réponses, réduit le volume de tickets et améliore la satisfaction client.
* [Créer un frontend personnalisé](/fr/guides/custom-frontend): Utilisez l’intégration Astro de Mintlify pour afficher votre documentation avec un frontend entièrement personnalisé.
