Les liens transforment votre documentation en un ensemble cohérent. Ils aident les utilisateurs à découvrir des contenus associés, à naviguer efficacement et à suivre un parcours logique à travers des sujets complexes. De mauvais liens — texte d’ancrage vague, références croisées manquantes, URL cassées — rendent la documentation plus difficile à utiliser et nuisent au SEO.

Ce guide explique comment créer différents types de liens dans Mintlify et comment préserver leur intégrité à mesure que votre documentation s’étoffe.

<div id="internal-links">
  ## Liens internes
</div>

Créez des liens vers d’autres pages de votre documentation à l’aide de chemins relatifs à la racine. Les chemins relatifs à la racine partent de la racine de votre répertoire de documentation et fonctionnent de manière cohérente, quel que soit l’emplacement de la page source dans votre arborescence de répertoires.

```mdx
- [Quickstart guide](/quickstart)
- [API overview](/api-playground/overview)
- [Custom components](/customize/react-components)
```

Évitez les chemins relatifs comme `../api-playground/overview`—ils ne fonctionnent plus lorsque les pages sont déplacées et sont plus difficiles à repérer lors de la relecture.

<div id="anchor-links">
  ## Liens d’ancrage
</div>

Les liens d’ancrage renvoient vers des sections précises d’une page. Chaque titre génère automatiquement une ancre à partir de son texte.

<div id="link-to-headers-on-the-same-page">
  ### Créer des liens vers les en-têtes de la même page
</div>

Référencez les en-têtes de la page actuelle à l’aide du symbole # :

```mdx
[Jump to best practices](#best-practices)
```

<div id="link-to-headers-on-other-pages">
  ### Créer un lien vers des titres sur d’autres pages
</div>

Combinez le chemin de la page avec l’ancre :

```mdx
- [Customize your playground](/api-playground/overview#customize-your-playground)
- [Cards properties](/components/cards#properties)
```

<div id="how-mintlify-generates-anchors">
  ### Comment Mintlify génère les ancres
</div>

Mintlify crée automatiquement des ancres à partir du texte des titres en le convertissant en minuscules, en remplaçant les espaces par des traits d’union et en supprimant les caractères spéciaux.

| Texte du titre           | Ancre générée         |
| ------------------------ | --------------------- |
| `## Getting Started`     | `#getting-started`    |
| `### API Authentication` | `#api-authentication` |
| `#### Step 1: Install`   | `#step-1-install`     |

<Note>
  Les titres avec la prop `noAnchor` ne génèrent pas de liens d’ancrage. Pour en savoir plus, consultez [Formater le texte](/fr/create/text#disabling-anchor-links).
</Note>

<div id="custom-anchor-ids">
  ### ID d’ancre personnalisés
</div>

Remplacez l’ancre générée automatiquement pour n’importe quel titre en ajoutant `{#custom-id}` au texte du titre :

```mdx
## Configuration options {#config}
```

Ce titre est accessible via `#config` au lieu de `#configuration-options`. Les ID personnalisés permettent de conserver des liens d’ancrage stables lorsque vous mettez à jour le texte des titres, ce qui est utile pour les titres vers lesquels vous pointez souvent. Consultez [Mettre en forme le texte](/fr/create/text#custom-heading-ids) pour plus de détails.

<div id="deep-links">
  ## Liens profonds
</div>

Les liens profonds renvoient à un état ou à un emplacement précis dans une page, et non simplement à la page elle-même.

<div id="accordion-deep-links">
  ### Liens profonds de l’Accordion
</div>

Lorsque vous ouvrez un Accordion, le hash de l’URL est mis à jour pour refléter son état ouvert. Si vous visitez une URL contenant ce hash, l’Accordion s’ouvre automatiquement et la page défile jusqu’à lui.

Par défaut, le hash est généré à partir du `title` de l’Accordion. Utilisez la propriété `id` pour définir un hash personnalisé :

```mdx
<Accordion title="Installation steps" id="install">
  ...
</Accordion>
```

Cet accordéon est accessible via `#install` au lieu de l’ancre générée automatiquement `#installation-steps`. Consultez [Accordions](/fr/components/accordions) pour en savoir plus.

<div id="api-playground-deep-links">
  ### Liens profonds vers le bac à sable API
</div>

Pour ouvrir directement le bac à sable API depuis un lien, ajoutez `?playground=open` à l’URL de n’importe quelle page de point de terminaison :

```text
https://your-docs-url/endpoint-path?playground=open
```

L’URL se met à jour lorsque les utilisateurs ouvrent ou ferment le bac à sable. Utilisez des liens profonds vers le bac à sable dans les conversations d’assistance ou les parcours d’intégration afin d’envoyer les utilisateurs directement vers le bac à sable interactif d’un point de terminaison. Consultez [bac à sable API](/fr/api-playground/overview#parameter-anchor-links) pour plus d’informations sur les liens d’ancrage des paramètres.

<div id="external-links">
  ## Liens externes
</div>

Lorsque vous créez des liens vers des ressources externes, choisissez un texte d’ancrage qui indique clairement la destination :

```mdx
See the [OpenAPI specification](https://swagger.io/specification/) in the Swagger documentation for details.
```

<div id="best-practices">
  ## Bonnes pratiques
</div>

<div id="write-descriptive-anchor-text">
  ### Rédigez un texte d’ancrage descriptif
</div>

Le texte d’ancrage doit indiquer aux utilisateurs où ils seront dirigés avant de cliquer. Les expressions vagues comme « click here » ou « read more » constituent aussi des signaux SEO moins pertinents qu’un texte descriptif.

<CodeGroup>
  ```mdx Good
  Voir [Pages masquées](/organize/hidden-pages) pour en savoir plus.
  [Configurer des domaines personnalisés](/customize/custom-domain)
  ```

  ```mdx Avoid
  [Cliquez ici](/api-playground/overview)
  [En savoir plus](/deploy/deployments)
  [Voir cette page](/customize/custom-domain)
  ```
</CodeGroup>

<div id="link-prerequisites-explicitly">
  ### Indiquez explicitement les prérequis
</div>

Lorsqu’une page suppose des étapes préalables, ajoutez des liens vers celles-ci en haut de la page, au lieu de supposer que les utilisateurs les trouveront d’eux-mêmes :

```mdx
## Prerequisites

Before deploying your documentation, ensure you have:

- Completed the [quickstart guide](/quickstart)
- Configured your [custom domain](/customize/custom-domain)
- Set up [authentication](/deploy/authentication-setup) if needed
```

<div id="build-topic-clusters">
  ### Créez des groupes thématiques
</div>

Reliez les contenus connexes entre eux pour aider les utilisateurs, ainsi que les moteurs de recherche, à comprendre comment votre documentation est organisée :

```mdx
## Related topics

- [API authentication](/api-playground/overview#authentication)
- [Adding SDK examples](/api-playground/adding-sdk-examples)
- [Managing page visibility](/api-playground/managing-page-visibility)
```

<div id="check-for-broken-links">
  ### Vérifiez les liens rompus
</div>

Exécutez le CLI Mintlify avant de publier pour repérer les liens internes et externes rompus :

```bash
mint broken-links
```

<div id="update-links-when-reorganizing">
  ### Mettez à jour les liens lors d’une réorganisation
</div>

Lorsque vous déplacez ou renommez des pages :

1. Mettez à jour le chemin de la page dans votre configuration de navigation.
2. Configurez des redirections de l’ancien chemin vers le nouveau.
3. Recherchez dans votre documentation les références à l’ancien chemin.
4. Mettez à jour tous les liens internes afin qu’ils utilisent le nouveau chemin.
5. Exécutez `mint broken-links` pour vérifier.

<div id="use-redirects-for-moved-content">
  ### Utiliser des redirections pour le contenu déplacé
</div>

Lorsque vous déplacez définitivement du contenu, ajoutez des redirections pour éviter les liens rompus pour les utilisateurs qui ont enregistré d’anciennes URL dans leurs favoris ou les ont partagées.

```json
{
  "redirects": [
    {
      "source": "/old-path",
      "destination": "/new-path"
    }
  ]
}
```

Consultez [Redirects](/fr/create/redirects) pour en savoir plus.

<div id="frequently-asked-questions">
  ## Questions fréquentes
</div>

<AccordionGroup>
  <Accordion title="Dois-je utiliser des URL relatives à la racine ou des URL absolues pour les liens internes ?">
    Les chemins relatifs à la racine (commençant par `/`) sont le bon choix pour les liens internes dans Mintlify. Ils fonctionnent de manière cohérente, quel que soit l’emplacement de la page contenant le lien dans votre répertoire, et ne se cassent pas si le domaine de votre documentation change. Les URL absolues pour les liens internes introduisent une fragilité inutile.
  </Accordion>

  <Accordion title="Comment garder des liens d’ancrage stables lorsque je mets à jour des titres ?">
    Utilisez des ID d’ancre personnalisés pour les titres vers lesquels vous créez souvent des liens. Ajouter `{#custom-id}` à un titre dissocie l’ancrage du texte du titre, ce qui vous permet de modifier ce dernier sans casser les liens qui pointent vers lui. C’est particulièrement utile pour les titres des sections de référence très consultées, dont le libellé peut devoir être affiné au fil du temps.
  </Accordion>

  <Accordion title="Que deviennent les liens ajoutés aux favoris lorsque je réorganise ma documentation ?">
    Sans redirections, les liens enregistrés dans les favoris et les liens partagés deviennent des erreurs 404. Configurez des redirections dans votre `docs.json` chaque fois que vous déplacez ou renommez une page. Les redirections sont simples à ajouter et évitent une mauvaise expérience utilisateur à toute personne ayant créé un lien vers votre documentation depuis une source externe — articles de blog, réponses sur Stack Overflow, wikis internes.
  </Accordion>

  <Accordion title="Combien de liens internes une page doit-elle contenir ?">
    Ajoutez un lien chaque fois qu’un concept connexe est réellement utile à l’utilisateur à ce moment précis, et non pour atteindre un quota. Trop peu de liens privent les utilisateurs de contexte ou de prochaines étapes. Trop de liens transforment la page en parcours de navigation qui détourne les utilisateurs de ce qu’ils essaient de faire. En règle générale, ajoutez un lien à la première mention d’un concept ou d’un outil, et ne répétez pas plusieurs fois le même lien sur une même page.
  </Accordion>
</AccordionGroup>
