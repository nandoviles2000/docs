Par défaut, les pages Mintlify utilisent une mise en page standard avec une barre latérale, une zone de contenu et une table des matières. Personnalisez cette mise en page avec les [modes de page](/fr/organize/pages#page-mode) pour créer des pages d’accueil, des présentations de fonctionnalités ou toute autre page nécessitant un design unique.

Ce guide explique comment utiliser les modes de page, Tailwind CSS et les composants pour créer des mises en page personnalisées.

<div id="choose-a-page-mode">
  ## Choisir un mode de page
</div>

Définissez le champ `mode` dans les métadonnées d’en-tête de votre page pour déterminer quels éléments d’interface s’affichent.

| Mode      | Barre latérale | Table des matières | Pied de page | Prise en charge des thèmes   | Idéal pour                                                           |
| --------- | -------------- | ------------------ | ------------ | ---------------------------- | -------------------------------------------------------------------- |
| `default` | Oui            | Oui                | Oui          | Tous les thèmes              | Pages de documentation standard                                      |
| `wide`    | Oui            | Non                | Oui          | Tous les thèmes              | Pages sans titres ou nécessitant plus de largeur                     |
| `custom`  | Non            | Non                | Non          | Tous les thèmes              | Pages d’accueil, pages marketing ou mises en page pleine page        |
| `frame`   | Oui            | Non                | Modifié      | Aspen, Almond, Luma, Sequoia | Contenu personnalisé nécessitant malgré tout une navigation latérale |
| `center`  | Non            | Non                | Oui          | Mint, Linden, Willow, Maple  | Changelogs, expériences de lecture plus ciblées                      |

Pour les pages d’accueil, le mode `custom` vous offre le plus de contrôle. Il supprime tous les éléments d’interface à l’exception de la barre de navigation supérieure, pour vous laisser une page vierge à personnaliser.

```yaml Example page frontmatter
---
title: "Welcome"
mode: "custom"
---
```

<div id="build-a-landing-page">
  ## Créer une page d’accueil
</div>

Une page d’accueil classique combine une section d’en-tête, des cartes de fonctionnalités et des appels à l’action.

<div id="set-up-the-page">
  ### Configurer la page
</div>

Créez un fichier MDX en mode `custom` :

```yaml Example landing page frontmatter
---
title: "Documentation"
description: "Everything you need to build with our platform."
mode: "custom"
---
```

<div id="create-a-hero-section">
  ### Créez une section d’en-tête
</div>

Utilisez du HTML avec des classes Tailwind CSS pour créer une section d’en-tête centrée :

```mdx Example hero section
<div className="px-4 py-16 lg:py-32 max-w-3xl mx-auto text-center">
  <h1 className="text-4xl font-medium text-gray-900 dark:text-zinc-50 tracking-tight">
    Documentation
  </h1>
  <p className="mt-4 text-lg text-gray-500 dark:text-zinc-500">
    Everything you need to build, deploy, and scale your application.
  </p>
</div>
```

<Tip>
  Prévoyez des styles pour les modes clair et sombre. Utilisez des classes Tailwind préfixées par `dark:` pour gérer le mode sombre.
</Tip>

<div id="add-navigation-cards">
  ### Ajouter des cartes de navigation
</div>

Utilisez les composants [Card](/fr/components/cards) et [Columns](/fr/components/columns) pour créer une grille de liens sous la section d’en-tête :

```mdx Example navigation cards
<div className="max-w-4xl mx-auto px-6">
  <Columns cols={2}>
    <Card title="Quickstart" icon="rocket" href="/quickstart">
      Lancez-vous en moins de cinq minutes.
    </Card>
    <Card title="API reference" icon="code" href="/api-reference">
      Explorez les endpoints, les paramètres et les exemples.
    </Card>
    <Card title="Guides" icon="book" href="/guides">
      Tutoriels pas à pas pour les tâches courantes.
    </Card>
    <Card title="Components" icon="puzzle" href="/components">
      Composants d'interface réutilisables pour votre documentation.
    </Card>
  </Columns>
</div>
```

<div id="use-images-with-dark-mode-support">
  ### Utiliser des images compatibles avec le mode sombre
</div>

Affichez des images différentes pour les modes clair et sombre à l’aide des classes de visibilité de Tailwind :

```mdx Example images with dark mode support
<img
  src="/images/hero-light.png"
  alt="Platform overview showing the main dashboard."
  className="block dark:hidden"
/>
<img
  src="/images/hero-dark.png"
  alt="Platform overview showing the main dashboard."
  className="hidden dark:block"
/>
```

<div id="use-react-components-for-interactive-layouts">
  ## Utilisez des composants React pour créer des mises en page interactives
</div>

Pour les éléments réutilisables ou interactifs, définissez des [composants React](/fr/customize/react-components) directement dans votre fichier MDX :

```mdx Example React component
export const FeatureCard = ({ title, description, href }) => (
  <a className="group block p-6 rounded-xl border border-gray-200 dark:border-zinc-800 hover:border-gray-300 dark:hover:border-zinc-700 transition-colors" href={href}>
    <h3 className="font-medium text-gray-900 dark:text-zinc-50 group-hover:underline">
      {title}
    </h3>
    <p className="mt-2 text-sm text-gray-500 dark:text-zinc-500">
      {description}
    </p>
  </a>
);

<div className="max-w-4xl mx-auto px-6 grid sm:grid-cols-2 gap-4">
  <FeatureCard
    title="Authentication"
    description="Set up OAuth, API keys, and session management."
    href="/guides/authentication"
  />
  <FeatureCard
    title="Webhooks"
    description="Receive real-time notifications for events."
    href="/guides/webhooks"
  />
</div>
```

<Warning>
  Évitez d’utiliser la prop `style` sur les éléments HTML. Cela peut provoquer un saut de mise en page au chargement de la page. Utilisez plutôt des classes Tailwind CSS ou un [fichier CSS personnalisé](/fr/customize/custom-scripts).
</Warning>

<div id="add-custom-css">
  ## Ajouter du CSS personnalisé
</div>

Pour les styles que Tailwind ne prend pas en charge, ajoutez un fichier CSS à votre dépôt. Mintlify applique les fichiers CSS à l’ensemble du site, ce qui rend leurs noms de classe disponibles dans tous les fichiers MDX.

<Note>
  Les valeurs arbitraires de Tailwind CSS (par exemple, `w-[350px]`) ne sont pas prises en charge. Utilisez un fichier CSS personnalisé pour les valeurs que les classes utilitaires de Tailwind ne couvrent pas.
</Note>

```css Example custom CSS file
.landing-hero {
  background: linear-gradient(135deg, #f0f9ff 0%, #e0f2fe 100%);
  padding: 4rem 2rem;
}

@media (prefers-color-scheme: dark) {
  .landing-hero {
    background: linear-gradient(135deg, #0c1222 0%, #1a1a2e 100%);
  }
}
```

Référencez ensuite la classe dans votre fichier MDX :

```mdx Example custom CSS usage
<div className="landing-hero">
  <h1>Welcome to the docs</h1>
</div>
```

Consultez [Custom scripts](/fr/customize/custom-scripts) pour en savoir plus sur le CSS personnalisé et les sélecteurs CSS disponibles.

<div id="tips">
  ## Conseils
</div>

* **Testez les modes clair et sombre.** Prévisualisez votre mise en page personnalisée dans les deux modes afin de repérer les styles `dark:` manquants.
* **Utilisez les classes `max-w-*`** pour limiter la largeur du contenu et conserver un texte lisible.
* **Veillez à la responsivité.** Utilisez les préfixes responsifs de Tailwind (`sm:`, `md:`, `lg:`) pour que votre mise en page fonctionne sur toutes les tailles d’écran.
* **Combinez les modes.** Utilisez le mode `custom` pour la page d’accueil de votre documentation et le mode `default` pour tout le reste. Vous définissez le mode pour chaque page, ce qui permet à différentes pages d’utiliser différentes mises en page.
* **Vérifiez les sauts de mise en page.** Si des éléments se déplacent au chargement de la page, remplacez les props `style` inline par des classes Tailwind ou du CSS personnalisé.
