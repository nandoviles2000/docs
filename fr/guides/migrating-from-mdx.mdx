---

sidebarTitle: "Migrer de MDX vers OAS"
description: "Migrez vos pages d’API MDX rédigées manuellement vers une documentation automatisée générée à partir d’OpenAPI, avec une navigation flexible et un regroupement des points de terminaison."
keywords: ["migration d’API", "migration OpenAPI", "extension x-mint"]
---

Si vous utilisez actuellement des pages MDX distinctes pour vos points de terminaison d’API, vous pouvez migrer vers la génération automatique de pages à partir de votre spécification OpenAPI tout en conservant la possibilité de personnaliser chaque page. Cela peut vous aider à réduire le nombre de fichiers à gérer et à améliorer la cohérence de votre documentation d’API.

Vous pouvez définir des métadonnées et du contenu pour chaque point de terminaison dans votre spécification OpenAPI, et organiser ces points de terminaison où vous le souhaitez dans votre navigation.

<div id="migration-steps">
  ## Étapes de migration
</div>

<Steps>
  <Step title="Préparez votre spécification OpenAPI.">
    Assurez-vous que votre spécification OpenAPI est valide et inclut tous les points de terminaison que vous souhaitez documenter.

    Pour chaque point de terminaison dont vous souhaitez personnaliser les métadonnées ou le contenu, ajoutez l’extension `x-mint` au point de terminaison. Consultez [l’extension x-mint](/fr/api-playground/openapi-setup#customize-your-endpoint-pages) pour en savoir plus.

    Pour chaque point de terminaison que vous souhaitez exclure de votre documentation, ajoutez l’extension `x-hidden` au point de terminaison.

    <Info>
      Validez votre fichier OpenAPI à l’aide de [Swagger Editor](https://editor.swagger.io/) ou de [Mint CLI](https://www.npmjs.com/package/mint).
    </Info>
  </Step>

  <Step title="Mettez à jour votre structure de navigation.">
    Remplacez les références aux pages MDX par des points de terminaison OpenAPI dans votre `docs.json`.

    ```json
    "navigation": {
      "groups": [
        {
          "group": "API Reference",
          "openapi": "/path/to/openapi.json",
          "pages": [
            "overview",
            "authentication",
            "introduction",
            "GET /health",
            "quickstart", 
            "POST /users",
            "GET /users/{id}",
            "advanced-features"
          ]
        }
      ]
    }
    ```
  </Step>

  <Step title="Supprimez les anciens fichiers MDX.">
    Après avoir vérifié que votre nouvelle navigation fonctionne correctement, supprimez les fichiers MDX des points de terminaison dont vous n’avez plus besoin.
  </Step>
</Steps>

<div id="navigation-patterns">
  ## Types de navigation
</div>

Vous pouvez personnaliser la façon dont votre documentation d’API apparaît dans la navigation.

<div id="mixed-content-navigation">
  ### Navigation mixte
</div>

Combinez des pages d’API générées automatiquement avec d’autres pages :

```json
"navigation": {
  "groups": [
    {
      "group": "API Reference",
      "openapi": "openapi.json",
      "pages": [
        "api/overview",
        "GET /users",
        "POST /users", 
        "api/authentication"
      ]
    }
  ]
}
```

<div id="multiple-api-versions">
  ### Plusieurs versions d’API
</div>

Organisez les différentes versions de l’API à l’aide d’onglets ou de groupes :

```json
"navigation": {
  "tabs": [
    {
      "tab": "API v1",
      "openapi": "specs/v1.json"
    },
    {
      "tab": "API v2", 
      "openapi": "specs/v2.json"
    }
  ]
}
```

<div id="when-to-use-individual-mdx-pages">
  ## Quand utiliser des pages MDX individuelles
</div>

Envisagez de conserver des pages MDX individuelles lorsque vous avez besoin de :

* Contenu personnalisé important pour chaque point de terminaison, comme des composants React ou de longs exemples.
* Mises en page uniques.
* Approches de documentation expérimentales pour des points de terminaison spécifiques.

Dans la plupart des cas d’usage, la navigation OpenAPI offre une meilleure maintenabilité et une plus grande cohérence.
