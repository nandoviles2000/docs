Une base de connaissances interne aide votre équipe à trouver des réponses et à maintenir une source d’information fiable. Si les informations de votre équipe sont dispersées sur différents canaux et plateformes, les utilisateurs risquent de trouver des informations inexactes, voire de ne rien trouver du tout, lorsqu’ils cherchent des réponses. Une base de connaissances centralisée résout ce problème en regroupant les réponses dans un emplacement accessible à tous et en donnant à votre équipe un endroit dédié pour consigner les connaissances partagées.

Mintlify fournit l’infrastructure nécessaire pour créer des bases de connaissances auxquelles toute votre équipe peut contribuer.

* **Recherche basée sur l’IA** : l’[assistant](/fr/assistant/index) répond aux questions à partir du contenu de votre base de connaissances, afin que chacun puisse trouver des réponses sans savoir exactement où chercher.
* **Intégrations Slack** : ajoutez l’assistant à [Slack](/fr/ai/slack-bot) pour que votre équipe puisse poser des questions et utiliser l’[agent](/fr/agent/slack) afin de capturer les connaissances issues des conversations.
* **Contributions simplifiées** : l’[éditeur web](/fr/editor) et l’[agent](/fr/agent/index) permettent à tous les membres de votre équipe de mettre à jour le contenu sans avoir à apprendre Git ou Markdown.
* **Authentification intégrée** : contrôlez l’accès avec le [SSO ou OAuth](/fr/deploy/authentication-setup), et utilisez les [groupes](/fr/deploy/authentication-setup#control-access-with-groups) pour afficher un contenu différent selon les équipes.

<div id="prerequisites">
  ## Prérequis
</div>

Si vous n’avez pas encore créé de projet Mintlify, consultez le [guide de démarrage rapide](/fr/quickstart) pour déployer votre site.

* Un système d’authentification (SSO ou un fournisseur OAuth comme Okta ou Azure AD)
* Le contrôle de votre domaine pour l’hébergement
* Un accès administrateur à votre organisation Mintlify

<div id="migrate-existing-content">
  ## Migrer le contenu existant
</div>

Si vous créez une base de connaissances à partir de zéro, passez à [Concevoir la structure de navigation](#design-the-navigation-structure).

<div id="audit-existing-content">
  ### Faire l’inventaire du contenu existant
</div>

Recensez le contenu dont vous disposez actuellement dans votre base de connaissances. Cela vous aide à déterminer ce que vous devez migrer, à planifier l’organisation de votre nouvelle base de connaissances, à repérer d’éventuelles lacunes et à vérifier que tout le contenu a bien été transféré vers votre nouvelle base de connaissances.

* **Nombre total d’articles** : aide à estimer l’ampleur de la migration et à en suivre l’exhaustivité.
* **Sujets et contenu** : permet de définir la structure de votre Navigation et l’organisation du contenu.
* **Organisation actuelle** : voyez comment votre contenu est structuré aujourd’hui et s’il correspond à l’organisation souhaitée.
* **Types de contenu** : déterminez les éventuels besoins de conversion pour le texte, les PDF, les vidéos et le contenu intégré.
* **Métadonnées** : identifiez les métadonnées à conserver, comme les dates, les auteurs et les étiquettes.
* **Exigences d’accès** : déterminez l’approche d’authentification la plus adaptée à votre base de connaissances.

<div id="export-your-existing-content">
  ### Exportez votre contenu existant
</div>

La plupart des plateformes de base de connaissances permettent d’exporter le contenu dans des formats standard. Le format à choisir dépend de votre plateforme actuelle et de vos priorités.

* Exportez au format **Markdown** pour migrer le plus facilement vers Mintlify. (recommandé)
* Exportez au format **HTML** si Markdown n’est pas disponible. Vous devrez ensuite convertir votre contenu en Markdown.
* Exportez au format **JSON ou CSV** si vous avez des métadonnées structurées à conserver.

<div id="design-the-navigation-structure">
  ## Concevez la structure de navigation
</div>

La structure de navigation détermine la manière dont les utilisateurs trouvent le contenu de votre base de connaissances. Vous pouvez recréer votre structure existante ou la repenser pour qu’elle corresponde mieux à la façon dont votre équipe organise le contenu.

<Tip>
  Une migration est un bon moment pour améliorer votre structure. Demandez-vous si votre organisation actuelle fonctionne réellement pour votre équipe, ou si vous pouvez la réorganiser pour rendre les informations plus faciles à trouver.
</Tip>

Votre fichier `docs.json` définit la structure de navigation de votre base de connaissances. Créez ce fichier à la racine du dépôt de votre projet.

```json
{
  "navigation": {
    "groups": [
      {
        "group": "Finance",
        "pages": [
            "finance/overview",
            "finance/budgeting-process",
            "finance/expense-reports",
            "finance/cost-allocation"
        ]
      },
      {
        "group": "HR",
        "pages": [
            "hr/overview",
            "hr/onboarding",
            "hr/benefits",
            "hr/time-off-policy"
        ]
      },
      {
        "group": "Engineering",
        "pages": [
          "engineering/overview",
          "engineering/dev-setup",
          "engineering/deployment",
          "engineering/code-standards"
        ]
      }
    ]
  }
}
```

Consultez [Navigation](/fr/organize/navigation) pour en savoir plus sur la manière de structurer votre base de connaissances.

<div id="set-up-authentication">
  ## Configurer l’authentification
</div>

Déterminez qui doit accéder à quels contenus dans votre base de connaissances.

Si tout le monde doit avoir accès à l’ensemble de la base de connaissances, configurez uniquement l’[authentification](/fr/deploy/authentication-setup).

Si vous devez restreindre l’accès à certains contenus à des utilisateurs ou à des groupes spécifiques, configurez l’authentification avec le [contrôle d’accès par groupe](/fr/deploy/authentication-setup#control-access-with-groups).

<div id="migrate-your-content">
  ## Migrez votre contenu
</div>

Déplacez le contenu exporté dans une structure de dossiers correspondant à la structure de navigation que vous avez définie. Convertissez le contenu en Markdown si nécessaire, ajoutez les métadonnées d’en-tête manquantes et configurez les liens internes.

<Steps>
  <Step title="Organiser les fichiers">
    Créez des dossiers qui correspondent à la structure de votre `docs.json`. Par exemple, si votre `docs.json` contient un groupe Finance, créez un dossier `finance/` :

    ```text
    your-project/
    ├── docs.json
    ├── finance/
    │   ├── overview.mdx
    │   ├── budgeting-process.mdx
    │   ├── expense-reports.mdx
    │   └── cost-allocation.mdx
    ├── hr/
    │   ├── overview.mdx
    │   ├── onboarding.mdx
    │   ├── benefits.mdx
    │   └── time-off-policy.mdx
    └── engineering/
        ├── overview.mdx
        ├── dev-setup.mdx
        ├── deployment.mdx
        └── code-standards.mdx
    ```

    Placez chaque article dans le dossier correspondant. Le chemin doit correspondre à celui indiqué dans votre `docs.json`. Par exemple, si `docs.json` référence `"finance/expense-reports"`, le fichier doit être `finance/expense-reports.mdx` dans le dépôt de votre projet.
  </Step>

  <Step title="Ajouter des métadonnées d’en-tête à chaque article">
    Chaque fichier `.mdx` doit commencer par des métadonnées d’en-tête. Chaque page doit comporter un titre et une description. Consultez [Pages](/fr/organize/pages) pour en savoir plus sur les métadonnées des pages.

    ```mdx
    ---
    title: "Processus de note de frais"
    description: "Comment soumettre et suivre les notes de frais"
    ---

    Votre contenu ici...
    ```
  </Step>

  <Step title="Configurer les liens internes">
    Créez des liens entre les pages à l’aide de chemins à partir de la racine de votre projet.

    ```mdx
    Consultez le [guide d’intégration](/hr/onboarding) pour la configuration des nouveaux employés.

    Pour toute question, contactez l’[équipe Avantages RH](/hr/benefits#common-questions).
    ```
  </Step>

  <Step title="Convertir le HTML et d’autres formats en Markdown">
    Si vous avez exporté votre contenu au format HTML, convertissez-le en Markdown. Voici quelques outils qui peuvent vous aider :

    * **Pandoc** : outil en ligne de commande qui convertit de nombreux formats.
    * **CloudConvert** : convertisseur en ligne compatible avec HTML, DOCX, PDF, etc.
    * **Extensions VS Code** : recherchez &quot;HTML to Markdown&quot; dans les extensions.
  </Step>

  <Step title="Gérer plusieurs formats de contenu">
    Si vous avez des PDF, des vidéos ou d’autres médias, déterminez comment les inclure dans votre base de connaissances.

    * **Intégrer des vidéos** : intégrez des vidéos ou ajoutez des liens vers des vidéos hébergées.
    * **Créer des liens vers des PDF** : ajoutez des PDF au dépôt de votre projet et créez des liens vers eux depuis les pages concernées.
    * **Convertir les PDF en Markdown** : si vous souhaitez transformer le contenu d’un PDF en page, convertissez les PDF en Markdown.
  </Step>
</Steps>

<div id="set-up-the-assistant">
  ## Configurer l’assistant
</div>

L’assistant est automatiquement activé pour les forfaits Pro et Enterprise. Il permet à votre équipe de poser des questions et d’obtenir des réponses avec citation des sources issues de votre base de connaissances.

Configurez l’assistant depuis votre [tableau de bord](https://dashboard.mintlify.com/products/assistant/settings) :

* **Exemples de questions** : ajoutez des questions fréquentes comme &quot;comment soumettre une note de frais&quot; ou &quot;quelle est la politique de congés&quot; afin que les utilisateurs puissent obtenir des réponses en un clic.
* **Sites de recherche** : incluez des sites supplémentaires que l’assistant peut consulter lorsqu’il répond aux questions.
* **E-mail de redirection** : définissez une adresse e-mail de support pour les questions auxquelles l’assistant ne peut pas répondre.

<div id="add-the-assistant-to-slack">
  ### Ajouter l’assistant à Slack
</div>

Le [bot Slack](/fr/ai/slack-bot) permet à votre équipe de poser des questions à l’assistant sans quitter Slack. Créez un canal où le bot répond à chaque message, ou permettez aux utilisateurs de mentionner le bot avec @ dans n’importe quel canal.

<div id="enable-team-contributions">
  ## Permettre les contributions de l&#39;équipe
</div>

Une base de connaissances reste fiable lorsque tout le monde peut la mettre à jour, et pas seulement les personnes qui l&#39;ont configurée. Mintlify propose trois façons pour les membres de l&#39;équipe de contribuer rapidement à votre base de connaissances.

<div id="web-editor">
  ### Éditeur web
</div>

L’[éditeur web](/fr/editor) permet à tout le monde de créer et de modifier des pages dans son navigateur. Les contributeurs peuvent :

* Modifier les pages visuellement ou en Markdown.
* Réorganiser la navigation par glisser-déposer.
* Importer des images et des médias.
* Créer des branches et des pull requests (PR) pour relecture.

Cette solution convient bien aux experts métier qui maîtrisent le contenu, mais ne sont pas à l’aise avec les flux de travail impliquant du code.

<div id="agent">
  ### Agent
</div>

L’[agent](/fr/agent/index) de votre tableau de bord crée des mises à jour de la documentation à partir de prompts en langage naturel. Décrivez ce que vous souhaitez modifier, et l’agent crée une pull request (PR) avec les mises à jour.

Par exemple, un membre de l’équipe pourrait saisir le prompt « ajouter une section à la page de politique de dépenses expliquant comment envoyer des reçus pour des repas de plus de 50 $ » et copier la page de politique de dépenses existante dans le prompt. L’agent rédigerait le contenu et ouvrirait une PR pour examen.

<div id="capture-knowledge-from-slack">
  ### Capturer les connaissances depuis Slack
</div>

Les équipes partagent dans Slack des informations précieuses qui ne sont souvent jamais intégrées à la documentation. L’[agent sur Slack](/fr/agent/slack) peut capturer ces connaissances et les convertir en documentation structurée.

Lorsqu’une personne partage des informations utiles dans un fil Slack, n’importe quel membre de l’équipe peut mentionner `@mintlify` avec des instructions pour les documenter. L’agent lit la conversation, extrait les informations pertinentes et crée une pull request (PR). Cela permet de consigner des décisions techniques, des solutions de dépannage et des explications de processus pendant que le contexte est encore frais.

Par exemple, si votre équipe a discuté dans un fil de la manière de configurer une nouvelle intégration, vous pourriez répondre :

> @mintlify Crée un guide pour configurer l’intégration Acme à partir de cette conversation.

L’agent utilise le contexte du fil pour créer une documentation qui reprend les informations clés de la discussion.

<div id="locally">
  ### En local
</div>

Toute personne ayant accès au dépôt de votre base de connaissances peut travailler en local dans l’éditeur de son choix et pousser les modifications vers votre dépôt.

<div id="establish-maintenance-workflows">
  ## Mettre en place des flux de travail de maintenance
</div>

Une base de connaissances peut rapidement se dégrader sans maintenance. Mettez en place des systèmes pour garder le contenu à jour et aider votre équipe à contribuer à la base de connaissances.

<Steps>
  <Step title="Définir des responsables de contenu">
    Désignez un responsable ou une petite équipe pour chaque section. Ils n&#39;ont pas besoin de rédiger tout le contenu, mais ils sont chargés de :

    * Réviser régulièrement le contenu.
    * Signaler les informations obsolètes.
    * Approuver les nouvelles pages de leur section.
    * Répondre aux signalements d&#39;erreurs.
  </Step>

  <Step title="Mettre en place des cycles de révision et de vérification du contenu">
    Le contenu devient obsolète avec le temps. Définissez un calendrier de révision.

    * **Contenu critique** : tous les 30 jours
    * **Contenu standard** : tous les 90 jours
    * **Contenu pérenne** : tous les ans

    Lors de chaque révision, vérifiez les points suivants :

    * Les liens sont-ils toujours valides ?
    * Les systèmes ou les processus ont-ils changé ?
    * Les exemples sont-ils à jour ?
    * Faut-il ajouter de nouvelles informations ?
  </Step>

  <Step title="Créer des consignes de contribution">
    Facilitez l&#39;amélioration de la base de connaissances pour tous. Vos consignes doivent couvrir les points suivants :

    * **Format** : utilisez-vous des modèles spécifiques ou des exigences de mise en forme particulières ?
    * **Processus** : comment faut-il proposer et soumettre des modifications ?
    * **Révision** : qui examine les contributions ? Quel est le délai de traitement ?
    * **Portée** : quels types de contenu sont inclus dans le périmètre ?
  </Step>

  <Step title="Suivre les indicateurs d'utilisation">
    Analysez la façon dont votre équipe utilise la base de connaissances afin de prioriser le contenu et d&#39;identifier les points à améliorer. Définissez une fréquence régulière pour examiner les indicateurs d&#39;utilisation : tous les mois ou tous les trimestres sont de bons rythmes.

    * Quels articles enregistrent le plus de vues ? Veillez à ce qu&#39;ils restent exacts et faciles à lire.
    * Quels articles n&#39;enregistrent aucune vue ? Envisagez de les supprimer ou d&#39;améliorer leur visibilité.
    * Quel est le taux de rebond ? Si les utilisateurs quittent la page immédiatement, le contenu n&#39;est peut-être pas utile ou la navigation pourrait être améliorée.
  </Step>
</Steps>

<div id="next-steps">
  ## Prochaines étapes
</div>

Votre base de connaissances est prête à être mise en ligne. Après le déploiement :

1. Annoncez la base de connaissances à votre équipe.
2. Surveillez l’utilisation et les habitudes de recherche dans vos analyses.
3. Encouragez les contributions lorsque des manques sont constatés.
4. Relisez et mettez régulièrement le contenu à jour.

Les bases de connaissances les plus efficaces évoluent en fonction de la façon dont les équipes les utilisent réellement.
