Claude Code est un outil en ligne de commande agentique qui peut vous aider à maintenir votre documentation. Il peut rédiger du nouveau contenu, relire des pages existantes et garder votre documentation à jour.

Vous pouvez apprendre à Claude Code à respecter les standards et les flux de travail de votre documentation en ajoutant un fichier `CLAUDE.md` à votre projet, puis en l&#39;affinant au fil du temps.

<div id="getting-started">
  ## Premiers pas
</div>

**Prérequis :**

* Abonnement Claude actif (Pro, Max ou accès API)

**Configuration :**

1. Installez Claude Code :

```bash
  npm install -g @anthropic-ai/claude-code
```

2. Accédez à votre répertoire de documentation.
3. (Facultatif) Ajoutez le fichier `CLAUDE.md` ci-dessous à votre projet.
4. Exécutez `claude` pour lancer l’outil.

<div id="claudemd-template">
  ## Modèle de CLAUDE.md
</div>

Enregistrez un fichier `CLAUDE.md` à la racine de votre répertoire de documentation pour aider Claude Code à comprendre votre projet. Ce fichier permet à Claude Code de se familiariser avec vos normes de documentation, vos préférences et vos flux de travail. Consultez [Gérer la mémoire de Claude](https://docs.anthropic.com/en/docs/claude-code/memory) dans la documentation d’Anthropic pour en savoir plus.

Copiez ce modèle d’exemple ou adaptez-le aux spécifications de votre documentation :

```mdx
# Documentation Mintlify

## Relation de travail
- Vous pouvez remettre en question des idées — cela peut mener à une meilleure documentation. Citez vos sources et expliquez votre raisonnement lorsque vous le faites
- Demandez TOUJOURS des clarifications plutôt que de faire des suppositions
- Ne mentez JAMAIS, ne devinez pas et n'inventez rien

## Contexte du projet
- Format : fichiers MDX avec métadonnées d'en-tête YAML
- Configuration : docs.json pour la navigation, le thème et les paramètres
- Composants : composants Mintlify

## Stratégie de contenu
- Documentez juste ce qu'il faut pour la réussite des utilisateurs — ni trop, ni trop peu
- Privilégiez l'exactitude et la facilité d'utilisation
- Rendez le contenu pérenne dans la mesure du possible
- Recherchez le contenu existant avant d'en ajouter. Évitez les doublons, sauf si cela répond à un objectif stratégique
- Vérifiez les modèles existants pour assurer la cohérence
- Commencez par les modifications les plus légères possibles

## docs.json

- Consultez le [schéma docs.json](https://mintlify.com/docs.json) lors de la création du fichier docs.json et de la navigation du site

## Exigences des métadonnées d'en-tête pour les pages
- title: Titre de page clair et descriptif
- description: Résumé concis pour le SEO/la navigation

## Normes rédactionnelles
- Voix à la deuxième personne (« vous »)
- Prérequis en début de contenu procédural
- Testez tous les exemples de code avant publication
- Respectez le style et la mise en forme des pages existantes
- Incluez des cas d'utilisation basiques et avancés
- Balises de langage sur tous les blocs de code
- Texte alternatif sur toutes les images
- Chemins relatifs pour les liens internes

## Flux de travail Git
- N'utilisez JAMAIS --no-verify lors des commits
- Demandez comment gérer les modifications non commitées avant de commencer
- Créez une nouvelle branche lorsqu'aucune branche appropriée n'existe pour les modifications
- Commitez fréquemment tout au long du développement
- Ne sautez JAMAIS les hooks de pré-commit et ne les désactivez pas

## À ne pas faire
- Omettre les métadonnées d'en-tête dans un fichier MDX
- Utiliser des URL absolues pour les liens internes
- Inclure des exemples de code non testés
- Faire des suppositions — demandez toujours des clarifications
```

<div id="sample-prompts">
  ## Exemples de prompts
</div>

Une fois Claude Code configuré, essayez ces prompts pour voir comment il peut vous aider dans les tâches courantes de documentation. Vous pouvez copier-coller ces exemples tels quels ou les adapter à vos besoins spécifiques.

<div id="convert-notes-to-polished-docs">
  ### Convertir des notes en documentation aboutie
</div>

Transformez des brouillons en véritables pages Markdown avec des composants et des métadonnées d’en-tête.

**Exemple de prompt :**

```text wrap
Convert this text into a properly formatted MDX page: [paste your text here]
```

<div id="review-docs-for-consistency">
  ### Vérifiez la cohérence de la documentation
</div>

Obtenez des suggestions pour améliorer le style, la mise en forme et l’utilisation des composants.

**Exemple de prompt :**

```text wrap
Review the files in docs/ and suggest improvements for consistency and clarity
```

<div id="update-docs-when-features-change">
  ### Mettez à jour la documentation lorsque les fonctionnalités évoluent
</div>

Gardez la documentation à jour à mesure que votre produit évolue.

**Exemple de prompt :**

```text wrap
Our API now requires a version parameter. Update our docs to include version=2024-01 in all examples
```

<div id="generate-comprehensive-code-examples">
  ### Générer des exemples de code complets
</div>

Créez des exemples multilingues avec gestion des erreurs.

**Exemple de prompt :**

```text wrap
Créer des exemples de code pour [your API endpoint] en JavaScript, Python et cURL avec gestion des erreurs
```

<div id="extend-claude-code">
  ## Étendez Claude Code
</div>

En plus de l’utiliser manuellement, vous pouvez intégrer Claude Code à vos flux de travail existants.

<div id="automate-with-github-actions">
  ### Automatisez avec GitHub Actions
</div>

Exécutez Claude Code automatiquement lorsque le code évolue afin de maintenir la documentation à jour. Vous pouvez déclencher des revues de la documentation sur les pull requests (PR) ou mettre à jour les exemples lorsque des modifications de l’API sont détectées.

<div id="multi-instance-workflows">
  ### Flux de travail multi-instances
</div>

Utilisez des sessions Claude Code distinctes pour différentes tâches - l’une pour rédiger du nouveau contenu et l’autre pour la relecture et le contrôle qualité. Cela permet de maintenir la cohérence et de repérer des problèmes qu’une seule session pourrait laisser passer.

<div id="team-collaboration">
  ### Collaboration en équipe
</div>

Partagez votre fichier `CLAUDE.md` peaufiné avec votre équipe afin d’assurer des standards de documentation cohérents pour l’ensemble des contributeurs. Les équipes développent souvent des prompts et des flux de travail propres au projet, qui s’intègrent à leur processus de documentation.

<div id="custom-commands">
  ### Commandes personnalisées
</div>

Créez des slash commands réutilisables dans `.claude/commands/` pour les tâches de documentation récurrentes propres à votre projet ou à votre équipe.

<div id="frequently-asked-questions">
  ## Questions fréquentes
</div>

<AccordionGroup>
  <Accordion title="Ai-je besoin d’un fichier CLAUDE.md pour utiliser Claude Code avec Mintlify ?">
    Non, mais cela améliore nettement la qualité du résultat. Sans fichier CLAUDE.md, Claude Code s’appuie sur un contexte général et peut ne pas respecter votre guide de style, vos préférences en matière de composants ou votre terminologie spécifique. Un fichier CLAUDE.md permet d’aligner Claude Code sur les standards de votre projet, afin que vous n’ayez pas à les réexpliquer dans chaque prompt.
  </Accordion>

  <Accordion title="En quoi Claude Code se distingue-t-il de Cursor ou Windsurf pour la documentation ?">
    Claude Code est un outil en ligne de commande conçu pour des tâches agentiques en plusieurs étapes à l’échelle d’un dépôt entier. Il est particulièrement adapté à des tâches comme l’audit de toutes les pages pour repérer les textes alternatifs manquants, la mise à jour d’un nom de paramètre dans chaque exemple de code ou la révision d’un ensemble de fichiers pour en vérifier la cohérence. Cursor et Windsurf sont des outils intégrés à l’IDE, mieux adaptés à la modification de fichiers individuels avec des suggestions en ligne. Les deux approches fonctionnent : le bon choix dépend de la nature de votre travail, fichier par fichier ou à l’échelle de l’ensemble du dépôt.
  </Accordion>

  <Accordion title="Puis-je utiliser Claude Code pour générer automatiquement de la documentation à partir du code ?">
    Oui. Claude Code peut lire votre code source et générer la documentation correspondante. Pointez-le vers un endpoint d’API, un fichier de configuration ou un ensemble de fonctions, puis demandez-lui de produire une documentation conforme aux standards définis dans votre fichier CLAUDE.md. Relisez et affinez le résultat : la génération automatisée fonctionne mieux lorsque vous considérez Claude Code comme l’auteur d’un premier jet, et non comme l’éditeur final.
  </Accordion>

  <Accordion title="Comment partager ma configuration CLAUDE.md avec mon équipe ?">
    Ajoutez le fichier CLAUDE.md à votre dépôt de documentation. Toute personne qui clone le dépôt et exécute Claude Code utilisera automatiquement la configuration de votre projet. Cela permet de maintenir des standards de documentation cohérents entre les contributeurs sans obliger chacun à configurer son propre contexte.
  </Accordion>
</AccordionGroup>
