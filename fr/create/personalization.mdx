<Note>
  La personnalisation nécessite que [l’authentification](/fr/deploy/authentication-setup) soit configurée avec OAuth ou JWT.
</Note>

Personnalisez le contenu pour vos utilisateurs lorsqu’ils se connectent à votre site de documentation. Vous pouvez préremplir des clés API, afficher du contenu propre à l’offre ou au rôle d’un utilisateur, et filtrer le contenu de la Référence de l’API en fonction de son appartenance à un groupe.

<div id="api-key-prefilling">
  ## Préremplissage des clés API
</div>

Préremplissez automatiquement les champs du bac à sable API avec des valeurs propres à l’utilisateur en renvoyant, dans vos données utilisateur, des noms de champs correspondants. Incluez les valeurs dans le champ `apiPlaygroundInputs` de vos [données utilisateur](/fr/deploy/authentication-setup#user-data-format).

```json
{
  "apiPlaygroundInputs": {
    "header": { "X-API-Key": "user_api_key_123" },
    "server": { "subdomain": "acme" }
  }
}
```

Les noms des champs doivent correspondre aux noms définis dans votre spécification OpenAPI. Seules les valeurs correspondant au schéma de sécurité du point de terminaison actuel sont prises en compte.

<div id="dynamic-mdx-content">
  ## Contenu MDX dynamique
</div>

Affichez du contenu en fonction d’informations utilisateur telles que le nom, l’abonnement ou l’organisation, à l’aide de la variable `user` dans vos pages MDX. Incluez des données personnalisées dans le champ `content` de vos [données utilisateur](/fr/deploy/authentication-setup#user-data-format).

```json
{
  "content": {
    "firstName": "Jane",
    "company": "Acme Corp",
    "plan": "Enterprise"
  }
}
```

Utilisez ces valeurs dans votre MDX.

```mdx
Welcome back, {user.firstName}! Your {user.plan} plan includes 100 seats for members in your {user.company} organization.
```

Pour effectuer un rendu conditionnel en fonction des données utilisateur, utilisez la variable `user` dans les composants JSX.

```jsx
{
  user.plan === 'enterprise'
    ? <>Contact your admin to enable this feature.</>
    : <>See <a href="https://yoursite.com/pricing">pricing</a> for information about upgrading.</>
}
```

<Note>
  La variable `user` est un objet vide lorsque l’utilisateur n’est pas connecté. Utilisez le chaînage optionnel sur tous les champs de `user` afin d’éviter les erreurs. Par exemple, `{user.org?.plan}` au lieu de `{user.org.plan}`.
</Note>

<div id="page-visibility">
  ## Visibilité de la page
</div>

Limitez l’accès aux pages à des groupes d’utilisateurs spécifiques en ajoutant `groups` aux métadonnées d’en-tête de la page. Les utilisateurs doivent appartenir à au moins un des groupes indiqués pour accéder à la page.

```mdx
---
title: "Admin settings"
groups: ["admin"]
---
```

Pour plus de détails sur la manière dont les groupes interagissent avec les pages publiques, consultez [Contrôler l’accès avec les groupes](/fr/deploy/authentication-setup#control-access-with-groups).

<div id="openapi-content-filtering">
  ## Filtrage du contenu OpenAPI
</div>

Filtrez le contenu de la Référence de l’API en fonction des groupes d’utilisateurs à l’aide de l’extension `x-mint` dans votre spécification OpenAPI. Vous pouvez filtrer des points de terminaison entiers, des propriétés de schéma individuelles, des variantes `oneOf` et des valeurs d’énumération.

<div id="filter-endpoints">
  ### Filtrer les points de terminaison
</div>

Ajoutez `x-mint.groups` à une opération ou à un chemin pour restreindre l’accès à la page du point de terminaison à certains groupes d’utilisateurs. Les utilisateurs qui ne font pas partie des groupes indiqués ne verront pas le point de terminaison dans la navigation et ne pourront pas accéder à sa page.

<CodeGroup>
  ```json {6-8} Opération restreinte
  {
    "paths": {
      "/billing": {
        "get": {
          "summary": "Get billing details",
          "x-mint": {
            "groups": ["admin", "billing"]
          },
          "responses": {
            "200": {
              "description": "Billing details"
            }
          }
        }
      }
    }
  }
  ```

  ```json {3-5} Chemin restreint
  {
    "paths": {
      "x-mint": {
        "groups": ["admin", "billing"]
      },
      "/billing": {
        "get": {
          "summary": "Get billing details",
        }
      },
      "/users": {
        "get": {
          "summary": "Get user details",
        }
      }
    }
  }
  ```
</CodeGroup>

<div id="filter-schema-properties">
  ### Filtrer les propriétés du schéma
</div>

Ajoutez `x-mint.groups` à des propriétés spécifiques dans les corps de requête, les paramètres ou les réponses. Les propriétés sans `x-mint.groups` restent visibles pour tous les utilisateurs.

```json {11-13} Restricted property
{
  "components": {
    "schemas": {
      "User": {
        "type": "object",
        "properties": {
          "name": {
            "type": "string"
          },
          "internal_id": {
            "type": "string",
            "x-mint": {
              "groups": ["admin"]
            }
          }
        }
      }
    }
  }
}
```

Dans cet exemple, tous les utilisateurs voient la propriété `name`. Seuls les utilisateurs du groupe `admin` voient la propriété `internal_id`.

<div id="filter-oneof-variants">
  ### Filtrer les variantes de `oneOf`
</div>

Ajoutez `x-mint.groups` à chaque option `oneOf` pour limiter les variantes de schéma visibles par l’utilisateur.

```json {7-9} Restricted oneOf variant
{
  "schema": {
    "oneOf": [
      {
        "title": "Enterprise config",
        "type": "object",
        "x-mint": {
          "groups": ["enterprise"]
        },
        "properties": {
          "sso_enabled": { "type": "boolean" }
        }
      },
      {
        "title": "Standard config",
        "type": "object",
        "properties": {
          "notifications": { "type": "boolean" }
        }
      }
    ]
  }
}
```

<div id="filter-enum-values">
  ### Filtrer les valeurs d’énumération
</div>

Utilisez l’extension `x-mint-enum` pour restreindre certaines valeurs d’énumération par groupe. Indiquez chaque valeur restreinte comme clé, et les groupes autorisés comme valeur. Les valeurs d’énumération qui ne figurent pas dans `x-mint-enum` sont visibles par tous les utilisateurs.

```json {4-7} Restricted enum values
{
  "type": "string",
  "enum": ["free", "pro", "enterprise"],
  "x-mint-enum": {
    "pro": ["pro", "enterprise"],
    "enterprise": ["enterprise"]
  }
}
```

Dans cet exemple, tous les utilisateurs voient `free`. Les utilisateurs des groupes `pro` ou `enterprise` voient `pro`. Seuls les utilisateurs du groupe `enterprise` voient `enterprise`.

<Note>
  `x-mint-enum` est une extension distincte de premier niveau dans l’objet de schéma, et non imbriquée sous `x-mint`.
</Note>

<div id="user-data-format">
  ## Format des données utilisateur
</div>

Votre système d’authentification renvoie des données utilisateur qui déterminent la personnalisation. Les champs `groups`, `content` et `apiPlaygroundInputs` décrits sur cette page font tous partie de l’objet de données utilisateur.

Pour consulter le format complet des données utilisateur et la référence des champs, voir [Format des données utilisateur](/fr/deploy/authentication-setup#user-data-format).

<div id="logout-behavior">
  ## Comportement de déconnexion
</div>

La déconnexion s’effectue côté client. Lorsque les utilisateurs cliquent sur le bouton de déconnexion, Mintlify efface les données de session enregistrées dans le navigateur.

Pour limiter la durée de conservation des données de personnalisation, définissez le champ `expiresAt` dans vos données utilisateur.
