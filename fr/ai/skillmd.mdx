Mintlify héberge un fichier `skill.md` à la racine de votre projet qui décrit ce que les agents IA peuvent faire avec votre produit.

La [spécification skill.md](https://agentskills.io/specification) est un format structuré et lisible par machine qui explicite les capacités, les entrées requises et les contraintes des produits afin que les agents puissent les utiliser de manière plus fiable.

Mintlify génère automatiquement un fichier `skill.md` pour votre projet en analysant votre documentation à l&#39;aide d&#39;une boucle agentique. Ce fichier reste à jour à mesure que vous modifiez votre documentation et ne nécessite aucune maintenance. Vous pouvez également ajouter un fichier `skill.md` personnalisé à la racine de votre projet pour remplacer celui généré automatiquement.

<Note>La génération ou la mise à jour d&#39;un fichier `skill.md` peut prendre jusqu&#39;à 24 heures.</Note>

Consultez votre `skill.md` en ajoutant `/skill.md` à l&#39;URL de votre site de documentation. Mintlify génère uniquement des fichiers `skill.md` pour les sites de documentation publics.

<PreviewButton href="https://mintlify.com/docs/skill.md">
  Ouvrir le skill.md de ce site
</PreviewButton>

<Tip>
  Les fichiers `llms.txt` et `skill.md` aident tous deux les agents à exploiter votre documentation, mais ils ont des rôles différents.

  * `llms.txt` est un répertoire. Il liste toutes les pages de votre documentation avec leur description afin que les agents sachent où trouver les informations.
  * `skill.md` est un résumé des capacités. Il indique aux agents ce qu&#39;ils peuvent accomplir avec votre produit, quelles entrées sont nécessaires et quelles contraintes s&#39;appliquent.
</Tip>

<div id="use-skillmd-files-with-agents">
  ## Utiliser les fichiers `skill.md` avec les agents
</div>

<Note>
  Si vous utilisez un [proxy inverse](/fr/deploy/reverse-proxy), configurez-le pour transférer les chemins `/skill.md`, `/.well-known/skills/*` et `/.well-known/agent-skills/*` vers votre sous-domaine Mintlify.
</Note>

Lorsque les utilisateurs se connectent à votre serveur MCP, leurs agents peuvent découvrir et utiliser vos fichiers `skill.md` comme [ressources MCP](/fr/ai/model-context-protocol#mcp-resources), sans avoir à installer les compétences séparément.

Pour ajouter manuellement vos compétences au contexte d’un agent, utilisez la [CLI skills](https://www.npmjs.com/package/skills).

```bash
npx skills add https://your-docs-domain.com
```

Cela ajoute les capacités de votre produit au contexte de l’agent afin qu’il puisse agir pour le compte des utilisateurs.

<Tip>
  Expliquez à vos utilisateurs comment utiliser les fichiers `skill.md` avec les agents afin qu’ils obtiennent de meilleurs résultats lorsqu’ils utilisent votre produit avec leurs outils d’IA.
</Tip>

<div id="skillmd-structure">
  ## Structure de `skill.md`
</div>

Mintlify génère un fichier `skill.md` conformément à la [spécification agentskills.io](https://agentskills.io/specification). Le fichier généré comprend :

* **Métadonnées** : nom du projet, description et version.
* **Capacités** : ce que les agents peuvent accomplir avec votre produit.
* **Compétences** : actions spécifiques organisées par catégorie.
* **Flux de travail** : procédures étape par étape pour les tâches courantes.
* **Intégration** : outils et services pris en charge.
* **Contexte** : contexte sur l&#39;architecture de votre produit.

<div id="custom-skill-files">
  ## Fichiers de compétences personnalisés
</div>

Ajoutez des fichiers de compétences personnalisés pour remplacer le fichier `skill.md` généré automatiquement. Mintlify permet d’héberger un fichier de compétences unique ainsi qu’un répertoire contenant plusieurs compétences. Si vous supprimez tous les fichiers de compétences personnalisés, Mintlify génère un nouveau fichier `skill.md`.

<div id="single-skill-file">
  ### Un seul fichier `skill`
</div>

Ajoutez un fichier `skill.md` à la racine de votre projet pour remplacer le fichier généré automatiquement.

<div id="multiple-skill-files">
  ### Plusieurs fichiers de compétences
</div>

Ajoutez plusieurs fichiers de compétences dans le répertoire `.mintlify/skills/` de votre projet. Chaque compétence doit se trouver dans son propre sous-répertoire et contenir un fichier `SKILL.md` :

```
.mintlify/
  skills/
    payments/
      SKILL.md
    analytics/
      SKILL.md
```

Lorsque vous avez plusieurs compétences, le point de terminaison `/skill.md` redirige vers le point de terminaison de découverte `/.well-known/skills/index.json`, qui répertorie toutes les compétences disponibles. Les points de terminaison de découverte rendent chaque compétence accessible individuellement.

<Note>
  Vous pouvez utiliser les deux approches ensemble avec un fichier `skill.md` à la racine et un répertoire `.mintlify/skills/`. L’index de découverte inclut toutes les compétences.
</Note>

<div id="use-symlinks-to-avoid-duplication">
  ### Utilisez des liens symboliques pour éviter les doublons
</div>

Si vos fichiers de compétences se trouvent ailleurs dans votre dépôt (par exemple, dans un répertoire `plugins/` ou `skills/`), vous pouvez créer un lien symbolique de `.mintlify/skills` vers cet emplacement au lieu de dupliquer les fichiers :

```bash
# Les skills se trouvent dans un répertoire skills/ à la racine du projet
ln -s ../skills .mintlify/skills
```

```
project/
  skills/
    payments/
      SKILL.md
    analytics/
      SKILL.md
  .mintlify/
    skills -> ../skills
  docs.json
```

Mintlify résout les liens symboliques lors du déploiement, de sorte que les fichiers de compétence sont détectés et servis comme s’ils se trouvaient directement dans `.mintlify/skills/`. Cela fonctionne aussi bien avec des liens symboliques vers des répertoires qu’avec des liens symboliques vers des compétences individuelles.

<div id="frontmatter-fields">
  ### Champs de métadonnées d’en-tête
</div>

Les fichiers `skill.md` personnalisés doivent commencer par un bloc de métadonnées d’en-tête YAML.

| Champ           | Type   | Description                                                                                                                |
| --------------- | ------ | -------------------------------------------------------------------------------------------------------------------------- |
| `name`          | string | Le nom de votre compétence.                                                                                                |
| `description`   | string | Une brève description de ce que fait votre compétence.                                                                     |
| `license`       | string | La licence de votre compétence (par exemple, `MIT` ou `Apache-2.0`).                                                       |
| `compatibility` | string | Exigences ou notes de compatibilité (par exemple, dépendances d’exécution).                                                |
| `metadata`      | object | Métadonnées supplémentaires sous forme de paires clé-valeur de chaînes de caractères (par exemple, `author` ou `version`). |
| `allowed-tools` | string | Liste d’outils préapprouvés, séparés par des espaces, que la compétence peut utiliser (expérimental).                     |

```md Example frontmatter
---
name: mintlify
description: Build and maintain documentation sites with Mintlify. Use when creating docs pages, configuring navigation, adding components, or setting up API references.
license: MIT
compatibility: Requires Node.js for CLI. Works with any Git-based workflow.
metadata:
  author: mintlify
  version: "1.0"
---
```

<div id="skills-discovery-endpoints">
  ## Points de terminaison de découverte des compétences
</div>

Mintlify héberge des répertoires de compétences à l’emplacement `/.well-known/skills/` et `/.well-known/agent-skills/`, que les agents peuvent utiliser pour découvrir et récupérer automatiquement vos fichiers de compétences.

<div id="agent-skills-discovery-recommended">
  ### Découverte des agent-skills (recommandée)
</div>

Le point de terminaison `/.well-known/agent-skills/` suit la [spécification de découverte agent-skills 0.2.0](https://schemas.agentskills.io/discovery/0.2.0/schema.json) et comprend une vérification de l’intégrité du contenu.

`GET /.well-known/agent-skills/index.json` renvoie un manifeste JSON qui répertorie toutes les compétences disponibles :

```json
{
  "$schema": "https://schemas.agentskills.io/discovery/0.2.0/schema.json",
  "skills": [
    {
      "name": "my-product",
      "type": "skill-md",
      "description": "A brief description of what your skill does.",
      "url": "/.well-known/agent-skills/my-product/SKILL.md",
      "digest": "sha256:a1b2c3..."
    }
  ]
}
```

| Champ         | Description                                                                                                 |
| ------------- | ----------------------------------------------------------------------------------------------------------- |
| `$schema`     | URL du schéma pour la spécification de découverte agent-skills 0.2.0.                                       |
| `name`        | Un slug compatible avec les URL, dérivé du champ `name` dans les métadonnées d’en-tête de votre `skill.md`. |
| `type`        | Le format de la compétence. Toujours `skill-md`.                                                            |
| `description` | Une brève description issue des métadonnées d’en-tête de votre `skill.md`, tronquée à 1024 caractères.      |
| `url`         | Le chemin permettant de récupérer le fichier de compétence complet.                                         |
| `digest`      | Un hachage `sha256` du contenu du fichier de compétence pour vérifier son intégrité.                        |

`GET /.well-known/agent-skills/{name}/SKILL.md` renvoie le fichier `skill.md` d’une compétence spécifique, identifiée par le slug de son nom dans l’index.

<div id="skills-index">
  ### Index des compétences
</div>

Le point de terminaison `/.well-known/skills/` correspond au format de découverte initial.

`GET /.well-known/skills/index.json` renvoie un manifeste JSON qui répertorie toutes les compétences disponibles :

```json
{
  "skills": [
    {
      "name": "my-product",
      "description": "A brief description of what your skill does.",
      "files": ["SKILL.md"]
    }
  ]
}
```

Le champ `name` est un slug utilisable dans une URL, dérivé du `name` dans les métadonnées d’en-tête de votre `skill.md`.

<div id="individual-skill-files">
  ### Fichiers de compétences individuels
</div>

`GET /.well-known/skills/{name}/skill.md` renvoie le fichier `skill.md` d’une compétence spécifique, identifiée par son nom converti en slug dans l’index.
