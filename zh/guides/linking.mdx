链接能将文档组织成一个连贯的整体。它们可以帮助用户发现相关内容、高效导航，并按照清晰的逻辑路径理解复杂主题。糟糕的链接——例如含糊的锚文本、缺失的交叉引用或失效的 URL——会让文档更难使用，也会影响 SEO。

本指南介绍如何在 Mintlify 中创建不同类型的链接，以及如何随着文档规模扩大持续维护链接完整性。

<div id="internal-links">
  ## 内部链接
</div>

使用根相对路径链接到文档中的其他页面。根相对路径从文档目录的根目录开始，无论链接页面在目录结构中的哪个位置，都能稳定生效。

```mdx
- [Quickstart guide](/quickstart)
- [API overview](/api-playground/overview)
- [Custom components](/customize/react-components)
```

避免使用像 `../api-playground/overview` 这样的相对路径——页面一旦移动，这些路径就会失效，而且在评审时也不便于快速浏览。

<div id="anchor-links">
  ## 锚点链接
</div>

锚点链接可指向页面中的特定章节。每个标题都会根据其文本自动生成一个锚点。

<div id="link-to-headers-on-the-same-page">
  ### 链接到同一页面中的标题
</div>

使用井号 (#) 引用当前页面中的标题：

```mdx
[Jump to best practices](#best-practices)
```

<div id="link-to-headers-on-other-pages">
  ### 链接到其他页面的标题
</div>

将页面路径与锚点结合：

```mdx
- [Customize your playground](/api-playground/overview#customize-your-playground)
- [Cards properties](/components/cards#properties)
```

<div id="how-mintlify-generates-anchors">
  ### Mintlify 如何生成锚点
</div>

Mintlify 会根据标题文本自动生成锚点：将文本转换为小写、将空格替换为连字符，并移除特殊字符。

| 标题文本                     | 生成的锚点                 |
| ------------------------ | --------------------- |
| `## Getting Started`     | `#getting-started`    |
| `### API Authentication` | `#api-authentication` |
| `#### Step 1: Install`   | `#step-1-install`     |

<Note>
  带有 `noAnchor` 属性的标题不会生成锚点链接。详情请参阅[设置文本格式](/zh/create/text#disabling-anchor-links)。
</Note>

<div id="custom-anchor-ids">
  ### 自定义锚点 ID
</div>

在标题文本后添加 `{#custom-id}`，即可覆盖任意标题自动生成的锚点：

```mdx
## Configuration options {#config}
```

此标题的链接可以使用 `#config`，而不是 `#configuration-options`。自定义 ID 能在你修改标题文本时保持锚点链接稳定，这对那些你经常链接的标题尤其有用。更多信息，请参阅[设置文本格式](/zh/create/text#custom-heading-ids)。

<div id="deep-links">
  ## 深层链接
</div>

深层链接会指向页面内的特定状态或位置，而不只是该页面本身。

<div id="accordion-deep-links">
  ### Accordion 深层链接
</div>

当用户展开某个 Accordion 时，URL hash 会更新，以反映其展开状态。访问带有该 hash 的 URL 时，会自动展开并滚动到该 Accordion。

默认情况下，hash 来自 Accordion 的 `title`。使用 `id` 属性可设置自定义 hash：

```mdx
<Accordion title="Installation steps" id="install">
  ...
</Accordion>
```

此 Accordion 可通过 `#install` 访问，而不是自动生成的 `#installation-steps`。更多信息，请参阅 [Accordions](/zh/components/accordions)。

<div id="api-playground-deep-links">
  ### API 操场深层链接
</div>

要通过链接直接打开 API 操场，请在任意端点页面的 URL 后追加 `?playground=open`：

```text
https://your-docs-url/endpoint-path?playground=open
```

当用户打开或关闭操场时，URL 会随之更新。在支持对话或引导流程中使用操场深层链接，可将用户直接带到某个端点的交互式操场。有关参数锚点链接的信息，请参阅 [API 操场](/zh/api-playground/overview#parameter-anchor-links)。

<div id="external-links">
  ## 外部链接
</div>

链接到外部资源时，请使用能清楚说明目标页面的锚文本：

```mdx
See the [OpenAPI specification](https://swagger.io/specification/) in the Swagger documentation for details.
```

<div id="best-practices">
  ## 最佳实践
</div>

<div id="write-descriptive-anchor-text">
  ### 编写具有描述性的锚文本
</div>

锚文本应在用户点击前清楚说明链接将指向何处。像“点击这里”或“阅读更多”这类模糊表述，相比描述性文本，传达的 SEO 信号也更弱。

<CodeGroup>
  ```mdx Good
  有关更多信息，请参阅 [隐藏页面](/organize/hidden-pages)。
  [配置自定义域名](/customize/custom-domain)
  ```

  ```mdx Avoid
  [点击这里](/api-playground/overview)
  [阅读更多](/deploy/deployments)
  [查看此页面](/customize/custom-domain)
  ```
</CodeGroup>

<div id="link-prerequisites-explicitly">
  ### 明确链接前置步骤
</div>

如果某个页面以前面的步骤为前提，请在页面顶部添加这些步骤的链接，而不要假设用户会自己找到：

```mdx
## Prerequisites

Before deploying your documentation, ensure you have:

- Completed the [quickstart guide](/quickstart)
- Configured your [custom domain](/customize/custom-domain)
- Set up [authentication](/deploy/authentication-setup) if needed
```

<div id="build-topic-clusters">
  ### 构建主题集群
</div>

将相关内容相互链接，帮助用户和搜索引擎理解你的文档是如何组织的：

```mdx
## Related topics

- [API authentication](/api-playground/overview#authentication)
- [Adding SDK examples](/api-playground/adding-sdk-examples)
- [Managing page visibility](/api-playground/managing-page-visibility)
```

<div id="check-for-broken-links">
  ### 检查失效链接
</div>

在发布前运行 Mintlify CLI，以检查内部和外部链接是否失效：

```bash
mint broken-links
```

<div id="update-links-when-reorganizing">
  ### 重新整理内容时更新链接
</div>

移动或重命名页面时：

1. 在导航配置中更新页面路径。
2. 配置从旧路径到新路径的重定向。
3. 在文档中搜索所有对旧路径的引用。
4. 将所有内部链接更新为使用新路径。
5. 运行 `mint broken-links` 进行检查。

<div id="use-redirects-for-moved-content">
  ### 为已迁移的内容设置重定向
</div>

当内容被永久迁移后，请添加重定向，避免已收藏或分享旧 URL 的用户遇到失效链接。

```json
{
  "redirects": [
    {
      "source": "/old-path",
      "destination": "/new-path"
    }
  ]
}
```

更多信息，请参阅 [重定向](/zh/create/redirects)。

<div id="frequently-asked-questions">
  ## 常见问题
</div>

<AccordionGroup>
  <Accordion title="内部链接应该使用根相对 URL 还是绝对 URL？">
    对于 Mintlify 中的内部链接，正确的选择是根相对路径 (以 `/` 开头) 。无论添加链接的页面位于目录中的哪个位置，它都能稳定生效；即使文档域名发生变化，也不会失效。对内部链接使用绝对 URL 只会增加不必要的脆弱性。
  </Accordion>

  <Accordion title="更新标题时，如何保持锚点链接稳定？">
    对于经常被链接到的标题，请使用自定义锚点 ID。给标题追加 `{#custom-id}` 后，锚点就会与标题文本解耦，因此即使你更新标题文本，也不会破坏任何指向它的链接。这对访问量较高的参考文档章节尤其有用，因为这些标题的文本往往需要随着时间推移不断调整。
  </Accordion>

  <Accordion title="重新组织文档后，已收藏的链接会怎样？">
    如果没有重定向，已收藏和已分享的链接就会变成 404 错误。每当你移动或重命名页面时，都应在 `docs.json` 中设置重定向。添加重定向的成本很低，却能避免给那些从外部来源链接到你文档的用户带来糟糕体验——例如博客文章、Stack Overflow 回答或内部 wiki。
  </Accordion>

  <Accordion title="一个页面应该有多少个内部链接？">
    当某个相关概念在当前场景下确实对用户有帮助时，就添加链接，而不是为了凑数量。链接太少，用户会缺少上下文或不知道下一步该做什么；链接太多，则会让页面变成一场导航练习，把用户从当前要完成的任务中分散开。一个大致的经验是：在概念或工具第一次出现时添加链接，不要在同一页面里多次重复添加相同的链接。
  </Accordion>
</AccordionGroup>
