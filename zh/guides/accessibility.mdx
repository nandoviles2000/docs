创建无障碍文档时，你应优先考虑一种内容设计方式：无论用户以何种方式访问或与文档交互，都能让尽可能多的人顺畅使用你的文档。

无障碍文档能够提升所有人的用户体验。你的内容会更清晰、结构更合理，也更便于浏览和导航。

本指南提供了一些创建无障碍文档的最佳实践，但并不全面。你应将无障碍视为一个持续推进的过程。技术和标准会随着时间推移而变化，这也会带来改进文档的新机会。

<div id="what-is-accessibility">
  ## 什么是无障碍？
</div>

无障碍 (有时缩写为 a11y，表示 “accessibility” 一词首尾字母之间的字母数) 是指在设计和构建网站与工具时，有意识地确保尽可能多的人都能使用。暂时性或永久性残障人士应当享有同等水平的数字技术访问权。而且，按无障碍原则进行设计会让所有人受益，包括通过移动设备或在网络较慢时访问你网站的人。

无障碍文档应遵循 Web 无障碍标准，主要是 [Web Content Accessibility Guidelines (WCAG)](https://www.w3.org/WAI/WCAG22/quickref/)。这些指南有助于确保你的内容具备可感知性、可操作性、可理解性和健壮性。

<div id="getting-started-with-accessibility">
  ## 开始着手提升无障碍
</div>

让文档具备良好的无障碍是一个持续推进的过程。你不必一次性解决所有问题，而且这也不是做一次就能完成的。

如果你刚开始在文档中落实无障碍实践，建议采用分阶段的方法，先从影响最大的改动入手，再逐步推进。

<div id="first-steps">
  ### 入门步骤
</div>

以下是你现在就可以采取的三项措施，用于提升文档的无障碍性：

1. **运行 `mint a11y`**，识别内容中的无障碍问题。
2. **为所有图片添加替代文本**。
3. **检查标题层级结构**，确保每个页面只有一个 H1，且各级标题按顺序排列。

<div id="plan-your-accessibility-work">
  ### 规划无障碍工作
</div>

最适合的工作流，就是适合你团队的工作流。下面提供一种开展无障碍工作的思路：

**第 1 阶段：图片与结构**

* 检查所有图片是否都提供了描述性的替代文本。
* 审核链接文本，避免使用“点击这里”之类的笼统说法。
* 修正文档中的标题层级问题。

**第 2 阶段：导航与媒体**

* 测试文档的键盘导航。
* 测试对屏幕阅读器的支持。
* 为嵌入的视频添加字幕和文字稿。
* 检查颜色对比度。

**第 3 阶段：将无障碍纳入工作流**

* 发布新内容前运行 `mint a11y`。
* 在内容审核流程中加入无障碍检查。
* 添加交互功能时测试键盘导航。
* 验证新的外部链接和嵌入内容是否包含合适的标题和描述。

从小处着手，并把无障碍纳入日常工作流，才能更容易长期坚持。每一项改进，都能帮助更多用户顺利访问你的文档。

<div id="structure-your-content">
  ## 组织内容
</div>

结构清晰的内容更便于浏览和理解，尤其有助于依靠标题在页面中跳转的屏幕阅读器用户，以及使用键盘导航的用户。

<div id="use-proper-heading-hierarchy">
  ### 使用正确的标题层级
</div>

每个页面都应只有一个 H1 标题，它由该页面 frontmatter 中的 `title:` 属性定义。其他标题也应按顺序使用，不要跳级。例如，不要从 H2 直接跳到 H4。

```mdx
<!-- 正确 -->
# 页面标题 (H1)

## 主要章节 (H2)

### 子章节 (H3)

### 另一个子章节 (H3)

## 另一个主要章节 (H2)

<!-- 错误 -->
# 页面标题 (H1)

## 主要章节 (H2)

#### 子章节 (H4)

### 另一个子章节 (H3)
```

同一级标题的名称应保持唯一。

```mdx
<!-- 正确 -->
## 无障碍提示 (H2)

### 编写有效的替代文本 (H3)

### 使用适当的颜色对比度 (H3)

<!-- 错误 -->
## 无障碍提示 (H2)

### Tip (H3)

### Tip (H3)
```

<div id="write-descriptive-link-text">
  ### 编写描述性的链接文本
</div>

链接文本应清晰明确，并与目标页面相关。避免使用像 &quot;click here&quot; 或 &quot;read more&quot; 这样的含糊表述。

```mdx
<!-- 好的示例 -->
Learn how to [configure your navigation](/organize/navigation).

<!-- 链接文本与目标页面关联不明确 -->
[Learn more](/organize/navigation).
```

<div id="keep-content-scannable">
  ### 保持内容清晰易读
</div>

* 将长段落拆开。
* 用列表呈现步骤和选项。
* 使用提示框突出关键信息。

<div id="use-proper-table-structure">
  ### 使用正确的表格结构
</div>

谨慎使用表格，仅在数据的含义依赖于行标题和列标题时才使用表格。

使用表格时，请添加标题行，以便屏幕阅读器能够将数据与对应的列关联起来：

```mdx
| Feature | Status |
| ------- | ------ |
| Search  | Active |
| Analytics | Active |
```

<div id="write-descriptive-alt-text">
  ## 编写清晰的替代文本
</div>

替代文本可帮助使用屏幕阅读器的用户理解图像内容，也会在图像加载失败时显示。在文档中，图像应包含替代文本，既要描述图像内容，也要清楚说明插入这张图像的原因。即使有替代文本，你也不应只依赖图像来传达信息。请确保你的正文内容也能说明图像所传达的信息。

<div id="write-effective-alt-text">
  ### 编写有效的替代文本
</div>

* **具体明确**：描述图片展示的内容，而不只是说明这是一张图片。
* **简明扼要**：尽量控制在一到两句话内。
* **避免冗余**：不要以 &quot;Image of&quot; 开头，因为屏幕阅读器已经知道替代文本对应的是图片。不过，如果这些上下文信息对理解图片很重要，你应该加上 &quot;Screenshot of&quot; 或 &quot;Diagram of&quot; 这类描述。

```mdx
<!-- 好的示例 -->
![Screenshot of the dashboard showing three active projects and two pending invitations](/images/dashboard.png)

<!-- 不够清晰 -->
![Dashboard screenshot](/images/dashboard.png)
```

<div id="add-alt-text-to-images">
  ### 为图片添加 替代文本
</div>

对于 Markdown 图片，请在方括号中添加 替代文本：

```mdx
![Description of the image](/path/to/image.png)
```

对于 HTML 中的图片，请使用 `alt` 属性：

```html
<img
  src="/images/screenshot.png"
  alt="Settings panel with accessibility options enabled. The options are emphasized with an orange rectangle."
/>
```

<div id="add-titles-to-embedded-content">
  ### 为嵌入内容添加标题
</div>

iframe 和嵌入式视频需要添加描述性标题：

```html
<iframe
  src="https://www.youtube.com/embed/example"
  title="Tutorial: Setting up your first documentation site"
></iframe>
```

<div id="design-for-readability">
  ## 为提升可读性而设计
</div>

视觉设计上的选择会影响低视力、色盲或其他视力障碍用户阅读和使用文档的难易程度。

<div id="ensure-sufficient-color-contrast">
  ### 确保足够的颜色对比度
</div>

如果您自定义了主题颜色，请确认对比度符合 WCAG 要求：

* 正文文本：最低对比度为 4.5:1
* 大号文本：最低对比度为 3:1
* 交互元素：最低对比度为 3:1

请同时测试浅色模式和深色模式。`mint a11y` 命令会检查颜色对比度。

<div id="dont-rely-on-color-alone">
  ### 不要只依赖颜色
</div>

如果你使用颜色传达信息，也要同时添加文字标签或图标。例如，不要只用红色文本来标示错误。请添加错误图标或“错误”字样。

<div id="use-clear-concise-language">
  ### 使用清晰简洁的语言
</div>

* 使用浅显易懂的语言。
* 首次使用技术术语时，先进行解释。
* 避免使用冗长的句子。
* 使用主动语态。

<div id="make-code-examples-accessible">
  ## 让代码示例更易于理解和访问
</div>

代码块是技术文档的重要组成部分，但为了确保使用屏幕阅读器的用户也能理解其内容，你需要特别关注无障碍性。通常，请遵循以下准则：

* 将较长的代码示例拆分成更小、更有逻辑的片段。
* 在代码中为复杂逻辑添加注释。
* 对于复杂算法，考虑提供文字说明。
* 展示文件结构时，请使用带语言标签的代码块，而不要使用 ASCII 图示。

<div id="specify-the-programming-language">
  ### 指定编程语言
</div>

请始终声明用于语法高亮的语言。这有助于屏幕阅读器向用户说明代码的上下文：

````mdx
```javascript
function getUserData(id) {
  return fetch(`/api/users/${id}`);
}
```
````

<div id="provide-context-around-code">
  ### 为代码提供上下文说明
</div>

为代码块提供清晰的上下文说明：

````mdx
以下函数从 API 获取用户数据：

```javascript
function getUserData(id) {
  return fetch(`/api/users/${id}`);
}
```

这将返回一个解析为用户对象的 Promise。
````

<div id="video-and-multimedia-accessibility">
  ## 视频与多媒体无障碍
</div>

视频、动画和其他多媒体内容都需要提供文本替代形式，以便所有用户都能获取其中的信息。

<div id="add-captions-to-videos">
  ### 为视频添加字幕
</div>

字幕可让失聪或听力障碍用户更方便地获取视频内容，也能帮助处于需保持安静环境中的用户以及非母语使用者：

* 为视频中所有口述内容添加字幕。
* 在字幕中加入相关音效说明。
* 确保字幕与音频同步。
* 多人发言时，使用恰当的标点，并标明说话者身份。

大多数视频托管平台都支持添加字幕。你可以上传字幕文件，或先使用自动生成的字幕，再检查其准确性。

<div id="provide-transcripts">
  ### 提供文字稿
</div>

文字稿为访问视频内容提供了另一种方式。它们支持搜索、更便于引用，也兼容屏幕阅读器：

```mdx
<iframe
  src="https://www.youtube.com/embed/example"
  title="Tutorial: Setting up authentication"
></iframe>

<Accordion title="Video transcript">
In this tutorial, we'll walk through setting up authentication...
</Accordion>
```

将文字稿放在视频旁边，或提供清晰易见的访问链接。

<div id="consider-alternatives-to-video-only-content">
  ### 考虑使用纯视频内容以外的替代形式
</div>

如果关键信息只出现在视频中：

* 以文本形式提供相同的信息。
* 添加带有描述性替代文本的关键截图。
* 编写涵盖相同内容的文字教程。

这样可以确保无法访问视频内容的用户仍然能够完成任务。

<div id="test-your-documentation">
  ## 测试你的文档
</div>

定期测试有助于你在用户遇到无障碍问题之前及时发现问题。

<div id="check-for-accessibility-issues-with-mint-a11y">
  ### 使用 `mint a11y` 检查无障碍问题
</div>

使用 `mint a11y` CLI 命令可自动扫描文档中常见的无障碍问题：

```bash
mint a11y
```

该命令会检查以下问题：

* 图片和视频是否缺少替代文本。
* 颜色对比度是否不足。

扫描完成后，请查看报告中的问题，并在内容中修复。然后再次运行该命令，验证修复结果。

使用标志检查特定的无障碍问题。

```bash
# 仅检查缺失的替代文本
mint a11y --skip-contrast

# 仅检查颜色对比度问题
mint a11y --skip-alt-text
```

<div id="basic-keyboard-navigation-test">
  ### 基本键盘导航测试
</div>

仅使用键盘浏览你的文档：

1. 按 <kbd>Tab</kbd> 键在交互元素之间向前移动。
2. 按 <kbd>Shift</kbd> + <kbd>Tab</kbd> 键向后移动。
3. 按 <kbd>Enter</kbd> 键激活链接和按钮。
4. 确认所有交互元素都可通过键盘访问，并且具有可见的焦点指示器。

<div id="go-deeper-with-accessibility-testing">
  ### 进一步开展无障碍测试
</div>

如需进行更全面的测试：

* **屏幕阅读器**：使用 [NVDA (Windows)](https://www.nvaccess.org/) 或 [VoiceOver (Mac)](https://www.apple.com/accessibility/voiceover/) 进行测试。
* **浏览器扩展**：安装 [axe DevTools](https://www.deque.com/axe/browser-extensions/) 或 [WAVE](https://wave.webaim.org/extension/) 来扫描页面并发现问题。
* **WCAG 指南**：查阅 [Web Content Accessibility Guidelines](https://www.w3.org/WAI/WCAG22/quickref/)，了解详细标准。
