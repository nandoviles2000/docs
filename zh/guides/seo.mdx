搜索引擎是用户查找文档最可靠的渠道之一。当有人搜索“如何为[你的产品]设置身份验证”时，优化良好的文档能让你的内容排在搜索结果前列，而不是让 Stack Overflow 上的帖子或竞争对手的页面占据更靠前的位置。

本指南介绍了对文档 SEO 影响最大的技巧，从撰写更优的页面标题到制定易于维护的内部链接策略。

<div id="write-page-titles-and-descriptions-that-rank">
  ## 撰写有利于排名的页面标题和描述
</div>

页面标题是页面中最重要的 SEO 信号。它们能让搜索引擎和用户准确了解页面涵盖的内容。

<div id="titles-50-60-characters">
  ### 标题 (50-60 个字符)
</div>

标题要贴合用户的搜索方式，而不是产品 UI 中的功能名称。“身份验证”是产品标签，“如何对 API 请求进行身份验证”则是搜索查询。

* 匹配用户意图：适当使用“如何”“指南”或“参考”
* 将主要关键词尽量放在标题靠前的位置
* 确保每个标题都唯一——重复标题会让搜索引擎感到困惑

<div id="descriptions-130-160-characters">
  ### 描述 (130-160 个字符)
</div>

描述会显示在搜索结果中页面标题下方。即使排名相同，好的描述也能提高点击率。

* 概括用户将能完成什么，而不只是页面介绍了什么内容
* 自然包含主要关键词
* 使用主动表达：“了解如何配置……”而不是“本页将解释……”

Mintlify 会根据你的 `title` 和 `description` frontmatter 自动生成 meta 标签。有关 Open Graph 图片、规范化 URL 或自定义 robots 指令等高级配置，请参阅 [SEO 配置参考](/zh/optimize/seo)。

<div id="do-keyword-research-for-your-docs">
  ## 为你的文档做关键词研究
</div>

关键词研究能帮助你了解，用户在查找你的文档所涵盖的内容时，实际会输入哪些词。

**从你自己的数据入手：** 如果你已将 [Google Search Console](https://search.google.com/search-console) 连接到你的文档，请查看“Search results”报告。最值得优化的目标，是那些用户已经通过其找到你的查询，以及那些你已经获得展示、但排名不够理想的查询。

**查找相关查询：** [Google Keyword Planner](https://ads.google.com/intl/en_us/home/tools/keyword-planner/) 和 [Ahrefs Free Keyword Generator](https://ahrefs.com/keyword-generator) 等免费工具，可以显示某个短语的搜索量，并推荐相关词条。

<div id="apply-keywords-where-they-belong">
  ### 在合适的位置使用关键词
</div>

* 页面标题和描述 (影响最大)
* H2 和 H3 标题
* 页面的首段
* 相关图片的 Alt 文本

不要机械地重复关键词。文档应该读起来自然流畅。如果某个标题显得很生硬，说明这个关键词并不适合这一部分。

<div id="structure-content-with-headings-search-engines-can-parse">
  ## 使用搜索引擎可识别的标题来组织内容
</div>

标题结构有两个作用：既能帮助用户快速浏览页面，也能让搜索引擎理解各个主题之间的关系。

Mintlify 会根据你的 frontmatter 中的 `title:` 属性自动为每个页面生成 H1。不要在页面正文中手动添加 H1。其余内容请使用 H2 及以下级别的标题来组织：

```mdx
## Main section (H2)

### Subsection (H3)

#### Detail (H4, use sparingly)
```

**将标题写成问题句或意图短语。** 对比一下：

| 较弱的标题 | 更强的标题       |
| ----- | ----------- |
| 身份验证  | 身份验证的工作原理   |
| 速率限制  | 了解 API 速率限制 |
| 配置    | 如何配置你的集成    |

写成问题句的标题更有可能出现在 Google 的“People Also Ask”框中。这类内容会显示在自然搜索结果上方，即使页面排名较低，也能带来点击。

<div id="build-internal-links-between-related-pages">
  ## 在相关页面之间建立内部链接
</div>

内部链接对 SEO 有两方面作用：一是帮助搜索引擎发现并理解你的内容，二是在页面之间传递排名权重。

在内容中**链接到相关概念**。当你在解释某个概念，而它又依赖于另一个概念时，请使用描述性的锚文本链接到该概念：

```mdx
<!-- 良好示例 -->
Learn how to [configure your sitemap](/optimize/seo#sitemaps-and-robots-txt-files).

<!-- 对 SEO 无益 -->
[Click here](/optimize/seo) to learn more.
```

**查找孤立页面：** 没有任何内部链接指向的页面就是孤立页面。对于没有从站内任何位置链接到的页面，搜索引擎更难发现，也更难给予较高排名。每月检查一次你的导航，有助于及时发现这类页面。

**创建主题集群：** 将相关页面归类组织，并在它们之间建立链接。入门页面应链接到身份验证参考文档，后者再链接到 API 密钥页面，而该页面再回链到概览页面。这会向搜索引擎表明，这些页面围绕的是同一个连贯主题。

<div id="add-alt-text-to-images">
  ## 为图片添加替代文本
</div>

替代文本对无障碍访问和 SEO 都很重要。搜索引擎无法理解图片，因此图片内容需要通过替代文本来为页面的相关性信号做出贡献。

编写替代文本时，请结合上下文描述图片展示的内容：

```mdx
<!-- 具体且描述性强 -->
![API authentication flow showing the token exchange between client, auth server, and API](/images/auth-flow.png)

<!-- 过于笼统 -->
![Diagram](/images/auth-flow.png)
```

在 alt 文本中自然地加入相关关键词。不要添加无法描述图片内容的关键词。

<div id="technical-seo-mintlify-handles-automatically">
  ## Mintlify 自动处理的技术 SEO
</div>

Mintlify 会自动处理多项技术 SEO 基础工作：

* **站点地图生成：** `sitemap.xml` 会自动生成并更新。你可以将其直接提交到 [Google Search Console](https://search.google.com/search-console)，以加快收录。
* **语义化 HTML：** 页面会以规范的 HTML 结构进行渲染，包括标题层级和导航地标。
* **移动端优化：** 文档默认采用响应式设计。
* **规范 URL：** 系统会自动生成规范标签，以避免重复内容问题。

对于需要手动配置的内容——全局元标签、单页覆盖、自定义站点地图、索引规则——请参阅 [SEO 配置参考](/zh/optimize/seo)。

<div id="keep-documentation-current">
  ## 保持文档内容为最新
</div>

搜索引擎会将内容的新鲜度视为排名信号，尤其是对于涵盖会随时间变化主题的页面 (如 API 参考、配置指南、集成说明) 。

一种实用的做法：

* 发布功能更新时，在同一个拉取请求 (PR) 中同步更新对应文档
* 每季度检查一次高流量页面，确保内容准确
* 发布前使用 `mint broken-links` 检查失效链接

<Tip>
  使用[工作流](/zh/agent/workflows)自动执行 SEO 维护任务。
</Tip>

过时的文档除了会影响 SEO，还会带来另一个问题：如果用户通过搜索找到你的页面，却发现其中的信息有误，他们就会失去对文档的信任。

<div id="monitor-your-search-performance">
  ## 监控你的搜索效果
</div>

为你的文档域名设置 [Google Search Console](https://search.google.com/search-console)。它可以向你显示：

* **展示次数和点击次数：** 哪些页面会出现在搜索结果中，以及用户点击这些页面的频率
* **平均排名：** 你的页面在特定查询中的排名位置
* **查询：** 带来流量的具体搜索词，有助于发现新的优化机会

建议每月检查一次，并优先处理展示次数高但点击次数低的页面 (说明你的标题或描述不够吸引人) ，以及针对重要查询排名较低的页面 (内容深度可能需要改进) 。

<div id="frequently-asked-questions">
  ## 常见问题
</div>

<AccordionGroup>
  <Accordion title="从 SEO 的角度看，文档页面应该写多长？">
    没有统一的理想长度。页面既要足够长，能够完整覆盖主题；也要足够精炼，保持内容聚焦。一篇入门指南可能是 800 字，一份详细的 API 参考 可能达到 3,000 字。真正重要的是，用户能否只靠这个页面就完成目标——如果他们还得离开页面去查找更多信息，那这个页面很可能内容过于单薄。一般来说，不到 300 字的页面很难在竞争激烈的查询中获得排名，因为它们无法体现主题深度。
  </Accordion>

  <Accordion title="文档 SEO 和博客 SEO 的做法不一样吗？">
    核心原则是一样的。相关的标题、结构清晰的内容和内部链接都很重要。不过，文档也有一些独特优势。文档页面通常针对非常具体的长尾查询 (例如“如何为 [product] 配置 OAuth&quot;) ，这类查询的竞争通常比普通博客主题更小。开发者在 Stack Overflow 回答、GitHub issue 和社区论坛中分享这些页面时，它们也会自然获得链接。与其追求数量，不如优先保证内容的具体性和准确性。
  </Accordion>

  <Accordion title="如何将我的文档站点地图提交到 Google？">
    在 [Google Search Console](https://search.google.com/search-console) 中，前往左侧边栏的 **Sitemaps**，然后输入你的站点地图 URL。对于 Mintlify 文档，站点地图地址为 `https://your-docs-domain.com/sitemap.xml`。提交站点地图并不能保证立即被索引，但可以加快发现速度，并帮助 Google 理解你的网站结构。
  </Accordion>

  <Accordion title="为了 SEO，我应该多久更新一次文档？">
    只要产品发生变化，就应更新文档——准确性是最重要的信号。就 SEO 而言，超过一年未更新的页面通常值得重新审查，以补充缺失信息、更新示例，并扩展内容较薄弱的部分。你可以使用 Google Search Console 来确定优先级：流量下降或排名下滑的页面，都是适合刷新的对象。
  </Accordion>

  <Accordion title="SEO 和 GEO 有什么区别？">
    SEO (搜索引擎优化) 侧重于在 Google 和 Bing 等传统搜索引擎中获得排名。GEO (生成式引擎优化) 则侧重于被 ChatGPT、Perplexity 和 Google AI Overviews 等 AI 驱动工具引用。两者的基本原则有重叠——准确且结构清晰的内容通常在两者中都表现良好——但 GEO 还包括一些额外做法，重点是让内容格式更便于 AI 解析。详情请参阅 [GEO 指南](/zh/guides/geo)。
  </Accordion>

  <Accordion title="Mintlify 会自动处理文档 SEO 吗？">
    Mintlify 会处理技术基础部分：站点地图生成、语义化 HTML、规范标签、meta 标签生成和移动端优化。但 Mintlify 无法替你完成的是撰写更好的标题、进行关键词研究、构建内部链接，或扩展内容单薄的页面——这些都需要编辑层面的判断。[SEO 配置参考](/zh/optimize/seo) 介绍了你可以通过 `docs.json` 和页面 frontmatter 控制的所有内容。
  </Accordion>
</AccordionGroup>
