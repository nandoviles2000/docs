国际化 (i18n) 是指在设计软件或内容时，使其能够适用于不同语言和区域设置的过程。本指南将介绍如何组织文件、配置导航，并高效维护译文，帮助用户以自己偏好的语言访问您的文档，并扩大其全球覆盖范围。

<div id="file-structure">
  ## 文件结构
</div>

将翻译内容按语言分别组织在对应的目录中，以便于维护文档，并按语言组织导航。

使用 [ISO 639-1 language codes](https://en.wikipedia.org/wiki/List_of_ISO_639-1_codes) 为每种语言创建单独的目录。将翻译后的文件按与默认语言相同的结构放置在这些目录中。

<Expandable title="支持的语言代码">
  * `ar` - 阿拉伯语
  * `ca` - 加泰罗尼亚语
  * `cs` - 捷克语
  * `zh` or `zh-Hans` - 中文 (简体) 
  * `zh-Hant` - 中文 (繁体) 
  * `de` - 德语
  * `en` - 英语
  * `es` - 西班牙语
  * `fi` - 芬兰语
  * `fr` - 法语
  * `fr-CA` - 法语 (加拿大) 
  * `he` - 希伯来语
  * `hi` - 印地语
  * `hu` - 匈牙利语
  * `id` - 印度尼西亚语
  * `it` - 意大利语
  * `ja` - 日语
  * `ko` - 韩语
  * `lv` - 拉脱维亚语
  * `nl` - 荷兰语
  * `no` - 挪威语
  * `pl` - 波兰语
  * `pt` or `pt-BR` - 葡萄牙语
  * `ro` - 罗马尼亚语
  * `ru` - 俄语
  * `sv` - 瑞典语
  * `tr` - 土耳其语
  * `uk` - 乌克兰语
  * `uz` - 乌兹别克语
  * `vi` - 越南语
</Expandable>

```text Example file structure
docs/
├── index.mdx                    # 英语（默认）
├── quickstart.mdx
├── fr/
│   ├── index.mdx               # 法语
│   ├── quickstart.mdx
├── es/
│   ├── index.mdx               # 西班牙语
│   ├── quickstart.mdx
└── zh/
    ├── index.mdx               # 中文
    └── quickstart.mdx
```

<Tip>
  在所有语言版本中保持相同的文件名和目录结构。这样更便于维护翻译内容并找出缺失的内容。
</Tip>

<div id="configure-the-language-switcher">
  ## 配置语言切换器
</div>

要为文档添加语言切换器，请在 `docs.json` 的导航配置中设置 `languages` 数组。

```json docs.json
{
  "navigation": {
    "languages": [
      {
        "language": "en",
        "groups": [
          {
            "group": "Getting started",
            "pages": ["index", "quickstart"]
          }
        ]
      },
      {
        "language": "es",
        "groups": [
          {
            "group": "Comenzando",
            "pages": ["es/index", "es/quickstart"]
          }
        ]
      }
    ]
  }
}
```

`languages` 数组中的每个语言条目都需要包含：

* `language`：ISO 639-1 语言代码
* 完整的导航结构
* 已翻译文件的路径

导航结构可因语言不同而有所差异，以适配特定语言的内容需求。

<Warning>
  不要在多种语言中使用相同的页面路径。不同语言之间重复使用路径会导致未定义行为。每个页面路径只能出现在一种语言的导航中。
</Warning>

<div id="set-default-language">
  ### 设置默认语言
</div>

`languages` 数组中的第一个语言会自动作为默认语言使用。若要将其他语言设为默认语言，可以调整数组顺序，或添加 `default` 属性：

```json docs.json
{
  "navigation": {
    "languages": [
      {
        "language": "es",
        "groups": [...]
      },
      {
        "language": "en",
        "groups": [...]
      }
    ]
  }
}
```

或者，也可以使用 `default` 属性来覆盖顺序：

```json docs.json
{
  "navigation": {
    "languages": [
      {
        "language": "en",
        "groups": [...]
      },
      {
        "language": "es",
        "default": true,
        "groups": [...]
      }
    ]
  }
}
```

<div id="single-language-documentation">
  ### 单语言文档
</div>

如果你只想提供一种语言且不显示语言切换器，请从导航配置中移除 `languages` 字段。然后直接定义导航结构：

```json docs.json
{
  "navigation": {
    "tabs": [
      {
        "tab": "Documentation",
        "groups": [
          {
            "group": "Getting started",
            "pages": ["index", "quickstart"]
          }
        ]
      }
    ]
  }
}
```

这会以单一语言显示你的文档，并且不显示语言切换器 UI。

<Tip>
  将导航标签 (如分组名称或 Tab 名称) 翻译成与内容语言一致的语言。这样可为用户提供完整的本地化体验。
</Tip>

<div id="global-navigation">
  ### 全局导航
</div>

如需添加在所有语言版本中都会显示的全局导航元素，请在 `docs.json` 的导航配置中设置 `global` 对象。

```json docs.json
{
  "navigation": {
    "global": {
      "anchors": [
        {
          "anchor": "Documentation",
          "href": "https://example.com/docs"
        },
        {
          "anchor": "Blog",
          "href": "https://example.com/blog"
        }
      ]
    },
    "languages": [
      // 特定语言的导航
    ]
  }
}
```

<div id="localized-footer-and-navbar">
  ### 本地化页脚和导航栏
</div>

为每种语言分别自定义页脚和导航栏，以显示翻译后的内容以及特定地区的链接。

为每种语言配置添加 `footer` 和 `navbar` 属性：

```json docs.json
{
  "navigation": {
    "languages": [
      {
        "language": "en",
        "footer": {
          "socials": {
            "x": "https://x.com/mintlify"
          },
          "links": [
            {
              "header": "Resources",
              "items": [
                { "label": "Documentation", "href": "/en/docs" },
                { "label": "Blog", "href": "https://mintlify.com/blog" }
              ]
            }
          ]
        },
        "navbar": {
          "links": [
            { "label": "Docs", "href": "/en/docs" }
          ],
          "primary": {
            "type": "button",
            "label": "Get Started",
            "href": "/en/quickstart"
          }
        },
        "groups": [
          {
            "group": "Getting started",
            "pages": ["en/quickstart", "en/index"]
          }
        ]
      },
      {
        "language": "es",
        "footer": {
          "socials": {
            "x": "https://x.com/mintlify"
          },
          "links": [
            {
              "header": "Recursos",
              "items": [
                { "label": "Documentación", "href": "/es/docs" },
                { "label": "Blog", "href": "https://mintlify.com/blog" }
              ]
            }
          ]
        },
        "navbar": {
          "links": [
            { "label": "Documentación", "href": "/es/docs" }
          ],
          "primary": {
            "type": "button",
            "label": "Comenzar",
            "href": "/es/quickstart"
          }
        },
        "groups": [
          {
            "group": "Comenzando",
            "pages": ["es/quickstart", "es/index"]
          }
        ]
      }
    ]
  }
}
```

语言专属的 `footer` 和 `navbar` 会覆盖该语言的全局设置。如果某种语言没有定义这些属性，则会继承全局配置。

你也可以用同样的方式为特定语言配置 `banner`。

<div id="maintain-translations">
  ## 维护翻译
</div>

确保译文准确，并与源内容保持同步。

<div id="translation-workflow">
  ### 翻译工作流
</div>

1. 用你的主要语言更新源内容。
2. 找出已更改的内容。
3. 翻译已更改的内容。
4. 审核译文的准确性。
5. 更新翻译后的文件。
6. 确认导航和链接正常可用。

<div id="automated-translations">
  ### 自动翻译
</div>

如需自动翻译解决方案，请[联系 Mintlify 销售团队](mailto:gtm@mintlify.com)。

<div id="external-translation-providers">
  ### 外部翻译供应商
</div>

如果你与自己的翻译供应商或本地化译员合作，可以使用 GitHub Actions 或类似的 CI/CD 工具，将他们的工作流集成到你的 Mintlify 文档中。

1. **导出源内容**：提取需要翻译的 MDX 文件。
2. **发送给译者**：将文件提供给你的翻译供应商。
3. **接收译文**：收回翻译后的 MDX 文件。
4. **导入并部署**：将翻译后的文件添加到语言目录中，并更新导航。

当 PR 合并到 main 时，此 GitHub Actions 工作流会自动导出已更改的英文内容以供翻译。

```yaml .github/workflows/export-for-translation.yml
name: Export content for translation

on:
  push:
    branches: [main]
    paths:
      - '*.mdx'
      - '!es/**'
      - '!fr/**'
      - '!zh/**'

# 防止并发工作流运行以避免竞争条件
concurrency:
  group: translation-export-${{ github.ref }}
  cancel-in-progress: false

jobs:
  export:
    runs-on: ubuntu-latest
    
    # 如果未检测到更改则提前退出（可选 - 作为额外的安全保障）
    outputs:
      files-changed: ${{ steps.changed.outputs.has-files }}
    
    steps:
      - name: Checkout repository
        uses: actions/checkout@v4
        with:
          fetch-depth: 2

      - name: Get changed MDX files
        id: changed
        run: |
          # 检查父提交是否存在（处理首次推送的情况）
          if ! git rev-parse HEAD~1 >/dev/null 2>&1; then
            echo "has-files=false" >> $GITHUB_OUTPUT
            echo "files=" >> $GITHUB_OUTPUT
            echo "No parent commit found - skipping export"
            exit 0
          fi
          
          # 获取已更改的 MDX 文件列表（排除翻译目录）
          files=$(git diff --name-only HEAD~1 HEAD -- '*.mdx' ':!es/' ':!fr/' ':!zh/' | tr '\n' ' ')
          
          if [ -z "$files" ]; then
            echo "has-files=false" >> $GITHUB_OUTPUT
            echo "files=" >> $GITHUB_OUTPUT
            echo "No MDX files changed - skipping export"
          else
            echo "has-files=true" >> $GITHUB_OUTPUT
            echo "files=$files" >> $GITHUB_OUTPUT
            echo "Found changed files: $files"
          fi
        shell: bash

      - name: Create translation package directory
        if: steps.changed.outputs.has-files == 'true'
        run: |
          mkdir -p translation-export
          echo "Created translation-export directory"

      - name: Copy changed files to export directory
        if: steps.changed.outputs.has-files == 'true'
        run: |
          failed_count=0
          for file in ${{ steps.changed.outputs.files }}; do
            if [ -f "$file" ]; then
              target_dir="translation-export/$(dirname "$file")"
              mkdir -p "$target_dir"
              cp "$file" "$target_dir/"
              echo "✓ Copied: $file"
            else
              echo "✗ File not found: $file"
              ((failed_count++))
            fi
          done
          
          if [ $failed_count -gt 0 ]; then
            echo "Warning: $failed_count file(s) could not be copied"
          fi
        shell: bash

      - name: Validate translation package
        if: steps.changed.outputs.has-files == 'true'
        run: |
          echo "Translation package contents:"
          find translation-export -type f -name "*.mdx" | sort
          echo ""
          file_count=$(find translation-export -type f -name "*.mdx" | wc -l)
          echo "Total MDX files: $file_count"

      - name: Upload translation package
        if: steps.changed.outputs.has-files == 'true'
        uses: actions/upload-artifact@v4
        with:
          name: translation-export-${{ github.sha }}
          path: translation-export/
          retention-days: 30
          if-no-files-found: error
          compression-level: 9

      - name: Print job summary
        if: steps.changed.outputs.has-files == 'true'
        run: |
          echo "## Translation Export Complete" >> $GITHUB_STEP_SUMMARY
          echo "" >> $GITHUB_STEP_SUMMARY
          echo "**Artifact:** \`translation-export-${{ github.sha }}\`" >> $GITHUB_STEP_SUMMARY
          echo "" >> $GITHUB_STEP_SUMMARY
          echo "**Changed Files:**" >> $GITHUB_STEP_SUMMARY
          echo "${{ steps.changed.outputs.files }}" | tr ' ' '\n' | sed 's/^/- /' >> $GITHUB_STEP_SUMMARY
```

此 GitHub Actions 工作流会在通过 PR 添加翻译内容时，验证并导入这些内容。

```yaml .github/workflows/import-translations.yml
name: Import translations

on:
  pull_request:
    paths:
      - 'es/**'
      - 'fr/**'
      - 'zh/**'

# 定义明确的权限
permissions:
  contents: read
  pull-requests: write

jobs:
  validate:
    runs-on: ubuntu-latest
    
    outputs:
      validation-status: ${{ steps.final-check.outputs.status }}
    
    steps:
      - name: Checkout repository
        uses: actions/checkout@v4
        with:
          fetch-depth: 0  # 完整历史记录，确保 origin/main 可用

      - name: Fetch origin/main reference
        run: |
          git fetch origin main:origin/main 2>/dev/null || echo "origin/main not available, using latest"
        continue-on-error: true

      - name: Get changed translation files
        id: changed-files
        run: |
          # 获取翻译目录中所有已变更的 MDX 文件
          files=$(git diff --name-only origin/main..HEAD -- 'es/**/*.mdx' 'fr/**/*.mdx' 'zh/**/*.mdx' | sort)
          
          if [ -z "$files" ]; then
            echo "No translation MDX files detected in this PR"
            echo "files=" >> $GITHUB_OUTPUT
            echo "count=0" >> $GITHUB_OUTPUT
          else
            echo "Found $(echo "$files" | wc -l) translation files"
            echo "$files"
            echo "files=$files" >> $GITHUB_OUTPUT
            echo "count=$(echo "$files" | wc -l)" >> $GITHUB_OUTPUT
          fi
        shell: bash

      - name: Validate frontmatter
        id: frontmatter
        if: steps.changed-files.outputs.count > 0
        run: |
          failed_files=()
          success_count=0
          total=${{ steps.changed-files.outputs.count }}
          
          while IFS= read -r file; do
            if [ ! -f "$file" ]; then
              echo "✗ File not found: $file"
              failed_files+=("$file")
              continue
            fi
            
            # 检查 frontmatter 是否有效（第 1-2 行必须为 ---）
            first_line=$(sed -n '1p' "$file")
            second_line=$(sed -n '2p' "$file")
            last_line=$(awk 'NF' "$file" | tail -1)
            
            if [ "$first_line" = "---" ] && grep -q "^---$" "$file"; then
              echo "✓ Valid frontmatter: $file"
              ((success_count++))
            else
              echo "✗ Invalid frontmatter in $file"
              echo "  Line 1: '$first_line'"
              failed_files+=("$file")
            fi
          done <<< "${{ steps.changed-files.outputs.files }}"
          
          echo ""
          echo "Frontmatter check: $success_count/$total passed"
          
          if [ ${#failed_files[@]} -gt 0 ]; then
            echo "frontmatter_valid=false" >> $GITHUB_OUTPUT
            printf 'failed_files=%s\n' "${failed_files[@]}" >> $GITHUB_OUTPUT
          else
            echo "frontmatter_valid=true" >> $GITHUB_OUTPUT
          fi
        shell: bash

      - name: Check file structure
        id: structure
        if: steps.changed-files.outputs.count > 0
        run: |
          missing_sources=()
          orphaned_count=0
          
          while IFS= read -r translated_file; do
            # 提取语言和相对路径
            # 例如，"es/docs/guide.mdx" -> lang="es", relative_path="docs/guide.mdx"
            lang=$(echo "$translated_file" | cut -d'/' -f1)
            relative_path=$(echo "$translated_file" | cut -d'/' -f2-)
            source_file="$relative_path"
            
            if [ ! -f "$source_file" ]; then
              echo "Missing source: $translated_file -> $source_file"
              missing_sources+=("$translated_file")
              ((orphaned_count++))
            else
              echo "✓ Found source: $translated_file -> $source_file"
            fi
          done <<< "${{ steps.changed-files.outputs.files }}"
          
          echo ""
          echo "Structure check: $orphaned_count orphaned file(s)"
          
          if [ $orphaned_count -gt 0 ]; then
            echo "structure_valid=false" >> $GITHUB_OUTPUT
            printf 'missing_sources=%s\n' "${missing_sources[@]}" >> $GITHUB_OUTPUT
          else
            echo "structure_valid=true" >> $GITHUB_OUTPUT
          fi
        shell: bash

      - name: Validate file integrity
        id: integrity
        if: steps.changed-files.outputs.count > 0
        run: |
          integrity_passed=true
          
          while IFS= read -r file; do
            # 检查文件是否可读且不为空
            if [ ! -r "$file" ] || [ ! -s "$file" ]; then
              echo "✗ File integrity issue: $file (not readable or empty)"
              integrity_passed=false
            fi
            
            # 基本检查：frontmatter 之后文件应包含内容
            line_count=$(wc -l < "$file")
            if [ "$line_count" -lt 5 ]; then
              echo "File is suspiciously short: $file ($line_count lines)"
            fi
          done <<< "${{ steps.changed-files.outputs.files }}"
          
          if [ "$integrity_passed" = true ]; then
            echo "integrity_valid=true" >> $GITHUB_OUTPUT
          else
            echo "integrity_valid=false" >> $GITHUB_OUTPUT
          fi
        shell: bash

      - name: Generate validation report
        if: always()
        run: |
          echo "## Translation Validation Report" >> $GITHUB_STEP_SUMMARY
          echo "" >> $GITHUB_STEP_SUMMARY
          echo "**Files Changed:** ${{ steps.changed-files.outputs.count }}" >> $GITHUB_STEP_SUMMARY
          echo "" >> $GITHUB_STEP_SUMMARY
          
          if [ "${{ steps.changed-files.outputs.count }}" = "0" ]; then
            echo "No translation MDX files found in this PR" >> $GITHUB_STEP_SUMMARY
            echo "" >> $GITHUB_STEP_SUMMARY
            echo "> This could mean:" >> $GITHUB_STEP_SUMMARY
            echo "- Only non-MDX files in es/, fr/, or zh/ directories were changed" >> $GITHUB_STEP_SUMMARY
            echo "- Workflow was triggered but no translation content to validate" >> $GITHUB_STEP_SUMMARY
          else
            echo "### Validation Results" >> $GITHUB_STEP_SUMMARY
            echo "- Frontmatter: ${{ steps.frontmatter.outputs.frontmatter_valid }}" >> $GITHUB_STEP_SUMMARY
            echo "- File Structure: ${{ steps.structure.outputs.structure_valid }}" >> $GITHUB_STEP_SUMMARY
            echo "- File Integrity: ${{ steps.integrity.outputs.integrity_valid }}" >> $GITHUB_STEP_SUMMARY
            echo "" >> $GITHUB_STEP_SUMMARY
          fi
        shell: bash

      - name: Final validation check
        id: final-check
        # 仅在存在需要验证的 MDX 文件时运行此检查
        if: steps.changed-files.outputs.count > 0
        run: |
          validation_failed=false
          
          if [ "${{ steps.frontmatter.outputs.frontmatter_valid }}" != "true" ]; then
            echo "Frontmatter validation failed"
            validation_failed=true
          fi
          
          if [ "${{ steps.structure.outputs.structure_valid }}" != "true" ]; then
            echo "File structure validation failed"
            validation_failed=true
          fi
          
          if [ "${{ steps.integrity.outputs.integrity_valid }}" != "true" ]; then
            echo "File integrity validation failed"
            validation_failed=true
          fi
          
          if [ "$validation_failed" = true ]; then
            echo "status=failed" >> $GITHUB_OUTPUT
            exit 1
          else
            echo "status=passed" >> $GITHUB_OUTPUT
            echo "All validations passed"
          fi
        shell: bash

      - name: Handle no-files-to-validate case
        # 仅在没有需要验证的 MDX 文件时运行
        if: steps.changed-files.outputs.count == 0
        run: |
          echo "No translation MDX files to validate - PR is valid"
          echo "status=no-changes" >> ${{ steps.final-check.outputs }}
        shell: bash
```

**外部翻译工作流最佳实践**

* **保留 frontmatter**：确保译者完整保留 YAML frontmatter，只翻译 `title` 和 `description` 的值。
* **保护代码块**：向翻译供应商明确标注代码块“请勿翻译”。
* **使用翻译记忆库**：提供术语表，标明哪些技术术语应保留英文，或需采用特定译法。
* **自动化验证**：在合并译文前，使用 CI 检查来验证 MDX 语法和 frontmatter。
* **版本控制**：跟踪每份译文对应的源文版本，以识别过时内容。

<div id="page-metadata">
  ### 页面元数据
</div>

在每个文件的 frontmatter 中添加翻译后的元数据：


<div id="date-and-number-formats">
  ### 日期和数字格式
</div>

请考虑日期和数字的本地化格式。

* 日期格式：MM/DD/YYYY (月/日/年) 与 DD/MM/YYYY (日/月/年) 
* 数字格式：1,000.00 与 1.000,00
* 货币符号：$100.00 与 100,00€

请为每种语言提供符合其格式习惯的示例，或使用通用且易于理解的格式。

<div id="maintain-consistency">
  ### 保持一致性
</div>

* 确保所有语言版本的内容保持一致，让每位用户都能获得同等质量的信息。
* 为技术术语建立翻译术语表。
* 在不同语言版本之间保持一致的内容结构。
* 保持与源内容相同的语气和风格。
* 使用 Git 分支，将翻译工作与 main 分支上的内容更新分开管理。

<div id="layout-differences">
  ### 布局差异
</div>

与英语相比，某些语言可能需要更多或更少的显示空间。请在不同屏幕尺寸下测试译文内容，确保：

* 导航能够正常显示。
* 代码块不会溢出。
* 表格和其他格式化文本仍然清晰易读。
* 图片能够按比例适当缩放。

<div id="character-encoding">
  ### 字符编码
</div>

确保你的开发环境和部署流水线支持 UTF-8 编码，以正确显示使用不同字母表及特殊字符的语言中的所有字符。

<div id="frequently-asked-questions">
  ## 常见问题
</div>

<AccordionGroup>
  <Accordion title="发布新语言前，我需要翻译每一页吗？">
    不需要。你可以在只完成部分内容翻译的情况下先上线一种语言，再逐步补齐。常见做法是优先翻译访问量最高的页面——通常包括入门内容、身份验证和热门操作指南——而将流量较低的参考内容暂时保留为默认语言，等翻译完成后再补上。一般来说，用户更愿意看到部分内容已翻译，而不是完全没有翻译。
  </Accordion>

  <Accordion title="如果某个翻译页面缺失，会发生什么？">
    如果用户访问一个不存在的翻译版 URL，就会看到 404。为避免这种情况，你可以只在特定语言的导航中加入已翻译页面，或者让默认语言与翻译内容保持一致。各语言使用相同的文件结构，也能帮助你轻松找出缺失的翻译。
  </Accordion>

  <Accordion title="导航标签需要翻译吗？">
    需要。导航标签——分组名称、Tab 标题、锚文本——应与内容所用语言保持一致。在西班牙语文档中出现英文 “Getting started” 标签，会让体验显得很割裂。Mintlify 支持按语言设置不同的导航结构，因此每种语言都可以使用完整翻译的标签。
  </Accordion>

  <Accordion title="如何处理翻译内容中的代码示例？">
    代码本身不应翻译——变量名、函数调用和语法都不受语言影响。如果代码块中的注释用于解释用户需要理解的概念，可以翻译这些注释。代码块前后的说明文字则应完整翻译。
  </Accordion>

  <Accordion title="Mintlify 是否支持阿拉伯语或希伯来语等从右到左的语言？">
    支持。阿拉伯语 (`ar`) 和希伯来语 (`he`) 都在支持的语言代码列表中。配置这些语言代码后，Mintlify 会自动处理 RTL 布局。请在 RTL 模式下测试文档，确认导航、表格和代码块都能正确显示。
  </Accordion>
</AccordionGroup>
