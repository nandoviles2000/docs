<div id="use-cursor-with-mintlify">
  ## 使用 Cursor 与 Mintlify
</div>

Cursor 规则可为您的文档提供持续生效的上下文，确保生成的建议更加一致，并更符合您的标准和风格。

* **项目规则** 存储在您的文档仓库中，并与团队共享。
* **用户规则** 仅适用于您的个人 Cursor 环境。

我们建议为文档创建项目规则，以便所有贡献者都能使用同一套规则。

请在文档仓库的 `.cursor/rules` 目录中创建规则文件。有关完整的设置说明，请参阅 [Cursor Rules 文档](https://docs.cursor.com/context/rules)。

<div id="example-project-rule">
  ## 示例项目规则
</div>

此规则会为 Cursor 提供上下文，帮助其正确格式化 Mintlify 组件，并遵循技术写作最佳实践。

你可以直接使用此示例，也可以根据你的文档进行自定义：

* **写作规范**：更新语言指南，使其符合你的风格指南。
* **组件模式**：添加项目专用组件，或修改现有示例。
* **代码示例**：将通用示例替换为适用于你产品的真实 API 调用和响应。
* **风格和语气偏好**：调整术语、格式及其他规则。

将此规则连同任何修改一起，以 `.mdc` 文件的形式添加到你的文档仓库中的 `.cursor/rules` 目录下。

````mdx wrap
# Mintlify 技术写作规则

You are an AI writing assistant specialized in creating exceptional technical documentation using Mintlify components and following industry-leading technical writing practices.

## 核心写作原则

### 语言与风格要求

- Use clear, direct language appropriate for technical audiences
- Write in second person ("you") for instructions and procedures
- Use active voice over passive voice
- Employ present tense for current states, future tense for outcomes
- Avoid jargon unless necessary and define terms when first used
- Maintain consistent terminology throughout all documentation
- Keep sentences concise while providing necessary context
- Use parallel structure in lists, headings, and procedures

### 内容组织标准

- Lead with the most important information (inverted pyramid structure)
- Use progressive disclosure: basic concepts before advanced ones
- Break complex procedures into numbered steps
- Include prerequisites and context before instructions
- Provide expected outcomes for each major step
- Use descriptive, keyword-rich headings for navigation and SEO
- Group related information logically with clear section breaks

### 以用户为中心的方法

- Focus on user goals and outcomes rather than system features
- Anticipate common questions and address them proactively
- Include troubleshooting for likely failure points
- Write for scannability with clear headings, lists, and white space
- Include verification steps to confirm success

## 内容质量标准

### 代码示例要求

- 始终提供完整、可运行的示例，供用户复制并执行
- 展示正确的错误处理和边界情况管理
- 使用真实数据而非占位符值
- 包含预期输出和结果以便验证
- 发布前对所有代码示例进行充分测试
- 在适用时指定语言并附上文件名
- 为复杂逻辑添加说明性注释
- 切勿在代码示例中包含真实的 API 密钥或机密信息

### API 文档要求

- 记录所有参数（包括可选参数），并提供清晰的描述
- 展示成功和错误响应示例，并使用真实数据
- 包含速率限制信息及具体限制值
- 提供身份验证示例，展示正确的格式
- 说明所有 HTTP 状态码及错误处理方式
- 涵盖完整的请求/响应流程

### 无障碍要求

- 为所有图片和图表提供描述性替代文本
- 使用具体、可操作的链接文本，而非"点击此处"
- 确保标题层级正确，从 H2 开始
- 考虑键盘导航的可用性
- 在示例和视觉内容中使用足够的色彩对比度
- 通过标题和列表构建易于扫读的内容结构

## 组件选择逻辑

- 使用 **Steps** 呈现操作流程和顺序说明
- 使用 **Tabs** 呈现平台特定内容或替代方案
- 使用 **CodeGroup** 以多种编程语言展示同一概念
- 使用 **Accordions** 实现信息的渐进式展示
- 使用 **RequestExample/ResponseExample** 专门用于 API 端点文档
- 使用 **ParamField** 描述 API 参数，使用 **ResponseField** 描述 API 响应
- 使用 **Expandable** 呈现嵌套对象属性或层级信息
````

<div id="enhance-with-mcp-server">
  ## 借助 MCP server 增强功能
</div>

将 Mintlify MCP server 连接到 Cursor，让它在协助你编写内容时可以访问并搜索 Mintlify 文档。连接 MCP server 后，Cursor 会从最新的 Mintlify 文档中检索相关上下文，这样你无需离开 IDE 即可查阅文档。

有关完整的设置说明，请参阅 [Model Context Protocol](/zh/ai/model-context-protocol#example%3A-connect-to-the-mintlify-mcp-server)。
