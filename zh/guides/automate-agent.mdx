<div id="what-you-will-build">
  ## 你将构建的内容
</div>

一个自动化流程：当你将代码推送到 `main` 分支时，它会自动更新你的文档。你可以在多个平台上搭建此工作流，包括 GitHub Actions 和 n8n。它会监控你的代码仓库，然后调用智能体 API，在单独的文档仓库中更新文档。

此工作流会连接两个独立的仓库：

* **代码仓库**：用于存放应用代码。你将在这个仓库中设置自动化触发器。示例包括后端 API、前端应用、SDK 或 CLI 工具。
* **文档仓库**：用于存放文档，并连接到你的 Mintlify 项目。智能体会在此仓库中创建包含文档更新的拉取请求 (PR) 。

本教程假设你的文档与应用代码分别存放在不同的仓库中。如果你使用的是单体仓库，请修改工作流，使其指向存放文档的目录。

<div id="workflow-overview">
  ### 工作流概览
</div>

1. 有人将代码推送到你的 main 分支。
2. 工作流被触发。
3. 工作流调用智能体 API 来更新文档。
4. 智能体会在你的文档仓库中创建一个包含文档更新的拉取请求 (PR) 。

  <Tab title="GitHub Actions">
    如果您的代码已托管在 GitHub 上，GitHub Actions 是最简便的选择，且无需任何额外服务。

    ## 前提条件

    * 已在你的代码和文档仓库中启用 GitHub Actions
    * [Mintlify GitHub 应用](/zh/deploy/github) 已安装在你的代码仓库和文档仓库中
    * [Mintlify 管理员 API 密钥](https://dashboard.mintlify.com/settings/organization/api-keys)
    * [Mintlify 项目 ID](https://dashboard.mintlify.com/settings/organization/api-keys)
    * [Mintlify Enterprise 套餐](https://mintlify.com/pricing)
    * 对存放您的代码和文档的 GitHub 仓库具有管理员访问权限

    ### 在您的代码仓库中安装 Mintlify 应用

    在您的代码仓库中安装 Mintlify 应用，以便智能体从代码库中获取上下文。若要将应用添加到新仓库：

    1. 前往仪表板中的 [代理](https://dashboard.mintlify.com/products/agent) 页面。
    2. 点击 **Add to New Organization**。系统会将你带到 GitHub 的应用安装页面。
    3. 从列表中选择要授予访问权限的仓库。
    4. 保存更改。

    ### 获取管理员 API 密钥

    1. 前往仪表板中的 [API 密钥](https://dashboard.mintlify.com/settings/organization/api-keys) 页面。
    2. 选择 **创建管理员 API 密钥**。
    3. 复制该密钥并妥善保管。

    ## 构建工作流

    ### 创建工作流文件

    1. 在代码仓库中，创建一个新文件：`.github/workflows/update-docs.yml`
    2. 添加此工作流：

       ```yaml
       name: Update Docs

       on:
         push:
           branches:
             - main

       jobs:
         update-docs:
           runs-on: ubuntu-latest
           steps:
             - uses: actions/github-script@v8
               env:
                 MINTLIFY_API_KEY: ${{ secrets.MINTLIFY_API_KEY }}
                 PROJECT_ID: ${{ secrets.MINTLIFY_PROJECT_ID }}
               with:
                 script: |
                   const { owner, repo } = context.repo;
                   const projectId = process.env.PROJECT_ID;
                   const apiKey = process.env.MINTLIFY_API_KEY;

                   if (!projectId || !apiKey) {
                     core.setFailed('Missing MINTLIFY_PROJECT_ID or MINTLIFY_API_KEY secrets');
                     return;
                   }

                   const url = `https://api.mintlify.com/v1/agent/${projectId}/job`;
                   const payload = {
                     branch: `mintlify/docs-update-${Date.now()}`,
                     messages: [
                       {
                         role: 'system',
                         content: 'You are an action runner that updates documentation based on code changes. You should never ask questions. If you are not able to access the repository, report the error and exit.'
                       },
                       {
                         role: 'user',
                         content: `Update the documentation for our recent pushes to main:\n\nRepository: ${owner}/${repo}`
                       }
                     ],
                     asDraft: false
                   };

                   try {
                     const response = await fetch(url, {
                       method: 'POST',
                       headers: {
                         'Authorization': `Bearer ${apiKey}`,
                         'Content-Type': 'application/json'
                       },
                       body: JSON.stringify(payload)
                     });

                     if (!response.ok) {
                       throw new Error(`API request failed with status ${response.status}: ${await response.text()}`);
                     }

                     const reader = response.body.getReader();
                     const decoder = new TextDecoder();
                     let buffer = '';

                     while (true) {
                       const { done, value } = await reader.read();
                       if (done) break;
                       buffer += decoder.decode(value, { stream: true });
                       const lines = buffer.split('\n');
                       buffer = lines.pop() || '';
                       for (const line of lines) {
                         if (line.trim()) {
                           console.log(line);
                         }
                       }
                     }
                     if (buffer.trim()) {
                       console.log(buffer);
                     }

                     core.notice(`Documentation update job triggered for ${owner}/${repo}`);
                   } catch (error) {
                     core.setFailed(`Failed to create documentation update job: ${error.message}`);
                   }
       ```

    ### 添加密钥

    1. 在代码仓库中，进入 **Settings** → **Secrets and variables** → **Actions**。
    2. 点击 **New repository secret**。
    3. 添加以下密钥：
       * 名称：`MINTLIFY_API_KEY`，密钥：您的 Mintlify 管理员 API 密钥
       * 名称：`MINTLIFY_PROJECT_ID`，密钥：您的 Mintlify 项目 ID (可在仪表板的 [API keys](https://dashboard.mintlify.com/settings/organization/api-keys) 页面中找到)

    如需了解更多信息，请参阅 GitHub 文档中的[在 GitHub Actions 中使用密钥](https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/use-secrets)。

    ## 测试自动化流程

    1. 在你的代码仓库中做一处小修改，并推送到 main：
       ```bash
       git add .
       git commit -m "Test: trigger docs automation"
       git push origin main
       ```

    2. 在代码仓库的 **Actions** 选项卡中查看正在运行的工作流。

    3. 工作流运行完成后，请检查你的文档仓库中是否有包含文档更新的新分支和拉取请求 (PR) 。

    ## 故障排除

    ### 工作流未运行

    * 确认你已在代码仓库中启用 GitHub Actions。
    * 在 **操作** 标签页中查看错误信息。
    * 确保工作流文件位于 `.github/workflows/` 目录中，且扩展名为 `.yml`。

    ### 来自 agent API 的 401 错误

    * 请确认你的 API 密钥以 `mint_` 开头。
    * 检查 Authorization 标头是否采用 `Bearer mint_yourkey` 格式。
    * 确认该 API 密钥对应正确的 Mintlify 组织。

    ### 文档更新未显示

    * 确认你已将文档仓库连接到你的 Mintlify 项目。
    * 确认智能体对文档仓库具有写权限。
    * 检查工作流日志中智能体返回的错误信息。

    ## 前提条件

    * n8n 工作区
    * [Mintlify 企业版套餐](https://mintlify.com/pricing)
    * 已在你的代码仓库中安装 Mintlify 应用
    * Mintlify 管理 API 密钥
    * 拥有存放您的代码和文档的 GitHub 仓库的管理员权限
    * GitHub 个人访问令牌

    ### 在代码仓库中安装 Mintlify 应用

    在您的代码仓库中安装 Mintlify 应用，以便智能体从代码库中获取上下文信息。若要将应用添加到新仓库：

    1. 前往仪表板中的 [Agent](https://dashboard.mintlify.com/products/agent) 页面。
    2. 点击 **Add to New Organization**。你将进入 GitHub 上的应用安装页面。
    3. 从列表中选择你要授权访问的仓库。
    4. 保存更改。

    ### 获取管理员 API 密钥

    1. 前往仪表板中的 [API 密钥](https://dashboard.mintlify.com/settings/organization/api-keys) 页面。
    2. 选择 **创建管理员 API 密钥**。
    3. 复制密钥并妥善保管。

    ### 获取您的 GitHub 个人访问令牌

    1. 在 GitHub 中，前往 **Settings**。
    2. 点击 **Developer settings**。
    3. 点击 **个人访问令牌**。
    4. 点击 **Tokens (classic)**。
    5. 点击 **Generate new token (classic)**。
    6. 选择以下作用域：
       * `repo` (对私有仓库的完全访问权限)
       * `admin:repo_hook` (如果你希望 n8n 创建 Webhook)
    7. 生成令牌并妥善保管。

    如需了解更多信息，请参阅 GitHub 文档中的[创建个人访问令牌 (经典) ](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens?versionId=free-pro-team%40latest\&productId=account-and-profile#creating-a-personal-access-token-classic)。

    ## 构建工作流

    ### 创建 Webhook 触发器

    1. 在 n8n 中，创建一个新工作流。
    2. 添加一个 Webhook 节点。
    3. 配置 webhook：
       * HTTP 方法：`POST`
       * 路径：`auto-update-documentation` (或任意唯一路径)
       * 身份验证：无
       * 响应：立即返回
    4. 保存工作流。
    5. 复制生产环境的 webhook URL。格式如下：`https://your-n8n-instance.app.n8n.cloud/webhook/auto-update-documentation`

    ### 设置 GitHub Webhook

    1. 转到你在 GitHub 上的代码仓库。
    2. 点击 **设置**。
    3. 点击 **Webhooks**。
    4. 点击**添加 webhook**。
    5. 配置 webhook：
       * Payload URL：粘贴你的 n8n webhook URL
       * Content type：`application/json`
       * 你希望通过哪些事件触发此 webhook？
         * 选择 **Let me select individual events.**
         * 仅选择 **Push events**。
       * 选择 **Active**
    6. 点击 **Add webhook**。

    ### 筛选 main 分支的推送

    在 webhook 之后添加一个代码节点，用于过滤推送到 main 分支的事件并提取相关信息。

    1. 添加代码节点。
    2. 将其命名为 &quot;筛选 main 分支的推送。&quot;
    3. 将模式设为 **Run Once for All Items**。
    4. 添加以下 JavaScript：

    ```javascript
    const webhookData = $input.first().json.body;

    // 仅在推送到 main 时继续
    if (webhookData.ref !== "refs/heads/main") {
      return [];
    }

    // 提取信息
    const repository = webhookData.repository;
    const pusher = webhookData.pusher;

    // 为智能体构建消息
    const agentMessage = `Update documentation for changes pushed to main in ${repository.name}. Always edit files and create a pull request.`;

    return {
      json: {
        codeRepoName: repository.full_name,
        codeRepoShortName: repository.name,
        agentMessage: agentMessage
      }
    };
    ```

    此代码会在推送目标不是 main 分支时终止工作流，从 GitHub webhook 中提取所有相关信息，并为 agent API 构建消息。

    ### 调用 agent API

    添加 HTTP 请求节点以创建文档任务。

    1. 添加 HTTP 请求节点。
    2. 将其命名为 &quot;创建智能体任务。&quot;
    3. 配置该请求：

       * 方法：`POST`
       * URL：`https://api.mintlify.com/v1/agent/YOUR_PROJECT_ID/job` (将 `YOUR_PROJECT_ID` 替换为你在 [API 密钥](https://dashboard.mintlify.com/settings/organization/api-keys) 页面上看到的项目 ID)
       * 身份验证：通用凭据类型 → Header Auth
         * 新建凭据：
           * 名称：`Authorization`
           * 值：`Bearer mint_YOUR_API_KEY` (替换为你的 API 密钥)
       * 发送正文：开启
       * 正文内容类型：JSON
       * 指定正文：使用 JSON
       * 添加以下 JSON：

       ```json
       {
       "branch": "docs-update-from-{{ $json.codeRepoShortName }}-{{ $now.toISOString() }}",
       "messages": [
           {
           "role": "system",
           "content": "{{ $json.agentMessage }}"
           }
       ],
       "asDraft": false
       }
       ```

    ## 测试自动化流程

    1. 在代码仓库中创建一个测试分支：
       ```bash
       git checkout -b test-docs-automation
       ```

    2. 做一处小修改并提交：
       ```bash
       git add .
       git commit -m "Test: trigger docs automation"
       git push origin test-docs-automation
       ```

    3. 在 GitHub 上创建拉取请求 (PR) 。

    4. 合并拉取请求 (PR) 。

    ### 验证自动化配置

    您应该会看到一个新的 n8n 执行任务 (所有节点均已成功完成) ，以及文档仓库中新建的分支和拉取请求 (PR) 。

    ## 故障排除

    ### Webhook 未触发

    * 确认该工作流在 n8n 中已启用。
    * 前往 GitHub 仓库的 Settings → Webhooks → Recent Deliveries，查看响应状态码。
    * 确保 webhook URL 与您的 n8n webhook URL 完全一致。

    ### agent API 返回 401 错误

    * 确认您的 API 密钥是否以 `mint_` 开头。
    * 检查 Authorization 标头是否采用 `Bearer mint_yourkey` 格式。
    * 确认该 API 密钥对应正确的 Mintlify 组织。

    ### 来自 GitHub 的 401 错误

    * 确认你的令牌具有 `repo` 权限范围。
    * 确认令牌尚未过期。
    * 确认你已在发送到 GitHub 的请求中包含 `User-Agent` 标头。
