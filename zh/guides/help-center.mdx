帮助中心可帮助客户排查问题并查找有关您产品的信息。当客户能够自行找到答案时，他们就能更快获得帮助，而您的支持团队也可以专注于需要专业知识的复杂问题。

Mintlify 提供可随客户规模增长而扩展的帮助中心基础设施。

* **AI 搜索**：[Assistant](/zh/assistant/index) 会基于您的支持内容回答客户问题，因此用户即使不清楚该去哪里查找，或不知道该搜索哪些具体术语，也能快速获得答案。
* **反馈收集**：内置的[反馈组件](/zh/optimize/feedback)可让客户为文章评分并报告问题，以便您改进内容。
* **分析**：在[分析仪表板](/zh/optimize/analytics)中跟踪哪些文章获得了浏览量、客户提出了哪些问题，以及他们在哪些环节遇到困难。
* **身份验证**：使用 [SSO 或 OAuth](/zh/deploy/authentication-setup) 根据客户的套餐或账户类型显示个性化内容。

<div id="start-from-a-template">
  ## 从模板开始
</div>

创建新的帮助中心，最快的方式是使用 `mint new --template` 命令。运行该命令，然后选择帮助中心入门模板。

```bash
mint new your-help-center-name --template help-center-starter
```

这会创建一个已为帮助中心预先配置好的新项目，其中包括导航结构、示例页面和目录列表。请查看[在线示例](https://help-center-starter.mintlify.app/)，或浏览[模板源代码](https://github.com/mintlify/templates/tree/main/help-center-starter)。

如果你希望在现有项目中配置帮助中心，请继续执行以下步骤。

  ## 前提条件

<div id="migrate-existing-content">
  ## 迁移现有内容
</div>

如果你要从零开始创建帮助中心，请直接跳到[规划帮助中心结构](#plan-your-help-center-structure)。

<div id="audit-existing-content">
  ### 盘点现有内容
</div>

查看你当前的支持资源，明确哪些内容需要迁移。

* **帮助文章**：涵盖了哪些主题？哪些文章的浏览量最高？
* **常见问题**：是否有适合整理成文章的常见问题？
* **支持工单**：客户反复提出哪些问题？这些内容应整理为可自助查阅的内容。
* **产品文档**：支持内容与产品文档之间是否存在重叠？

<div id="export-your-existing-content">
  ### 导出现有内容
</div>

* 导出为 **Markdown**，以最简便的方式迁移到 Mintlify。
* 如果无法导出为 Markdown，请导出为 **HTML**，再将其转换为 Markdown。
* 导出**工单数据**，找出需要编写文档说明的常见问题。

<div id="plan-your-help-center-structure">
  ## 规划帮助中心结构
</div>

帮助中心应围绕客户遇到的问题来组织，而不是围绕产品功能。客户带着问题和目标而来，因此你应按照他们理解产品和完成常见任务的方式来组织内容。

<Tip>
  查看支持工单，了解客户实际会问什么。这有助于你确定内容优先级，并围绕真实问题来组织导航。
</Tip>

使用 `directory` 属性为导航中的每个分组创建索引页。启用 `directory` 属性后，每个 `root` 页面都会显示同一导航分组中其他页面的目录列表。这样，客户就能先概览各个部分的内容，再点击进入所需的具体页面。

将 `directory` 设置为 `"card"` 可使用横向卡片布局，设置为 `"accordion"` 则显示为列表。除非你在后续层级中明确覆盖，否则该值会沿着导航树向下继承。

```json Example navigation structure
{
  "navigation": {
    "directory": "card",
    "groups": [
      {
        "group": "Get Started",
        "root": "getting-started/index",
        "pages": [
          "getting-started/quick-setup",
          "getting-started/first-steps"
        ]
      },
      {
        "group": "Account",
        "root": "account/index",
        "pages": [
          "account/billing",
          "account/plans",
          "account/team-management",
          "account/security"
        ]
      },
      {
        "group": "Using the Product",
        "root": "product/index",
        "pages": [
          "product/feature-one",
          "product/feature-two",
          "product/integrations"
        ]
      },
      {
        "group": "Troubleshooting",
        "root": "troubleshooting/index",
        "pages": [
          "troubleshooting/common-errors",
          "troubleshooting/connectivity",
          "troubleshooting/performance"
        ]
      }
    ]
  }
}
```

更多配置选项，请参阅[导航](/zh/organize/navigation)和[目录列表](/zh/organize/navigation#directory-listings)。

<div id="write-effective-support-content">
  ## 编写高质量的支持内容
</div>

支持内容应帮助客户快速解决问题。每篇文章都应回答一个具体问题，或解决一个具体问题。将相关内容归类整理，避免创建信息过多、篇幅过长的页面。

<div id="structure-articles-for-scanning">
  ### 让文章便于快速浏览
</div>

客户会快速浏览支持页面，寻找与自身具体问题相关的内容。请使用清晰的标题和简短的段落。

```mdx Example support page
---
title: "Fix login issues"
description: "Troubleshoot common problems signing in to your account"
---

## Reset your password

If you forgot your password, request a reset link from the login page.

1. Go to the login page.
2. Select **Forgot password**.
3. Enter your email address.
4. Check your inbox for the reset link.

## Clear browser cache

Old cached data can cause login problems. Clear your browser cache and try again.

## Check account status

If your account is suspended or deactivated, you'll see an error when logging in.
Contact support if you believe this is a mistake.
```

<div id="set-up-the-assistant">
  ## 设置Assistant
</div>

Assistant会根据您的支持内容回答客户问题。您可以在[仪表板](https://dashboard.mintlify.com/products/assistant/settings)中进行配置。

<Steps>
  <Step title="添加示例问题">
    添加客户经常提出的问题，例如：

    * “如何取消订阅？”
    * “为什么我的付款被拒绝了？”
    * “如何添加团队成员？”

    示例问题会显示为快捷按钮，帮助客户一键获得答案。
  </Step>

  <Step title="设置转接邮箱">
    为Assistant无法回答的问题配置一个支持邮箱。这样一来，当自助服务无法解决问题时，客户仍然可以联系到您的团队。
  </Step>

  <Step title="查看对话">
    定期查看Assistant对话，以识别：

    * Assistant无法回答的问题 (内容缺口)
    * 错误或不完整的回答 (需要改进的内容)
    * 常见提问模式 (需要优先完善的内容)
  </Step>
</Steps>

<div id="enable-feedback-collection">
  ## 启用反馈收集
</div>

反馈可帮助您了解哪些页面对用户有帮助，哪些页面需要改进。查看[反馈](/zh/optimize/feedback)，了解客户认为哪些页面有帮助，哪些页面还需改进。阅读所有评论，并根据有效反馈更新页面。

<div id="set-up-analytics">
  ## 设置分析
</div>

在仪表板中查看[分析](/zh/optimize/analytics)，了解客户如何使用你的帮助中心，并持续优化内容。

* **热门文章**：哪些文章的浏览量最高？请确保这些文章内容准确，并得到妥善维护。
* **搜索查询**：客户会搜索哪些内容？针对常见但没有搜索结果的查询创建内容。
* **Assistant 对话**：Assistant 收到了哪些问题？利用这些信息找出内容缺口。

<div id="restrict-content-by-customer-segment">
  ## 按客户细分限制内容
</div>

如果您有不同的客户等级或产品方案，可使用基于用户组的访问控制，向各个细分客户群显示相关内容。

<Steps>
  <Step title="设置身份验证">
    配置[身份验证](/zh/deploy/authentication-setup)，以便在客户访问您的帮助中心时识别其身份。
  </Step>

  <Step title="配置用户组">
    在用户数据中返回组信息，以便根据方案类型、账户状态或其他属性定义客户细分。详见[用户数据格式](/zh/deploy/authentication-setup#user-data-format)。
  </Step>

  <Step title="按组标记内容">
    使用 frontmatter 指定哪些组可以查看每篇文章。

    ```mdx
    ---
    title: "Enterprise SSO setup"
    groups: ["enterprise"]
    ---
    ```
  </Step>
</Steps>

<div id="maintain-your-help-center">
  ## 维护您的帮助中心
</div>

随着产品不断迭代，支持内容也会逐渐过时。请建立相应流程，确保内容始终准确。

<Steps>
  <Step title="随产品发布及时更新">
    每次发布产品变更时，都要更新受影响的支持文章。将文档更新纳入发布流程。
  </Step>

  <Step title="定期查看反馈">
    每周检查文章评分和客户反馈。及时处理负面反馈，因为这往往表明内容表述不清或存在错误。
  </Step>

  <Step title="监控支持工单">
    如果客户为帮助中心已覆盖的问题提交工单，请排查自助服务为何没有解决问题。相关文章可能难以找到、表述不清，或内容不完整。
  </Step>

  <Step title="归档过时内容">
    删除或归档与已弃用功能相关的文章。过时内容会让客户感到困惑，并降低他们对帮助中心的信任。
  </Step>
</Steps>

<div id="next-steps">
  ## 后续步骤
</div>

你的帮助中心已准备好上线。部署后：

1. 在产品和网站中添加指向帮助中心的链接。
2. 监控Assistant对话和搜索查询，找出内容空白。
3. 每周查看反馈评分，改进评分较低的文章。
4. 跟踪工单量，衡量自助服务的效果。

优秀的帮助中心既能降低支持成本，又能提升客户满意度。请投入精力完善内容，有效解答常见问题。
