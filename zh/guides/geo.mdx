像 ChatGPT、Perplexity 和 Google AI Overviews 这样的 AI 工具，越来越多地会直接回答用户问题，并引用信息来源，而不是只列出链接。当开发者问“如何用[你的产品]进行身份验证”时，优化良好的文档页面就会在答案中被引用。结构不佳的页面则会被跳过——即使它在传统搜索中的排名很高。

生成式引擎优化 (GEO) 是指通过合理组织内容，让 AI 系统能够理解、信任并准确引用内容的一种实践。

<div id="how-geo-differs-from-seo">
  ## GEO 与 SEO 的区别
</div>

传统 SEO 是针对会对网页进行排序并提供链接的搜索引擎进行优化。GEO 则是针对会在生成式回答中读取、总结并引用网页内容的 AI 系统进行优化。

两者在机制上有几个重要区别：

|      | SEO            | GEO                |
| ---- | -------------- | ------------------ |
| 目标   | 在搜索结果中获得更高排名   | 在 AI 生成的回答中被引用     |
| 关键信号 | 反向链接、关键词、页面权威性 | 内容准确性、结构、直接明了      |
| 用户行为 | 点击链接           | 阅读 AI 生成的回答        |
| 偏好格式 | 任何结构良好的内容      | 易于快速浏览、能够直接回答问题的内容 |

好消息是：两者的基础原则高度重叠。准确、结构清晰且能直接回答问题的内容，在两种场景下通常都表现良好。GEO 与其说依赖技巧，不如说更依赖表达是否清晰。

<div id="how-ai-systems-decide-what-to-cite">
  ## AI 系统如何决定引用哪些内容
</div>

AI 答案引擎会根据几个关键因素来评估内容：

**直接性。** AI 系统会优先选择能直接回答问题的内容。相比先用三段背景铺垫、之后才给出答案的页面，开头就直接回答问题的页面更可能被引用。

**准确性和可信度信号。** AI 系统更青睐来自权威来源、且事实可靠的内容。对文档而言，这意味着技术内容准确、版本保持一致，以及内容与产品的实际行为相符。

**结构清晰度。** 逻辑组织清晰的内容——包含明确的标题、列表和代码块——更容易被 AI 系统正确解析和摘录。

**具体性。** 含糊、停留在高层概述的内容 (“此功能灵活且强大”) 不如具体、详细的内容更容易被引用 (“当超过每分钟 100 次请求的速率限制时，此端点会返回 429 状态码”) 。

<div id="write-content-ai-systems-can-cite">
  ## 编写便于 AI 系统引用的内容
</div>

<div id="lead-with-the-answer">
  ### 先说答案
</div>

组织每个章节时，都要把最重要的信息放在最前面。向 AI 工具提问的用户想要的是直接的答案——不要铺垫，不要先讲背景，也不要在切入重点前先加一堆限定说明。

````mdx
<!-- 直接给出答案 -->
## How to authenticate API requests

Include your API key in the Authorization header of every request:

```bash
curl -H "Authorization: Bearer YOUR_API_KEY" https://api.example.com/endpoint
```

<!-- 答案被藏在后面 -->
## Authentication

Authentication is an important part of using our API. Before you can make any requests, you'll need to understand how our authentication system works. Our API uses bearer tokens...
````

<div id="use-headings-that-match-questions">
  ### 使用与用户问题一致的标题
</div>

将 H2 和 H3 标题写成用户会提出的问题，而不是主题标签。AI 系统在决定呈现哪些内容时，会将用户查询与标题文本进行匹配。

```mdx
<!-- 匹配查询的标题 -->
## How do I rotate my API keys?

<!-- 主题标签——较弱 -->
## API key management
```

<div id="be-specific-with-numbers-limits-and-examples">
  ### 明确写出数字、限制和示例
</div>

模糊的描述不会被引用，具体且准确的细节才会。AI 系统可以准确引用“速率限制：每个 API 密钥 每分钟 100 次请求”这类表述；而“我们的 API 有速率限制”则无法为 AI 提供任何有用的可引用信息。

对于每个配置选项、参数或行为：

* 写明确切的值或范围
* 说明达到边界值时会发生什么
* 提供具体的代码示例

<div id="keep-a-consistent-terminology">
  ### 保持术语前后一致
</div>

AI 系统会在整个页面中建立上下文。如果你把同一事物交替称为“API 密钥”“access token”和“API token”，AI 生成摘要时可能会用错术语，或混淆这些词是否指的是同一个概念。保持术语一致——每个概念只使用一个名称，并在全文中统一使用——有助于 AI 系统准确表达你的内容。

<div id="format-for-ai-parsing">
  ## 供 AI 解析的格式
</div>

<div id="use-sequential-non-skipping-heading-hierarchy">
  ### 使用连续且不跳级的标题层级
</div>

不要从 H2 跳到 H4。AI 系统会通过标题层级来理解各个主题之间的关系。层级清晰且保持一致的结构，更容易被正确解析。

<div id="label-all-code-blocks">
  ### 为所有代码块标明语言
</div>

始终为代码块声明其编程语言。这有助于 AI 系统理解其读取的内容，并根据用户所处的上下文提供合适的示例。

````mdx
```python
import requests
response = requests.get(url, headers={"Authorization": f"Bearer {api_key}"})
```
````

<div id="write-alt-text-for-images-and-diagrams">
  ### 为图片和图表编写替代文本
</div>

AI 系统无法看见图片。如果某个图表是解释某个概念的主要方式，请添加一段能传达相同信息的文字描述。替代文本应说明图表具体展示了什么，而不只是写“架构图”，这样 AI 系统才能据此理解内容。

<div id="use-specific-references-instead-of-pronouns">
  ### 使用具体指代，而不是代词
</div>

写“API 密钥”，不要写“它”或“这个值”。AI 系统会摘录内容，导致周围的上下文丢失。具体的名词指代即使被摘录出来也仍然准确；代词则容易产生歧义。

<div id="mintlify-configuration-for-geo">
  ## Mintlify 的 GEO 配置
</div>

<div id="add-descriptive-page-metadata">
  ### 添加具有说明性的页面元数据
</div>

页面标题和描述是 AI 系统理解页面主题时最重要的信号之一。撰写时，请把它们当作对“这个页面能帮助用户完成什么？”这一问题的回答。

```mdx
---
title: "How to authenticate API requests"
description: "Add your API key to the Authorization header to authenticate requests. Includes examples in JavaScript, Python, and cURL."
---
```

<div id="control-indexing-settings">
  ### 控制索引设置
</div>

默认情况下，Mintlify 会为 `docs.json` 导航中包含的页面编制索引。若要将隐藏页面也纳入 AI 助手上下文和搜索范围：

```json docs.json
{
  "seo": {
    "indexing": "all"
  }
}
```

<div id="llmstxt">
  ### LLMs.txt
</div>

Mintlify 会自动为你的文档生成 `llms.txt` 文件。LLMs.txt 的作用类似于传统搜索中的 `sitemap.xml`，会为 AI 系统提供文档的结构化索引。无需任何配置。

你可以在文档 URL 后追加 `/llms.txt`，查看对应的 LLMs.txt。

<div id="allow-ai-agents-in-robotstxt">
  ### 在 robots.txt 中允许 AI 智能体访问
</div>

你的 `robots.txt` 文件决定哪些爬虫可以抓取你的网站。如果其中屏蔽了 AI 用户代理，ChatGPT、Claude 和 Perplexity 等工具就无法读取你的文档，也无法在回答中引用这些内容。

Mintlify 自动生成的 `robots.txt` 默认允许所有爬虫访问。如果你使用[自定义 robots.txt 文件](/zh/optimize/seo#custom-sitemaps-and-robotstxt-files)，请确保它不会屏蔽 AI 智能体。常见的 AI 用户代理包括：

* `GPTBot`, `OAI-SearchBot`, `ChatGPT-User` (OpenAI)
* `ClaudeBot`, `Claude-User` (Anthropic)
* `PerplexityBot` (Perplexity)
* `Google-Extended` (Gemini)

会屏蔽所有爬虫的 `robots.txt` 同样也会屏蔽 AI 智能体：

```txt Bad — blocks all AI agents
User-agent: *
Disallow: /
```

如果你想在允许 AI 智能体访问的同时屏蔽特定爬虫，只需针对你想限制的机器人：

```txt Good — allows AI agents
User-agent: BadBot
Disallow: /

User-agent: *
Disallow: /private/
```

运行 [`mint score`](/zh/cli/commands#mint-score)，检查您站点的 `robots.txt` 是否允许 AI 智能体访问。未屏蔽任何 AI 用户代理时，`robotsTxtAllowsAI` 检查即会通过。

<div id="test-how-ai-tools-represent-your-docs">
  ## 测试 AI 工具如何表述你的文档
</div>

定期测试 AI 工具是否准确引用你的文档。

在 ChatGPT、Perplexity 和 Claude 中针对你的产品提出具体问题：

* “如何使用 [your product] 对 API 请求进行身份验证？”
* “如果我超出 [your product] 的速率限制，会发生什么？”
* “请展示如何处理 [your product] API 中的错误。”

检查回复中的以下几点：

* 是否有引用你的文档
* 引用的内容是否准确
* 代码示例是否正确
* AI 推荐的方法是否恰当

如果 AI 工具就你的产品给出了错误答案，通常说明你的文档表述含糊、内容缺失或前后矛盾，而不是 AI 本身出了问题。

<div id="frequently-asked-questions">
  ## 常见问题
</div>

<AccordionGroup>
  <Accordion title="GEO 会取代 SEO 吗？">
    不会。传统搜索仍然带来大量流量，而且很多用户更愿意点击进入文档，而不是阅读 AI 生成的摘要。GEO 和 SEO 是互补的——结构清晰、内容准确并且能直接回答问题的文档，在两者中都会有良好表现。这些做法也会彼此强化。
  </Accordion>

  <Accordion title="GEO 优化通常多久会见效？">
    很多情况下会比 SEO 更快。Perplexity 和 ChatGPT 这类 AI 系统抓取和索引内容的频率通常高于传统搜索引擎。内容清晰度和结构上的改进，可能在几天到几周内就反映在 AI 生成的回答中。不过，AI 系统也会考虑域名权威性和链接信号，而这些因素往往需要更长时间积累。
  </Accordion>

  <Accordion title="我需要专门针对 Google AI Overviews 做额外优化吗？">
    Google AI Overviews 使用的信号与 Google 搜索基本相同，但会对能直接回答特定查询的内容赋予更高权重。对于某个查询，已经在 Google 搜索中表现良好的页面，更有可能出现在同一查询的 AI Overviews 中。这里同样适用 GEO 的核心做法——先给出答案、提供具体细节、保持结构清晰。
  </Accordion>

  <Accordion title="面向 AI 和真人读者，写法需要不同吗？">
    不需要。对人类读者来说清晰直接的内容，对 AI 系统同样清晰直接。为了迎合 AI 而牺牲人类可读性，往往会适得其反，最终写出的内容既不好读，也不容易被准确引用。先为你的用户而写；只要技术写作做得好，GEO 自然会随之提升。
  </Accordion>

  <Accordion title="什么是 llms.txt？我需要配置它吗？">
    LLMs.txt 是一种约定，类似 robots.txt，用于向 AI 系统提供文档的结构化索引。Mintlify 会自动生成它，你不需要手动配置。你可以在 `https://your-docs-domain.com/llms.txt` 查看你的 LLMs.txt 文件。
  </Accordion>
</AccordionGroup>
