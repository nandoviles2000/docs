开发者文档可帮助开发者理解你的产品并完成集成。优质文档能帮助他们更充分地使用你的产品，减轻支持压力，加快采用进程，并提升开发者体验。

Mintlify 提供专为开发者文档打造的基础设施。

* **API 参考生成**：根据 OpenAPI 规范生成交互式 [API 参考](/zh/api-playground/overview)，让开发者能够直接在文档中测试端点。
* **带解释的代码块**：[助手](/zh/assistant/index) 可结合上下文解释代码示例，帮助开发者理解实现细节。
* **Git 同步**：通过 [GitHub](/zh/deploy/github) 或 [GitLab](/zh/deploy/gitlab) 让文档与代码库保持同步。
* **版本管理**：为多个[版本](/zh/organize/navigation#versions)维护文档，让使用旧版本的开发者也能找到准确的信息。

<div id="prerequisites">
  ## 先决条件
</div>

如果你还没有创建 Mintlify 项目，请参阅[快速入门](/zh/quickstart)部署你的网站。

* OpenAPI 格式的 API 规范 (如果你要为 API 编写文档)
* 用于存放文档的 Git 仓库
* 你的 Mintlify 组织的管理员访问权限

<div id="migrate-existing-documentation">
  ## 迁移现有文档
</div>

如果你是从零开始编写文档，请跳到[规划文档结构](#plan-your-documentation-structure)。

<div id="audit-existing-content">
  ### 盘点现有内容
</div>

检查您当前的文档，了解已有内容以及需要迁移的内容。

* **API 参考**：是根据规范生成的，还是手动编写的？您为哪些端点编写了文档？
* **指南和教程**：目前有哪些集成指南？它们是否还是最新的？
* **代码示例**：您使用哪些语言和框架？
* **SDK 文档**：您是否为每个 SDK 分别提供文档？
* **变更日志**：您是否维护变更日志或发布说明？
* **元数据**：您的内容是否包含日期、作者和标签等元数据？

<div id="export-your-existing-content">
  ### 导出现有内容
</div>

* 导出为 **Markdown**，可最方便地迁移到 Mintlify。
* 导出 **OpenAPI 规范**，用于 API 参考内容。
* 如果无法导出为 Markdown，请导出为 **HTML**，再将其转换为 Markdown。

<div id="plan-your-documentation-structure">
  ## 规划文档结构
</div>

开发者文档通常包含多种内容类型。请根据用户理解您产品的方式来组织导航。

```json docs.json example
{
  "navigation": {
    "groups": [
      {
        "group": "Get Started",
        "pages": [
          "introduction",
          "quickstart",
          "authentication"
        ]
      },
      {
        "group": "Guides",
        "pages": [
          "guides/webhooks",
          "guides/error-handling",
          "guides/rate-limits",
          "guides/pagination"
        ]
      },
      {
        "group": "API Reference",
        "pages": [
          "api-reference/overview",
          "api-reference/users",
          "api-reference/orders",
          "api-reference/products"
        ]
      },
      {
        "group": "SDKs",
        "pages": [
          "sdks/javascript",
          "sdks/python",
          "sdks/go"
        ]
      }
    ]
  }
}
```

更多配置选项，请参阅[导航](/zh/organize/navigation)。

<div id="set-up-your-api-reference">
  ## 设置 API 参考
</div>

如果你已有 API，可以根据 OpenAPI 规范生成交互式 API 参考。

<Steps>
  <Step title="添加 OpenAPI 规范">
    将 OpenAPI 规范文件添加到项目中。支持 YAML 或 JSON 格式。

    ```text
    your-project/
    ├── docs.json
    ├── openapi.yaml
    └── api-reference/
        └── overview.mdx
    ```
  </Step>

  <Step title="在 docs.json 中配置规范">
    在 `docs.json` 配置中引用 OpenAPI 文件。

    ```json Configuration example
    {
      "openapi": "openapi.yaml"
    }
    ```
  </Step>

  <Step title="将端点添加到导航">
    将这些端点添加到 `docs.json` 的导航中。有关配置选项，请参阅 [OpenAPI 设置](/zh/api-playground/openapi-setup)。

    ```json Navigation example
    {
      "group": "API Reference",
      "pages": [
        "api-reference/overview",
        "api-reference/users/list-users",
        "api-reference/users/get-user",
        "api-reference/users/create-user"
      ]
    }
    ```
  </Step>
</Steps>

<div id="set-up-the-assistant">
  ## 设置助手
</div>

助手可帮助开发者查找答案并理解代码示例。你可以在[仪表板](https://dashboard.mintlify.com/products/assistant/settings)中进行配置。

* **示例问题**：添加面向开发者的示例问题，例如“如何对 API 请求进行身份验证？”或“如何处理 webhook？”
* **代码解释**：当开发者针对特定示例提问时，助手可以结合上下文解释代码块。

<div id="set-up-versioning">
  ## 设置版本管理
</div>

如果你维护多个 API 版本，请配置版本管理，以便开发者找到对应版本的文档。

```json Versioning example
{
  "versions": ["v2", "v1"],
  "navigation": {
    "groups": [
      {
        "group": "API Reference",
        "version": "v2",
        "pages": ["v2/api-reference/users"]
      },
      {
        "group": "API Reference",
        "version": "v1",
        "pages": ["v1/api-reference/users"]
      }
    ]
  }
}
```

更多信息，请参阅 [版本](/zh/organize/navigation#versions)。

<div id="connect-to-your-repository">
  ## 连接你的仓库
</div>

安装 Mintlify [GitHub App](/zh/deploy/github)，让文档与代码库保持同步，并支持协作贡献。

<Steps>
  <Step title="连接你的仓库">
    在 [仪表板](https://dashboard.mintlify.com) 中关联你的 GitHub 仓库。这样一来，你推送更改时就会自动部署。
  </Step>

  <Step title="配置分支设置">
    设置你的生产分支，并为拉取请求 (PR) 启用预览部署。这样你就可以在文档更改正式上线前先进行预览和检查。
  </Step>
</Steps>

<Note>
  如果你使用 GitLab，请参阅 [GitLab](/zh/deploy/gitlab) 了解配置说明。
</Note>

<div id="maintain-your-documentation">
  ## 维护你的文档
</div>

开发者文档需要定期更新，才能确保信息准确、可用。

<Steps>
  <Step title="保持 API 参考最新">
    每次发布变更时，都应更新 OpenAPI 规范。如果规范是从代码生成的，请在发布流程中将这一步自动化。
  </Step>

  <Step title="更新代码示例">
    发布新的 SDK 版本或产品更新时，请检查代码示例。过时的示例会导致集成失败，并增加支持请求。
  </Step>

  <Step title="维护变更日志">
    记录破坏性变更、新功能和弃用项。开发者依靠变更日志来了解不同版本之间的变化。更多信息，请参阅 [Changelogs](/zh/create/changelogs)。
  </Step>

  <Step title="监控反馈">
    查看助手对话和搜索分析，找出文档中的内容空白。如果开发者反复询问同一主题，请改进该部分。更多信息，请参阅 [Maintenance](/zh/guides/maintenance)。
  </Step>
</Steps>

<div id="next-steps">
  ## 后续步骤
</div>

您的开发者文档已准备好上线。部署完成后：

1. 向开发者社区宣布文档已上线。
2. 监控搜索趋势和助手对话，找出内容缺口。
3. 建立流程，在每次 API 发布时同步更新文档。
4. 收集开发者反馈，持续改进内容。
