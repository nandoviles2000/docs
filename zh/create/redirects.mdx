当你更改 docs 文件夹中文件的路径时，该页面的 URL 路径也会随之改变。这种情况可能发生在你重新组织文档结构或更改侧边栏标题时。

<div id="redirects">
  ## 重定向
</div>

<Note>
  重定向**不能**包含 URL 锚点 (如 `path#anchor`) 或查询参数 (如 `path?query=value`) 。
</Note>

在 `docs.json` 文件中添加 `redirects` 字段以设置重定向。

```json
"redirects": [
  {
    "source": "/source/path",
    "destination": "/destination/path"
  }
]
```

这会将 `/source/path` 重定向到 `/destination/path`。

默认情况下，重定向为永久性 (308)。如需使用临时重定向 (307)，请将 `permanent` 设置为 `false`。

```json
"redirects": [
  {
    "source": "/source/path",
    "destination": "/destination/path",
    "permanent": false
  }
]
```

307 和 308 都会保留原始请求的 HTTP 方法 (与 301 和 302 不同) ，因此适合用于重定向 POST 请求。

<div id="wildcard-redirects">
  ### 通配符重定向
</div>

要匹配通配符路径，请在参数后添加 `*`。在此示例中，`/beta/:slug*` 会匹配 `/beta/introduction`，并将其重定向到 `/v2/introduction`。

```json
"redirects": [
  {
    "source": "/beta/:slug*",
    "destination": "/v2/:slug*"
  }
]
```

<div id="partial-wildcard-redirects">
  ### 部分通配符重定向
</div>

使用部分通配符匹配以特定前缀开头的 URL 路径段。

```json
"redirects": [
  {
    "source": "/articles/concepts-*",
    "destination": "/collections/overview"
  }
]
```

这会匹配所有带有 `/articles/concepts-` 路径的 URL，例如 `/articles/concepts-getting-started` 和 `/articles/concepts-overview`，并将它们统一重定向到 `/collections/overview`。

你还可以在目标 URL 中使用捕获到的通配符值进行替换。

```json
"redirects": [
  {
    "source": "/old/article-*",
    "destination": "/new/article-*"
  }
]
```

这会将 `/old/article-123` 重定向到 `/new/article-123`，并保留前缀后捕获的值。

<div id="avoid-infinite-redirects">
  ### 避免无限重定向
</div>

为避免无限循环，请不要创建让路径相互重定向的循环重定向。

```json
"redirects": [
  {
    "source": "/docs/:slug*",
    "destination": "/help/:slug*"
  },
  {
    "source": "/help/:slug*",
    "destination": "/docs/:slug*"
  }
]
```

<div id="check-for-broken-links">
  ## 检查失效链接
</div>

使用 [CLI](/zh/cli) 查找失效链接。

```bash
mint broken-links
```
