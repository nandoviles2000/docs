Mintlify 会自动处理许多 SEO 最佳实践，包括：

* 自动生成元标签
* 自动生成站点地图和 `robots.txt` 文件
* 语义化 HTML 结构
* 移动设备优化

你可以通过在 `docs.json` 或页面的 frontmatter 中添加 `metatags` 字段，完全自定义站点的元标签。

<div id="automatically-generated-meta-tags">
  ## 自动生成的 元标签
</div>

Mintlify 会为每个页面生成以下 元标签。你可以在 `docs.json` 或页面的 frontmatter 中指定这些 元标签，以覆盖默认值。

**基础元数据：**

* `charset: utf-8` - 字符编码
* `og:type: website` - Open Graph 类型
* `og:site_name` - 你的文档站点名称
* `twitter:card: summary_large_image` - Twitter 卡片类型

**页面级元数据：**

* `title` - 页面标题，格式为“页面标题 - 站点名称”
* `og:title` - Open Graph 标题，默认为页面标题
* `twitter:title` - Twitter 标题，依次回退为 `og:title` 和页面标题
* `description` - 页面描述
* `og:description` - Open Graph 描述，回退为页面描述
* `twitter:description` - Twitter 描述，依次回退为 `og:description` 和页面描述

**URL 和规范链接：**

* `canonical` - 根据页面 URL 自动生成
* `og:url` - 设置为规范 URL

**SEO 和索引：**

* `robots` - 根据页面元数据生成
* `noindex` - 根据页面元数据生成
* `keywords` - 根据页面元数据生成

**图片：**

* `og:image` - Open Graph 图片，`og:image:width` 设为 1200，`og:image:height` 设为 630
* `twitter:image` - Twitter 图片，`twitter:image:width` 设为 1200，`twitter:image:height` 设为 630

**浏览器和应用元数据：**

* `applicationName` - 你的文档站点名称
* `generator: Mintlify` - 标明站点生成器为 Mintlify
* `apple-mobile-web-app-title` - iOS 主屏幕应用名称
* `msapplication-TileColor` - Windows 磁贴颜色
* 来自你的配置的 favicon 和图标
* Sitemap 引用链接

你在 `docs.json` 的 `seo.metatags` 配置中定义的任何 元标签，也会自动注入到每个页面中，例如用于 Search Console 验证的 `google-site-verification`。

<div id="og-images">
  ## OG 图片
</div>

Mintlify 会自动为每个页面生成一张 Open Graph (OG) 图片。当你在社交媒体平台或即时通讯应用中分享链接时，这张图片会显示为社交预览图。

默认 OG 图片包含以下属性：

* 宽度：1200px
* 高度：630px
* 你的站点 logo，来自 `docs.json` 中的 `logo` 字段
* 页面标题，来自页面 frontmatter 中的 `title`
* 页面描述，来自页面 frontmatter 中的 `description`
* 你的站点主色，来自 `docs.json` 中的 `colors` 字段

<div id="custom-og-images">
  ### 自定义 OG 图片
</div>

根据你需要的控制程度，自定义 OG 图片有三种方式。

**自定义背景图片**

如果你想使用自定义背景图片，同时保留自动生成的 logo、标题和描述叠加层，请在 `docs.json` 中设置 `thumbnails.background`。

```json Example docs.json
"thumbnails": {
  "background": "/images/og-background.png"
}
```

完整的自定义选项列表，请参阅 [`thumbnails`](/zh/organize/settings-appearance#thumbnails)。

**所有页面共用的静态 OG 图片**

如果要用同一张静态图片完全替换所有页面自动生成的图片，请在全局元标签中设置 `og:image`。

```json Example docs.json
"seo": {
  "metatags": {
    "og:image": "https://example.com/og-image.png"
  }
}
```

**特定页面的静态 OG 图片**

如需为单个页面覆盖 OG 图片，请在该页面的 frontmatter 中设置 `og:image`。

```yaml Example frontmatter
---
title: "Your page title"
description: "Your page description"
"og:image": "https://example.com/custom-og.png"
---
```

<Note>
  在 meta 标签中全局或按页面设置 `og:image`，会将自动生成的社交预览图替换为静态图片。如果你想让 Mintlify 在自定义背景上自动叠加你的徽标、页面标题和描述，请改用 [`thumbnails.background`](/zh/organize/settings-appearance#param-thumbnails-background)。
</Note>

<div id="global-meta-tags">
  ## 全局元标签
</div>

要为所有页面设置默认的元标签，请在 `docs.json` 中添加 `metatags` 字段。

```json
"seo": {
    "metatags": {
        "og:image": "link to your default meta tag image"
    }
}
```

<div id="set-a-canonical-url">
  ### 设置规范 URL
</div>

如果你使用自定义域名，请设置 `canonical` 元标签，以确保搜索引擎将你首选的域名编入索引。规范 URL 可告知搜索引擎，你的文档应以哪个版本为主。当你的文档可通过多个 URL 访问时，这样做可以提升 SEO 效果，并避免重复内容问题。

```json
"seo": {
    "metatags": {
        "canonical": "https://www.your-custom-domain-here.com"
    }
}
```

<Note>
  务必在已部署的网站上验证规范 URL 的行为。本地构建会在 URL 中额外带上 `/src/_props`，但这只是构建产物，不属于规范 URL 的一部分。
</Note>

<div id="page-specific-meta-tags">
  ## 页面级 元标签
</div>

要设置页面级 元标签，请将它们添加到页面的 frontmatter 中。

页面级 元标签包括：

* `title` - 页面标题
* `description` - 页面描述，显示在页面标题下方，也会出现在某些搜索引擎结果中
* `keywords` - 以逗号分隔的关键词
* `og:title` - 用于社交分享的 Open Graph 标题
* `og:description` - Open Graph 描述，未设置时回退到 `description`
* `og:image` - Open Graph 图片 URL
* `og:url` - Open Graph URL
* `og:type` - Open Graph 类型，例如 &quot;article&quot; 或 &quot;website&quot;
* `og:image:width` - Open Graph 图片宽度
* `og:image:height` - Open Graph 图片高度
* `twitter:title` - Twitter 卡片标题，未设置时回退到 `og:title`，再回退到 `title`
* `twitter:description` - Twitter 卡片描述，未设置时回退到 `og:description`，再回退到 `description`
* `twitter:image` - Twitter 卡片图片
* `twitter:card` - Twitter 卡片类型，例如 `summary` 或 `summary_large_image`
* `twitter:site` - Twitter 站点账号
* `twitter:image:width` - Twitter 图片宽度
* `twitter:image:height` - Twitter 图片高度
* `noindex` - 设置为 `true` 以阻止搜索引擎收录
* `robots` - `robots` 元标签的值

<Tip>
  Twitter 元标签会自动继承对应的 Open Graph 标签。例如，如果你设置了 `og:title` 但没有设置 `twitter:title`，Twitter 卡片会使用 `og:title` 的值。只有当你希望 Twitter 上显示的文本与其他平台不同时，才需要显式设置 `twitter:title` 或 `twitter:description`。
</Tip>

```mdx
---
title: "Your example page title"
description: "Page-specific description"
"og:title": "Social media title"
"og:description": "Custom description for social sharing"
"og:image": "link to your meta tag image"
"twitter:title": "Twitter-specific title"
keywords: ["keyword1", "keyword2"]
---
```

<Note>
  你必须将包含冒号的 元标签放在引号中。例如：`og:title: "社交媒体标题"`。

  你必须将 `keywords` 字段写成 YAML 数组格式。例如：`keywords: ["keyword1", "keyword2", "keyword3"]`。
</Note>

<div id="sitemaps-and-robotstxt-files">
  ## 站点地图和 robots.txt 文件
</div>

Mintlify 会自动生成 `sitemap.xml` 文件和 `robots.txt` 文件。你可以在文档站点 URL 后附加 `/sitemap.xml` 来查看站点地图。

默认情况下，Mintlify 只会索引你在 `docs.json` 导航中包含的页面。对于仓库中存在但未在导航中列出的[隐藏页面](/zh/organize/hidden-pages)，Mintlify 不会将其纳入以下内容：

* 搜索引擎站点地图
  * 站内文档搜索
  * [AI 助手](/zh/assistant/index)上下文
  * [MCP server](/zh/ai/model-context-protocol)搜索结果

如需将隐藏页面纳入搜索索引，请在 `docs.json` 中添加 `seo.indexing`：

```json
"seo": {
    "indexing": "all"
}
```

<Note>
  对于需要身份验证的文档站点，访问 sitemap 和 `robots.txt` 文件同样需要先进行身份验证。Sitemap 不包含属于[用户组](/zh/deploy/authentication-setup#control-access-with-groups)的页面。
</Note>

<div id="custom-sitemaps-and-robotstxt-files">
  ### 自定义 sitemap.xml 和 robots.txt 文件
</div>

如需添加自定义 `sitemap.xml` 或 `robots.txt` 文件，请在项目根目录下创建相应的 `sitemap.xml` 或 `robots.txt` 文件。添加自定义文件后，会覆盖系统自动生成的同名文件。如果删除自定义文件，则会重新使用默认文件。

<Tip>
  如果你的自定义 `robots.txt` 屏蔽了 `GPTBot`、`ClaudeBot` 或 `PerplexityBot` 等 AI 用户代理，AI 工具将无法抓取你的文档，也无法在回答中引用这些文档。详情请参阅 [在 robots.txt 中允许 AI 智能体](/zh/guides/geo#allow-ai-agents-in-robotstxt)。
</Tip>

<div id="disable-indexing">
  ## 禁止索引
</div>

如需防止搜索引擎收录某个页面，请在该页面的 [frontmatter](/zh/organize/pages) 中添加 `noindex: true`。

```yaml
---
noindex: true
---
```

<Tip>
  frontmatter 中设置了 `hidden: true` 的页面会自动视为 `noindex: true`。更多详情，请参阅[隐藏页面](/zh/organize/hidden-pages)。
</Tip>

你也可以在 `docs.json` 中将 `metatags.robots` 字段设为 `"noindex"`，为文档中的所有页面指定 `noindex`：

```json
"seo": {
    "metatags": {
      "robots": "noindex"
    }
  }
```

<div id="seo-best-practices">
  ## SEO 最佳实践
</div>

<AccordionGroup>
  <Accordion title="撰写清晰且具有描述性的标题和描述">
    * 使用清晰、描述准确的页面标题 (50–60 个字符)
    * 撰写有吸引力的描述 (150–160 个字符)
    * 包含相关关键词
    * 确保每个页面的标题和描述各不相同
  </Accordion>

  <Accordion title="优化内容结构">
    * 使用正确的标题层级 (H1 → H2 → H3)
    * 优先为读者写作，其次再考虑搜索引擎
    * 在标题和正文中加入相关关键词
    * 保持 URL 简短、表意明确，并按层级组织
    * 使用小标题和列表拆分长篇内容
  </Accordion>

  <Accordion title="内部链接策略">
    * 在文档中链接到相关页面
    * 使用描述明确的锚文本，而不是“点击这里”
    * 通过关联相关概念建立主题集群
    * 使用自动交叉引用功能
  </Accordion>

  <Accordion title="图片 SEO">
    * 为图片使用描述明确的文件名
    * 始终添加 alt 文本，以提升无障碍性和 SEO 效果
    * 优化图片文件大小，加快加载速度
    * 使用与内容相关且能提供支持的图片
  </Accordion>
</AccordionGroup>
