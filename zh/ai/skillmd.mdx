Mintlify 会在你项目的根目录下托管一个 `skill.md` 文件，用于说明 AI 智能体能通过你的产品执行哪些操作。

[skill.md 规范](https://agentskills.io/specification)是一种结构化的机器可读格式，可明确说明产品的能力、所需输入和约束条件，从而让智能体更可靠地使用这些信息。

Mintlify 会通过智能体循环分析你的文档，自动为项目生成一个 `skill.md` 文件。该文件会随着文档更新自动保持最新状态，无需手动维护。你也可以选择在项目根目录添加自定义 `skill.md` 文件，以覆盖自动生成的版本。

<Note>生成或更新 `skill.md` 文件最多可能需要 24 小时。</Note>

如需查看你的 `skill.md`，请在文档站点的 URL 后附加 `/skill.md`。Mintlify 仅为公开的文档站点生成 `skill.md` 文件。

<PreviewButton href="https://mintlify.com/docs/skill.md">
  打开此站点的 skill.md。
</PreviewButton>

<Tip>
  `llms.txt` 和 `skill.md` 文件都能帮助智能体使用你的文档，但两者用途不同。

  * `llms.txt` 是一个目录，列出所有文档页面及其描述，帮助智能体知道应到哪里查找信息。
  * `skill.md` 是一份能力摘要，告诉智能体可以通过你的产品完成什么、需要哪些输入，以及适用哪些约束条件。
</Tip>

<div id="use-skillmd-files-with-agents">
  ## 配合智能体使用 `skill.md` 文件
</div>

<Note>
  如果你使用[反向代理](/zh/deploy/reverse-proxy)，请将 `/skill.md`、`/.well-known/skills/*` 和 `/.well-known/agent-skills/*` 这些路径配置为转发到你的 Mintlify 子域名。
</Note>

当用户连接到你的 MCP server 时，其智能体无需单独安装这些技能，就能发现并使用你的 `skill.md` 文件作为 [MCP 资源](/zh/ai/model-context-protocol#mcp-resources)。

如需手动将你的技能添加到智能体上下文中，请使用 [skills CLI](https://www.npmjs.com/package/skills)。

```bash
npx skills add https://your-docs-domain.com
```

这会将您产品的能力加入智能体的上下文，使其能够代表用户执行操作。

<Tip>
  教用户如何将 `skill.md` 文件与智能体配合使用，这样他们在通过 AI 工具使用您的产品时就能获得更好的效果。
</Tip>

<div id="skillmd-structure">
  ## `skill.md` 结构
</div>

Mintlify 会根据 [agentskills.io 规范](https://agentskills.io/specification) 生成一个 `skill.md` 文件。生成的文件包括：

* **元数据**：项目名称、描述和版本。
* **能力**：智能体可以借助你的产品完成的事项。
* **技能**：按类别组织的具体操作。
* **工作流**：完成常见任务的分步流程。
* **集成**：支持的工具和服务。
* **上下文**：有关产品架构的背景信息。

<div id="custom-skill-files">
  ## 自定义技能文件
</div>

添加自定义技能文件，以覆盖自动生成的 `skill.md`。Mintlify 支持托管单个技能文件，也支持托管包含多个技能的目录。如果你删除所有自定义技能文件，Mintlify 会重新生成一个新的 `skill.md` 文件。

<div id="single-skill-file">
  ### 单个技能文件
</div>

在项目根目录中添加 `skill.md` 文件，以覆盖自动生成的文件。

<div id="multiple-skill-files">
  ### 多个技能文件
</div>

将多个技能文件添加到项目的 `.mintlify/skills/` 目录中。每个技能都必须放在各自的子目录里，并包含一个 `SKILL.md` 文件：

```
.mintlify/
  skills/
    payments/
      SKILL.md
    analytics/
      SKILL.md
```

当你有多个技能时，`/skill.md` 端点 会重定向到 `/.well-known/skills/index.json` 发现 端点，其中会列出所有可用技能。发现 端点 让每个技能都可以单独访问。

<Note>
  你可以同时使用这两种方式：使用根目录下的 `skill.md` 文件和 `.mintlify/skills/` 目录。发现索引会包含所有技能。
</Note>

<div id="use-symlinks-to-avoid-duplication">
  ### 使用符号链接避免重复
</div>

如果你的技能文件位于仓库中的其他位置 (例如 `plugins/` 或 `skills/` 目录) ，你可以将 `.mintlify/skills` 符号链接到该位置，而无需重复存放这些文件：

```bash
# Skills 文件位于顶层 skills/ 目录中
ln -s ../skills .mintlify/skills
```

```
project/
  skills/
    payments/
      SKILL.md
    analytics/
      SKILL.md
  .mintlify/
    skills -> ../skills
  docs.json
```

Mintlify 会在部署期间解析符号链接，因此技能文件会像直接存放在 `.mintlify/skills/` 中一样被识别并提供服务。这同时适用于目录符号链接和单个技能文件的符号链接。

<div id="frontmatter-fields">
  ### Frontmatter 字段
</div>

自定义 `skill.md` 文件必须以 YAML frontmatter 开头。

| Field           | Type   | Description                                   |
| --------------- | ------ | --------------------------------------------- |
| `name`          | string | 你的技能名称。                                       |
| `description`   | string | 对技能功能的简要描述。                                   |
| `license`       | string | 你的技能使用的许可证 (例如 `MIT` 或 `Apache-2.0`) 。        |
| `compatibility` | string | 要求或兼容性说明 (例如运行时依赖项) 。                         |
| `metadata`      | object | 以字符串键值对形式提供的附加元数据 (例如 `author` 或 `version`) 。 |
| `allowed-tools` | string | 该技能可使用的预先批准工具列表，以空格分隔 (实验性) 。                 |

```md Example frontmatter
---
name: mintlify
description: Build and maintain documentation sites with Mintlify. Use when creating docs pages, configuring navigation, adding components, or setting up API references.
license: MIT
compatibility: Requires Node.js for CLI. Works with any Git-based workflow.
metadata:
  author: mintlify
  version: "1.0"
---
```

<div id="skills-discovery-endpoints">
  ## Skills 发现端点
</div>

Mintlify 在 `/.well-known/skills/` 和 `/.well-known/agent-skills/` 提供 skills 目录，智能体可通过编程方式发现并获取你的技能文件。

<div id="agent-skills-discovery-recommended">
  ### 代理技能发现 (推荐)
</div>

`/.well-known/agent-skills/` 端点遵循 [agent-skills 0.2.0 discovery spec](https://schemas.agentskills.io/discovery/0.2.0/schema.json)，并支持内容完整性校验。

`GET /.well-known/agent-skills/index.json` 返回一个 JSON 清单，其中列出了所有可用技能：

```json
{
  "$schema": "https://schemas.agentskills.io/discovery/0.2.0/schema.json",
  "skills": [
    {
      "name": "my-product",
      "type": "skill-md",
      "description": "A brief description of what your skill does.",
      "url": "/.well-known/agent-skills/my-product/SKILL.md",
      "digest": "sha256:a1b2c3..."
    }
  ]
}
```

| 字段            | 描述                                                          |
| ------------- | ----------------------------------------------------------- |
| `$schema`     | agent-skills 0.2.0 发现规范的 Schema URL。                        |
| `name`        | 根据你的 `skill.md` frontmatter 中的 `name` 生成的、可安全用于 URL 的 slug。 |
| `type`        | 技能格式。始终为 `skill-md`。                                        |
| `description` | 来自你的 `skill.md` frontmatter 的简短描述，最多 1024 个字符。              |
| `url`         | 用于获取完整技能文件的路径。                                              |
| `digest`      | 技能文件内容的 `sha256` 哈希值，用于验证完整性。                               |

`GET /.well-known/agent-skills/{name}/SKILL.md` 返回特定技能的 `skill.md` 文件，该技能通过索引中其 slug 名称来标识。

<div id="skills-index">
  ### 技能索引
</div>

`/.well-known/skills/` 端点是最初的发现格式。

`GET /.well-known/skills/index.json` 会返回一个 JSON 清单，其中列出了所有可用技能：

```json
{
  "skills": [
    {
      "name": "my-product",
      "description": "A brief description of what your skill does.",
      "files": ["SKILL.md"]
    }
  ]
}
```

`name` 字段是根据 `skill.md` 的 frontmatter 中的 `name` 生成的、可安全用于 URL 的 slug。

<div id="single-skill-file">
  ### 单个技能文件
</div>

`GET /.well-known/skills/{name}/skill.md` 返回索引中按 slug 化名称标识的特定技能的 `skill.md` 文件。
