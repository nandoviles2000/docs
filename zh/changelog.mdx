<Update label="2026 年 4 月 17 日" tags={["新发布", "改进"]} rss={{ title: "Visibility 组件、MCP 文件系统访问、代理反馈、Git 设置向导等" }}>
  ## Visibility 组件

  全新的 [`Visibility`](/zh/components/visibility) 组件让你可以在同一页面上为人类读者和 AI 代理显示不同内容。将内容包裹在 `<Visibility for="humans">` 中，可仅在页面的 Web 版本中显示；包裹在 `<Visibility for="agents">` 中，则只会包含在供 AI 工具使用的 [Markdown 输出](/zh/ai/markdown-export)中。这样，你就可以针对不同受众定制说明、示例或格式，而无需维护单独的页面。

  ## 代理反馈

  在部署设置中启用[代理反馈](/zh/optimize/feedback#agent-feedback)，让代理能够针对你的文档提交结构化反馈。开启后，页面的 Markdown 版本会包含反馈说明，以便代理在访问文档时遇到问题时知道如何报告。目前，该功能作为测试版在仪表板的部署附加组件中提供。

  ## MCP 文件系统访问

  [MCP servers](/zh/ai/model-context-protocol) 现已包含 query docs filesystem 工具，让代理能够直接浏览和读取你的文档文件结构。代理可以浏览目录、读取完整页面内容，并在一次调用中批量读取多个页面。该工具取代了 `get_page` 工具。

  ## Git 设置向导

  Git 设置页面新增了一个分步向导，引导你首次连接 GitHub 或 GitLab 仓库。你可以选择一键克隆或手动选择仓库，并支持组织选择、分支配置和子目录设置。

  ## 工作流的 GitLab OAuth

  [工作流](/zh/agent/workflows)现已支持通过 OAuth 身份验证连接 GitLab 仓库。你可以在仪表板中连接 GitLab 账户，在工作流中将 GitLab 仓库用作文档源、触发仓库或上下文仓库。代理在 GitLab 上发起合并请求的方式，与它在 GitHub 上发起拉取请求 (PR) 类似。

  ## 改进

  * 现在，将有效的 MDX 组件粘贴到编辑器中时，会保留组件结构，而不是转换为纯文本。
  * 现在，较长的侧边栏导航标题会自动断字，以防止溢出。
  * 编辑器现在可以解析拆分配置文件中的 [`$ref` 引用](/zh/organize/settings#split-configuration-with-%24ref)。
  * [Slack 代理](/zh/agent/slack)的系统提示现已改进，可提供更准确、更有帮助的响应。
  * `llms.txt` 现在包含引用块摘要，以提供更好的页面描述。
  * 现在会在部署期间正确检测仓库中的自定义 `skill.md` 文件。

  ## 弃用

  * 基于文件的工作流已弃用。请改为在仪表板中创建工作流。现有的文件工作流将继续可用，但新的工作流必须在仪表板中创建。

  ## 错误修复

  * 修复了 `index.mdx` 文件中的相对链接无法正确解析的问题。
  * 修复了 Assistant 回复中代码块的复制按钮问题。
  * 修复了页面内容更改后目录未更新的问题。
  * 修复了代码块标题无法正确显示的问题。
  * 修复了深色模式的默认边框颜色问题。
  * 修复了 `mint analytics feedback` CLI 命令发送错误反馈类型值的问题。
  * 修复了数字步进按钮上的阴影瑕疵问题。
  * 修复了相关链接的客户端导航问题。
</Update>

<Update label="2026 年 4 月 10 日" tags={["新发布", "改进"]} rss={{ title: "CLI 分析、目录列表、多技能支持、Slack 机器人改进等" }}>
  ## CLI 分析

  [`mint analytics`](/zh/cli/analytics) 命令可让你直接在终端中查看流量、搜索查询、用户反馈和 Assistant 对话，从而更方便地与代理集成。

  使用子命令查看特定数据：

  * `mint analytics stats` — 查看指定日期范围内的浏览量、访客数、搜索次数、反馈和 Assistant 使用情况
  * `mint analytics search` — 查看搜索查询及其命中次数和点击率
  * `mint analytics feedback` — 查看用户提交的页面和代码片段反馈
  * `mint analytics conversation list` — 查看最近的 Assistant 对话

  所有子命令都支持 `--from`、`--to` 和 `--format` 标志。输出格式包括 `plain` (默认) 、`table`、`json` 和 `graph`。

  ## 目录列表

  带有[根页面](/zh/organize/navigation#root-page)的导航分组现在可以显示其子页面的[目录列表](/zh/organize/navigation#directory-listings)。你可以在分组、Tab 或顶层 `navigation` 对象上将 `directory` 属性设为 `"accordion"` 或 `"card"`，自动生成该部分内容的概览。这对于帮助中心以及其他需要让用户快速浏览某个部分全部页面的网站特别有用。

  ## 多技能支持

  你现在可以通过 `.mintlify/skills/` 目录提供多个[技能文件](/zh/ai/skillmd)。每个包含 `SKILL.md` 文件的子目录都会被自动发现并提供，因此你可以按功能或领域组织技能。

  ## Slack 代理改进

  * **多个部署**：拥有多个文档站点的组织现在可以在所有站点中使用 [Slack 代理](/zh/agent/slack)。首次使用时，该代理会提示你选择一个部署，并按 Slack 账户保存你的偏好设置。
  * **只读模式**：Slack 代理现在会对消息进行分类，对于只需检索信息的问题会以只读模式回复，而将写入权限保留给需要修改文档的请求。

  ## 用于认证 MCP 的客户端凭据

  认证 MCP server 现已支持[客户端凭据](/zh/ai/model-context-protocol#client-credentials)。你可以使用客户端凭据以编程方式连接，而无需通过浏览器登录——这非常适合服务端集成、CI/CD 流水线和自动化工作流。你可以在仪表板中的 MCP server 页面创建和管理凭据。

  * [`mint new`](/zh/cli/commands#mint-new) 命令现在支持通过 `--template` 标志从预定义模板创建项目。

<Update label="2026 年 3 月 27 日" tags={["新发布", "改进"]} rss={{ title: "Linear 和 Notion 集成、离线导出、内联 AI 编辑等更多功能" }}>
  ## Linear 集成

  在代理设置页面连接你的 Linear 工作区，即可授予[代理](/zh/agent/linear)访问 Linear issue 的权限。代理在生成文档更新时，可以将 issue 和评论作为上下文引用；你也可以直接在 Linear 工作区中将 issue 委派给代理处理。

  ## Notion 集成

  在代理设置页面连接你的 Notion 工作区，即可授予[代理](/zh/agent/notion)对你的 Notion 内容的读取权限。代理在生成文档更新时，可以将 Notion 页面作为上下文引用。

  ## 离线导出

  使用 [`mint export`](/zh/deploy/export) CLI 命令，可将整个文档站点打包为一个自包含的 zip 压缩包。分享该 zip 文件后，用户无需联网或拥有 Mintlify 账户，也能在浏览器中查看你的文档。

  ## 内联 AI 编辑

  使用内联 AI 编辑功能，直接在可视化编辑器中生成、重写和重组内容。选中文本后，可选择预设操作，或输入自定义指令。更改会以高亮差异的形式实时显示，方便你在应用前先行审查。

  ## 可组合的 `docs.json`

  使用 [`$ref` 引用](/zh/organize/settings#split-configuration-with-%24ref) 将大型配置拆分为多个较小的文件。每个 `$ref` 都指向一个在构建时解析的独立 JSON 文件。

  ## `data-active` CSS 选择器

  侧边栏项目、目录条目和导航下拉菜单现在都会暴露稳定的 [`data-active` 属性](/zh/customize/custom-scripts#css-selectors)，便于自定义 CSS 精确选中。你可以使用 `.toc-item[data-active]` 或 `#sidebar-content li[data-active]` 这类选择器来设置活动状态样式，而无需依赖内部类名。

  ## 代理技能发现端点

  文档站点现在会提供 `/.well-known/agent-skills/` 发现端点，并遵循 [agent-skills 0.2.0 规范](https://schemas.agentskills.io/discovery/0.2.0/schema.json)。AI 代理可以通过编程方式发现并获取你的[技能文件](/zh/ai/skillmd#discovery)，同时验证内容完整性。

  ## API 操场凭据

  新增的 [`api.playground.credentials`](/zh/api-playground/overview) 选项会在禁用代理时，随 API 操场请求发送由浏览器管理的凭据 (如 cookie 和会话令牌) 。这对于使用基于 cookie 的身份验证的 API 非常有用。

  ## 工作流 CLI 命令

  你现在可以使用 `mint workflow` CLI 命令通过命令行创建[工作流](/zh/agent/workflows)文件。交互式提示会引导你完成名称、触发器、上下文和说明的设置。

  ## 智能体 API v2

  你现在可以通过新的 `/v2/agent` [端点](/zh/api/agent/v2/create-agent-job) 以编程方式触发智能体。提交包含提示词和可选上下文的作业，然后轮询完成状态以及生成的拉取请求 (PR) 链接。这对于将智能体驱动的文档更新集成到你自己的 CI/CD 流程或内部工具中非常有用。

  ## 新增语言支持

  * 通过去除每个页面 `rsc` 负载中重复的 `navigation` 数据，页面体积进一步缩小——对于页面较多或导航结构复杂的站点，性能提升尤为明显
  * 更积极的预取机制让页面瞬时加载的情况更常见
