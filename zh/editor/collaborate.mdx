使用基于分支的工作流、拉取请求 (PR) 和预览部署，与团队协作文档。

如果你不熟悉 Git，请参阅[网页编辑器中的 Git 基础](/zh/editor/git-essentials)。

<div id="branch-based-collaboration">
  ## 基于分支的协作
</div>

使用分支并行处理文档更新，而不影响您的线上站点。

<div id="why-use-branches">
  ### 为什么要使用分支
</div>

* **隔离更改**：在不影响线上文档的情况下进行更新。
* **发布前审查**：在更改上线前获得团队成员的反馈。
* **并行工作**：多个团队成员可以同时在不同分支上开展工作。

<div id="recommended-workflow">
  ## 推荐工作流程
</div>

使用拉取请求 (PR) 提出更改，并在合并到线上文档之前与团队协作。此工作流程可确保团队在发布前审核更改，并保留清晰的更新历史。

<Steps>
  <Step title="创建拉取请求（PR）">
    准备好发布更改后，请在编辑器中创建拉取请求 (PR) 。如需详细了解如何使用拉取请求 (PR) ，请参阅 <a href="/zh/editor/publish">在网页编辑器中发布更改</a>。
  </Step>

  <Step title="审核拉取请求（PR）">
    在 GitHub 或 GitLab 等 Git 服务提供商中审核拉取请求 (PR) 。
  </Step>

  <Step title="处理反馈">
    当审核者请求修改时，请按要求进行修改并保存。后续更改会自动推送到现有的拉取请求 (PR) 。
  </Step>

  <Step title="合并拉取请求（PR）">
    在完成所有要求的修改、所需审核者已批准拉取请求 (PR) ，且所有自动化检查均已通过后，合并你的拉取请求 (PR) 。
  </Step>
</Steps>

<div id="preview-deployments">
  ## 预览部署
</div>

预览部署会生成临时 URL，方便您在更改正式上线前查看渲染后的效果。您可以使用预览部署收集对更改的反馈。

每次您将更改保存到分支时，预览部署都会自动更新。

<div id="access-preview-deployments">
  ### 访问预览部署
</div>

1. 点击编辑器工具栏中的 **发布**。
2. 点击预览 URL，即可在新标签页中打开预览部署。URL 格式为 `organization-branch-name.mintlify.app`。

<div id="share-previews">
  ### 共享预览
</div>

将预览部署 URL 分享给团队成员，以收集反馈。保存后续更改时，预览会自动更新。

<div id="preview-authentication">
  ### 预览身份验证
</div>

预览 URL 默认可公开访问。要仅允许已通过身份验证的组织成员访问，请在仪表板的 [Add-ons](https://dashboard.mintlify.com/products/addons) 页面启用预览身份验证。

<div id="share-editor-links">
  ## 分享编辑器链接
</div>

将编辑器中特定页面的直接链接分享给团队成员。你可以使用编辑器链接协作更新内容并修改页面。

打开页面时，编辑器会将该页面路径保存在 URL 中。复制浏览器地址栏中的 URL，即可分享给有权访问编辑器的团队成员。

URL 格式为：`https://dashboard.mintlify.com/{org}/{project}/editor/{branch}/~/{filepath}`

例如，`https://dashboard.mintlify.com/acme/docs/editor/main/~/guides/quickstart.mdx` 会在 `main` 分支中打开 `quickstart.mdx`。

任何有权访问你的 Mintlify 组织的用户，都可以使用该链接直接在编辑器中打开该文件。

<Tip>
  分享页面时，请告知对方你正在使用的分支，以便他们确认自己查看的是正确的版本。
</Tip>
