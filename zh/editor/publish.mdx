<div id="publishing-workflows">
  ## 发布工作流
</div>

编辑器支持两种发布文档更新的工作流。使用哪种工作流取决于仓库的分支保护规则以及您所使用的分支。

**创建拉取请求 (PR)&#x20;**：如果您的仓库配置了分支保护规则，要求更改在合并到部署分支前必须先通过拉取请求 (PR) ，编辑器会在您发布更改时创建一个拉取请求 (PR) 。

<Tip>
  当您在编辑器中创建拉取请求 (PR) 时，Mintlify 智能体会根据您的更改生成标题和描述。您可以在创建拉取请求 (PR) 之前编辑生成的标题和描述。
</Tip>

**直接发布**：如果您的仓库没有分支保护规则，您发布后，更改会合并到部署分支并立即部署。

| 分支类型                                                                     | 分支保护         | 发布工作流         |
| ------------------------------------------------------------------------ | ------------ | ------------- |
| <Tooltip headline="部署分支" tip="发布到您的线上文档站点的分支，通常为 'main'。">部署分支</Tooltip> | 无            | 提交并部署更改       |
| 部署分支                                                                     | 需要拉取请求 (PR)  | 创建拉取请求 (PR)   |
| <Tooltip headline="功能分支" tip="在合并到部署分支之前，您用于处理更新的独立分支。">功能分支</Tooltip>   | 无            | 将更改合并到部署分支并部署 |
| 功能分支                                                                     | 需要拉取请求 (PR)  | 创建拉取请求 (PR)   |

<Tip>
  您可以在 Git 服务提供商中配置分支保护规则，以要求使用拉取请求 (PR) 。请参阅 GitHub 文档中的 [About protected branches](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches) 或 GitLab 文档中的 [Protected branches](https://docs.gitlab.com/user/project/repository/branches/protected/)。
</Tip>

<div id="save-changes">
  ## 保存更改
</div>

在你编辑时，编辑器会跟踪你所做的更改。

* 新增或删除的文件。
* 页面内容编辑。
* 导航结构变更。
* 媒体上传与整理。
* 配置更新。

在部署分支上工作时，更改会自动保存。

<div id="review-branch-changes">
  ## 查看分支变更
</div>

当你在功能分支上工作时，发布面板会在 **Saved in branch** 下显示你的分支与部署分支之间的所有文件变更。其中包括你自己保存的更改，以及其他在同一分支上协作的队友所做的更改。

点击列表中的文件，即可打开差异视图，查看该分支与已发布内容之间的变更。文档文件会以可视化差异视图打开，其他类型的文件则会以源码差异视图打开。你可以借此在发布前检查分支上的全部变更。

无法显示差异的文件 (例如图片或已删除的文件) 也会显示在列表中，但无法点击。

<div id="publish-your-changes">
  ## 发布更改
</div>

点击工具栏中的 **Publish**。根据你的工作流，你的更改会立即部署，或者会在你的 Git 提供平台中创建一个拉取请求 (PR) ，供你合并。如果你当前在功能分支上，请先保存更改，再发布。

如果没有待处理的更改，或者当前分支已存在打开的拉取请求 (PR) ，则 **Publish** 按钮不可点击。

<Note>
  Mintlify 构建并部署你已发布的更改后，你的线上文档站点就会更新。这个过程通常需要 30 秒到几分钟。你可以在[仪表板](https://dashboard.mintlify.com)上查看更改的部署状态。
</Note>

## 解决冲突

当你的分支和部署分支对同一文件进行了互不兼容的更改时，就会产生冲突。

<div id="what-causes-conflicts">
  ### 导致冲突的原因
</div>

当你尝试合并分支，而这些分支对同一文件做出了不兼容的更改时，就会发生冲突。

* 你和另一位团队成员在不同分支上编辑了同一文件中的相同行。
* 你在一个分支上移动、重命名或删除了文件，而在另一个分支上又以不同方式修改了这些文件。

<div id="resolve-conflicts">
  ### 解决冲突
</div>

当冲突导致无法执行发布或切换分支等操作时，编辑器会显示警告。要解决冲突，请按照编辑器中的说明选择要保留的更改。

<div id="commit-signing">
  ## 提交签名
</div>

在你的[账户设置](https://dashboard.mintlify.com/settings/account)中完成授权后，即可使用你的 GitHub 账户为提交签名。未授权时，在网页编辑器中进行的提交会由 Mintlify GitHub App 签名。

将提交关联到你的账户，有助于准确记录是谁对你的文档进行了更改。
