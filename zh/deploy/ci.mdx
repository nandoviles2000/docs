<Info>
  [Pro and Enterprise plans](https://mintlify.com/pricing?ref=docs-ci) 包含适用于 GitHub 仓库的 CI 检查功能。
</Info>

使用 CI 检查可对文档进行 lint，发现错误，并在部署前收到警告。Mintlify CI 检查会在针对已配置部署分支发起的拉取请求 (PR) 中运行。

<div id="installation">
  ## 安装
</div>

首先，请按照 [GitHub](/zh/deploy/github) 页面中的步骤进行操作。

<Tip>
  Mintlify GitHub App 仅需访问存放文档内容的仓库。建议仅向其授予该仓库的访问权限。
</Tip>

## 配置

前往仪表板中的 [附加组件](https://dashboard.mintlify.com/products/addons) 页面，配置部署时启用的 CI 检查。开启你想运行的检查。

启用检查时，你可以选择以 `Warning` 或 `Blocking` 级别运行它们。

* `Warning` 级别的检查即使存在错误或建议，也不会返回失败状态。
* `Blocking` 级别的检查如果存在错误或建议，则会返回失败状态。

<div id="available-ci-checks">
  ## 可用的 CI 检查
</div>

<div id="broken-links">
  ### 失效链接
</div>

与 [CLI 链接检查器](/zh/cli/commands#mint-broken-links) 在本地计算机上的工作方式类似，失效链接 CI 检查会自动扫描文档内容，查找站点内页面之间失效的内部链接。它不会检查指向其他网站的外部链接。

要查看拉取请求 (PR) 中的失效链接详细结果，请点击 **Checks** 选项卡，然后选择 Mintlify 失效链接检查。结果会列出在该拉取请求 (PR) 中发现失效链接的所有文件。

<div id="vale">
  ### Vale
</div>

[Vale](https://vale.sh/) 是一款开源的规则式文稿检查工具，支持多种文档类型，包括 Markdown 和 MDX。使用 Vale 可检查文档在风格和语气上的一致性。

Mintlify 支持在 CI 检查中自动运行 Vale，并将结果显示为检查状态。

<div id="configuration">
  #### 配置
</div>

如果你的部署根内容目录中有 `.vale.ini` 文件，Vale CI 检查会使用该配置文件，以及你指定的 `stylesPath` 中的所有配置文件。

如果没有 Vale 配置文件，则会自动加载默认配置。

```mdx Default vale.ini configuration expandable
# 顶级样式
StylesPath = /app/styles
MinAlertLevel = suggestion
# 要忽略的内联 HTML 标签（code/tt 用于代码片段，img/url 用于链接/图片，a 用于锚点标签）
IgnoredScopes = code, tt, img, url, a
SkippedScopes = script, style, pre, figure

# 词汇表
Vocab = Mintlify

# 将 MDX 解析为 MD，以避免 JSX 解析的脆弱性问题
[formats]
mdx = md

# 仅匹配 MDX
[*.mdx]
BasedOnStyles = Vale
Vale.Terms = NO # 会强制执行非常严格的大小写规则，保持关闭

# 忽略 JSX/MDX 特有的语法模式
# `import ...`, `export ...`
# `<Component ... />`
# `<Component>...</Component>`
# `{ ... }`
TokenIgnores = (?sm)((?:import|export) .+?$), \
(?<!`)(<\w+ ?.+ ?\/>)(?!`), \
(<[A-Z]\w+>.+?<\/[A-Z]\w+>), \
\{[^}]*\}

# 排除多行 JSX 和花括号
# `<Component \n ... />`
BlockIgnores = (?sm)^(<\w+\n .*\s\/>)$, \
(?sm)^({.+.*})
```

如需在默认配置中添加自定义词汇表，请创建 `styles/config/vocabularies/Mintlify` 目录，并添加 `accept.txt` 和 `reject.txt` 文件。

* `accept.txt`：Vale linter 应忽略的词语。例如，产品名称或不常见的术语。
* `reject.txt`：Vale linter 应标记为错误的词语。例如，术语黑话或不符合文档语气的用词。

```text Example Vale file structure
/your-project
  |- docs.json
  |- .vale.ini
  |- styles/
    |- config/
      |- vocabularies/
        |- Mintlify/
          |- accept.txt
          |- reject.txt
  |- example-page.mdx
```

```text Example monorepo Vale file structure
/your-monorepo
  |- main.ts
  |- docs/
    |- docs.json
    |- .vale.ini
    |- styles/
      |- config/
      |- vocabularies/
        |- Mintlify/
          |- accept.txt
          |- reject.txt
    |- example-page.mdx
  |- test/
```

<Note>
  出于安全考虑，不支持使用绝对 `stylesPath`，也不支持包含 `..` 的 `stylesPath`。

  请使用相对路径，并将 `stylesPath` 文件包含在你的仓库中。
</Note>

<div id="packages">
  #### 软件包
</div>

Vale 支持一系列用于检查拼写和文风错误的[软件包](https://vale.sh/docs/keys/packages)。只要你将这些软件包按正确的 `stylesPath` 放在代码仓库中，它们就会根据你的 Vale 配置自动安装并运行。

对于未包含在代码仓库中的软件包，你可以指定 [Vale 软件包注册表](https://vale.sh/explorer)中的任意软件包，它们会自动下载并用于你的 Vale 配置。

<Note>
  出于安全原因，不支持自动下载不来自 [Vale 软件包注册表](https://vale.sh/explorer)的 软件包。
</Note>

<div id="vale-with-mdx">
  #### 在 `MDX` 中使用 Vale
</div>

<Note>
  MDX 原生支持需要 Vale 3.10.0 或更高版本。使用 `vale --version` 检查你的 Vale 版本。
</Note>

如需在 MDX 文件中使用 Vale 的文档内注释，请使用 MDX 风格的注释 `{/* ... */}`：

```mdx
{/* vale off */}

Vale ignores this text

{/* vale on */}
```

Vale 会自动识别并遵循 MDX 文件中的这些注释，无需额外配置。使用注释可跳过你希望 linter 忽略的行或部分内容。

<Warning>
  不要将 `{/* vale off */}` 或类似的 MDX 表达式注释，作为 JSX 组件的直接子节点放在同级元素之间。例如，不要放在 `<Steps>` 组件内两个 `<Step>` 元素之间。

  请将注释放在特定元素的内容内部，或调整内容结构，以避免使用注释。
</Warning>
