<Info>
  [Pro 计划](https://mintlify.com/pricing?ref=authentication) 包含密码身份验证。

  [Enterprise 计划](https://mintlify.com/pricing?ref=authentication) 包含所有身份验证方式。
</Info>

<Warning>
  身份验证仅适用于托管在自定义域名或 Mintlify 子域名上的文档 (例如 `docs.example.com` 或 `example.mintlify.dev`) 。使用[自定义基础路径](/zh/deploy/docs-subpath)时**不支持**身份验证 (例如 `example.com/docs`) 。
</Warning>

身份验证要求用户在访问您的文档前先登录。

启用身份验证后，用户必须登录才能访问任何内容。您可以将特定页面或分组配置为公开，同时保护其他页面。

<div id="configure-authentication">
  ## 配置身份验证
</div>

选择要配置的握手方式。

<Tabs>
  <Tab title="密码">
    <Info>
      密码身份验证仅提供访问控制，**不**支持按用户区分的功能，例如基于组的访问控制或 API 操场预填充。
    </Info>

    ### 前提条件

    * 您的安全要求允许用户之间共享密码。

    ### 设置

    <Steps>
      <Step title="创建密码。">
        1. 在您的仪表板中，前往 [身份验证](https://dashboard.mintlify.com/products/authentication)。
        2. 启用身份验证。
        3. 在 **Password Protection** 部分，输入一个高强度密码

        输入密码后，您的站点会重新部署。部署完成后，任何访问您站点的人都必须输入该密码才能访问您的内容。
      </Step>

      <Step title="分发访问权限。">
        通过安全方式将密码和文档 URL 发送给已获授权的用户。
      </Step>
    </Steps>

    ### 示例

    您的文档托管在 `docs.foo.com`，您需要一种无需跟踪单个用户的基础访问控制方式。您希望阻止公众访问，同时保持设置简单。

    在您的仪表板中**创建一个高强度密码**。向已获授权的用户**共享凭据**。
  </Tab>

  <Tab title="Mintlify 仪表板">
    ### 前提条件

    * 所有需要访问您的文档的用户都必须是您的 Mintlify 组织成员。

    ### 设置

    <Steps>
      <Step title="启用 Mintlify 仪表板身份验证。">
        1. 在您的仪表板中，前往 [身份验证](https://dashboard.mintlify.com/products/authentication)。
        2. 启用身份验证。
        3. 在 **自定义身份验证** 部分，点击 **Mintlify Auth**。
        4. 点击 **启用 Mintlify Auth**。

        启用 Mintlify 身份验证后，您的站点会重新部署。部署完成后，所有访问您站点的用户都必须登录其 Mintlify 组织账号，才能查看您的内容。
      </Step>

      <Step title="添加授权用户。">
        1. 在您的仪表板中，前往 [成员](https://dashboard.mintlify.com/settings/organization/members)。
        2. 添加所有需要访问您文档的用户。
        3. 根据他们的编辑权限分配相应的角色。
      </Step>
    </Steps>

    ### 示例

    您的文档托管在 `docs.foo.com`，并且整个团队都可以访问您的仪表板。您希望仅允许团队成员访问。

    在仪表板设置中**启用 Mintlify 身份验证**。

    通过检查所有团队成员在您的组织中是否均处于活跃状态来**验证团队访问权限**。
  </Tab>

  <Tab title="OAuth 2.0">
    ### 前提条件

    * 支持 Authorization Code Flow 的 OAuth 或 OIDC 服务器。
    * 能够创建一个可通过 OAuth 访问令牌访问的 API 端点 (可选，用于启用基于组的访问控制) 。

    ### 设置

    <Steps>
      <Step title="配置你的 OAuth 设置。">
        1. 在你的仪表板中，前往 [身份验证](https://dashboard.mintlify.com/products/authentication)。
        2. 启用身份验证。
        3. 在 **Custom Authentication** 部分中，点击 **OAuth**。
        4. 配置以下字段：

        * **Authorization URL**：你的 OAuth 端点。
        * **Client ID**：你的 OAuth 2.0 客户端标识符。
        * **Client Secret**：你的 OAuth 2.0 客户端密钥。
        * **Scopes** (可选) ：要请求的权限。复制**完整**的作用域字符串 (例如，对于 `provider.users.docs` 这样的作用域，请复制完整的 `provider.users.docs`) 。如果你需要不同的访问级别，请使用多个作用域。
        * **Additional authorization parameters** (可选) ：要添加到初始授权请求中的额外查询参数。
        * **Token URL**：你的 OAuth 令牌交换端点。
        * **Info API URL** (可选) ：你服务器上的端点，Mintlify 会调用它来获取用户信息。基于组的访问控制需要此项。如果省略，OAuth 流程将仅验证身份。
        * **Logout URL** (可选) ：你的 OAuth 提供商的原生登出 URL。当用户登出时，Mintlify 会根据此处配置的 URL 验证登出重定向，以确保安全。只有当重定向与配置的 `logoutUrl` 完全匹配时，重定向才会成功。如果你未配置登出 URL，用户将被重定向到 `/login`。Mintlify 使用 `GET` 请求重定向用户，并且不会附加查询参数，因此请将任何参数 (例如 `returnTo`) 直接包含在 URL 中。
        * **Redirect URL** (可选) ：用户完成身份验证后要重定向到的 URL。

        5. 点击 **Save changes**。

        配置好 OAuth 设置后，你的站点会重新部署。部署完成后，任何访问你站点的人都必须登录到你的 OAuth 提供商才能访问你的内容。
      </Step>

      <Step title="配置你的 OAuth 服务器。">
        1. 从你的[身份验证设置](https://dashboard.mintlify.com/products/authentication)中复制 **Redirect URL**。
        2. 将该重定向 URL 添加为你的 OAuth 服务器的已授权重定向 URL。
      </Step>

      <Step title="创建你的用户信息端点（可选）。">
        要启用基于组的访问控制，请创建一个 API 端点，并满足以下条件：

        * 响应 `GET` 请求。
        * 接受 `Authorization: Bearer <access_token>` 标头进行身份验证。
        * 以 `User` 格式返回用户数据。更多信息，请参阅[用户数据格式](#user-data-format)。

        Mintlify 会使用 OAuth 访问令牌调用此端点来获取用户信息。不会发送额外的查询参数。

        将此端点 URL 添加到你的[身份验证设置](https://dashboard.mintlify.com/products/authentication)中的 **Info API URL** 字段。
      </Step>
    </Steps>

    ### 示例

    你将文档托管在 `foo.com/docs`，并且在 `auth.foo.com` 上已有一个支持 Authorization Code Flow 的 OAuth 服务器。

    在你的仪表板中**配置 OAuth 服务器详细信息**：

    * **Authorization URL**：`https://auth.foo.com/authorization`
    * **Client ID**：`ydybo4SD8PR73vzWWd6S0ObH`
    * **Scopes**：`['provider.users.docs']`
    * **Token URL**：`https://auth.foo.com/exchange`
    * **Info API URL**：`https://api.foo.com/docs/user-info`
    * **Logout URL**：`https://auth.foo.com/logout?returnTo=https%3A%2F%2Ffoo.com%2Fdocs`

    在 `api.foo.com/docs/user-info` 创建一个**用户信息端点**，它需要具有 `provider.users.docs` 作用域的 OAuth 访问令牌，并返回：

    ```json
    {
      "groups": ["engineering", "admin"],
      "expiresAt": 1735689600,
      "apiPlaygroundInputs": {
        "header": {
          "Authorization": "Bearer user_abc123"
        }
      }
    }
    ```

    <Note>
      使用用户信息响应中的 `expiresAt` 字段控制会话时长。它是一个 Unix 时间戳 (自纪元以来的秒数) ，用于指定会话何时过期。更多详细信息，请参阅[用户数据格式](#user-data-format)。
    </Note>

    **将你的 OAuth 服务器配置为允许重定向到你的回调 URL。**
  </Tab>

  <Tab title="JWT">
    ### 前提条件

    * 可生成并签名 JWT 的身份验证系统。
    * 用于生成重定向 URL 的后端服务。

    ### 设置

    <Steps>
      <Step title="生成私钥。">
        1. 在你的仪表板中，前往 [身份验证](https://dashboard.mintlify.com/products/authentication)。
        2. 启用身份验证。
        3. 在 **自定义身份验证** 部分中，点击 **JWT**。
        4. 输入你现有登录流程的 URL。
        5. 点击 **保存更改**。
        6. 点击 **生成新密钥**。
        7. 将你的密钥安全地存储在后端可访问的位置。

        生成私钥后，你的网站会重新部署。部署完成后，任何访问你网站的人都必须登录你的 JWT 身份验证系统才能访问内容。
      </Step>

      <Step title="将 Mintlify 身份验证集成到你的登录流程中。">
        修改你现有的登录流程，在用户完成身份验证后执行以下步骤：

        * 创建一个 JWT，其中包含已通过身份验证的用户信息，并采用 `User` 格式。更多信息请参阅[用户数据格式](#user-data-format)。
        * 使用你的私钥并通过 EdDSA 算法对 JWT 进行签名。
        * 创建一个重定向 URL，指回你的文档中的 `/login/jwt-callback` 路径，并将 JWT 作为 hash 附加到该 URL 中。
      </Step>
    </Steps>

    ### 示例

    您将文档托管在 `docs.foo.com`，并在 `foo.com` 上部署了现有的身份验证系统。您希望扩展登录流程以授予文档访问权限，同时将文档与仪表板分开维护 (或者您没有仪表板) 。

    在 `https://foo.com/docs-login` 创建一个登录端点，用于扩展您现有的身份验证。

    验证用户凭据后：

    * 生成一个符合 Mintlify 格式并包含用户数据的 JWT。
    * 为 JWT 签名，然后重定向到 `https://docs.foo.com/login/jwt-callback#{SIGNED_JWT}`。

    <CodeGroup>
      ```ts TypeScript
      import * as jose from 'jose';
      import { Request, Response } from 'express';

      const TWO_WEEKS_IN_MS = 1000 * 60 * 60 * 24 * 7 * 2;
      const DOCS_HOST = 'docs.example.com';

      const signingKey = await jose.importPKCS8(process.env.MINTLIFY_PRIVATE_KEY, 'EdDSA');

      export async function handleRequest(req: Request, res: Response) {
        const user = {
          host: DOCS_HOST, // 必须与您的文档 URL 匹配
          expiresAt: Math.floor((Date.now() + TWO_WEEKS_IN_MS) / 1000), // 2 周会话过期时间
          groups: res.locals.user.groups,
          apiPlaygroundInputs: {
            header: {
              "Authorization": `Bearer ${res.locals.user.apiKey}`,
            },
          },
        };

        const jwt = await new jose.SignJWT(user)
          .setProtectedHeader({ alg: 'EdDSA' })
          .setExpirationTime('10 s') // 10 秒 JWT 过期时间
          .sign(signingKey);

        return res.redirect(`https://${DOCS_HOST}/login/jwt-callback#${jwt}`);
      }
      ```

      ```python Python
      import jwt # pyjwt
      import os

      from datetime import datetime, timedelta
      from fastapi.responses import RedirectResponse

      private_key = os.getenv(MINTLIFY_JWT_PEM_SECRET_NAME, '')
      DOCS_HOST = 'docs.example.com'

      @router.get('/auth')
      async def return_mintlify_auth_status(current_user):
        jwt_token = jwt.encode(
          payload={
            'host': DOCS_HOST, # 必须与您的文档 URL 匹配
            'exp': int((datetime.now() + timedelta(seconds=10)).timestamp()),    # JWT 有效期 10 秒
            'expiresAt': int((datetime.now() + timedelta(weeks=2)).timestamp()), # 会话有效期 2 周
            'groups': ['admin'] if current_user.is_admin else [],
            'apiPlaygroundInputs': {
              'header': {
                'Authorization': f'Bearer {current_user.api_key}',
              },
            },
          },
          key=private_key,
          algorithm='EdDSA'
        )

        return RedirectResponse(url=f'https://{DOCS_HOST}/login/jwt-callback#{jwt_token}', status_code=302)
      ```
    </CodeGroup>

    ### 重定向未登录用户

    当未经身份验证的用户尝试访问受保护页面时，系统会将其重定向至登录 URL，并保留用户原本想访问的目标页面。

    1. 用户尝试访问受保护页面：`https://docs.foo.com/quickstart`。
    2. 重定向到您的登录 URL，并带上 redirect 查询参数：`https://foo.com/docs-login?redirect=%2Fquickstart`。
    3. 身份验证完成后，重定向到 `https://docs.foo.com/login/jwt-callback?redirect=%2Fquickstart#{SIGNED_JWT}`。
    4. 用户将进入其原本要访问的页面。

</Tabs>

<div id="make-pages-public">
  ## 将页面设为公开
</div>

使用身份验证时，默认所有页面都需要先通过身份验证才能访问。你可以通过 `public` 属性，在页面或分组级别将特定页面设为无需身份验证即可查看。

<div id="individual-pages">
  ### 单个页面
</div>

要将某个页面设为公开，请在该页面的 frontmatter 中添加 `public: true`。

```mdx Public page example
---
title: "Public page"
public: true
---
```

<div id="groups-of-pages">
  ### 页面组
</div>

如需将某个页面组中的所有页面设为公开，请在 `docs.json` 的 `navigation` 对象中，在该组名称下方添加 `"public": true`。

```json Public group example
{
  "navigation": {
    "groups": [
      {
        "group": "Public group",
        "public": true,
        "icon": "play",
        "pages": [
          "quickstart",
          "installation",
          "settings"
        ]
      },
      {
        "group": "Private group",
        "icon": "pause",
        "pages": [
          "private-information",
          "secret-settings"
        ]
      }
    ]
  }
}
```

<div id="control-access-with-groups">
  ## 使用用户组控制访问权限
</div>

使用 OAuth 或 JWT 身份验证时，你可以将特定页面限制为仅特定用户组可访问。当你希望不同用户根据其角色或属性看到不同内容时，这样做会很有用。

通过身份验证期间传递的用户数据管理用户组。详情请参阅[用户数据格式](#user-data-format)。

```json Example user info
{
  "groups": ["admin", "beta-users"],
  "expiresAt": 1735689600
}
```

使用 frontmatter 中的 `groups` 属性指定哪些用户组可以访问特定页面。

```mdx Example page restricted to the admin group highlight={3}
---
title: "Admin dashboard"
groups: ["admin"]
---
```

用户必须属于所列出的至少一个用户组，才能访问该页面。如果用户尝试访问页面但不属于所需用户组，将收到 404 错误。

<div id="how-groups-interact-with-public-pages">
  ### 用户组与公开页面的交互方式
</div>

* 默认情况下，所有页面都需要身份验证。
* 带有 `groups` 属性的页面仅限这些用户组中的已验证用户访问。
* 不带 `groups` 属性的页面对所有已验证用户开放。
* 带有 `public: true` 且不带 `groups` 属性的页面对所有人开放。

<CodeGroup>
  ```mdx 公开页面
  ---
  title: "公开指南"
  public: true
  ---
  ```

  ```mdx 受保护页面
  ---
  title: "API 参考"
  ---
  ```

  ```mdx 带用户组的受保护页面
  ---
  title: "高级配置"
  groups: ["pro", "enterprise"]
  ---
  ```
</CodeGroup>

<div id="user-data-format">
  ## 用户数据格式
</div>

使用 OAuth 或 JWT 身份验证时，您的系统会返回用户数据，用于控制会话时长、用户组成员资格以及[内容个性化](/zh/create/personalization)。

<CodeGroup>
  ```tsx Format
  type User = {
    host?: string;
    expiresAt?: number;
    groups?: string[];
    content?: Record<string, any>;
    apiPlaygroundInputs?: {
      server?: Record<string, string>;
      header?: Record<string, unknown>;
      query?: Record<string, unknown>;
      cookie?: Record<string, unknown>;
      path?: Record<string, unknown>;
    };
  };
  ```

  ```json Example
  {
    "host": "docs.example.com",
    "expiresAt": 1735689600,
    "groups": ["admin", "beta-users"],
    "content": {
      "firstName": "Jane",
      "company": "Acme Corp"
    },
    "apiPlaygroundInputs": {
      "header": {
        "Authorization": "Bearer user_abc123"
      },
      "server": {
        "baseUrl": "https://api.foo.com"
      }
    }
  }
  ```
</CodeGroup>

<ParamField path="host" type="string">
  **JWT 身份验证时必填。** 您的文档站点主机名。该字符串必须与您部署文档的域名完全一致。Mintlify 会验证 JWT 中的 host 是否与发起请求的主机一致，以防止令牌在不同站点之间被重复使用。
</ParamField>

<ParamField path="expiresAt" type="number">
  自 Unix 纪元起按秒计算的会话过期时间。当前时间超过此值后，用户必须重新进行身份验证。

  <Warning>**对于 JWT：** 这与 JWT 的 `exp` 声明不同，后者决定 JWT 何时会被视为无效。出于安全考虑，请将 JWT 的 `exp` 声明设置为较短时长 (10 秒或更短) 。使用 `expiresAt` 表示实际的会话时长 (几小时到几周) 。</Warning>
</ParamField>

<ParamField path="groups" type="string[]">
  用户所属的用户组列表。页面 frontmatter 中 `groups` 与之匹配时，该用户即可访问该页面。

  **示例**：具有 `groups: ["admin", "engineering"]` 的用户可以访问标记了 `admin` 或 `engineering` 用户组的页面。
</ParamField>

<ParamField path="content" type="Record<string, any>">
  自定义数据，可在 MDX 页面中通过 `user` 变量访问，用于[个性化内容](/zh/create/personalization#dynamic-mdx-content)。
</ParamField>

<ParamField path="apiPlaygroundInputs" type="object">
  使用用户特定的值预填 API 操场字段。用户完成身份验证后，这些值会填入 API 操场中对应的输入字段。用户可以覆盖预填充值，且这些覆盖值会保存在本地存储中。

  仅会应用与当前端点安全方案匹配的值。

  <Expandable title="属性">
    <ParamField path="header" type="Record<string, unknown>">
      要预填的请求头值，以请求头名称为键。
    </ParamField>

    <ParamField path="query" type="Record<string, unknown>">
      要预填的查询参数值，以参数名称为键。
    </ParamField>

    <ParamField path="cookie" type="Record<string, unknown>">
      要预填的 Cookie 值，以 Cookie 名称为键。
    </ParamField>

    <ParamField path="server" type="Record<string, string>">
      要预填的服务器变量值，以变量名称为键。
    </ParamField>

    <ParamField path="path" type="Record<string, unknown>">
      要预填的路径参数值，以参数名称为键。
    </ParamField>
  </Expandable>
</ParamField>

<div id="feature-availability">
  ## 功能可用性
</div>

启用身份验证后，某些功能的行为会发生变化，或者将无法使用。Mintlify 不支持在启用身份验证的网站上公开提供任意文件。所有托管文件 (包括 `llms.txt`、`llms-full.txt` 和 `skill.md`) 都与您的文档页面适用相同的身份验证要求。

| 功能                                                       | 公开   | 完全启用身份验证 (所有页面均受保护)            | 部分启用身份验证 (部分页面公开)              |
