要通过 Cloudflare 将文档托管到 `yoursite.com/docs` 这类子路径下，你必须创建并配置一个 Cloudflare Worker。

<Info>
  开始前，你需要一个 Cloudflare 账户和一个域名 (该域名可以由 Cloudflare 或其他服务商管理) 。
</Info>

<div id="set-up-a-worker">
  ## 设置 Worker
</div>

如果你还没有创建 Cloudflare Worker，请按照 [Cloudflare Workers 入门指南](https://developers.cloudflare.com/workers/get-started/dashboard/) 进行创建。

<Tip>
  如果你的 DNS 提供商是 Cloudflare，请关闭该 CNAME 记录的代理，以避免潜在的配置问题。
</Tip>

<div id="proxies-with-vercel-deployments">
  ### 在 Vercel 部署中使用代理
</div>

如果您在 Vercel 部署中使用 Cloudflare 作为代理，必须确保配置正确，以避免与 Vercel 的域名验证和 SSL 证书签发产生冲突。

代理配置不当可能会导致 Vercel 无法签发 Let&#39;s Encrypt SSL 证书，并造成域名验证失败。

<div id="required-path-allowlist">
  #### 必需的路径允许列表
</div>

你的 Cloudflare Worker 必须允许流量通过以下特定路径，且不得拦截或重定向：

* `/.well-known/acme-challenge/*` - Let&#39;s Encrypt 证书验证所必需
* `/.well-known/vercel/*` - Vercel 域名验证所必需

虽然 Cloudflare 会自动处理许多验证规则，但如果创建了额外的自定义规则，可能会无意中拦截这些关键流量。

<div id="header-forwarding-requirements">
  #### 请求头转发要求
</div>

请确保在 Worker 配置中正确转发 `HOST` 请求头。否则，验证请求将会失败。

<div id="configure-routing">
  ### 配置路由
</div>

在 Cloudflare 仪表板中，选择 **Edit Code**，然后将以下脚本添加到 Worker 的代码中。有关编辑 Worker 的更多信息，请参阅 [Cloudflare 文档](https://developers.cloudflare.com/workers-ai/get-started/dashboard/#development)。

<Tip>
  将 `[SUBDOMAIN]` 替换为你的唯一子域名，将 `[YOUR_DOMAIN]` 替换为你网站的基础 URL；如果你想使用其他子路径，请将 `/docs` 替换为所需的子路径。
</Tip>

```javascript
addEventListener("fetch", (event) => {
  event.respondWith(handleRequest(event.request));
});

async function handleRequest(request) {
  try {
    const urlObject = new URL(request.url);
    
    // 如果请求指向 Vercel 验证路径，则允许直接通过
    if (urlObject.pathname.startsWith('/.well-known/')) {
      return await fetch(request);
    }
    
    // 如果请求指向文档子路径
    if (/^\/docs/.test(urlObject.pathname)) {
      // 则代理到 Mintlify
      const DOCS_URL = "[SUBDOMAIN].mintlify.dev";
      const CUSTOM_URL = "[YOUR_DOMAIN]";

      let url = new URL(request.url);
      url.hostname = DOCS_URL;

      let proxyRequest = new Request(url, request);

      proxyRequest.headers.set("Host", DOCS_URL);
      proxyRequest.headers.set("X-Forwarded-Host", CUSTOM_URL);
      proxyRequest.headers.set("X-Forwarded-Proto", "https");
      // 如果部署到 Vercel，则保留客户端 IP
      proxyRequest.headers.set("CF-Connecting-IP", request.headers.get("CF-Connecting-IP"));

      return await fetch(proxyRequest);
    }
  } catch (error) {
    // 如果未匹配到任何操作，则按常规方式处理请求
    return await fetch(request);
  }
}
```

选择 **Deploy**，然后等待更改生效。

<div id="test-your-worker">
  ### 测试你的 Worker
</div>

代码部署完成后，请测试你的 Worker，确保它会正确路由到你的 Mintlify 文档。

1. 使用 Worker 的预览 URL 进行测试：`your-worker.your-subdomain.workers.dev/docs`
2. 确认 Worker 能正确路由到你的 Mintlify 文档和网站。

<div id="add-custom-domain">
  ### 添加自定义域名
</div>

1. 在 [Cloudflare 仪表板](https://dash.cloudflare.com/) 中，找到你的 Worker。
2. 依次进入 **Settings &gt; Domains &amp; Routes &gt; Add &gt; Custom Domain**。
3. 添加你的域名。

<Tip>
  我们建议同时添加带有 `www.` 前缀和不带 `www.` 前缀的域名。
</Tip>

更多信息，请参阅 Cloudflare 文档中的 [Add a custom domain](https://developers.cloudflare.com/workers/configuration/routing/custom-domains/#add-a-custom-domain)。 

<div id="resolve-dns-conflicts">
  ### 解决 DNS 冲突
</div>

如果您的域名已指向其他服务，则必须删除现有的 DNS 记录。您的 Cloudflare Worker 必须配置为接管您域名的全部流量。

1. 删除您域名现有的 DNS 记录。更多信息，请参阅 Cloudflare 文档中的 [删除 DNS 记录](https://developers.cloudflare.com/dns/manage-dns-records/how-to/create-dns-records/#delete-dns-records)。
2. 返回 Worker，并添加您的自定义域名。

<div id="webflow-custom-routing">
  ## Webflow 自定义路由
</div>

如果你使用 Webflow 托管主站，并希望在同一域名下通过 `/docs` 提供 Mintlify 文档，则需要通过 Cloudflare Workers 配置自定义路由，将所有非文档流量代理到主站。

<Warning>
  部署此 Worker 之前，请确保已将主站设置到一个着陆页上，否则访问主站的用户可能会看到错误。
</Warning>

1. 在 Webflow 中，为你的主站设置一个着陆页，例如 `landing.yoursite.com`。当用户访问你的网站时，他们看到的就是这个页面。
2. 将主站部署到该着陆页。这样可确保你在配置 Worker 时，主站仍然可访问。
3. 为避免冲突，请将主站中的所有绝对 URL 更新为相对 URL。
4. 在 Cloudflare 中，选择 **Edit Code**，然后将以下脚本添加到 Worker 代码中。

<Tip> 将 `[SUBDOMAIN]` 替换为你的唯一子域名，将 `[YOUR_DOMAIN]` 替换为你网站的基础 URL，将 `[LANDING_DOMAIN]` 替换为你的着陆页 URL。如果你想使用其他子路径，请将 `/docs` 替换为所需的子路径。 </Tip>

```javascript
  addEventListener("fetch", (event) => {
  event.respondWith(handleRequest(event.request));
  });
  async function handleRequest(request) {
  try {
    const urlObject = new URL(request.url);
    
    // 如果请求指向 Vercel 验证路径，则允许直接通过
    if (urlObject.pathname.startsWith('/.well-known/')) {
      return await fetch(request);
    }
    
    // 如果请求指向文档子路径
    if (/^\/docs/.test(urlObject.pathname)) {
      // 代理到 Mintlify
      const DOCS_URL = "[SUBDOMAIN].mintlify.dev";
      const CUSTOM_URL = "[YOUR_DOMAIN]";
      let url = new URL(request.url);
      url.hostname = DOCS_URL;
      let proxyRequest = new Request(url, request);
      proxyRequest.headers.set("Host", DOCS_URL);
      proxyRequest.headers.set("X-Forwarded-Host", CUSTOM_URL);
      proxyRequest.headers.set("X-Forwarded-Proto", "https");
      // 如果部署到 Vercel，则保留客户端 IP
      proxyRequest.headers.set("CF-Connecting-IP", request.headers.get("CF-Connecting-IP"));
      return await fetch(proxyRequest);
    }
    // 将其他所有请求路由到主站点
    const MAIN_SITE_URL = "[LANDING_DOMAIN]";
    if (MAIN_SITE_URL && MAIN_SITE_URL !== "[LANDING_DOMAIN]") {
      let mainSiteUrl = new URL(request.url);
      mainSiteUrl.hostname = MAIN_SITE_URL;
      return await fetch(mainSiteUrl, {
        method: request.method,
        headers: request.headers,
        body: request.body
      });
    }
  } catch (error) {
    // 如果未匹配到任何操作，则正常处理请求
    return await fetch(request);
  }
  }
```

5. 选择 **Deploy**，然后等待更改传播完成。
