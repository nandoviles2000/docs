要通过 AWS Route 53 和 CloudFront 将文档托管在 `yoursite.com/docs` 这类子路径下，你必须将 DNS 提供商配置为指向你的 CloudFront 分配。

<div id="overview">
  ## 概述
</div>

将流量路由到以下路径，并将 Cache Policy 设为 **CachingDisabled**：

* `/.well-known/acme-challenge/*` - Let&#39;s Encrypt 证书验证所必需
* `/.well-known/vercel/*` - 域名验证所必需
* `/docs/*` - 子路径路由所必需
* `/docs/` - 子路径路由所必需

将流量路由到此路径，并将 Cache Policy 设为 **CachingEnabled**：

* `/mintlify-assets/_next/static/*`
* `Default (*)`	- 您网站的首页

所有 Behavior 都必须将 **origin request policy** 设为 `AllViewerExceptHostHeader`。

![CloudFront “Behaviors”页面，包含 4 个 behavior：/docs/\*、/docs、Default 和 /.well-known/\*。](/images/cloudfront/all-behaviors.png)

<div id="create-cloudfront-distribution">
  ## 创建 CloudFront 分配
</div>

1. 在 AWS 控制台中打开 [CloudFront](https://aws.amazon.com/cloudfront)。
2. 选择 **Create distribution**。

<Frame>
  ![CloudFront Distributions 页面，重点标出了“Create distribution”按钮。](/images/cloudfront/create-distribution.png)
</Frame>

3. 在 Origin domain 中输入 `[SUBDOMAIN].mintlify.dev`，其中 `[SUBDOMAIN]` 是你的项目专属子域名。

<Frame>
  ![CloudFront“Create distribution”页面，其中“acme.mintlify.dev”显示为源域名。](/images/cloudfront/origin-name.png)
</Frame>

4. 对于“Web Application Firewall (WAF)”，启用安全防护。

<Frame>
  ![Web Application Firewall (WAF) 选项，其中已选中“Enable security protections”。](/images/cloudfront/enable-security-protections.png)
</Frame>

5. 其余设置保持默认即可。
6. 选择 **Create distribution**。

<div id="add-default-origin">
  ## 添加默认源站
</div>

1. 创建分配后，前往“Origins”标签页。

<Frame>
  ![已高亮“Origins”标签页的 CloudFront 分配。](/images/cloudfront/origins.png)
</Frame>

2. 找到与你的主域名相对应的预发布 URL。具体地址取决于你的落地页托管方式。例如，Mintlify 的预发布 URL 是 [mintlify-landing-page.vercel.app](https://mintlify-landing-page.vercel.app)。

<Info>
  如果你的落地页托管在 Webflow 上，请使用 Webflow 的预发布 URL，通常类似于 `.webflow.io`。

  如果你使用 Vercel，请使用每个项目都会提供的 `.vercel.app` 域名。
</Info>

3. 创建一个新的 Origin，并将你的预发布 URL 添加为“Origin domain”。

<Frame>
  ![CloudFront“Create origin”页面，其中“Origin domain”输入框已高亮。](/images/cloudfront/default-origin.png)
</Frame>

完成后，你应该会有两个 Origin：一个是 `[SUBDOMAIN].mintlify.app`，另一个是你的预发布 URL。

<Frame>
  ![CloudFront“Origins”页面，其中有两个源站：一个用于 mintlify，另一个用于 mintlify-landing-page。](/images/cloudfront/final-origins.png)
</Frame>

<div id="set-behaviors">
  ## 设置行为
</div>

CloudFront 中的行为可用于控制子路径逻辑。简而言之，您需要创建以下逻辑：

* **如果用户访问您的自定义子路径**，则转到 `[SUBDOMAIN].mintlify.dev`。
* **如果用户访问任何其他页面**，则转到当前落地页。

1. 前往 CloudFront 分配中的 “Behaviors” 选项卡。

<Frame>
  ![高亮显示的 CloudFront“Behaviors”选项卡。](/images/cloudfront/behaviors.png)
</Frame>

2. 选择 **Create behavior** 按钮，并创建以下行为。

<div id="well-known">
  ### `/.well-known/*`
</div>

为 Vercel 域名验证路径创建行为，将 **Path pattern** 设为 `/.well-known/*`，并将 **Origin and origin groups** 指向你的文档 URL。

对于“Cache policy”，请选择 **CachingDisabled**，以确保这些验证请求不经缓存直接透传。

<Frame>
  ![CloudFront“创建行为”页面，其中“Path pattern”为“/.well-known/\*”，“Origin and origin groups”指向预发布 URL。](/images/cloudfront/well-known-policy.png)
</Frame>

<Info>
  如果 `.well-known/*` 过于笼统，至少可以将其收窄为 Vercel 所需的 2 条行为：

  * `/.well-known/vercel/*` - Vercel 域名验证必需
  * `/.well-known/acme-challenge/*` - Let&#39;s Encrypt 证书验证必需
</Info>

<div id="your-subpath">
  ### 你的子路径
</div>

创建一条行为规则，将 **Path pattern** 设为你选择的子路径，例如 `/docs`，并将 **Origin and origin groups** 指向 `.mintlify.dev` URL (本例中为 `acme.mintlify.dev`) 。

* 将“Cache policy”设置为 **CachingOptimized**。
* 将“Origin request policy”设置为 **AllViewerExceptHostHeader**。
* 将 Viewer protocol policy 设置为 **Redirect HTTP to HTTPS**

<Frame>
  ![CloudFront“Create behavior”页面，其中“Path pattern”为“/docs/\*”，且“Origin and origin groups”指向 acme.mintlify.dev URL。](/images/cloudfront/behavior-1.png)
</Frame>

<div id="your-subpath-with-wildcard">
  ### 带通配符的子路径
</div>

创建一个行为，将 **Path pattern** 设为你选择的子路径并在后面加上 `/*`，例如 `/docs/*`；同时将 **Origin and origin groups** 指向同一个 `.mintlify.dev` URL。

除 **Path pattern** 外，这些设置应与基础子路径行为完全一致。

* 将 &quot;Cache policy&quot; 设置为 **CachingOptimized**。
* 将 &quot;Origin request policy&quot; 设置为 **AllViewerExceptHostHeader**。
* 将 &quot;Viewer protocol policy&quot; 设置为 **Redirect HTTP to HTTPS**

<div id="mintlify-assets_nextstatic">
  ### `/mintlify-assets/_next/static/*`
</div>

* 将“Cache policy”设为 **CachingOptimized**
* 将“Origin request policy”设为 **AllViewerExceptHostHeader**
* 将“Viewer protocol policy”设为 **Redirect HTTP to HTTPS**

<div id="default">
  ### `Default (*)`
</div>

最后，编辑 `Default (*)` 行为。

<Frame>
  ![已选中“Default (\*)”行为并突出显示“Edit”按钮的 CloudFront 分配。](/images/cloudfront/default-behavior-1.png)
</Frame>

1. 将默认行为的 **Origin and origin groups** 改为预发布 URL (本例中为 `mintlify-landing-page.vercel.app`) 。

<Frame>
  ![CloudFront“Edit behavior”页面，其中“Origin and origin groups”输入字段已高亮显示。](/images/cloudfront/default-behavior-2.png)
</Frame>

2. 选择 **Save changes**。

<div id="check-behaviors-are-set-up-correctly">
  ### 确认行为已正确配置
</div>

如果你按照前面的步骤操作，你的行为应如下所示：

<Frame>
  ![CloudFront“Behaviors”页面，包含 4 条行为：/docs/\*、/docs、Default 和 /.well-known/\*。](/images/cloudfront/all-behaviors.png)
</Frame>

<div id="preview-distribution">
  ## 预览分配
</div>

现在，你可以前往“General”标签页并访问 **Distribution domain name** URL，测试你的分配是否已正确设置。

<Frame>
  ![CloudFront“General”标签页，其中“Distribution domain name”URL 已高亮显示。](/images/cloudfront/preview-distribution.png)
</Frame>

现在，所有页面都应指向你的主落地页；但如果你在该 URL 后附加所选的子路径 (例如 `/docs`) ，则应会看到它跳转到你的 Mintlify 文档站点。

<div id="connect-with-route-53">
  ## 连接到 Route 53
</div>

现在，我们将把 CloudFront 分发的能力接入你的主域名。

<Note>
  在本节中，你也可以参考 AWS 官方指南：[配置
  Amazon Route 53 以将流量路由到 CloudFront
  分发](https://docs.aws.amazon.com/Route53/latest/DeveloperGuide/routing-to-cloudfront-distribution.html#routing-to-cloudfront-distribution-config)
</Note>

1. 在 AWS 控制台中打开 [Route53](https://aws.amazon.com/route53)。
2. 进入你的主域名对应的“Hosted zone”。
3. 选择 **Create record**。

<Frame>
  ![Route 53 “Records”页面，突出显示了“Create record”按钮。](/images/cloudfront/route53-create-record.png)
</Frame>

4. 打开 `Alias`，然后在 **Route traffic to** 中选择 `Alias to CloudFront distribution` 选项。

<Frame>
  ![Route 53 “Create record”页面，突出显示了“Alias”开关和“Route traffic to”菜单。](/images/cloudfront/create-record-alias.png)
</Frame>

5. 选择 **Create records**。

<Note>
  如果当前已存在 A 记录，你可能需要先将其删除。
</Note>

现在，你的文档已在主域名下所选的子路径上上线。
