如果你在 Vercel 部署前使用了 Cloudflare 或 AWS CloudFront 等外部代理，必须正确配置它，以免与 Vercel 的域名验证和 SSL 证书签发产生冲突。

代理配置不当可能会导致 Vercel 无法签发 Let&#39;s Encrypt SSL 证书，并造成域名验证失败。

请参阅 Vercel 文档中的[受支持的提供商](https://vercel.com/guides/how-to-setup-verified-proxy#supported-providers-verified-proxy-lite)。

<div id="required-path-allowlist">
  ## 必需放行的路径列表
</div>

你的外部代理必须允许流量访问以下特定路径，不得拦截、重定向或进行激进缓存：

* `/.well-known/acme-challenge/*` - Let&#39;s Encrypt 证书验证所必需
* `/.well-known/vercel/*` - Vercel 域名验证所必需
* `/mintlify-assets/_next/static/*` - 静态资源所必需

这些路径应直接透传到你的 Vercel 部署，不得做任何修改。

<div id="header-forwarding-requirements">
  ## 请求头转发要求
</div>

确保代理正确转发 `HOST` 请求头。否则，验证请求将失败。

<div id="testing-your-proxy-setup">
  ## 测试你的代理设置
</div>

要验证代理是否已正确配置，请执行以下检查：

1. 测试 `https://[yourdomain].com/.well-known/vercel/` 是否会返回响应。
2. 确认 SSL 证书已在你的 Vercel 仪表板中正确签发。
3. 检查域名验证是否已成功完成。
