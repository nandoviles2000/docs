在文档项目的根目录下创建 `.mintlify/AGENTS.md` 文件，以自定义智能体的行为 (`Agents.md` 也可作为文件名) 。

<Warning>
  请将 `AGENTS.md` 文件放在 `.mintlify/` 目录中，而不是项目根目录。如果将该文件存放在项目根目录，你的自定义指令将可通过 `/agents.md` 路径被公开访问。`.mintlify/` 目录不会被公开提供，因此将 `AGENTS.md` 文件放在该目录中时，外部无法访问它。

  如果你必须将 `AGENTS.md` 文件存放在项目根目录或任何其他目录中，请将其添加到 [`.mintignore`](/zh/organize/mintignore) 文件中，以将其从文档站点中排除。
</Warning>

添加你希望智能体遵循的任意指令。智能体会将这些指令附加到其系统提示中，因此无论你是在仪表板中、在 Slack 上，还是通过 API 使用智能体，这些指令都会应用于所有任务。

<div id="what-to-include-in-agentsmd">
  ## AGENTS.md 中应包含的内容
</div>

可以考虑添加以下说明：

* **风格偏好**：文档特有的语气、风格、格式和术语。
* **代码标准**：示例中应使用的编程语言、框架和编码规范。
* **内容要求**：不同类型的页面应包含哪些章节或信息。
* **项目背景**：有关你的产品、架构或用户群体的具体细节，这些信息会影响文档编写决策。

<div id="example-agentsmd-file">
  ## AGENTS.md 示例文件
</div>

```markdown .mintlify/AGENTS.md
# 文档智能体说明

## 代码示例
- 所有代码示例均使用 TypeScript。我们的用户主要是 TypeScript 开发者。
- API 调用示例中必须始终包含错误处理。
- 为所有端点同时展示成功和错误响应示例。
- 在代码示例顶部包含 import 语句。

## API 文档规范
- 每个端点必须记录：身份验证要求、速率限制和常见错误代码。
- 示例中使用真实的参数值（而非 foo/bar 等占位符）。
- 为每个端点提供完整的请求/响应流程示例。

## 风格与格式
- 面向有 2-5 年经验的开发者写作。不要过度简化，但需解释不易理解的概念。
- 使用主动语态和第二人称（"你"）。
- 日期格式：ISO 8601（YYYY-MM-DD）。
- 引用 UI 元素时使用粗体：**Settings** 按钮。

## 应包含的内容
- 当用户需要 API 密钥、环境配置或依赖项时，在指南中添加前提条件章节。
- 包含链接到相关文档的"后续步骤"章节。
- 针对支持工单中常见问题添加故障排查章节。
```
