如果您的 API 页面显示不正常，请检查以下常见配置问题。

<AccordionGroup>
  <Accordion title="我的所有 OpenAPI 页面都是空白的">
    在这种情况下，很可能是 Mintlify 找不到你的 OpenAPI 文档，
    或者你的 OpenAPI 文档无效。

    在本地运行 `mint dev` 应该会暴露其中一些问题。

    要验证你的 OpenAPI 文档是否通过校验：

    1. 访问[这个验证工具](https://editor.swagger.io/)
    2. 切换到“Validate text”选项卡
    3. 粘贴你的 OpenAPI 文档
    4. 点击“Validate it!”

    如果下方出现的文本框带有绿色边框，则说明你的文档已通过校验。
    Mintlify 正是使用这个校验包来验证 OpenAPI 文档，因此如果你的文档
    在这里通过了校验，问题很可能出在别处。

    此外，Mintlify 不支持 OpenAPI 2.0。如果你的文档使用的是这个版本的规范，
    就可能会遇到这个问题。你可以在 [editor.swagger.io](https://editor.swagger.io/) 中转换文档 (路径为 Edit &gt; Convert to OpenAPI 3) ：

    <Frame>
      ![Swagger Editor 的截图，其中 Edit 菜单已展开，且“Convert to OpenAPI 3”菜单项已高亮。](/images/convert-oas-3.png)
    </Frame>
  </Accordion>

  <Accordion title="某个 OpenAPI 页面完全空白">
    这通常是因为页面元数据中的 `openapi` 字段拼写有误。请确保
    HTTP 方法和路径与 OpenAPI 文档中的 HTTP 方法和路径完全一致。

    下面是一个可能出错的示例：

    ```mdx get-user.mdx
    ---
    openapi: "GET /users/{id}/"
    ---
    ```

    ```yaml openapi.yaml
    paths:
      "/users/{id}":
        get: ...
    ```

    请注意，`openapi` 字段中的路径末尾带有斜杠，而 OpenAPI
    文档中的路径末尾则没有。

    另一个常见问题是文件名拼写有误。如果你在 `openapi` 字段中指定了某个特定的 OpenAPI 文档，
    请确保文件名填写正确。例如，如果你有两个 OpenAPI
    文档 `openapi/v1.json` 和 `openapi/v2.json`，元数据可能如下所示：

    ```mdx api-reference/v1/users/get-user.mdx
    ---
    openapi: "v1 GET /users/{id}"
    ---
    ```
  </Accordion>

  <Accordion title="API 操场中的请求无法正常运行">
    如果您配置了自定义域名，问题可能出在反向代理上。默认情况下，通过 API 操场 发出的请求会先向文档站点上的
    `/_mintlify/api/request` 路径发送一个 `POST` 请求。如果您将反向代理配置为仅允许 `GET`
    请求，这些请求就都会失败。要解决此问题，请将反向代理配置为
    允许向 `/_mintlify/api/request` 路径发送 `POST` 请求。

    或者，如果您的反向代理不允许接受 `POST` 请求，您可以按照[设置文档](/zh/organize/settings-api)中的说明，在 `docs.json` 中使用 `api.playground.proxy` 设置，将 Mintlify 配置为直接向您的后端发送请求。使用此配置时，您必须在服务器上配置 CORS，因为这些请求将直接来自用户的浏览器，而不是通过您的代理。
  </Accordion>

  <Accordion title="OpenAPI 导航项未生成页面">
    如果你使用的是 OpenAPI 导航配置，但页面未生成，请检查以下常见问题：

    1. **缺少默认 OpenAPI 规范**：请确保已为该导航元素设置 `openapi` 字段：

    ```json {5}
    "navigation": {
      "groups": [
        {
          "group": "API reference",
          "openapi": "/path/to/openapi.json",
          "pages": [
            "GET /users",
            "POST /users"
          ]
        }
      ]
    }
    ```

    2. **OpenAPI 规范继承**：如果使用嵌套导航，请确保子分组继承了正确的 OpenAPI 规范，或为其单独指定规范。

    3. **验证问题**：使用 `mint validate` 检查你的 OpenAPI 文档是否有效。
  </Accordion>

  <Accordion title="某些 OpenAPI 操作会显示在导航中，而有些则不会">
    1. **隐藏的操作**：在你的 OpenAPI 规范中标记为 `x-hidden: true` 的操作，不会出现在自动生成的导航中。
    2. **无效操作**：OpenAPI 规范中存在校验错误的操作可能会被跳过。请检查你的 OpenAPI 文档是否有语法错误。
    3. **手动包含与自动包含**：如果你引用了某个 OpenAPI 规范中的任意端点，则只有明确引用的操作才会显示在导航中。其他页面都不会自动添加。这也包括在子导航元素中引用的操作。
  </Accordion>

  <Accordion title="混合导航（OpenAPI 和 MDX 页面）无法正常工作">
    当在导航中将 OpenAPI 操作与常规文档页面结合使用时：

    1. **文件冲突**：同一操作不能同时对应 `MDX` 文件和导航条目。例如，如果你有 `get-users.mdx`，就不要再在导航中加入 `"GET /users"`。如果你需要让某个文件与某个操作重名，请为该 endpoint 使用 `x-mint` 扩展，让 href 指向其他位置。
    2. **路径解析**：与 OpenAPI 操作不匹配的导航条目会被视为文件路径。请确保你的 `MDX` 文件位于预期位置。
    3. **区分大小写**：OpenAPI 操作匹配区分大小写。请确保导航条目中的 HTTP 方法为大写。
  </Accordion>
</AccordionGroup>
