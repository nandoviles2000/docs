API 操场是一个交互式环境，用户可以在其中测试和探索您的 API 端点。开发者无需离开文档，即可构建 API 请求、发送请求并查看响应。

API 操场的实际效果示例，请参阅[触发更新](/zh/api/update/trigger)。

操场会根据您的 OpenAPI 规范或 AsyncAPI 架构，为各个端点生成交互式页面。如果您修改了 API，操场会自动更新相应页面。

我们建议根据 OpenAPI 规范生成 API 操场。不过，您也可以先在 `docs.json` 中定义基础 URL 和身份验证方法，再手动创建 API 参考页面。

<div id="get-started">
  ## 快速开始
</div>

<Steps>
  <Step title="添加您的 OpenAPI 规范文件。">
    <Tip>
      使用 [Swagger Editor](https://editor.swagger.io/) 或 [Mint CLI](https://www.npmjs.com/package/mint) 的 `mint validate` 命令验证您的 OpenAPI 规范文件。
    </Tip>

    ```bash {3}
    /your-project
      |- docs.json
      |- openapi.json
    ```
  </Step>

  <Step title="生成端点页面。">
    更新您的 `docs.json`，以引用 OpenAPI 规范。

    **如需为 OpenAPI 规范中的所有端点自动生成页面**，请为任意导航元素添加 `openapi` 属性。

    此示例会为 `openapi.json` 中定义的每个端点生成一个页面，并将这些页面归入“API 参考”分组。

    ```json Generate all endpoint pages
    "navigation": {
      "groups": [
        {
          "group": "API reference",
          "openapi": "openapi.json"
        }
      ]
    }
    ```

    **如需仅为特定端点生成页面**，请在该导航元素的 `pages` 属性中列出这些端点。

    此示例仅为 `GET /users` 和 `POST /users` 端点生成页面。要生成其他端点页面，请将更多端点添加到 `pages` 数组中。

    ```json Generate specific endpoint pages
    "navigation": {
      "groups": [
          {
            "group": "API reference",
            "openapi": "openapi.json",
            "pages": [
              "GET /users",
              "POST /users"
            ]
          }
      ]
    }
    ```
  </Step>
</Steps>

<div id="customize-your-playground">
  ## 自定义 API 操场
</div>

通过在 `docs.json` 中定义以下属性，自定义 API 操场。

<ResponseField name="playground" type="object">
  API 操场的配置。

  <Expandable title="playground" defaultOpen="True">
    <ResponseField name="display" type="&#x22;interactive&#x22; | &#x22;simple&#x22; | &#x22;none&#x22; | &#x22;auth&#x22;">
      API 操场的显示模式。

      * `"interactive"`：显示交互式 操场。
      * `"simple"`：显示可复制的端点，不显示 操场。
      * `"none"`：不显示任何内容。
      * `"auth"`：仅向已身份验证的用户显示交互式 操场。未身份验证的用户或不在所需组中的用户将看不到 操场。

      默认为 `interactive`。
    </ResponseField>

    <ResponseField name="proxy" type="boolean" defaultOpen="True">
      是否通过 Mintlify 的代理服务器转发 API 请求。默认为 `true`。

      当为 `true` 时，操场 请求会通过 Mintlify 的服务器转发。当为 `false` 时，操场 会直接从浏览器向你的 API 发送请求。如果你的 API 接受来自浏览器的直接请求，且你不需要 Mintlify 代理流量，请将其设为 `false`。例如，当你的 API 需要某些无法通过代理转发的特定请求头，或者出于身份验证目的，需要让请求直接从用户的浏览器发起时。
    </ResponseField>

    <ResponseField name="credentials" type="boolean">
      当 `proxy` 为 `false` 时，是否在跨源请求中包含 cookie、授权请求头和 TLS 客户端证书。默认为 `false`。

      当为 `true` 且 `proxy` 为 `false` 时，操场 发送请求时会附带由浏览器管理的凭据。例如，当你的 API 使用基于 cookie 的身份验证或 HTTP 会话令牌时。

      当 `proxy` 为 `true` 时，此选项不起作用。
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="url" type="&#x22;full&#x22;">
  端点页眉中基准 URL 的显示模式。设为 `full` 时，每个端点页面都会显示完整的基准 URL。默认情况下，仅显示相对端点路径。
</ResponseField>

<ResponseField name="examples" type="object">
  自动生成的 API 示例配置。

  <Expandable title="examples" defaultOpen="True">
    <ResponseField name="languages" type="array of string">
      自动生成的 API 代码示例所使用的语言。

      语言会按指定顺序显示。

      <Accordion title="所有支持的语言">
        | 显示名称       | 键            | 别名                        |
        | ---------- | ------------ | ------------------------- |
        | cURL       | `bash`       | `curl`, `sh`, `shell`     |
        | Python     | `python`     | `py`                      |
        | JavaScript | `javascript` | `js`                      |
        | Node.js    | `node`       | `nodejs`, `node.js`       |
        | PHP        | `php`        |                           |
        | Go         | `go`         | `golang`                  |
        | Java       | `java`       |                           |
        | Ruby       | `ruby`       | `rb`                      |
        | PowerShell | `powershell` |                           |
        | Swift      | `swift`      |                           |
        | C#         | `csharp`     | `c#`                      |
        | .NET       | `dotnet`     | `.net`, `.NET`, `dot-net` |
        | TypeScript | `typescript` | `ts`                      |
        | C          | `c`          |                           |
        | C++        | `c++`        | `cpp`                     |
        | Kotlin     | `kotlin`     | `kt`                      |
        | Rust       | `rust`       | `rs`                      |
        | Dart       | `dart`       | `flutter`                 |
      </Accordion>
    </ResponseField>

    <ResponseField name="defaults" type="&#x22;required&#x22; | &#x22;all&#x22;">
      是否在 API 示例中显示可选参数。默认为 `all`。
    </ResponseField>

    <ResponseField name="prefill" type="boolean">
      是否使用 schema 示例中的数据预填充 API 操场。启用后，操场 会自动使用 OpenAPI 规范中的示例值填充请求字段。默认为 `false`。
    </ResponseField>

    <ResponseField name="autogenerate" type="boolean">
      是否根据 API 规范为端点生成代码示例。默认为 `true`。设为 `false` 时，API 操场中只会显示手动编写的代码示例 (来自 OpenAPI 规范中的 `x-codeSamples` 或 MDX 中的 `<RequestExample>` 组件) 。
    </ResponseField>
  </Expandable>
</ResponseField>

<div id="example-configuration">
  ### 配置示例
</div>

此示例将 API 操场 配置为可交互模式，并提供 cURL、Python 和 JavaScript 的示例代码片段。代码片段中仅显示必填参数，操场则会用示例值预填请求体。

```json
{
 "api": {
   "playground": {
     "display": "interactive"
   },
   "examples": {
     "languages": ["curl", "python", "javascript"],
     "defaults": "required",
     "prefill": true
   }
 }
}
```

<div id="auth-based-playground-display">
  ### 基于身份验证的 操场 显示
</div>

使用 `auth` 显示模式，仅向已登录用户显示交互式 操场。当你希望用户可以公开查看你的 API 文档，同时只允许已登录用户访问 操场 时，这种方式很有用。

当 `display` 设置为 `auth` 时：

* 已登录用户会看到交互式 操场。
* 未登录用户不会看到 操场 (等同于 `none`) 。

你还可以将 `auth` 与页面 frontmatter 中的 `groups` 属性结合使用，将 操场 的访问权限限制为特定用户组。

```mdx Page with group-restricted playground
---
title: "Create user"
openapi: POST /users
playground: auth
groups: ["admin", "developer"]
public: true
---
```

在此示例中：

* 页面公开可见 (任何人都可以查看文档) 。
* 只有 `admin` 或 `developer` 组中已通过身份验证的用户才能看到交互式 操场。
* 不在这些组中的用户将看不到 操场。

如果页面没有 `groups` 属性，则所有已通过身份验证的用户都能看到交互式 操场。

<Note>
  `auth` 显示模式要求你的文档已配置[身份验证](/zh/deploy/authentication-setup)。
</Note>

<div id="custom-endpoint-pages">
  ### 自定义端点页面
</div>

当你需要更灵活地控制 API 文档时，可以在 OpenAPI 规范中使用 `x-mint` 扩展，或为各个端点创建单独的 MDX 页面。

这两种方式都可以让你：

* 自定义页面元数据
* 添加示例等额外内容
* 按页面控制操场的行为

我们推荐使用 `x-mint` 扩展，这样你的所有 API 文档都能根据 OpenAPI 规范自动生成，并统一在一个文件中维护。

如果是小型 API，或者你想按页面逐一试验更改，我们建议使用单独的 MDX 页面。

<div id="response-rendering">
  ## 响应渲染
</div>

操场 会根据 API 返回的 `Content-Type` 标头自动渲染响应。

* **图片**：直接内联渲染 (`image/*`) 。
* **音频**：使用内置音频播放器渲染 (`audio/*`) 。
* **视频**：使用内置视频播放器渲染 (`video/*`) 。任何 `Content-Type` 为 `video/*` 的响应 (例如 `video/mp4` 或 `video/webm`) 都会直接在 操场 中显示为可播放的视频。
* **所有其他响应**：显示为代码块。

<div id="parameter-anchor-links">
  ## 参数锚点链接
</div>

API 操场中的每个参数都有一个可点击的锚点链接。将鼠标悬停在参数名称上即可显示链接图标，然后点击即可复制指向该参数的直达 URL。

使用参数锚点链接可以：

* 在技术支持沟通或文档中分享指向特定参数的链接
* 从其他页面或外部资源直接跳转到某个参数
* 为经常引用的参数添加书签

URL 格式为 `your-docs-url/endpoint-path#parameter-name`。对于嵌套参数，锚点会包含父级路径。
