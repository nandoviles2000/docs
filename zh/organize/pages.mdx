每个页面都是一个 Markdown 文件。你可以为页面使用 `.mdx` 或 `.md` 文件。我们推荐使用 MDX，它将 Markdown 与 React 组件结合，可用于创建更丰富、可交互的文档。纯 Markdown (`.md`) 可以加快从其他平台迁移的过程，但切换到 MDX 能解锁更多功能。

<div id="page-metadata">
  ## 页面元数据
</div>

每个页面都以 frontmatter 开头，即文件顶部由 `---` 包裹的 YAML 元数据。该元数据控制页面的显示方式和行为。

你可以使用 frontmatter 控制：

* 页面标题和描述
* 侧边栏标题、图标和标签
* 页面布局
* SEO 元标签
* 自定义元数据

<ResponseField name="title" type="string">
  显示在导航和浏览器标签页中的页面标题。

  如果省略，Mintlify 会根据路径自动生成标题。路径的最后一段会作为标题，其中的连字符和下划线会被替换为空格，并将首字母大写。例如，`guides/getting-started.md` 会变为 **Getting started**。
</ResponseField>

<ResponseField name="description" type="string">
  对页面内容的简要描述。显示在标题下方，并有助于提升 SEO。
</ResponseField>

<ResponseField name="sidebarTitle" type="string">
  显示在侧边栏导航中的简短标题。
</ResponseField>

<ResponseField name="icon" type="string">
  要显示的图标。

  选项：

  * [Font Awesome 图标](https://fontawesome.com/icons)名称
  * [Lucide 图标](https://lucide.dev/icons)名称
  * [Tabler 图标](https://tabler.io/icons)名称
  * 外部托管图标的 URL
  * 项目中图标文件的路径
</ResponseField>

<ResponseField name="iconType" type="string">
  仅适用于 [Font Awesome](https://fontawesome.com/icons) 图标。用于指定图标样式。

  选项：`regular`、`solid`、`light`、`thin`、`sharp-solid`、`duotone`、`brands`。
</ResponseField>

<ResponseField name="tag" type="string">
  显示在侧边栏页面标题旁边的标签。
</ResponseField>

<ResponseField name="hidden" type="boolean">
  设为 `true` 可将该页面从侧边栏导航中移除。用户仍可通过其 URL 访问该页面，但搜索引擎不会将其编入索引。若要让页面重新可见，请完全删除此字段。**不要**将其设为 `false`，否则会导致未定义行为。详见 [隐藏页面](/zh/organize/hidden-pages)。
</ResponseField>

<ResponseField name="noindex" type="boolean">
  设为 `true` 可阻止搜索引擎索引该页面。详见 [禁用索引](/zh/optimize/seo#disable-indexing)。所有在 frontmatter 中设置了 `hidden: true` 的页面，都会自动获得 `noindex: true`。
</ResponseField>

<ResponseField name="deprecated" type="boolean">
  设为 `true` 会在页面标题旁显示“deprecated”标签。可用于标记过时内容或旧版功能，同时保持页面可访问。
</ResponseField>

<ResponseField name="hideFooterPagination" type="boolean">
  设为 `true` 可隐藏页面底部的上一页/下一页导航链接。适用于落地页或参考页等独立页面，因为这类页面不需要顺序导航。
</ResponseField>

<ResponseField name="hideApiMarker" type="boolean">
  设为 `true` 可隐藏侧边栏中页面标题旁的 HTTP 方法标记 (如 GET 或 POST) 。适用于希望侧边栏外观更简洁的 API 页面。
</ResponseField>

<ResponseField name="groups" type="string[]">
  将页面访问限制为特定用户组中的用户。用户必须至少属于所列组中的一个，才能访问该页面。你必须先配置 [身份验证](/zh/deploy/authentication-setup)。更多信息请参见 [使用组控制访问](/zh/deploy/authentication-setup#control-access-with-groups)。
</ResponseField>

<ResponseField name="<custom>" type="string">
  任何有效的 YAML frontmatter。例如，`product: "API"` 或 `version: "1.0.0"`。
</ResponseField>

```yaml Example YAML frontmatter wrap
---
title: "About frontmatter"
description: "Frontmatter is the metadata that controls how your page appears and behaves"
sidebarTitle: "Frontmatter"
icon: "book"
tag: "NEW"
---
```

<div id="page-mode">
  ## 页面模式
</div>

使用 `mode` 设置来控制页面布局。

<div id="default">
  ### 默认
</div>

如果你未定义模式，页面会使用带有侧边栏导航和目录的标准布局。

```yaml
---
title: "Default page title"
---
```

<div id="wide">
  ### 宽版
</div>

宽版模式会隐藏目录。对于没有标题的页面，或需要更多水平空间时，请使用此模式。所有主题都支持宽版模式。

```yaml
---
title: "Wide page title"
mode: "wide"
---
```

<div id="custom">
  ### 自定义
</div>

自定义模式提供极简布局，除顶部导航栏外会移除所有元素。此模式会隐藏侧边栏、目录和页脚。你可以将自定义模式视为空白画布，以最少的导航打造落地页或独特布局。所有主题都支持自定义模式。

```yaml
---
title: "Custom page title"
mode: "custom"
---
```

<Warning>
  `style` 属性可能会在页面加载时导致布局跳动。建议优先使用 [Tailwind CSS 或自定义 CSS](/zh/customize/custom-scripts) 来避免此问题。
</Warning>

<div id="frame">
  ### Frame
</div>

Frame 模式提供与自定义模式相似的布局，但会保留侧边栏导航。使用此模式，你可以在保留默认导航体验的同时加入自定义 HTML 和组件。Aspen、Almond、Luma 和 Sequoia 主题均支持 Frame 模式。

```yaml
---
title: "Frame page title"
mode: "frame"
---
```

<div id="center">
  ### Center
</div>

Center 模式会移除侧边栏和目录，并将内容居中显示。对于更新日志或其他希望将重点放在内容上的页面，请使用 Center 模式。Mint、Linden、Willow 和 Maple 主题支持 Center 模式。

```yaml
---
title: "Center page title"
mode: "center"
---
```

<div id="api-pages">
  ## API 页面
</div>

要创建交互式 API 操场，请在 frontmatter 中通过设置 `api` 或 `openapi` 来添加 API 规范。

```yaml
---
openapi: "GET /endpoint"
---
```

详细了解如何搭建 [API 文档](/zh/api-playground/overview)。

<div id="external-links">
  ## 外部链接
</div>

使用 `url` 元数据，直接从导航链接到外部站点。

```yaml
---
title: "npm Package"
url: "https://www.npmjs.com/package/mint"
---
```

<div id="search-engine-optimization">
  ## 搜索引擎优化
</div>

Mintlify 会自动生成大多数 SEO 元标签。你也可以手动设置 SEO 元标签，以自定义 SEO、社交分享和浏览器兼容性相关配置。

<Note>
  始终将带冒号的元标签用引号括起来。
</Note>

```yaml
---
"twitter:image": "/images/social-preview.jpg"
---
```

有关 SEO 元数据选项的完整列表，参见 [SEO](/zh/optimize/seo)。

<div id="internal-search-keywords">
  ## 内部搜索关键词
</div>

你可以在元数据中提供 `keywords`，帮助用户在搜索结果中找到特定页面。这些关键词不会显示在页面内容中。如果用户搜索这些关键词，该页面就会出现在搜索结果里。

```yaml
---
keywords: ['configuration', 'setup', 'getting started']
---
```

<div id="last-modified-timestamp">
  ## 最后修改时间戳
</div>

在[全局设置](/zh/organize/settings-seo#metadata)中启用 `metadata.timestamp` 后，所有页面都会显示“最后修改于 [date]”时间戳。

```json docs.json
"metadata": {
  "timestamp": true
}
```

如需为单个页面覆盖全局时间戳设置，请使用 frontmatter 中的 `timestamp` 字段。你可以使用此字段在特定页面上显示或隐藏时间戳。

```yaml
---
title: "Page title"
timestamp: false
---
```

如果将 `timestamp: true`，该页面会始终显示时间戳，即使全局设置为 `false`。如果将 `timestamp: false`，该页面则会隐藏时间戳，即使全局设置为 `true`。
