`docs.json` 中的 [navigation](/zh/organize/settings-structure#navigation) 属性决定了文档的结构和信息层级。

正确配置导航后，你可以更好地组织内容，让用户准确找到所需信息。

在导航的根级别选择一种主要组织模式。选定主要模式后，你可以在其中嵌套其他导航元素。

<div id="pages">
  ## 页面
</div>

页面是最基础的导航组件。每个页面都是文档仓库中的一个 MDX 文件。

<img className="block dark:hidden pointer-events-none" src="/images/navigation/pages-light.png" alt="页面装饰示意图。" />

<img className="hidden dark:block pointer-events-none" src="/images/navigation/pages-dark.png" alt="页面装饰示意图。" />

在 `navigation` 对象中，`pages` 是一个数组，其中每个条目都必须引用某个[页面文件](/zh/organize/pages)的路径。

```json
{
  "navigation": {
    "pages": [
      "settings",
      "pages",
      "navigation",
      "themes",
      "custom-domain"
    ]
  }
}
```

<div id="groups">
  ## 分组
</div>

使用分组可将侧边栏导航整理为不同的区段。你可以在分组中嵌套其他分组，为其添加标签，并用图标设置样式。

<img className="block dark:hidden pointer-events-none" src="/images/navigation/groups-light.png" alt="分组的装饰性图示。" />

<img className="hidden dark:block pointer-events-none" src="/images/navigation/groups-dark.png" alt="分组的装饰性图示。" />

在 `navigation` 对象中，`groups` 是一个数组，其中每一项都是一个对象，必须包含 `group` 字段和 `pages` 字段。`icon`、`tag`、`root` 和 `expanded` 字段为可选项。

```json
{
  "navigation": {
    "groups": [
      {
        "group": "Getting started",
        "icon": "play",
        "pages": [
          "quickstart",
          {
            "group": "Editing",
            "expanded": false,
            "icon": "pencil",
            "pages": [
              "installation",
              "editor"
            ]
          }
        ]
      },
      {
        "group": "Writing content",
        "icon": "notebook-text",
        "tag": "NEW",
        "pages": [
          "writing-content/page",
          "writing-content/text"
        ]
      }
    ]
  }
}
```

<div id="root-page">
  ### 根页面
</div>

使用 `root` 属性为分组指定一个主页面。为分组设置根页面后，点击侧边栏导航中的分组标题即可打开该根页面。根页面既适用于顶层分组，也适用于嵌套分组。

```json Example group with a root page
{
  "navigation": {
    "groups": [
      {
        "group": "API pages",
        "root": "api-overview",
        "pages": [
          "api-reference/get",
          "api-reference/post",
          "api-reference/delete"
        ]
      }
    ]
  }
}
```

<div id="directory-listings">
  ### 目录列表
</div>

使用 `directory` 属性，可以在分组的根页面上自动渲染子页面和子分组的目录列表。当你在 `docs.json` 的 `navigation` 树中任意对象上设置 `directory` 时，`root` 页面与该对象对应或位于其下级的分组，会在页面内容下方显示其页面和分组的列表。

`directory` 属性支持三个值：

| 值             | 行为                 |
| :------------ | :----------------- |
| `"none"`      | 不显示目录列表。默认值。       |
| `"accordion"` | 以按区段分组的可折叠列表显示子页面。 |
| `"card"`      | 以水平卡片布局显示子页面。      |

`directory` 的值会沿导航树递归继承。你可以在导航对象中的任意位置设置它，所有后代分组都会继承相同的值。任何后代都可以通过将 `directory` 设置为其他值来覆盖继承的值。

你可以在 `docs.json` 文件的导航对象中的任意位置设置 `directory`，包括 Tabs、锚点、下拉菜单、产品、版本、语言和各个分组。

```json
{
  "navigation": {
    "groups": [
      {
        "group": "Help Center",
        "root": "help/index",
        "directory": "accordion",
        "pages": [
          {
            "group": "Getting Started",
            "root": "help/getting-started/index",
            "pages": [
              "help/getting-started/quickstart",
              "help/getting-started/install"
            ]
          },
          {
            "group": "API Reference",
            "root": "help/api/index",
            "directory": "none",
            "pages": [
              "help/api/overview",
              "help/api/endpoints"
            ]
          }
        ]
      }
    ]
  }
}
```

在此示例中：

* **Help Center** 使用 `"accordion"`，其根页面会显示目录列表。
* **Getting Started** 从父级继承 `"accordion"`，其根页面同样会显示目录列表。
* **API 参考** 则用 `"none"` 进行覆盖，因此其根页面不会显示目录列表。

<Note>
  `directory` 属性仅影响具有 `root` 页面的分组。没有 `root` 页面的分组不受影响。
</Note>

<div id="default-expanded-state">
  ### 默认展开状态
</div>

使用 `expanded` 属性控制导航侧边栏中嵌套分组的默认状态。

* `expanded: true`：该分组默认展开。
* `expanded: false` 或省略：该分组默认折叠。

<Note>
  `expanded` 属性仅影响嵌套分组，也就是分组中的分组。顶级分组始终处于展开状态，且无法折叠。
</Note>

```json
{
  "group": "Getting started",
  "pages": [
    "quickstart",
    {
      "group": "Advanced",
      "expanded": false,
      "pages": ["installation", "configuration"]
    }
  ]
}
```

<div id="tabs">
  ## Tabs
</div>

Tabs 会通过不同的 URL 路径，将文档划分为多个独立部分。它还会在文档顶部生成一个水平导航栏，方便用户在这些部分之间切换。

<img className="block dark:hidden pointer-events-none" src="/images/navigation/tabs-light.png" alt="Tabs 导航的装饰图。" />

<img className="hidden dark:block pointer-events-none" src="/images/navigation/tabs-dark.png" alt="Tabs 导航的装饰图。" />

在 `navigation` 对象中，`tabs` 是一个数组，其中每一项都是一个对象，必须包含 `tab` 字段，还可以包含其他导航字段，例如 groups、pages、icons 或指向外部页面的链接。

```json
{
  "navigation": {
    "tabs": [
      {
        "tab": "API reference",
        "icon": "square-terminal",
        "pages": [
          "api-reference/get",
          "api-reference/post",
          "api-reference/delete"
        ]
      },
      {
        "tab": "SDKs",
        "icon": "code",
        "pages": [
          "sdk/fetch",
          "sdk/create",
          "sdk/delete"
        ]
      },
      {
        "tab": "Blog",
        "icon": "newspaper",
        "href": "https://external-link.com/blog"
      }
    ]
  }
}
```

<div id="menus">
  ### 菜单
</div>

菜单可为 Tab 添加下拉导航项。使用菜单可帮助用户直接跳转到 Tab 内的特定页面。

在 `navigation` 对象中，`menu` 是一个数组，其中每个条目都是一个对象，必须包含 `item` 字段，还可以包含其他导航字段，例如分组、页面、图标或指向外部页面的链接。

菜单项只能包含分组、页面和外部链接。

```json
{
  "navigation": {
    "tabs": [
      {
        "tab": "Developer tools",
        "icon": "square-terminal",
        "menu": [
          {
            "item": "API reference",
            "icon": "rocket",
            "groups": [
              {
                "group": "Core endpoints",
                "icon": "square-terminal",
                "pages": [
                  "api-reference/get",
                  "api-reference/post",
                  "api-reference/delete"
                ]
              }
            ]
          },
          {
            "item": "SDKs",
            "icon": "code",
            "description": "SDKs are used to interact with the API.",
            "pages": [
              "sdk/fetch",
              "sdk/create",
              "sdk/delete"
            ]
          }
        ]
      }
    ]
  }
}
```

<div id="anchors">
  ## 锚点
</div>

锚点会在侧边栏顶部添加固定显示的导航项。你可以使用锚点来划分内容板块、快速访问外部资源，或创建醒目的行动引导。

<img className="block dark:hidden pointer-events-none" src="/images/navigation/anchors-light.png" alt="锚点导航的装饰性图示。" />

<img className="hidden dark:block pointer-events-none" src="/images/navigation/anchors-dark.png" alt="锚点导航的装饰性图示。" />

在 `navigation` 对象中，`anchors` 是一个数组，其中每一项都是一个对象，必须包含 `anchor` 字段，也可以包含其他导航字段，例如 groups、pages、icons 或指向外部页面的链接。

```json
{
  "navigation": {
    "anchors": [
      {
        "anchor": "Documentation",
        "icon": "book-open",
        "pages": [
          "quickstart",
          "development",
          "navigation"
        ]
      },
      {
        "anchor": "API reference",
        "icon": "square-terminal",
        "pages": [
          "api-reference/get",
          "api-reference/post",
          "api-reference/delete"
        ]
      },
      {
        "anchor": "Blog",
        "href": "https://external-link.com/blog"
      }
    ]
  }
}
```

<div id="global-anchors">
  ### 全局锚点
</div>

对于需要在所有页面显示的链接，无论用户当前查看的是导航中的哪个部分，都请使用全局锚点。全局锚点尤其适合链接到文档外部的资源 (如博客、社区论坛或支持门户) ，也适合为重要的内部页面 (如更新日志或状态页面) 提供统一的访问入口。

全局锚点同时支持外部 URL 和指向文档内页面的相对路径。

```json
{
  "navigation": {
    "global":  {
      "anchors": [
        {
          "anchor": "Changelog",
          "icon": "list",
          "href": "/changelog"
        },
        {
          "anchor": "Blog",
          "icon": "pencil",
          "href": "https://mintlify.com/blog"
        }
      ]
    },
    "tabs": /*...*/
  }
}
```

  ## 产品

产品会在导航中创建一个专属分区，用于组织按产品划分的文档。你可以使用产品来区分文档中的不同产品、服务或主要功能集合。

在 `navigation` 对象中，`products` 是一个数组，其中每一项都是一个对象，必须包含 `product` 字段，也可以包含其他导航字段，例如分组、页面、图标或指向外部页面的链接。

```json
{

    "products": [
      {
        "product": "Core API",
        "description": "Core API description",    
        "icon": "api",
        "groups": [
          {
            "group": "Getting started",
            "pages": [
              "core-api/quickstart",
              "core-api/authentication"
            ]
          },
          {
            "group": "Endpoints",
            "pages": [
              "core-api/users",
              "core-api/orders"
            ]
          }
        ]
      },
      {
        "product": "Analytics Platform",
        "description": "Analytics Platform description",
        "icon": "chart-bar",
        "pages": [
          "analytics/overview",
          "analytics/dashboard",
          "analytics/reports"
        ]
      },
      {
        "product": "Mobile SDK",
        "description": "Mobile SDK description",
        "icon": "smartphone",
        "href": "https://mobile-sdk-docs.example.com"
      }
    ]
  }
}
```

<div id="openapi">
  ## OpenAPI
</div>

将 OpenAPI 规范直接集成到导航结构中，即可自动生成 API 文档。你可以创建专门的 API 章节，也可以将端点页面放在其他导航组件中。

你可以在导航层级的任意级别设置默认的 OpenAPI 规范。除非子元素定义了自己的规范，否则会继承该规范。

<Note>
  当你为某个导航元素 (例如锚点、Tab 或分组) 添加 `openapi` 属性，但未指定任何页面时，Mintlify 会自动为 OpenAPI 规范中定义的**所有端点**生成页面。

  如需控制显示哪些端点，请在 `pages` 数组中显式列出所需的端点。
</Note>

如需详细了解如何在文档中引用 OpenAPI 端点，请参阅 [OpenAPI 设置](/zh/api-playground/openapi-setup)。

```json
{
  "navigation": {
    "groups": [
      {
        "group": "API reference",
        "openapi": "/path/to/openapi-v1.json",
        "pages": [
          "overview",
          "authentication",
          "GET /users",
          "POST /users",
          {
            "group": "Products",
            "openapi": "/path/to/openapi-v2.json",
            "pages": [
              "GET /products",
              "POST /products"
            ]
          }
        ]
      }
    ]
  }
}
```

<div id="versions">
  ## 版本
</div>

将导航划分为不同版本。你可以通过下拉菜单选择版本。

<img className="block dark:hidden pointer-events-none" src="/images/navigation/versions-light.png" alt="版本切换器的装饰性示意图。" />

<img className="hidden dark:block pointer-events-none" src="/images/navigation/versions-dark.png" alt="版本切换器的装饰性示意图。" />

在 `navigation` 对象中，`versions` 是一个数组，其中每一项都是一个对象，必须包含 `version` 字段，也可以包含其他任意导航字段。

```json
{
  "navigation": {
    "versions": [
      {
        "version": "1.0.0",
        "groups": [
          {
            "group": "Getting started",
            "pages": ["v1/overview", "v1/quickstart", "v1/development"]
          }
        ]
      },
      {
        "version": "2.0.0",
        "groups": [
          {
            "group": "Getting started",
            "pages": ["v2/overview", "v2/quickstart", "v2/development"]
          }
        ]
      }
    ]
  }
}
```

<div id="default-version">
  ### 默认版本
</div>

Mintlify 默认使用 `versions` 数组中的第一个版本。使用 `default` 字段可将其他版本设为默认版本。

```json
{
  "navigation": {
    "versions": [
      {
        "version": "1.0.0",
        "groups": [
          {
            "group": "Getting started",
            "pages": ["v1/overview", "v1/quickstart"]
          }
        ]
      },
      {
        "version": "2.0.0",
        "default": true,
        "groups": [
          {
            "group": "Getting started",
            "pages": ["v2/overview", "v2/quickstart"]
          }
        ]
      }
    ]
  }
}
```

<div id="version-tags">
  ### 版本标签
</div>

使用可选的 `tag` 字段，为版本选择器下拉菜单中的版本条目添加徽章。你可以用标签突出显示特定版本，例如 &quot;最新&quot;、&quot;推荐&quot; 或 &quot;测试版&quot;。

```json
{
  "navigation": {
    "versions": [
      {
        "version": "2026_03",
        "tag": "Latest",
        "groups": [
          {
            "group": "Getting started",
            "pages": ["getting-started", "quickstart"]
          }
        ]
      },
      {
        "version": "2025_12",
        "tag": "Recommended",
        "groups": [
          {
            "group": "Getting started",
            "pages": ["2025_12/getting-started", "2025_12/quickstart"]
          }
        ]
      },
      {
        "version": "2025_09",
        "tag": "Deprecated",
        "groups": [
          {
            "group": "Getting started",
            "pages": ["2025_09/getting-started", "2025_09/quickstart"]
          }
        ]
      }
    ]
  }
}
```

<div id="nesting">
  ## 嵌套
</div>

在导航层级结构的每一层中，每个导航元素只能包含一种类型的子元素。例如，Tabs 可以包含锚点，而锚点又可以包含分组；但 Tabs 不能在同一层级同时包含锚点和分组。

<div id="breadcrumbs">
  ## 面包屑导航
</div>

面包屑导航会在页面顶部显示完整的导航路径。某些主题默认启用面包屑导航，其他主题则默认不启用。你可以通过 `docs.json` 中的 `styling` 属性控制站点是否显示面包屑导航。

<CodeGroup>
  ```json 显示完整面包屑导航
  "styling": {
    "eyebrows": "breadcrumbs"
  }
  ```

  ```json 仅显示父级部分
  "styling": {
    "eyebrows": "section"
  }
  ```
</CodeGroup>

<div id="interaction-configuration">
  ## 交互配置
</div>

使用 `docs.json` 中的 `interaction` 属性，控制用户与导航元素的交互方式。

<div id="enable-auto-navigation-for-groups">
  ### 为导航分组启用自动导航
</div>

当用户展开某个导航分组时，某些主题会自动跳转到该组中的第一页。你可以使用 `drilldown` 选项覆盖主题的默认行为。

* 设置为 `true` 时，当用户选择某个导航分组，会强制自动跳转到第一页。
* 设置为 `false` 时，当用户选择某个导航分组，不会发生跳转，而只会展开或折叠该组。
* 保持未设置，则使用主题的默认行为。

<CodeGroup>
  ```json 强制跳转
  "interaction": {
    "drilldown": true  // 当用户展开下拉菜单时，强制跳转到第一页
  }
  ```

  ```json 阻止跳转
  "interaction": {
    "drilldown": false // 永不跳转，只展开或折叠该组
  }
  ```
</CodeGroup>
