`docs.json` 文件是你的 Mintlify 文档站点的核心配置文件。它控制站点的全局设置，包括品牌视觉、导航结构、集成、API 设置等。你可以将其视为站点的蓝图。

<div id="required-fields">
  ## 必填字段
</div>

您必须定义四个字段，才能构建一个可正常运行的网站。

| 字段               | 描述                           |
| ---------------- | ---------------------------- |
| `name`           | 您的项目或组织名称                    |
| `theme`          | 网站的布局[主题](/zh/customize/themes) |
| `colors.primary` | 以十六进制代码表示的品牌主色               |
| `navigation`     | 您的内容结构                       |

其他所有字段都是可选的。您可以在自定义和完善网站的过程中逐步添加它们。

<div id="minimal-configuration">
  ## 最小配置
</div>

为获得最佳编辑体验，请在 `docs.json` 顶部添加 `$schema` 引用。这样可在大多数编辑器中启用自动补全、验证和内嵌文档。

```json docs.json
{
  "$schema": "https://mintlify.com/docs.json",
  "theme": "mint",
  "name": "Your project name",
  "colors": {
    "primary": "#ff0000"
  },
  "navigation": {
    "groups": [
      {
        "group": "Home",
        "pages": ["index"]
      }
    ]
  }
}
```

<div id="split-configuration-with-ref">
  ## 使用 `$ref` 拆分配置
</div>

随着配置变得越来越复杂，你可以使用 `$ref` 引用将 `docs.json` 拆分成多个较小的文件。每个引用都指向一个单独的 JSON 文件，并在构建时解析。

你可以在 `docs.json` 的任意位置添加一个包含相对文件路径的 `$ref` 属性。Mintlify 会用引用文件的内容替换该 `$ref` 对象。

```json docs.json
{
  "$schema": "https://mintlify.com/docs.json",
  "theme": "mint",
  "name": "Acme Docs",
  "colors": {
    "primary": "#1a73e8"
  },
  "navigation": {
    "$ref": "./config/navigation.json"
  }
}
```

```json config/navigation.json
{
  "groups": [
    {
      "group": "Get started",
      "pages": ["index", "quickstart"]
    },
    {
      "group": "Guides",
      "pages": ["guides/first-steps", "guides/advanced"]
    }
  ]
}
```

* 被引用的文件可以包含自己的 `$ref` 引用。嵌套路径会相对于包含该引用的文件解析，而不是相对于 `docs.json`。
* 引用必须指向有效的 JSON 文件。
* 路径必须为相对路径，并且只能位于项目根目录内。不允许使用路径遍历 (例如 `../../outside`) 。
* 循环引用会导致构建错误。

<div id="merging-sibling-keys">
  ### 合并同级键
</div>

如果 `$ref` 解析为对象，Mintlify 会将同一代码块中的同级键合并到引用内容上，并以这些键的值优先覆盖引用中对应的键。如果 `$ref` 解析为非对象值 (例如数组) ，Mintlify 则会忽略所有同级键。

```json docs.json
{
  "appearance": {
    "$ref": "./config/appearance.json",
    "strict": true
  }
}
```

<div id="upgrading-from-mintjson">
  ## 从 `mint.json` 迁移
</div>

如果你的项目仍在使用已弃用的 `mint.json` 文件，请使用 [CLI](/zh/cli) 升级到 `docs.json`。

<Steps>
  <Step title="安装或更新 CLI">
    如果你尚未安装 [CLI](/zh/cli/install)，请先安装：

    <CodeGroup>
      ```bash npm
      npm i -g mint
      ```

      ```bash yarn
      yarn global add mint
      ```

      ```bash pnpm
      pnpm add -g mint
      ```
    </CodeGroup>

    如果你已经安装了 CLI，请确保它已更新到最新版本：

    ```bash
    mint update
    ```
  </Step>

  <Step title="创建 docs.json 文件">
    在文档仓库中，运行：

    ```bash
    mint dev
    ```

    此命令会根据你现有的 `mint.json` 生成一个 `docs.json` 文件。请检查生成的文件，确保所有配置都正确无误。
  </Step>

  <Step title="删除 mint.json 文件">
    确认 `docs.json` 配置无误后，你就可以安全地删除旧的 `mint.json` 文件。
  </Step>
</Steps>
